## 1. Question

> Thumbnails per version, named versions, "what changed" in words (per artboard / element), restore one artboard,
> object-scoped history from the journal; cloud and local parity

Brief additions: one version model for local git projects, local non-git projects and cloud cells; named-version
storage; the words-diff algorithm, its fallback and its **measured** accuracy on a fixture corpus built from real
history; one-artboard restore as a new version (C5: Now is never rewritten); object-scoped history (B11: "may be

kernel over `bun:sqlite` in `_state/`. V2-1.16 binds: a canvas-scoped member learns nothing about other canvases'

## 3. Options

**Words ("what changed").**
1. **Plan default — artboard line ranges.** Changed lines → the artboard whose line range holds them → style props
   in words; else "Changed layout in <artboard>". *Breaks:* on this repo's git history **77.8 %** of versions touch a
   line outside every artboard body (shared components, data arrays, the canvas frame), which the default can only
   answer canvas-wide; on real studio edits **44.8 %** (§6). It also cannot see the CSS lane, where most v2 canvases
   keep their look.
2. **AST describer (chosen; the default's intent, made structural).** Parse both versions (oxc, as V2-1.4/1.5),
   match artboards by id and elements A↔B, compare props; declarations outside artboards are diffed the same way and
   attributed through V2-1.5's reference closure; the CSS lane is diffed per rule and mapped to the elements whose
   classes the selector names; the meta lane per artboard. The fallback stays exactly the default's sentence.
   Canvas-wide fallback: **0.3 %** of real studio edits, **14.8 %** of git versions (§6).
3. **AI-written summaries.** A2 makes AI bring-your-own and absent for Can view / Can comment (C30); not
   deterministic, costs a run per version, cannot run in a browser tab. Rejected for v2.0.
4. **A text diff only.** Rejected: CONTRACT §3 (no code words outside Advanced).

**Version model.** (a) every action is a row — a designer's 10 minutes of nudging becomes 40 rows; (b) **rows are
derived groups of actions (chosen)**; (c) explicit save points — contradicts 05 "Every change is kept on its own.
There's nothing to save."

**Local projects.** (i) **V2-1.5's local kernel (agreed, §5.3)**; (ii) git as the history — non-git projects get
none, no AI rows, no per-person undo; (iii) `_history/<slug>/` snapshots — structural edits only, per Mac, no actor.

**Named versions.** (A) **a kernel op + an additive `names` table (chosen)**; (B) a versioned `.meta.json` key —
naming would itself be a content change (a new version), and revision numbers mean nothing to a git or Syncthing
peer; (C) git tags — git-only, and Maude does not write git under the person (d_e9f5d…).

**Seeing a past version.** (a) today's build (old TSX, today's CSS + layout) — wrong whenever the CSS lane moved:
**39 %** of the versions that changed a canvas's TSX in this repo also changed its same-name CSS (§6); (b) **overlay
the version's own lanes (TSX, CSS, meta) and keep shared modules as they are now (chosen)**; (c) check out the whole
tree at the version — no tree exists for kernel revisions, and file-plane files have no history (d_e3072…).

**Restore one artboard.** (α) **splice the artboard and the declarations / CSS rules only it uses; keep shared parts
as they are now and say so (chosen)**; (β) fork shared parts into copies — faithful pixels, but the artboard silently
stops following the shared component; (γ) whole-canvas restore only — fails 11 `pn-compare`.

**Object-scoped history.** (a) **derived on read from the op log (chosen, B11)**; (b) a stored per-object log — a
second history to keep consistent with undo, restore, moves and peers.

## 4. Decision (DDR draft)

**Title:** One version model over the kernel action log for every project; rows are derived groups; "what changed"
is an AST describer with the default's fallback; named versions are a kernel op; the past renders from its own
lanes; one-artboard and one-object restores are new versions; object history is derived from the journal.

**Context.** B11 promises pictures, names, words, a narrow restore and object history, with cloud/local parity. Today
only synced projects in transactions mode have a history (the kernel), local projects have none, a past version
renders with today's CSS, and nothing turns a change into words. V2-1.5 made the kernel action log the op log for
every project and asked this spike to agree to the local store.

**Decision.**
1. **A version is an accepted kernel action that changed a canvas** — any of its lanes but `comments`, or its
   manifest entry (create, move, trash, restore). One model everywhere: synced projects read the hub store; local
   projects (git or not) read the same kernel running in-process (point 2). Git commits are not versions; they live
   under Version history › Advanced (06 `ad-history`, d_2fb53ddb).
2. **Agreement to V2-1.5 Q5.** Local projects run `kernel.mjs` + `store-core.mjs` over `bun:sqlite` at
   `<designRoot>/_state/project-store.sqlite`, with the four conditions of §5.3 (machine stamp + foreign-store rule,
   single writer, baseline, gzip bodies).
3. **Rows are derived, never stored** (§5.1 rule G): one row per AI run, restore, chat undo, trash, outside change,
   baseline or kept-aside version; a person's consecutive edits on one canvas group while gaps stay ≤ 10 min and the
   row spans ≤ 60 min, never across a name or another actor's version.
4. **Words** come from `describeChanges(before, after)` (§5.5): designer words per artboard and element, attributed
   through the reference closure; anything it cannot say becomes "Changed layout in <artboard>", and only
   unattributable module code becomes "Changed this canvas". Computed where the version lands, cached per
   `(actionId, canvas)` in V2-1.17's attribution cache, recomputable.
5. **Named versions** (§5.4): kernel op `history.name { doc, revision, name | null }`, an action of kind `name`
   (never a row, never an undo entry) plus an additive `names` table. Names are per canvas.
6. **The past renders from its own lanes** (§5.6): a historical build overlays the version's TSX, same-name CSS and
   `.meta.json`; shared modules, the design system and assets render as they are now. One path for time travel,
   Compare, pictures (V2-1.17 `thumb({ at })`) and "export a past version" (B4).
7. **Every restore is a new version** (C5): whole canvas (`history.restore`), one artboard (studio-computed splice
   published as one `lane.replace` proposal, kind `restore`), one object, "Go back to 14:05". Nothing is rewound.
8. **Object-scoped history is derived from the journal** (B11): keyed by V2-1.4 `ElementRef` (exact) or an
   annotation element id; versions before the element had an id are re-found by chained matching that stops on
   ambiguity and are marked "found by matching".
9. **The version you didn't keep stays a version** (10 `co-conflict`, 13 ds conflict pick, V2-1.12 kept-aside
   edits): additive kernel op `history.aside` records the losing body as an effect without moving any head, so it
   is listed and restorable for everyone.
10. **v2.0 deletes no version.** Retention is measured (§5.15) and left to a later DDR; Advanced shows the size.

**Consequences.**
- Positive: one history under Version history, ⌘Z (V2-1.5), "Undo this chat", object history and Compare, the same on
  a Mac, in a cloud tab and offline (read); words are right for 96–97 % of single edits; in real history "Changed layout
  in" covers 9–11 % of changed artboards and "Changed this canvas" 0.3 % (studio edits) to 15 % (git) of versions,
  against 45–78 % canvas-wide for line ranges; local projects gain a real history.
- Negative: a local project keeps a growing SQLite store; the hub gains three additive ops (`history.name`,
  `history.aside`, V2-1.5's `actionIds`) and one table; a one-artboard restore of an artboard that leans on shared
  code is not pixel-identical to the old version (it says which parts stay as now); cloud tabs show no row pictures in
  v2.0 (V2-1.17: cells render nothing); `http.ts` `serveHistoricalCanvas` and the shell's meta injection change
  (lead patch).
- Extends DDR-113 (historical build overlays the canvas's own lanes), DDR-241 (two ops, one table, gzip bodies in the
  local home), V2-1.5 (row grouping, the local store conditions). Amends V2-1.11's verb rows (§5.11).

**Rejected:** Options 1, 3, 4 (words); (a) and (c) (model); (ii), (iii) (local); (B), (C) (names); (a), (c)
(render); (β), (γ) (restore); (b) (object history); pruning in v2.0.

## 5. Contract

### 5.1 Version model

```ts
/** A point in a canvas's history, as it travels on the wire. */
type VersionRef =
  | `r${number}`                 // kernel revision (already accepted by `?sha=` — http.ts serveHistoricalCanvas)
  | `git:${string}`;             // a commit, Version history › Advanced only (local git, cloud cell git)

/** One accepted action as one canvas sees it (V2-1.5 §5.1 ActionRow + per-canvas fields). */
interface Version {
  ref: `r${number}`; actionId: string; actor: string; mine: boolean;
  kind: 'edit' | 'ai' | 'undo' | 'redo' | 'restore' | 'outside' | 'trash' | 'migration.import' | 'aside' | string;
  label: string | null; madeAt: number; committedAt: number; partial?: boolean;
  runId?: string; chatId?: string; undoes?: string[];
  canvas: string;                // designRoot-relative path at that revision (follows moves via the entry)
  artboards: string[];           // V2-1.5 §5.7 attributeArtboards
}

/** What Version history lists. Derived from Version[] by rule G; never stored. */
interface VersionRow {
  id: string;                    // first actionId of the row (stable while the row is open)
  ref: `r${number}`;             // the row's LAST revision: Restore, Compare, picture and Viewing use it
  from: `r${number}` | null;     // the revision before the row's first action (null = canvas created here)
  canvas: string;
  who: { kind: 'person' | 'ai' | 'outside'; actor: string; name: string; you: boolean };  // ai = that person's AI
  kind: 'edit' | 'ai' | 'restore' | 'undo' | 'outside' | 'trash' | 'baseline' | 'aside' | 'moved';
  title: string;                 // §5.5.4
  sub: string;                   // "14:32 · Venkovní dres · přední" (ai) | "14:05 · You" | "18:40 · Jonas" (named)
  named?: { name: string; by: string; at: number };
  chips: Array<'Named' | 'Made by AI' | 'Restored' | 'Stopped' | 'Not kept'>;
  artboards: string[];           // changed artboards, most changes first; [0] is the picture's artboard
  changes: number;               // count of change lines (§5.5)
  actions: string[];             // actionIds in the row — Undo history, multi-target undo (V2-1.5 §5.2)
  thumb: ThumbRequest | null;    // V2-1.17 §5.8, at: { rev }
}
```

**Visible versions of canvas C:** actions with an effect on C's entry in lanes `html css meta annotations`, or a
`@manifest` effect on it (`create delete move`), excluding kinds `name` and `comment` and comments-only actions.
Viewport and selection never reach the log (V2-1.5).

**Rule G (rows).** Walk the visible versions oldest → newest; version *x* joins the open row *R* iff all hold:
- `R.kind = 'edit'` and *x* is an `edit`, or an `undo`/`redo` whose targets all lie inside *R* (⌘Z tinkering);
- same actor, same `who.kind`;
- `x.madeAt − R.last.madeAt ≤ 10 min` and `x.madeAt − R.first.madeAt ≤ 60 min`;
- no named revision ends *R*, and no other actor's version of C lies between them.

Every `ai` run (one action, V2-1.5), `restore`, chat / history `undo`, `trash`, `outside`, `migration.import`
(→ `baseline`), `aside` and a move is a row of its own. Naming a revision inside a row splits the row there. The
thresholds are constants of the row reducer (`client/v2/history/rows.ts`), changeable without migration.

**Now row** (11 `pn-vh-now`): "Now · <canvas> · <save status word>" (CONTRACT §6, C2) + "Name this version…"
(`edit`). It names the newest accepted version of C; while C has unsent changes the button reads "Saving…" and is
disabled.

**Filters** (11 owns; 03 drew three): All · Named · Made by AI · People. Named = rows with `named`; Made by AI =
`kind 'ai'`; People = `who.kind 'person'`. `outside`, `baseline`, `aside` show under All.

### 5.3 The local store — agreement to V2-1.5 Q5, with four conditions

1. **One machine per store.** `store_meta.machine` = this install's id (the kgai `kg.config.json` lesson: shared
   identity forks the shard). A store whose `machine` differs — a Syncthing / Dropbox / iCloud copy or a `cp -R` of
   the project — is never written: it is renamed `_state/project-store.<machine>.sqlite`, kept read-only, and listed
   in Version history › Advanced as "History from <Mac name>"; a fresh store starts with a baseline. Same rule as
   the unlink-before-boot memory for copied synced projects.
2. **One writer.** `_state/project-store.lock` (pid + boot id). A second studio on the same folder opens the store
   read-only and its edits wait ("Another Maude window is saving this project"). `journal_mode=WAL`,
   `synchronous=FULL` (DDR-241's self-host settings).
3. **Baseline.** The first v2 boot of a local project imports every canvas as one `migration.import` action per
   canvas (`baseline.mjs` shape). That row reads "Version history starts here"; for git projects the line under it
   adds "Earlier versions are in Advanced (git)"; for others "Earlier snapshots are in Advanced" (`_history/<slug>/`,
   read-only, `/design:rollback` keeps reading them).
4. **gzip bodies.** `createStoreCore(sql, { codec })` — an optional, additive codec (default identity) applied to
   `blobs.body`; the local home passes gzip (§6: 26–33 % of raw). The hub keeps plain bodies until its own release
   decides (Q4). The shared store conformance corpus runs with both codecs.

Moving a local project to the cloud leaves its local store on that Mac: Version history shows the cloud's history,
and Advanced lists "Before it moved to the cloud (this Mac)" read-only (Q3). Disconnecting a cloud project starts a
local store with a baseline; the cloud's history stays in the cloud.

### 5.4 Named versions

**Kernel op** (hub, additive, ships in V2-2.18 with V2-1.5's extension; the local kernel has it from day one):

```ts
{ op: 'history.name', doc: string, revision: number, name: string | null }   // null removes the name
```

- Needs `edit` on `doc` (V2-1.16 L4 per-op rule; observers and viewers are refused; canvas-only editors only on
  their canvases). `revision ≤ head`; if `revision` did not change `doc`, the kernel snaps it to the newest revision
  `≤ revision` that did. `name`: trimmed, 1–80 characters, no control characters; duplicates allowed.
- Commits one action `kind: 'name'`, `label: name`, no lane effects, and upserts the additive table
  `names (entry TEXT, target_rev INTEGER, name TEXT, actor TEXT, at INTEGER, rev INTEGER, PRIMARY KEY (entry, target_rev))`
  in the same transaction (`CREATE TABLE IF NOT EXISTS`; `store.names(entry)` reader). Newest write wins; a `null`
  deletes the row (the `name` action stays in the log).
- `kind 'name'` is not a row (it decorates the target row), not in V2-1.5's undo projection, and not counted in U5
  aggregates. Peers learn names from the revision feed like any action.
- A v1 studio never sends it; a v2 studio against a hub without it gets `invalid` and shows "Naming versions needs the
  team server to be updated" (V2-1.5 Q2 pattern).

**Words:** row title = the name; chip "Named"; sub "<time> · <who named it>". A restore of a named version is
labelled "Restored “<name>”" (11 `pn-history`).

### 5.5 "What changed" — `describeChanges`

```ts
// apps/studio/history/describe.ts (new; prototype: apps/studio/scratch-v2-spike/describe.ts, not committed)
interface Lanes { tsx: string; css?: string | null; meta?: string | null; annotations?: string | null }
type Grade = 'W1' | 'W2' | 'F';
interface Change {
  artboards: string[];           // [] = canvas level
  grade: Grade;                  // W1 element/artboard + property + before → after · W2 element named, change unspecified · F fallback
  kind: 'style' | 'text' | 'attr' | 'class' | 'content' | 'added' | 'removed' | 'wrapped' | 'unwrapped' | 'moved'
      | 'reordered' | 'data' | 'css' | 'artboard-added' | 'artboard-removed' | 'artboard-renamed' | 'artboard-resized'
      | 'artboard-moved' | 'artboard-reordered' | 'artboard-settings' | 'section' | 'canvas-text' | 'imports'
      | 'annotation' | 'meta' | 'layout' | 'canvas';
  words: string;                 // CONTRACT §3–§4 voice
  element?: ElementRef | { artboard: string; print: string };   // V2-1.4; print for unstamped elements
  prop?: string;                 // source property, for blame keys and object history
}
function describeChanges(canvas: string, before: Lanes, after: Lanes): { changes: Change[]; ms: number };
```

**5.5.1 Algorithm.**
1. **Parse** both sides (oxc). Comments are blanked first (same length, offsets kept) — a comment change is no change.
2. **Artboards** by `DCArtboard id`; a template id (`` id={`disc-${d.id}`} ``) is a family keyed `disc-*` (one entry,
   every instance). Added / removed / renamed (`label`) / resized (`width`, `height`) / canvas order.
3. **Elements** per artboard (JSX children, JSX inside expressions and JSX in attribute slots such as
   `note={<Note>…</Note>}`). Matched A↔B: authored `data-cd-id` (V2-1.4) → unique identical subtree → top-down
   child alignment (LCS on tag + name + classes + text) → mutual best by score → a stricter global mutual-best pass
   for moves (score ≥ 5, margin ≥ 2). Matched pairs compare inline style keys, literal attributes, classes, own text,
   expression content, parent (moved into …) and sibling order (moved up/down); top-most unmatched elements are
   added / removed, or wrapped / unwrapped when they hold matched elements. Every `data-cd-*` is ignored (canvas-only).
4. **Declarations outside artboards** (components, data arrays, constants) that differ are diffed the same way —
   JSX roots paired, data arrays item by item, literals one by one — and each change is attributed to every artboard
   whose JSX reaches the declaration (V2-1.5 §5.7 closure; declarations the canvas frame renders, such as a
   `<WebStyles/>` beside the sections, reach every artboard). A declaration change it cannot put in words gives
   "Changed layout in <artboard>" for each artboard it reaches.
5. **The canvas frame** (`DesignCanvas`, `DCSection`): sections added / removed / reordered / retitled, frame texts.
   Anything else outside artboards and declarations, and imports that change nothing else, is the only path to
   "Changed this canvas" (a design-system import switch reads "Now uses the <ds> design system").
6. **CSS lane** (postcss): per rule (at-rule context + selector) and property. The selector's rightmost compound with
   classes names the elements (static class tokens, `cx()` / template / `"a-" + x` prefixes); the rule's artboards are
   theirs (declarations via the closure; elements gone since are looked up on the old side). A rule naming no element
   of the canvas is "Changed the style …" at canvas level (F) — the production describer first checks the canvas's
   import closure (kit-rendered classes) and drops rules nothing uses.
7. **Meta lane:** `layout.artboards[]` by id → moved / resized; top-level keys (`present`, `artboardMeta`, `links`,
   V2-1.12 §5.1) → canvas or artboard level words; `last_modified` and viewport keys never count.
8. **Annotations lane** (S4): by element id — "Sticky added", "Sticky: “old…” → “new…”", "Arrow moved", parented to
   `parentArtboard` (V2-1.12) when set.

**5.5.2 Words grammar** (English only, A20; mono never — CONTRACT §3):
- element name: `data-dc-element` → `aria-label` / `alt` / `title` / `label` / `name` → own text, first five words in
  quotes → component name in words ("Jersey") → role (`img` Image, `button` Button, `div` Frame, `h1`–`h6` Heading,
  `p`/`span` Text, `svg` Icon …); a change inside a shared component is prefixed "Jersey › ";
- property words: the reverse of S2's words → CSS table (`background` Fill, `color` Text colour, `fontSize` Font size,
  `borderRadius` Corner, `left`/`top` X/Y, `gap` Gap, …); unknown properties in sentence case;
- values: `var(--token)` → the token's display name (`tokens.json`, V2-1.13) else its name in words; colours → a
  colour word (black, white, grey, red … green, dark/light); numbers → "120 → 150 px"; keywords bare; long text →
  the changed words with two words of context ("…od 10 let" → "…od 9 let"); computed values → "a formula" (W2);
- shapes: `<El>: <Prop> <a> → <b>` · `<El>: <Prop> set to <b>` · `<El>: <Prop> removed (was <a>)` ·
  `<El> added` · `<El> removed` · `Frame added around <El>` · `<El> moved into <Parent>` · `<El> moved up` ·
  `Artboard “<label>” added / removed / renamed to “…”` · `<label>: size 390 × 800 → 1080 × 800` ·
  `<label> moved on the canvas` · `Changed layout in <label>` · `Changed this canvas`.

**5.5.3 Collapsing.** An artboard with more than 12 change lines, or whose elements were more than half added or
removed, shows one line "Reworked <label> — 624 changes" (expandable in Compare). A version row never shows more than
its title.

**5.5.4 Row titles** (CONTRACT §4 voice): named → the name · `ai` → the prompt, shortened to 60 characters (for a
canvas-only session: the words title instead, U4) · `restore` → "Restored “<name>”" / "Restored 5 Oct, 18:40"
(+ " — only <artboard>") · own-row `undo` → "Undid “<title>”" / "Undid a chat — 3 changes" · `outside` → the words
title, sub "· changed outside Maude" · `trash` → "Moved “<label>” to the trash" · `baseline` → "Version history starts
here" · `aside` → "Your version, not kept" / "Jonas's version, not kept" · `edit` → the first W1 change of the
primary artboard by priority (artboard added/removed/renamed > element added/removed > text > style/css/attr >
data > other) + " + N more"; only fallbacks → "Changed layout in <label>".

**5.5.5 Where it runs.** On the studio server that sees the action land (desktop sidecar, cell studio child, local
kernel), off the hot path, once per `(actionId, canvas)`, cached by V2-1.17's `attribution-cache` extractor next to
V2-1.5's artboard sets (never in `describe/`, which holds picture descriptions). A miss recomputes from the store's
before/after blobs; consecutive rows share a parse. Only lanes of that canvas are read, so a canvas-only session's
words never name another canvas.

### 5.6 Seeing a past version (Viewing)

- **Enter:** click a row (11 `pn-history`). The canvas switches to V2-1.2's Viewing slot, read-only (no tools, no AI,
  no soft locks); the bar reads "Viewing “<title>” · 5 Oct, 18:40 · Jonas" with "esc back to now". Selected-row
  actions: Compare · Restore this version (edit only; 04 `md-viewer`: Can view looks without Restore).
- **Build:** the canvas iframe loads `<canvas>.tsx?sha=<VersionRef>` on the canvas origin (unchanged route). The
  historical build overlays the version's **same-name CSS lane** and **meta lane**:
  `BuildCanvasOptions.overrides?: Record<absPath, string>` (`canvas-build.ts`, S1) — the CSS `onLoad` uses an
  override when present; `serveHistoricalCanvas` passes `{ <canvas>.css: cssAt(ref) }` and the shell injects
  `window.__canvas_meta__` from `metaAt(ref)` when the URL carries `sha` (**lead patch**, `http.ts`). The cache key
  keeps `(path, ref)`. Shared modules, DS CSS, fonts and assets resolve as they are now (stated in Advanced: "Shared
  parts show as they are now"). Content-addressed assets don't change; the usage index keeps assets referenced by
  any retained version (V2-1.17 history refs).
- **Sources per ref:** `r<rev>` → `laneAt(doc, lane, rev)` (hub) / the local store; `git:<sha>` → `gitShowFile`, then
  the cloud's `/api/history/file`. `cssAt`/`metaAt` use the same source as the TSX.

### 5.7 Compare (11 `pn-compare`)

- **A / B:** the selected row is A, Now is B; clicking a second row while comparing makes it B ("A" / "B" marks on
  rows). The canvas area shows the first changed artboard at A and at B as two isolated, read-only canvas iframes
  (DiffView's `CanvasView`, `?sha=` + hide-chrome + artboard focus — two iframes because both versions' CSS cannot
  share one document), "Side by side | Overlay".
- **List:** `describeChanges(lanes(A), lanes(B))` grouped by artboard; header "4 changes between A and B — 3 on
  Venkovní dres · přední, 1 on Helma z boku". Each line names the version that made it (face or spark + time): the
  newest row in (A, B] whose own cached description has a change with the same key (artboard + element + kind +
  property); none found → no face ("changed in between"). Clicking a line focuses its artboard.
- **Actions:** "Stop comparing" · "Restore only <artboard>" (§5.8, shown when A holds that artboard and it changed) ·
  "Restore this version". The why-line names what Restore takes back from others, from the same blame:
  "Restores the whole canvas as it was at A, as a new version — Tereza's helmet logo goes too. Now stays in the list."
- **Compare pictures** (D10) under Version history › Advanced: DiffView full panel with A/B as `?sha=` panes, side by
  side / overlay wipe / locked zoom, unchanged.

### 5.8 Restores (C5: every one is a new version)

| Restore | How | Label | Refused when |
| --- | --- | --- | --- |
| **This version** (whole canvas) | kernel `history.restore { revision, docs: [doc] }` (lanes `html css meta annotations`, as today) | "Restored “<name>” / 5 Oct, 18:40" | the canvas was trashed since (Trash restores it first) |
| **Only <artboard>** | studio computes the splice (below) and proposes `lane.replace` for each changed lane with `baseContent` = the head it read, one proposal, `kind: 'restore'`; the kernel merges three-way onto the head | "Restored <label> to 5 Oct, 18:40" | the artboard is not in A (`not-in-version`), is a mapped family (`family`), or the result does not parse (`invalid-result`) → "Can't restore only <label> — restore the whole canvas instead." |
| **One object** (object history) | annotation element: the annotations lane with that element replaced by its old record (by id); canvas element with an authored id in both versions: its source range replaced by the old element's (re-inserted after its old previous sibling when gone) | "Restored <element> to yesterday 21:40" | the element has no id at that version (matched rows) → "Restore the artboard instead" |
| **Go back to 14:05** (01 `cf-err`) | whole restore to `lastGood(canvas)` = the newest revision this Mac rendered without error (`_state/render-ok.json { [canvas]: { ref, srcHash } }`), else the newest whose TSX passes `sourceError` and builds. When the broken content is an un-accepted disk candidate (an outside write the kernel refused), Go back re-projects the accepted head and keeps the candidate in `_history/<slug>/` — no version | "Went back to 14:05" | — |
| **A version you didn't keep** | as This version, from the `aside` body | "Restored your version from yesterday 21:40" | — |

**The one-artboard splice** (`restoreArtboard(canvas, now, old, id)`, prototype `restore.ts`):
1. Replace the artboard's element range in Now with A's; if it was removed since, insert it after the nearest earlier
   artboard (A's order) that still exists, else before the next one.
2. Every declaration A's artboard reaches: unchanged → nothing; reached **only** by this artboard now → restored
   (or added back before the canvas component); reached by other artboards or the frame → kept as now and listed in
   `sharedKept`. Imports A's artboard needs that Now lacks are added.
3. CSS rules whose every class is used only inside this artboard (in A and in Now) → A's rule; others kept and listed.
4. Meta: `layout.artboards[id]` and per-artboard maps (`artboardMeta[id]`, V2-1.12 R6) → A's.
5. Annotations whose `parentArtboard` is `id` → A's records by id (added-since ones go; they stay in Version history).
6. Parse check; the why-line: "Restores Venkovní dres as it was at A, as a new version. It uses parts other artboards
   share — Jersey, 2 styles — they stay as they are now." (only when `sharedKept` is non-empty).

**Undo of a restore** = ⌘Z / the toast's Undo (V2-1.5 U16) — today's "Undo a restore" banner (D10).

### 5.9 Object-scoped history (B11)

- **Key:** `ElementRef` (V2-1.4) for canvas elements; the annotation element id (`.annotations.json`, V2-1.12) for
  stickies, arrows, stickers. Comments keep their own thread history (not here).
- **Derivation:** filter the canvas's cached descriptions (§5.5.5) for changes whose `element` is the key; an element
  with an authored id is exact in every version that carries the id. For versions before its id was stamped, walk
  back by chained matching (§5.5.1 step 3) and **stop at the first step without a mutual-best match** — never guess;
  those rows are marked "found by matching" (Advanced shows why). Opening an object's history is a durable reference:
  it queues a stamp for an unstamped element (V2-1.4 §4.3; a Can view / Can comment person never causes a write).
- **Rows:** the object's versions (one per action that changed its own props, text, attributes, or added / removed /
  moved it), each "<who> · <time>" + the value at that version (a sticky's text quoted, 10 `co-vh`), Restore per row
  (`edit`).
- **Entry points:** the sticky / annotation menu "Version history" (10 `co-conflict`, header "Version history ·
  this sticky"); for canvas objects the object menu › "Version history" (opens Version history filtered to the
  object, header "· this object") — Q6.

### 5.15 Storage and retention (v2.0: nothing deleted)

- The store keeps every accepted lane body whole. Measured per version (§6): git history median 46.5 KB whole,
  10.2 KB gzipped (26 %), 1.3 KB as a delta; studio edits median 2.5 KB, 1.1 KB gzipped (33 %), 163 B as a delta.
- Projection (assumption: a 100 KB canvas, 200 accepted actions a working day): ~20 MB/day raw, ~5–6 MB gzipped,
  ~0.3 MB as deltas. A busy month on one canvas: ~400 MB raw, ~110 MB gzipped.
- v2.0: local bodies gzipped (§5.3); hub bodies as today (Q4); no pruning. Version history › Advanced and Diagnostics
  show "History on this Mac: 240 MB" (local) / "History on the team server: 1.2 GB" (hub `store_meta` sum).
- A later pruning DDR must never touch: heads, named revisions, `restore` / `ai` / `aside` actions, every row's last
  revision, anything younger than 30 days; it prunes bodies only (rows stay), calls V2-1.17 `forgetVersion`.

## Decisions

- `decision:maude/v2-V2-1.9-one-version-model`: a version is an accepted kernel action that changed a canvas; rows
  are derived groups (rule G), never stored; git commits live only under Advanced. Rejected: every action a row,
  explicit save points, git as the version store.
- `decision:maude/v2-V2-1.9-local-store-agreed`: V2-1.5 Q5 agreed — the in-process kernel over `bun:sqlite` in
  `_state/` — with a machine stamp (a copied store is moved aside, never written), one writer, a baseline import and
  gzip bodies. Rejected: git-only or `_history/`-based local history.
- `decision:maude/v2-V2-1.9-ast-words-diff`: "what changed" is an AST describer (artboards, elements, closure-attributed
  declarations, CSS lane rules, meta) with the plan default's sentence as fallback; measured 96.7 % words right on
  767 synthetic edits, canvas-wide fallback 0.3 % on 317 real studio edits vs 44.8 % for line ranges. Rejected:
  line-range attribution, AI-written summaries, text diffs.
- `decision:maude/v2-V2-1.9-named-versions-kernel-op`: named versions are kernel op `history.name` (kind `name`,
  never a row) plus an additive `names` table, per canvas, `edit` to write. Rejected: a versioned `.meta.json` key,
  git tags.
- `decision:maude/v2-V2-1.9-past-renders-own-lanes`: a historical build overlays the version's TSX, same-name CSS and
  meta (`BuildCanvasOptions.overrides`, lead patch in `serveHistoricalCanvas`); shared modules render as now. One path
  for Viewing, Compare, pictures and past-version export. Rejected: today's TSX-only swap (wrong look for 39 % of
  versions), a whole-tree checkout.
- `decision:maude/v2-V2-1.9-restores-are-versions`: whole, one-artboard (splice + exclusive closure, shared parts kept
  and named), one-object and "Go back" restores are all new versions. Rejected: forking shared parts, rewinding.
- `decision:maude/v2-V2-1.9-object-history-derived`: B11 — object-scoped history is derived on read from the op log,
  keyed by `ElementRef` / annotation id; pre-stamp versions by chained matching that stops on ambiguity. Rejected: a
  stored per-object log.
- `decision:maude/v2-V2-1.9-kept-aside-versions`: the side a person didn't keep (conflict, DS pick, first-sight) is
  recorded by additive kernel op `history.aside` and stays a restorable version for everyone. Rejected: per-Mac
  `_history/` copies only.
- `decision:maude/v2-V2-1.9-no-pruning-in-v2`: v2.0 deletes no version; storage is measured and shown; a retention DDR
  comes before GA. Rejected: pruning or delta chains in v2.0.
