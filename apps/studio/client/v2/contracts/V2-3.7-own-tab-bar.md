# V2-3.7 spike: our own tab bar

**Decision.** Option **B**: Maude has ONE native window, `shell`. Inside it are child webviews (Tauri 2 multi-webview,
`Window::add_child`): a tab-strip webview `strip` across the top, and one webview per tab (`home`, `p-<pid>`, later
`c-*`). Only the active tab's webview is shown. A switch is `show()` on the new tab and `hide()` on the old one.
Rust's `WindowBook` stays the only source of truth for the tab list. The strip is a trusted app-local page and only
displays what Rust sends it.

The design keeps the V2-3.2 guarantees:
- labels, the per-label `data_store_identifier`, `check_caller` on `webview.label()` and origin, open-once, rest/reap;
- e2e handles are labels.

It changes:
- capabilities move to `webviews`;
- the embedded WebDriver plugin is retargeted from `WebviewWindow` to `Webview` (59-line patch);
- the shell owns focus, close and layout itself.

This supersedes the native-tabbing part of V2-3.2 (`tabbing_identifier`, `addTabbedWindow:`).

Evidence: prototype `apps/desktop/src-tauri/src/tabbar_spike.rs` + `apps/desktop/src/spike-tabbar.html`. It is a debug
build with `--features tabbar-spike` and `MAUDE_TABBAR_SPIKE=a|b|c`, on branch `v2-3.7-own-tab-bar`, commit
`ec34becf` (do not merge). Test machine: macOS 26.5.1, screen unlocked, Tauri 2.12.1, wry 0.57.0. Runs: 4 of B (one of
them in fullscreen), 1 of C, 1 of A.

## 1. Measurements

| What | A: window per tab, untabbed, same frame | **B: one window + child webviews** | C: native tab group, bar hidden |

| Move / resize | must be synced by hand on every `Moved`/`Resized` | one frame (children need relayout, §3.3) | native |

Flicker was measured as switch → first rAF of the new tab. Nobody watched the switch on screen; that is open question 1.

Incidental finding: in `setup` (inside tao's event handler), calling `run_on_main_thread` → `addTabbedWindow:` runs
synchronously. It redraws, re-enters tao and **deadlocks** on tao's handler mutex (sampled). Production's
`attach_as_tab` uses the same call path at boot. B removes it.

## 2. Rejected alternatives

- **C, native tab group with the bar hidden.** AppKit keeps the bar visible with ≥ 2 tabs (measured). Without that, C
  is the V2-3.2 model, so it cannot pin Home or draw a dot.
- **A, one window per tab, frames kept in sync by hand.** It is as slow as native tabs (44–55 ms). Fullscreen means one
  Space per window. Mission Control, ⌘\`, the Window menu and the Dock all see N windows. The strip is duplicated in
  every project page, so every project page learns every other tab's name.
- **A titlebar Home button with native tabs kept** (option (a) of the kg decision). Michal chose an own bar.
- **Fork wry/tao for a tab-bar-less NSWindow tab group.** The private-API surface is too large to justify.

## 3. Mechanism

### 3.1 Topology

```
NSWindow "shell" (WindowBuilder; titleBarStyle Overlay, hiddenTitle; title = active tab's name)
├─ webview "strip"     tauri://localhost/strip.html   y=0,  h=38, full width   (app-local, trusted)
├─ webview "home"      Home origin                    y=38, rest of window      pinned, always exists
├─ webview "p-<pid>"   its project server origin      y=38, rest of window      one per open project
└─ webview "c-<hash>"  cell (later)                   same
```

- Labels and data stores are the V2-1.1 §5.2 rules unchanged. `strip` also gets its own store id.
- The canvas iframe stays inside its project webview, with the same protections (`invoke_key`, `CANVAS_SAFE_API`).
- The strip sits in the titlebar row. Its left 78 px are kept free for the traffic lights. Empty strip areas are
  `data-tauri-drag-region` (`core:window:allow-start-dragging` granted to `strip` only). A double-click on them zooms.

### 3.2 Source of truth and events

`WindowBook` (windows.rs) keeps `entries`, `tabs` (project/cell order, **Home never in it**) and `focused`, which
**means the active tab**. Every change goes through one function, `tabs::changed(app)`. It debounces for 16 ms and
emits to `strip` only:

```ts
// event "tabs://state" (emit_to strip); also returned by the strip's `tabs_state` command on mount
interface TabStripState {
  tabs: Array<{ label: string; kind: 'project' | 'cell'; name: string;   // name: sanitize_title'd
                dot: null | 'done' | 'needs-you'; resting: boolean; closing: boolean }>;
  home: { label: 'home' };           // pinned, drawn icon-only at the far right, never closable
  active: string;                    // a tab label or 'home'
}
```

Strip → Rust commands. Each one checks `caller label == "strip"` AND app-local URL (`is_app_local`):

| Command | Args | Effect |
| --- | --- | --- |
| `tabs_state` | — | the current `TabStripState` |
| `tab_activate` | `{label}` | `activate(label)` |
| `tab_close` | `{label}` (not `home`) | the user close path: `close_guard` (the "Stop AI in …?" confirm), then `close_tab` |
| `tab_reorder` | `{label, to}` | reorders `book.tabs`; session save |

`activate(label)` does, under one lock: book `focused = label` + `last_focused`. Then it shows the new webview, hides
the old one, calls `set_focus`, sets the window title, applies the menu role (§5), clears the dot, and runs today's
`on_focused` (mark_shown, `notify::project_focused`, wake a resting tab after `WAKE_SETTLE`, session save,
`home::state_changed`). The `shell` window's `Focused(true)` re-runs only the "window became key" half
(`updater::check_now`) for the active tab.

## 4. Home pinned, and relaunch

- Home is the right-most strip slot. It is icon-only (`aria-label="Home"`, tooltip "Home"), never closable, never
  reorderable, and **never in `book.tabs` or `session.tabs`**.
- ⌘W on Home does nothing (§5). The last project tab closing activates Home.
- New tabs go after the active tab, or at the end when Home is active. Home itself never moves.
- Save: `session.tabs` = project/cell tabs in strip order. `session.focused` = the active label, `"home"` included. The
  `app-state.json` schema does not change.
- Restore (`plan_tabs`, prototyped, 3 unit tests green):
  - project tabs come back in saved order, each pid once, only when its root still has `.design/`;
  - a `home` entry from a pre-V2-3.7 session is dropped. That entry was the stray Home tab;
  - `focused == "home"` → Home active;
  - a focused tab that is gone → the first survivor, else Home.
- Only the active tab spawns. A single-tab session takes the same path, not the `len() > 1` special case.
- `shell://tabs-restored {count}` goes to the active webview when count ≥ 2.

## 5. Menu enablement

`menu::apply_role(app, role)` runs on every `activate`. The prototype sets and reads back `set_enabled`.

| Item | Accel | On a project tab | On Home |
| --- | --- | --- | --- |
| New Canvas | ⌘N | enabled → `menu://action canvas.new` to the active tab | **disabled** |
| New Project… | ⇧⌘N | enabled (IdentityBar create dialog) | **enabled** → Home's create sheet (`menu://action project.new` to `home`) |
| Open Project… | ⌘O | enabled | enabled |
| New Home Tab → rename **Show Home** | ⌘T (keep) | enabled → `activate("home")` | **disabled** |
| Close Tab (new) | ⌘W | enabled → `tab_close` user path | **disabled** |
| Show Next / Previous Tab (new) | ⌃⇥ / ⌃⇧⇥ | cycle `tabs` then Home | same |
| Select Tab 1…8 / Home (new) | ⌘1…⌘8 / ⌘9 | tab by position; ⌘9 = Home | same |
| Window ▸ native tab items | | gone; nothing is native-tabbed | |

`menu.actions.json` is generated from the V2-1.3 action registry. New ids `tab.close`, `tab.next`, `tab.prev`,
`tab.select-n` and the rename go into the registry (a lead-owned shared file).

## 6. AI dot

- **Source:** the V2-3.5 activity poller (`notify.rs`). It already polls only tabs that are **not active**
  (`poll_targets`) and computes `transition_kind`.
- **Hook:** right after `fired` is non-empty and **before** the cooldown/cap (the dot is a bounded boolean, never an OS
  ping), call `tabs::set_dot(app, root, AwaitingInput ⇒ 'needs-you' | Finished ⇒ 'done')`. 'needs-you' outranks
  'done'.
- **Clear:** in `notify::project_focused` (called by `activate`). Close or rest drops the dot too.
- Live only, never on disk. The Dock badge is unchanged.
- **Untrusted input:** the dot is a two-value enum decided in Rust. No project text reaches the strip except the
  sanitized name.

## 7. e2e plan

1. **Driver.** Vendor `tauri-plugin-wdio-webdriver` 1.2.0 with `spike/wdio-webdriver-webviews.diff` under
   `apps/desktop/src-tauri/vendor/` + `[patch.crates-io]`. The patch replaces `webview_windows()` with `webviews()`
   and the executor type `WebviewWindow` with `Webview`. Window-level ops go through `.window()`; close uses
   `webview.close()`. Today's single-webview windows are webviews too, so handles do not change before T2 lands.
   Track the upstream issue and drop the fork when upstream ships webview handles.
2. **Handles** become `home`, `strip`, `p-*`. `wdio.conf` already pins `windowLabel: 'home'`. Keep it, because session
   create lands on the first label otherwise, which could be `strip`.
3. **`helpers/windows.ts`.**
   - `focusTab` = `switchToWindow(label)` + `invokeTauri('e2e_focus_window')` (now `activate`) + wait `!document.hidden`.
     A background child is frozen exactly like a background native tab, so this rule is unchanged.
   - `closeTab` always uses `e2e_close_window` (→ `close_tab`). `browser.closeWindow()` bypasses the book.
   - New `strip()` helper: switch to `strip` and read `[data-testid^="tab-"]`.
4. **Lanes that change:** `project-tabs`, `home`, `tabs-identity`, and every scenario through `helpers/windows.ts`. New
   assertions:
   - the strip lists `tab-p-*` in open order, then `tab-home` last; `tab-home` has no text and `aria-label="Home"`;
   - activate via a strip click → that webview is `!document.hidden` and the others are hidden;
   - a background tab whose fixture AI finishes gets `tab-dot`; activating it clears the dot;
   - relaunch with `MAUDE_E2E_RESTORE=1`: handles = `home`, `strip` + the saved `p-*` only; the active one matches;
     no extra project tab;
   - `e2e_menu_state` (new debug command): `{new_canvas, new_home_tab, close_tab, new_project}` enabled on Home vs
     project, per §5;
   - New Project from Home opens Home's create sheet.
5. **Guard test:** a grep test refuses `closeWindow(` in `apps/desktop/e2e/**`.

## 8. Security impact

- **Capability matching is `webviews` OR `windows`** (tauri `ipc/authority.rs:477`). Every child lives in window
  `shell`, so a capability that names `shell` in `windows` would grant its permissions to **every** tab, Home and
  projects alike. Rules:
  - no capability (static or runtime) names `shell` or a `*` that matches it in `windows`;
  - every capability uses `webviews` only.

  A unit test scans `capabilities/**/*.json` + `home_capability()` + any runtime capability builder for this.
- **`strip` capability** (`capabilities/strip.json`): `webviews: ["strip"]`, **no `remote`** (app-local only).
  Permissions: `tabs_state`, `tab_activate`, `tab_close`, `tab_reorder`, `core:window:allow-start-dragging` (+
  `internal-toggle-maximize`). **No page capability grants `core:event:*`** (decision
  `maude/v2-3.10-1d-shell-bus-channel`): Tauri 2.12 delivers an `emit_to` to every `Any`-target listener in every
  webview, so the shell reaches pages only through Channels: `tabs_state` for the strip, `shell_subscribe`
  (one per page, keyed on the caller's own label) for Home and project pages. Scan tests
  `no_page_capability_grants_events` + `the_shell_never_emits_to_a_page` pin it. Each command re-checks label `strip` + app-local URL. `on_navigation` pins
  `strip` to `strip.html`, and `on_new_window` = Deny. `every_granted_command_checks_its_caller` covers the strip
  commands.
- **Project pages** keep their own capability and caller checks. They cannot activate, close or reorder another tab,
  because the strip commands refuse them. They no longer see other projects' names (option A would have pushed every
  name into every page). They cannot emit to `strip`: no emit permission, M5 unchanged.
- **`tauri/unstable` in release builds** is new surface. `add_child`, `Webview::show/hide/set_bounds` and
  `Manager::get_webview` are API-unstable, not unsafe.
  - Pin `tauri = "~2.12"` and bump deliberately.
  - The V2-3.2 `check_caller` path does not change. It already reads `webview.label()`, which is now the child label.
- The vendored WebDriver fork is compiled in release but **registered only under `debug_assertions`**, as today. The
  release `.app` never starts it. The diff is 59 changed lines and has been reviewed.

## 9. Tests that prove it

- Unit (windows.rs / tabs.rs):
  - `plan_tabs` (the 3 prototype cases + an old session with a `home` entry);
  - the `TabStripState` projection puts Home last and never in tabs, and uses sanitized names;
  - activate updates focused + dot clear + menu role;
  - close of the last tab activates Home;
  - strip commands refuse a non-strip label and a non-app-local URL;
  - the capability `windows`-scan test.
- e2e: §7.4.
- Fail-first: revert the `plan_tabs` home-drop and watch the "no stray Home" case go red. Revert the dot clear and
  watch the dot assertion go red.

## 10. Open questions (recommended default in bold)

1. Is there visible flicker or a stale frame on switch? rAF says 1–9 ms; nobody looked. **Builder T2 records a 60 fps
   screen capture of 10 switches before merge.** If a stale frame shows, show the new tab before hiding the old one
   (the spike already orders it that way).
2. Multiple shell windows ("Move Tab to New Window")? **No in v1: one `shell`.**
3. Drag tabs out of or between windows? **No** (follows from 2). Reorder is in-strip only.
4. Cell tabs `c-*` in the strip? **Yes, same row, a "cloud" glyph.** No capability, as today.
5. Linux/Windows: multi-webview works there too, but the e2e plugin does not build on Windows today. **macOS first;
   other platforms keep one webview per window until verified.**
6. Child relayout on resize and fullscreen was not measured (the spike used fixed bounds). **T2 asserts child bounds
   after `set_size` and fullscreen in a unit/e2e check.**
