## 4. Decision (DDR draft)

**Title:** One action registry and focus-scoped key resolver for menus, ⌘K, "?", native menu and docs.

**Context.** Maude has ~60 keydown listeners across the shell and the canvas iframe, four display lists
(palette, menubar, "?" sheet, `DEFAULT_TOOLS` mirror), a hand-kept canvas→shell forward list and a
native menu, none derived from another. §2 lists nine shipped defects that come from that duplication.
v2 adds two toolbars, three modes, a timeline focus, focus-scoped keys (C26), role-based visibility
(rule 12) and a key-migration table (rule 13), which cannot be held by hand.

**Decision.**
1. Every user-invocable capability is an `ActionDef` in `apps/studio/actions/` (data only: no React,
   no DOM, erasable TypeScript so the client bundle, the canvas runtime bundle, Bun and Node 24 all
   import it). Menus, ⌘K, the "?" sheet, the native menu, the generated docs and V2-1.11's AI manifest
   read it. Handlers are bound per runtime by action id; the registry holds no closures.
2. One declarative predicate (`Pred`) per action is the only visibility rule. Every surface calls
   `isVisible(action, ctx)`; the server enforces the role half (`minRole`, V2-1.11). Hidden and
   disabled are different things: hidden = predicate false, also refused on the server; disabled =
   shown greyed.
3. Keys resolve through one pure function, `resolveChord(index, chord, ctx, press)`, with layers in C26
   order — `timeline > selection > tools > global`. A focused text field is not a layer: it swallows the
   key unless the binding opts in (`inText`). Within a layer at most one binding may be live for any
   context; a finite-lattice test enforces it. Tap and hold never compete. A disabled winner still
   swallows the key.
4. Each document (shell, canvas iframe) runs the resolver once per keydown in one capture listener. The
   iframe executes `exec:'canvas'` actions locally and forwards everything else as
   `{dgn:'key', chord}`; the shell re-resolves the chord with its own context and runs it only when
   `fromCanvas` is true and `e.source === activeWin`. The shell runs `exec:'canvas'` actions in the
   iframe with `{dgn:'run-action', id}` (or V2-1.2's `tool-set`/`set-mode` for tools).
5. The native menu is built from a generated slice of the registry; a chord owned by a native
   accelerator has no live web binding in the desktop shell (single owner per chord per shell).
6. `where` paths are derived from the menu tree and the places registry, never typed by hand. The "?"
   sheet, its "Keys and tools that moved" fold and the docs page are generated.
7. Migration keeps v1 behaviour: first a pure swap that reproduces every v1 binding (proved
   representable by the spike), then the v1 → v2 flips commit by commit under rule 13.

**Consequences.** One file set becomes the most-touched shared surface: schema, resolver, menu tree and
"?" layout stay lead-owned; per-area entry files are lane-owned (§5.1). The canvas runtime bundle grows
by the slim generated keymap (§5.7), not the whole registry. The nine defects in §2 become test
failures instead of reviews. v1's per-surface display strings survive only until Phase 4 (`legacy`
field, deleted in V2-8.0).

**Rejected.** Options 2–4 above (reasons in §3); a user-rebindable keymap (not in any canvas or Gate 0
row; the schema leaves room for it); storing handlers in the registry (closures can't cross bundles and
can't be serialised into the manifest).

### 5.2 Types

```ts
// apps/studio/actions/types.ts — erasable TS only (no enum, namespace, parameter properties)
export type ActionId = string;      // dotted '<area>.<verb>[-<object>]', lower kebab segments; append-only
export type Role = 'view' | 'comment' | 'edit' | 'owner';            // A6; a local project is 'owner'
export type Shell = 'desktop' | 'browser' | 'cloud' | 'viewer' | 'embed' | 'home';
export type Mode = 'edit' | 'preview' | 'present' | 'viewing';       // V2-1.2; 'viewing' = read-only slot
export type Focus = 'text' | 'timeline' | 'canvas' | 'chrome' | 'modal';
export type SelKind = 'none' | 'artboard' | 'object' | 'annotation' | 'video-artboard' | 'generated-image' | 'clip';
export const LAYERS = ['timeline', 'selection', 'tools', 'global'] as const;   // C26, high → low
export type Layer = (typeof LAYERS)[number];
export type Fact =                                   // closed set; adding one is a registry change
  | 'native' | 'canvasOpen' | 'videoCanvas' | 'timelineVisible' | 'linkedHub' | 'aiConnected'
  | 'online' | 'hasShareLink' | 'canUndo' | 'canRedo' | 'presenting' | 'commentFocused' | 'selfHostedHub';

export interface Pred {                              // all present fields must hold (AND)
  minRole?: Role; shell?: Shell[]; notShell?: Shell[]; mode?: Mode[]; focus?: Focus[];
  selection?: SelKind[]; facts?: Fact[]; notFacts?: Fact[]; any?: Pred[];
}

export type Chord = string;                          // canonical, produced only by keys.ts (§5.4)
export interface KeyBinding {
  chord: Chord;
  layer: Layer;
  when?: Pred;                                       // binding-specific, on top of the action's `visible`
  inText?: boolean;                                  // default: has ⌘/⌃ and not TEXT_RESERVED
  inModal?: boolean;                                 // default false
  hold?: boolean;                                    // press-and-hold (Space = Hand); taps never compete
  alias?: boolean;                                   // secondary key (⌘G for ⌥⌘G, ⌘B for S): "?" lists it as "or"
}

export type Exec = 'shell' | 'canvas' | 'native' | 'server';
export type HelpGroup =
  | 'edit-tools' | 'preview-tools' | 'file' | 'canvas' | 'panels-ai' | 'objects' | 'timeline' | 'present';

export interface ActionDef {
  id: ActionId;
  label: string;                                     // CONTRACT §3 words; one label on every surface
  kind: 'command' | 'toggle' | 'tool' | 'place';     // 'place' = a navigable home (⌘K "Places")
  icon?: string;                                     // maude-v2 icon name
  keys?: KeyBinding[];                               // keys[0] is the primary (menus, ⌘K)
  exec: Exec;                                        // which runtime owns the handler
  visible?: Pred;                                    // rule 12: the ONE predicate set
  enabled?: Pred;                                    // greyed, never hidden
  fromCanvas?: boolean;                              // may be invoked from the canvas iframe (§5.7)
  homes?: ActionId[];                                // non-menu homes: ids of kind:'place' actions
  help?: { group: HelpGroup; order: number };        // "?" placement; Advanced fold is derived (§5.10)
  native?: { menu: 'App' | 'File' | 'Edit' | 'View' | 'Window' | 'Help'; order: number; predefined?: string };
  aliases?: ActionId[];                              // old ids that still resolve here
  search?: { keywords?: string[]; hidden?: boolean };// ⌘K matching (accent/typo folding is the matcher's)
  legacy?: { palette?: string; menu?: string; sheet?: string };   // v1 display strings — deleted in V2-8.0
  // V2-1.11 adds: params, effect, minRole, server, undo, agent, askAI
}

// Role gate (with V2-1.11): isVisible(a, ctx) = rank(ctx.role) ≥ rank(a.minRole) && holds(a.visible, ctx).
// `Pred.minRole` is for a binding's `when` only; on an action the role lives in `minRole` (server-enforced).

export interface MovedKey { was: string; now: string; note?: string; to?: ActionId }   // "?" › Advanced
export interface KeyCtx {
  role: Role; shell: Shell; mode: Mode; focus: Focus; selection: SelKind; facts: ReadonlySet<Fact>;
}
```

### 5.4 Chords

- Canonical form: modifiers in macOS order `⌃⌥⇧⌘`, then the key. Letters upper case. Named keys:
  `↵ esc Space tab ⌫ ⌦ ← → ↑ ↓ Home End F1…F12`; minus is `−`. Examples: `⇧⌘E`, `⌥⌘↵`, `⇧S`, `?`.
  `chord('⌘ ⇧ M') === chord('Cmd+Shift+M') === '⇧⌘M'`. Pointer gestures (`⌘ click`) are not chords
  (`chord()` returns `null`); the "?" sheet lists them as literal rows.
- `chordFromEvent(e)`: `e.key` when it is a printable ASCII character (layout-aware, what macOS menus
  show), else the key from `e.code` (`KeyP` → `P`, `Digit1` → `1`). This covers ⌥ chords on macOS
  (⌥⌘P arrives as `e.key === 'π'`). ⇧ is kept for letters and named keys and dropped where the
  character already encodes it (`?`, `+`) **and for digits**. Digits matter because a layout that types
  digits with ⇧ still has to reach ⌘0/⌘1; v1 ignored ⇧ there. On Czech QWERTZ, ⌘1 is pressed as ⌘⇧ +
  the `+` key, and ⌘+ is the unshifted `+` key. ⌃ folds into ⌘, matching v1's `metaKey || ctrlKey`.
- `TEXT_RESERVED` (owned by a focused text field): `⌘Z ⇧⌘Z ⌘Y ⌘A ⌘C ⌘X ⌘V ⇧⌘V ⌥⇧⌘V ⌘B ⌘I ⌘U
  ⌘← ⌘→ ⌘↑ ⌘↓ ⇧⌘← ⇧⌘→ ⌥← ⌥→ ⌘⌫ ⌥⌫` plus every chord without ⌘/⌃.
- `BROWSER_RESERVED` (never delivered to a page by Chrome/Safari): `⌘N ⇧⌘N ⌘T ⌘W ⌘Q ⌘L` (best effort).
  Bindings on these carry `when:{shell:['desktop']}`; in other shells "?" shows the menu path instead.

### 5.5 Resolution (C26)

```
resolveChord(index, chord, ctx, press = 'tap'):
  live = bindings for chord where
           (press === 'hold') === !!binding.hold
           and (ctx.focus !== 'text'  or binding.inText ?? (hasCmd(chord) and chord ∉ TEXT_RESERVED))
           and (ctx.focus !== 'modal' or binding.inModal)
           and (binding.layer !== 'timeline' or ctx.focus === 'timeline')
           and holds(action.visible, ctx) and holds(binding.when, ctx)
  for layer in ['timeline', 'selection', 'tools', 'global']:
    if any live binding has this layer → return it (and the rest of that layer as `ambiguous`, which
    the uniqueness test forbids)
  return null                             // the key is not ours: let the browser / text field have it
```

- If a binding matched, the listener calls `preventDefault()` synchronously, then runs the handler if
  `isEnabled()`; a disabled winner swallows the key (no fall-through to a lower layer).
- Tap vs hold: on keydown of a chord that has a live `hold` binding, the hold starts at once (Hand
  cursor); on keyup within 200 ms with no pointer drag, the `tap` winner runs. Space: tap plays a
  selected video artboard (§7), hold is Hand, and in Present Space moves on (04 md-keys) — hold Hand is
  scoped out of Present.
- ⌘B always splits: the timeline layer binds `S` and alias `⌘B`; the selection layer binds `⌘B` with
  `when:{facts:['timelineVisible']}`, so ⌘B splits whenever the timeline is shown, even without timeline
  focus. A focused text field still wins (open question Q1).
- Esc is one action, `ui.step-back`, with a handler in each document. The ladder (04 md-esc) runs where
  focus is: close menu/sheet → leave text editing → clip/object selection → tool → resting tool → base
  mode. The iframe's last step posts V2-1.2's `mode-request {mode:'back'}`; embeds keep the DDR-247
  relay. Widget-local esc/↵/arrows/tab inside one component (dialogs, menus, trees, pickers, the chat
  composer) are ARIA behaviour, not registry actions; they run first and stop propagation.

### 5.6 Execution

- `runAction(id, { source: 'key' | 'menu' | 'palette' | 'native' | 'canvas' | 'agent', params })` is
  the only entry point in each document. It looks up the action, checks `isVisible` and `isEnabled`
  against the current `KeyCtx`, then calls the handler for its `exec`:
  - `shell` → `SHELL_HANDLERS[id]`;
  - `canvas` → if the call is in the shell: tools post `tool-set {tool}` / `set-mode {mode, tool}`
    (V2-1.2), everything else posts `{dgn:'run-action', v:1, id, params}` to the active iframe; in the
    iframe: `CANVAS_HANDLERS[id]`;
  - `native` → `invoke('run_native_action', { id })` (desktop only);
  - `server` → the route in V2-1.11's `server` field.
- Handler coverage is a test: every action with `exec: X` has an entry in the X handler map, and no map
  has an id that isn't in the registry.

### 5.7 How the iframe joins (DDR-054)

The canvas bundle imports `actions/keymap.gen.ts`: for every binding that can be live with
`focus ∈ {canvas, text}`, the entry `{ chord, layer, id, exec, when, visible, inText, hold, fromCanvas }`
(no labels, no docs). It is generated from the registry and drift-gated, so the iframe never depends on
a runtime push.

| Message | Direction | Shape | Gate on the receiver |
| --- | --- | --- | --- |
| `key` | canvas → shell | `{dgn:'key', v:1, chord, hint?:{artboardId?:string}}` | origin = canvas origin **and** `e.source === activeWin`; the shell re-resolves `chord` with its own `KeyCtx` and `focus:'canvas'`; runs only an action with `fromCanvas: true`; `hint` is advisory (the shell's selection mirror wins on conflict) |
| `request-action` | canvas → shell | `{dgn:'request-action', v:1, id, params?}` (canvas UI clicks: export, open timeline, stickers, inspector, present) | same gate + `fromCanvas: true` + `isVisible`; `params` validated against the action's `params` schema (V2-1.11) |
| `run-action` | shell → canvas | `{dgn:'run-action', v:1, id, params?}` | `e.source === window.parent`; `id ∈ CANVAS_HANDLERS`; `isVisible` with the iframe's context |
| `tool-set`, `set-mode`, `mode-request` | per V2-1.2 | per V2-1.2 | per V2-1.2 |

- `fromCanvas: true` is legal only for actions whose V2-1.11 `effect` is `'none'` (they open UI and
  change nothing). Untrusted canvas JS can forge a `key` message today's way (it can already forge
  `shell-shortcut`), so the gate bounds the damage to opening a panel or dialog on the active canvas.
- Pre-React fallback: `inspect.ts` keeps one doc-capture listener, registered at page load, that
  forwards only the global-layer `exec !== 'canvas'` chords with `inText: true` (⌘K, ⌘R, ⇧⌘E, ⌘\, …)
  as `key` — so a canvas that failed to build, or a legacy `.html` canvas, still answers ⌘R and ⌘K. When
  the canvas key router mounts it sets `window.__maudeKeysReady = true` and the fallback returns early.
  The fallback list is interpolated into `INSPECTOR_SCRIPT` from the registry by `http.ts`.
- Retired with the swap (rule 13 applies to lanes too): `toggle-palette`, `shell-shortcut` (→ `key`);
  `undo`, `redo`, `zoom`, `selection-clear`, `annotation-select-all` (→ `run-action`); later
  `open-export`, `open-timeline-request`, `open-sticker-picker`, `open-inspector`, `present-enter`
  (→ `request-action`) as each package touches them.

### 5.8 Native menu (C3, D19)

- `menu.actions.json` (generated): `[{ id, menu, order, label, accel?, exec, predefined? }]`, where
  `accel` is the Tauri accelerator from `toTauriAccel('⇧⌘N') === 'CmdOrCtrl+Shift+N'`.
  `menu.rs` reads it with `include_str!("../menu.actions.json")` + serde. OS-provided items (About,
  Services, Hide, Quit, the predefined Edit items, macOS window-tab items) stay `PredefinedMenuItem`s,
  declared in the registry with `native.predefined` so "?" and the docs can show them.
- Click: `exec:'native'` ids have a Rust arm (`open_project`, `check_updates`, `new_home_tab`…);
  `exec:'shell'` ids emit `menu://action {id}` to the focused window's webview → `runAction(id,
  {source:'native'})`. `menu://new-project` and `menu://report-bug` are retired in the same commit.
- Single owner: the generator adds `when:{notShell:['desktop']}` to any web binding whose chord is a
  native accelerator, so in the desktop shell only the menu fires (and it fires with canvas focus,
  because AppKit handles key equivalents before the web view).
- v2 File menu per C3: New canvas ⌘N · New project… ⇧⌘N · Open project… ⌘O · New Home tab ⌘T; a Window
  menu with the native tab commands (Phase 3); About · Check for updates… · Quit · Help › Report a bug…
  unchanged (D19).

### 5.9 Menu tree and `where`

`PROJECT_MENU` encodes CONTRACT §1 exactly (nodes are action ids, separators, submenus with
`advanced: true` for the Advanced groups). `menuPaths()` derives every `Menu › File › Export…` path.
Non-menu homes are `kind:'place'` actions (`place.canvases-advanced` = "Canvases › Advanced",
`place.inspector-advanced`, `place.settings-advanced`…), whose handler opens that panel and its fold.
An action's `where` is its first menu path, else its first home's label. A test asserts every action
has at least one home (menu, home, toolbar via `kind:'tool'`, or native) — this is the registry half of
the nothing-deleted test (V2-2.0c, `scripts/check-v2-nothing-deleted.mjs`).

### 5.10 ⌘K, "?" and docs

- ⌘K lists `ACTIONS.filter(a => isVisible(a, ctx) && !a.search?.hidden)`, greys `!isEnabled`, shows
  `where` and the primary key. "N hidden tools" counts results whose `where` passes through an
  Advanced fold. Places are their own group. "Ask AI" is the last row (S5).
- "?" sheet: `HELP_GROUPS` (06 ad-search) — Edit tools · Preview tools ("the key switches to
  Preview") · File · Canvas · Panels and AI, plus Objects (A11) and Timeline (07), each listing visible
  actions with `help.group`, ordered by `help.order`. The Advanced fold lists actions whose `where`
  passes through an Advanced group, with the path, and then `MOVED_KEYS`. "Find a shortcut" uses the
  ⌘K matcher. In browser shells, `BROWSER_RESERVED` keys are replaced by the menu path.
- `MOVED_KEYS` is append-only. Each row lands in the same commit that removes the v1 binding (rule 13);
  06 ad-search draws the first ten rows.
- `scripts/gen-actions.mjs` writes `site/content/docs/shortcuts.mdx` (and the AI parts of
  `actions.manifest.json`, V2-1.11); `--check` joins the "Site generated content drift" step in
  `quality.yml`.

### 5.11 Invariants (each is a test, §7)

1. Per layer, at most one live binding per chord and press for every context in the lattice.
2. Every v1 binding is either still bound to its action, or listed in `MOVED_KEYS`.
3. `fromCanvas: true` ⇒ `effect: 'none'`.
4. No chord is owned twice in one shell (native accelerator ⇒ no live web binding in `desktop`).
5. Every action has a home; every `homes[]` id is a `kind:'place'` action.
6. Every action's `exec` has a handler in that runtime.
7. `keymap.gen.ts`, `menu.actions.json`, `actions.manifest.json`, `shortcuts.mdx` match the generator.
8. Ids are append-only: a removed id must appear in some action's `aliases`.

## 9. Open questions (conservative default in bold)

- **Q1 — "⌘B always splits": does it beat a focused text field?** C26 puts the text field first, and
  inline text editing may use ⌘B for bold. **Default: the text field wins.** ⌘B splits whenever the
  timeline is shown and focus isn't in a text field.
- **Q2 — Are the "?" Objects (A11) and Timeline groups in the main grid?** 06 ad-search draws only five
  groups, and its fold holds only Advanced and moved keys. **Default: add Objects and Timeline (and
  Present) as main-grid groups below the drawn ones.** Nothing about them is Advanced.
- **Q3 — What do browser shells show for desktop-only keys** (⌘N ⌘T ⌘O; ⌘1 is also Chrome's tab
  switch)? **Default: the menu path, not the key.** The action stays reachable via the menu and ⌘K. No
  replacement chord is invented.
- **Q4 — Other non-US layouts.** §5.4 covers US and Czech QWERTZ: ⌥ chords go by `e.code`, digits
  ignore ⇧, and ⌘= / ⌘+ both zoom in. Other layouts are untested. **Default: `e.key`-first matching as
  in v1; record any layout bug as a defect.** A full layout-aware remap would need its own DDR.
- **Q5 — Are the §8 step 7 deltas approved inside V2-2.4?** **Default: no.** Ship the pure swap; the
  deltas land in Phase 4 with their v2 bindings.
- **Q6 — Do lanes own `defs/<area>.ts`?** **Default: yes, lanes own them; the lead owns schema,
  resolver, menu tree, "?" layout, the aggregate and the uniqueness test.** Fallback: lanes send
  patches.
