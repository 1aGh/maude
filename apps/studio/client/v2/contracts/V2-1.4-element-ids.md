# V2-1.4 — Stable element ids and canvas-only metadata

Spike: V2-1.4 (Phase 1). Builds in: V2-2.19 (moved to Phase 2), then S2, S4, S5, and the PostToolUse
id check of V2-1.11 / V2-1.18. Status: proposed, for the lead to merge and record as a DDR.

## 1. Question

> Ids that survive AI rewrites and drive Layers, locks, undo scopes, bound arrows, co-edit;
> canvas-only metadata store (lock, hide-in-editor, Place freely) that never leaks to export.

The brief also asks for: the id format, who assigns ids (the server on write, or Claude by a rule plus a
check), how an AI rewrite keeps ids (skill rule + PostToolUse `maude design check` diff + `--fix=safe`
re-attach), where canvas-only metadata lives (versioned or runtime, DDR-115), and how exporters strip it.

## 2. What exists today

**Three identity schemes, none of them stable under a rewrite.**

| Scheme | Where | Stable? |
| --- | --- | --- |
| `data-cd-id` **computed** = `Bun.hash(componentName + ":" + preOrderIndex)` → 8 hex | `canvas-pipeline.ts` `walkInjectIds` / `computeId`, mirrored in five `canvas-edit.ts` walkers (`findOpening`, `collectElements`, `collectElementsFull`, `printAll`, …) | No. DDR-019 records this choice: a sibling inserted earlier in the same component renumbers everything after it. |
| `data-cd-id` **authored** (a string literal in the source) | Pipeline skips injection when the attribute exists (`hasJsxAttr`); every walker prefers it (`canvas-edit.ts` `authoredCdId`) | Yes, by construction. Six uses in the repo corpus, all in lab canvases (`wal-hero-nav`, `akl-alpha-title`, …). Gap: authored ids get **no** `_locator.json` entry (the locator is written only on injection). Gap: an expression value (`data-cd-id={x}`) skips injection but is invisible to `authoredCdId` (it only reads a `Literal`), so the DOM id and the edit engine's id disagree. |
| `data-dc-element` (DDR-007) | Author-emitted kebab handle. The Layers rename (`client/inspector/inspector-panel.jsx` `renameLayer`) also writes it, as free text | Survives while the author keeps it. It is a name, not a guaranteed-unique id. |
| `data-dc-screen` / `DCArtboard id` | Artboards | Yes (authored). |

**Recovery layers built on top of the positional id:**

- `canvas-edit.ts` `elementPrint` / `relocateElement` / `listElements` / `printUniqueness` (plan T23/T24,
  DDR-241). A print is the component, the tag, the ancestor-tag chain, the literal attributes (minus
  `data-cd-*`, `style`, `key`) and the element's own text. `sync/source-ops.ts` uses it to re-apply a UI
  edit that lost a race. It refuses ambiguity.
- DDR-138 reorder re-settle chain: `movedId` → `semanticId` (`data-dc-element`) → `jsxPath`.
- Comments (`comments-overlay.tsx` `resolveCommentTarget`, `dom-selection.ts` `resolveByDomPath`) fall back
  to a stored `dom_path` + tag + classes. A pin that stays unresolvable is detached, never deleted (RCA
  "comment pins float free after Claude Code rewrites the canvas").

**Canvas-only metadata today:**

- **Lock** of a layer is **per-user runtime**, not shared: `_canvas-state/<slug>.view.json` `locked: ["<cdId>:<occurrence>"]`
  (`api.ts` `patchCanvasMeta` locked lane, `normalizeLocked`; `canvas-shell.tsx` `lockedKeySet` /
  `isLockedElement`). The key is the **positional** id, so any structural edit re-points it.
- **Hidden** (Layers eye) writes `style.display = "none"` through `/_api/edit-css` (undo RCA phase 1c);
  "show" removes the inline `display`, so an element that had `display: flex` inline loses it.
- **Layer name** = `data-dc-element` in the source.
- Annotation lock (DDR-246) lives on the annotation element record (`locked`), synced per field.

**Exporters and `data-cd-*`:** `handoff.ts` `stripDataCdId` removes only `data-cd-id` and
`data-cd-editable`. The HTML export (`bin/_html-playwright.mjs`, `neutralize`) removes only `on*` and
`javascript:` attributes, so every `data-cd-*` attribute in the DOM reaches the exported `index.html` today.

**Bound arrows:** `annotations-bindings.ts` `recomputeBoundArrows` binds only to annotation elements
(`ArrowBind.hostId` = an annotation id). A deleted host strips the bind and freezes the endpoint.

**Decisions that constrain this (kg, read as data):** DDR-007 (paired `data-dc-*` attributes), DDR-019
(positional `data-cd-id`, "use `data-dc-element` for an author-stable handle"), DDR-138 (rejected "stable
per-node uuids in source — pollutes authored TSX and fights DDR-019"), DDR-241 (prints re-find elements
after a lost race), DDR-246 (lock is a UX guard, not a permission; AI writes to a locked element are
refused, not filtered), DDR-115 (`*.tsx` and `*.meta.json` are versioned; `_canvas-state/`, `_state/` are
runtime), the RCA above (positional ids are the cause of drifting comment pins after a Claude rewrite).

**Spec (topic owners):** 14 Editing (`ed-obj-order`: "A locked object can't be picked — the click goes to
its parent"; "A hidden object stays in the file and in Layers, greyed. It never exports."; the words → CSS
table: `Hidden → display: none (kept in Layers)`, `Locked → — (canvas only, never in the CSS)`; inspector
Advanced "CSS · tokens · id" with an editable **Element id** field `book-call`; `ed-obj-enter` /
`ed-lay-free`: **Place freely** is a Position switch in auto layout), 15 Annotations (arrows bound to
artboards and elements, "Bound ends follow", "Locked still follows"), CONTRACT §2 (⇧⌘L locks objects in
Edit, annotations in Preview).

## 3. Options

**Option 1 — authored `data-cd-id` literals, stamped lazily, kept by rule + check (recommended).**
Durable references use an authored id written into the source. An element gets one the first time
something durable points at it, or when a studio writer creates or edits it. Claude keeps every id it
sees (skill rule); a PostToolUse check reports a lost id; the run end re-attaches what it can prove.
Canvas-only metadata is more `data-cd-*` attributes on the same element.
- Cost: some readable attributes in the TSX (only on referenced elements); a check verb; generalized strip
  in exporters; five walkers already honour authored ids.
- Breaks: overturns DDR-138's rejection of ids in source. The rejection was about **every** element and
  **opaque uuids**. Option 1 is readable ids on referenced elements only (see §6: the reason for the
  rejection is real; eager stamping costs +23 % bytes).

**Option 2 — keep positional ids, rely on prints (`relocateElement`) for every durable reference.**
- Cost: none new.
- Breaks: after a typical AI rewrite of one artboard, prints re-find only 57 % of that artboard's elements
  and point 1.9 % at the **wrong** element (heavy rewrite: 20 % / 5.4 %). Locks, arrows and history scopes
  live exactly in the artboard the AI just changed. Fails the canvas (14 ed-edge-ai, 15 "Bound ends follow").

**Option 3 — artboard-scoped positional ids** (`hash(component + artboardId + indexInArtboard)`).
- Cost: change `computeId` in the pipeline and five walkers (`data-cd-id-version` 2, DDR-019 knob).
- Gain: measured 100 % stability **outside** the edited artboard (today 74–80 %).
- Breaks: inside the edited artboard still 42–83 % of ids point at the wrong element. Not enough for
  durable references. Kept as a possible later improvement for transient handles (§9 Q8).

**Option 4 — canvas-only metadata in `.meta.json` keyed by element id** (instead of attributes).
- Cost: a new versioned `elements` map, per-key merge in the kernel's `meta` lane, a v1-peer rule (a v1
  writer may drop the unknown key), and an orphan reconciler when an id disappears.
- Breaks: Claude reads the TSX, not the sidecar, so a lock is invisible where the edit happens (A13 "files
  are the API"). Rejected.

**Option 5 — opaque random ids on every element at write time (Figma-style uuids).**
- Breaks: +18–23 % canvas bytes (§6), unreadable in checks and errors (K-agent-architecture [A8]
  "readable ids"), and a full-corpus diff at migration. Rejected.

## 4. Decision (DDR draft)

**Title:** Stable element ids are authored `data-cd-id` literals, stamped on first durable reference, kept
by AI under a check; canvas-only metadata is the `data-cd-*` attribute namespace.

**Context.** v2 needs element identity that survives AI rewrites: Layers rows, locks, Undo history and
object-scoped history (B11), arrows bound to elements (B10), the co-edit soft lock (A10), ⌘/ AI scope,
comment pins. Today's `data-cd-id` is positional by design (DDR-019). On the v2 canvases every artboard is
inside one component, so one insertion in one artboard re-points about a third of the ids in the **whole
file** to different elements, silently (§6). Prints recover most elements in untouched artboards but lose
or mis-point many in the artboard that changed, which is where references matter.

**Decision.**
1. **One identity attribute.** The stable id of a canvas element is an **authored string literal**
   `data-cd-id="<id>"` in the TSX. The pipeline keeps it (it already does); all walkers use it (they
   already do). A computed 8-hex id stays the fallback for elements that have no authored id, and is
   **transient only**: it may appear in selection, hover, Layers row keys and presence, never in anything
   stored.
2. **Format.** `^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$`, at most 48 characters, never exactly 8 hex characters
   (so it can't collide with a computed id), unique within the canvas file. Readable: it is built from the
   element's `data-dc-element` → its own text (first three words, accents removed) → its first class →
   its tag, plus `-2`, `-3` … on collision. The stamper never hands out an id that a durable reference
   still holds, detached ones included, so a removed element's comments can't land on a newcomer.
3. **Who assigns (lazy, never behind a writer's back).**
   - Studio writers that **create** elements (insert, duplicate, paste, frame selection, Make editable,
     detach) stamp every element they create. A copy always gets a new id and starts unlocked
     (DDR-246 rule for copies).
   - Studio writers that **write to** an existing element (every `/_api/edit-*`, lock, hide, rename,
     reorder, set kind, ⌘/ scope capture) stamp it in the same write.
   - A **durable reference** (comment pin, arrow bind, lock, ⌘/ AI scope, an undo record, an
     object-history query) to an unstamped element is resolved by print and **queued**: the next write an
     **editor's** studio makes to that file stamps every queued element. A Can comment or Can view person
     never causes a source write (rule 12).
   - Claude **may** add ids to new elements (the skill encourages it); it is never required.
   - Nothing rewrites a file only to stamp it while a run or an external editor may be writing it.
4. **AI keeps ids.** The `design` skill rule: *keep every `data-cd-*` attribute on every element you keep,
   byte for byte; never copy an id onto a second element; never change or unlock an element that carries
   `data-cd-locked` — tell the person to unlock it (⇧⌘L).* Enforced by `maude design check` (§5.3) in the
   PostToolUse hook: a lost id, a duplicated id, an expression-valued id or a changed locked element
   blocks with a message that names the element and the line. The fix is Claude's own one-line Edit.
5. **Re-attach at run end.** At `run.end` (before the run's action is published, V2-1.5) and in
   `maude design check --fix=safe`, a lost id is re-attached to the new element that is **provably** the
   same one (mutual best match with a margin; §5.4). Anything ambiguous gets no old id: references to it
   detach (comments keep their last place, arrows freeze, a lock is reported lost). Measured precision on
   the repo corpus and the v2 canvases: 0 wrong attachments in 4,800+ dropped ids (§6).
6. **Canvas-only metadata = the `data-cd-*` namespace, on the element, in the TSX (versioned).**
   - `data-cd-id` — identity (above).
   - `data-cd-locked` — boolean attribute: the object is locked for everyone (shared, versioned,
     replaces the per-user `view.json` lock). UX guard, not a permission (DDR-246).
   - `data-cd-hidden="<previous inline display, or empty>"` — set together with `display: none` by the
     Layers eye / Hide. Show restores the remembered value. `display: none` stays in the CSS, as the
     words → CSS table in 14 says.
   - `data-cd-editable` stays pipeline-injected (never authored).
   - Rule: every `data-cd-*` attribute is canvas-only. It is never part of an element's print, never
     written by the CSS / words writer, never offered as a raw attribute row (D18), and stripped by every
     exporter that emits markup or code.
   - **Place freely is not canvas-only.** In 14 it moves a child out of auto layout and pins it with
     constraints (`ed-lay-free`: Right · Top → `right: 64px; top: 64px`). That is `position: absolute` plus
     offsets in the CSS, and it must export identically. It goes through the CSS writer.
   - Layer **name** stays `data-dc-element` (today's rename path). The id is not the name.
7. **Durable references hold `(canvas, artboardId, elementId[, occurrence])`.** `artboardId` scopes an
   element that a shared component renders in several artboards (`dom-selection.ts` `scopedCdSelector`
   already does this). `occurrence` addresses one instance of a `.map()` row. A lock or hide on such an
   element applies to the source element, so to every instance.
8. **Arrows bound to artboards and elements** (B10): `ArrowBind.hostId` gains two host forms, `ab:<artboardId>` and
   `el:<artboardId>/<elementId>[#<occurrence>]`. Their boxes come from the `canvas-rects` manifest (DDR-151).
   An unresolvable element host keeps the bind and freezes the endpoint at its last place ("dangling"); only a
   person removes the bind.

**Consequences.**
- Positive: references survive rewrites as long as Claude keeps attributes, which is a rule Claude can
  follow and a check can prove. Locks become shared and visible to Claude where it edits. No new file, no
  new runtime path, no change to the four DDR-115 lists. v1 peers render the same: unknown `data-*`
  attributes are inert, and the v1 edit engine preserves bytes.
- Negative: some readable attributes in authored TSX on referenced elements. A full stamp of every element
  would add +23 % bytes (§6). This is why stamping is lazy. A lost id that can't be proven to be the same
  element detaches its references. That is visible and honest, never a guess. v1 handoff leaks
  `data-cd-locked` / `data-cd-hidden` (it strips only `data-cd-id`).
- Overturns part of DDR-138 ("stable per-node uuids in source") for **referenced** elements, with readable
  ids. Amends DDR-019: the authored id is the identity; the computed id is the fallback handle. Amends
  DDR-007: `data-dc-element` is the name and an alias handle, not the identity.

**Rejected:** Option 2 (prints only: wrong-element risk where references live), Option 4 (sidecar
metadata: invisible to Claude, new merge and orphan machinery), Option 5 (opaque ids everywhere: bytes,
readability), eager stamping of every element (+23 % canvas bytes, measured), stamping from the file
watcher (it would race Claude's next `Edit`, which refuses a file modified since it was read).

## 5. Contract

### 5.1 Types

```ts
/** Authored element id. */
type ElementId = string; // /^[a-z][a-z0-9]*(?:-[a-z0-9]+)*$/, ≤ 48 chars, !/^[0-9a-f]{8}$/, unique per file

/** A durable pointer at a canvas element. Never holds a computed (8-hex) id. */
interface ElementRef {
  canvas: string;          // repo-relative canvas path (follows moves via the manifest)
  artboard: string;        // DCArtboard id
  element: ElementId;
  occurrence?: number;     // index among same-id DOM nodes in that artboard (.map rows)
}

/** What a durable store keeps when the element is not stamped yet (queued stamp). */
interface PendingElementRef {
  canvas: string;
  artboard: string;
  print: ElementPrint;     // canvas-edit.ts
  hint: string;            // computed id at capture time — a hint, never the key
  occurrence?: number;
}

/** Canvas-only metadata, read from the element's attributes. */
interface CanvasOnly {
  locked: boolean;                 // data-cd-locked present
  hiddenPrevDisplay: string | null; // data-cd-hidden value; null when not hidden by the eye
}
```

### 5.2 Source rules (`canvas-edit.ts`, `canvas-pipeline.ts`)

| Rule | Owner | Today |
| --- | --- | --- |
| `data-cd-id` must be a string literal; an expression value is an error in `check` and refused by every writer | canvas-edit + check | not checked |
| The pipeline adds a `_locator.json` entry for **authored** ids as well as injected ones | `canvas-pipeline.ts` `walkInjectIds` | missing |
| `stampIds(source, targets: Array<{hint, print, occurrence?}>): { source, ids: Map<hint, ElementId> }` — pure, magic-string, reparse gate (DDR-138) | canvas-edit (new) | — |
| `generateElementId(el, used: Set<string>): ElementId` — the readable rule in §4.2 | canvas-edit (new) | — |
| Duplicate / paste / insert strip `data-cd-id` and `data-cd-locked` from the copy and stamp new ids | canvas-edit writers | duplicate copies attributes verbatim |
| `literalAttrs` already ignores every `data-cd-*`; keep it (prints must not change when a lock toggles) | canvas-edit | yes |
| The CSS / words writer and the D18 raw-attribute rows never read or write `data-cd-*` | inspector + edit routes | partial |

### 5.3 `maude design check <file.tsx> [--against <snapshot>] [--json] [--fix=safe]` — the id part

`--against` defaults to the run's start snapshot of that file (V2-1.18 run bracket) or, with no run, to
the last accepted content. Exit 0 = clean, 1 = errors. Budget: a two-sided check (parse both sides, walk
both) takes 26–44 ms on the four largest v2 canvases (§6). That leaves room in V2-1.18's < 1.5 s
PostToolUse budget.

| Code | When | Severity | Message shape (names the element by role, label and id, plus the line) |
| --- | --- | --- | --- |
| `id-lost` | an id in `--against` is missing and **re-attach finds the element** | error | `Button "See pricing" (line 212) lost data-cd-id="see-pricing" — put it back: comments, locks and arrows point at it.` |
| `id-removed` | an id is missing and re-attach finds **no** match | info (reported in the run result) | `Removed "Footer note" (footer-note). 1 comment detached.` |
| `id-duplicate` | two elements carry one id | error | `data-cd-id="hero" is on two elements (lines 40, 88) — give the copy a new id or drop it.` |
| `id-expression` | `data-cd-id={…}` | error | `data-cd-id must be a plain string ("…"), line 51.` |
| `id-format` | fails §4.2 | error | — |
| `locked-changed` | an element locked in `--against` has a different print, lost its lock, or was removed | error | `"Logo" is locked — leave it as it is, or ask the person to unlock it (⇧⌘L).` |
| `cd-attr-changed` | any other `data-cd-*` on a kept element changed | error | — |

`--json` shape: `{ file, errors: Finding[], infos: Finding[], reattach: Array<{ id, line }> }` with
`Finding = { code, id?, line, element: { tag, label, artboard } , message }`.

`--fix=safe` applies only `reattach` (and fills nothing else). It runs at `run.end` and from the CLI, **never**
from the PostToolUse hook (a write there would fail Claude's next `Edit`, which refuses a file changed
since it was read).

### 5.4 Re-attach (the `safe` matcher) — prototype algorithm, measured in §6

- Anchors: elements whose id exists on both sides.
- Candidates: for each new element without an id, the old elements whose id is missing, with the **same
  tag, component and artboard**.
- Score: same own text +3 (word overlap ≥ 0.5: +2) · same class list +3 (overlap ≥ 0.5: +2) · each equal
  literal attribute +1 (max 3) · parent is the anchor of the old parent +2 · each child anchored under the
  old element +2 (max 4).
- Accept only a **mutual best** pair with score ≥ 5 and a margin ≥ 2 over the runner-up, on both sides.
  Repeat until nothing new attaches (new matches become anchors).
- Everything else: no old id. A new element (inserted or a new wrapper) must never inherit an old id.

### 5.5 Canvas-only metadata

| Gesture | Source write (one action, V2-1.5) | Notes |
| --- | --- | --- |
| Lock ⇧⌘L / Layers lock | stamp + add `data-cd-locked` | Mixed selection locks all (DDR-246 parity). Click on a locked object selects its parent (14). |
| Unlock | remove `data-cd-locked` | Anyone with edit rights; never Claude. |
| Hide (Layers eye, object menu) | stamp + `style.display = "none"` + `data-cd-hidden="<prev inline display>"` | Kept in Layers, greyed. |
| Show | restore inline `display` from `data-cd-hidden` (remove it when empty) + remove `data-cd-hidden` | Fixes today's loss of an inline `display`. |
| Rename layer | `data-dc-element` (as today) + stamp | The name is not the id. |
| Edit element id (inspector › Advanced) | rename `data-cd-id` **and** every durable reference to it in the same action | Refused if the new id is taken or invalid. |

**Strip (export never sees canvas-only state):** one shared helper `stripCanvasOnly` removes every attribute
whose name starts with `data-cd-`:
- `handoff.ts` (`stripDataCdId` generalized to the prefix);
- the HTML export's cloned DOM in `bin/_html-playwright.mjs` (next to `neutralize`);
- SVG export, Copy CSS and any copy-as-code action, `to-rn`, the Canva handoff prompt when it embeds source;
- every new markup exporter from S8.

Pixel exports need no strip: a hidden object is `display: none`, and a lock draws nothing.

**Migration (V2-2.14 `maude migrate v2`):** per-user `view.json` `locked: ["<cdId>:<occ>"]` → resolve each
key at the current revision → stamp + `data-cd-locked`. Listed in the dry-run; reverse removes only what
it added. `data-dc-element` values are left alone.

## 6. Evidence

Prototype (not committed): `ids.ts`, `attrib.ts` and `timing.ts` in the spike worktree at
`apps/studio/scratch-v2-spike/` (untracked; raw whole-corpus output in `run-all.txt`), run through
`scripts/v2-test-lane.sh -- bun run <script> [--v2only] [--trials N]`.
Method: every JSX element gets a ground-truth tag `data-cd-gt="gN"`; the id walkers and prints ignore it,
because both skip `data-cd-*`. One artboard per trial is then rewritten the way an AI that keeps attributes
on kept elements would rewrite it. Three recipes:

- **small**: 1 insert + 5 % restyle;
- **typical**: 2 inserts, 1 wrap, 1 delete, 1 swap, 20 % restyle, 10 % text;
- **heavy**: 5 inserts, 3 wraps, 3 deletes, 3 swaps, 60 % restyle, 40 % text.

Then, for each element kept by the rewrite: is its old reference still on the same element (kept), on
**another** element (WRONG, silent), or nowhere (lost)?

**Whole corpus** (130 canvases, 1 trial per recipe and canvas, 139 s):

| Reference kind | small: edited artboard | small: rest of file | typical: edited | typical: rest | heavy: edited | heavy: rest |
| --- | --- | --- | --- | --- | --- | --- |
| positional `data-cd-id` (today) | 57.4 % kept · **42.2 % WRONG** | 76.7 % · **23.3 % WRONG** | 31.8 % · **68.2 % WRONG** | 79.9 % · **20.0 % WRONG** | 16.7 % · **83.1 % WRONG** | 73.8 % · **26.0 % WRONG** |
| artboard-scoped positional (Option 3) | 57.0 % · 43.0 % WRONG | **100 %** · 0 | 31.7 % · 66.1 % WRONG | **100 %** · 0 | 15.9 % · 82.4 % WRONG | **100 %** · 0 |
| print relocation (`relocateElement`) | 84.3 % · 0.4 % WRONG · 15.3 % lost | 93.0 % · 0.1 % · 6.9 % | 56.7 % · 1.9 % · 41.3 % | 93.6 % · 0.3 % · 6.1 % | 19.8 % · 5.4 % · 74.8 % | 92.0 % · 0.2 % · 7.8 % |
| authored id kept by the AI (Option 1) | 100 % | 100 % | 100 % | 100 % | 100 % | 100 % |

**v2 canvases only** (18 files, 2 trials, 216 s): the same shape. Small edit, positional: 49.3 % WRONG in
the edited artboard and **33.9 % WRONG across the rest of the file** (every artboard of a v2 canvas lives
in one component, so an insert renumbers every later artboard).

**Re-attach when the AI drops ids** (a fraction p of the ids in the edited artboard removed after the
rewrite), whole corpus:

| Recipe | p = 0.1 | p = 0.3 | p = 1.0 (artboard regenerated without ids) |
| --- | --- | --- | --- |
| small | 86.4 % re-attached · **0 wrong** | 86.4 % · 0 | 67.7 % · 0 |
| typical | 88.6 % · 0 | 84.4 % · 0 | 69.4 % · 0 |
| heavy | 74.5 % · 0 | 72.2 % · 0 | 45.2 % · 0 |

Across every run (whole corpus + v2 runs), **no** new element received an old id. The re-attach is safe.
It is not complete: the PostToolUse `id-lost` error (Claude puts the id back itself) is the first line of
defence, and re-attach is the second.

**Stamping cost:** a readable id on **every** element would add 799,329 B to 3,421,250 B (+23.4 %) across
the corpus, and +23.3 % on the v2 canvases (15,610 elements). 16,971 of 34,271 generated ids needed a
`-N` suffix (generic `div` / `span`). This is why stamping is lazy (§4.3) and Option 5 is rejected.

**Check speed** (`timing.ts`): parse + element walk of both sides of the four largest v2 canvases
(106–143 KB, 1,186–1,539 elements): 26–44 ms.

**Code facts confirmed while reading:**
- authored ids get no `_locator.json` entry (`walkInjectIds` writes entries only when it injects);
- `authoredCdId` ignores expression values while the pipeline skips injection for them;
- HTML export keeps every `data-cd-*`;
- the layer lock is per-user `view.json`, keyed by positional id.

## Decisions

- `decision:maude/v2-V2-1.4-authored-element-ids`: the stable element id is an authored `data-cd-id`
  string literal, readable, unique per file, never 8-hex; computed ids are transient. Why: positional ids
  re-point 23–83 % of references to wrong elements after an AI rewrite (measured). Rejected: prints only,
  artboard-scoped positional ids, opaque uuids on every element.
- `decision:maude/v2-V2-1.4-lazy-stamping`: ids are stamped on first durable reference or a studio
  write to the element, never eagerly and never from the file watcher. Why: eager stamping adds +23 %
  canvas bytes, and a watcher write breaks Claude's next `Edit`. Rejected: stamp-all at migration, server
  stamp on every fs event.
- `decision:maude/v2-V2-1.4-id-check-and-safe-reattach`: Claude keeps ids by skill rule; the PostToolUse
  `check` blocks lost, duplicate, expression, locked-changed; `--fix=safe` re-attaches only mutual-best
  matches at run end (0 wrong in the corpus simulation). Rejected: fixing in PostToolUse (races `Edit`),
  best-guess re-attach.
- `decision:maude/v2-V2-1.4-canvas-only-data-cd-namespace`: lock and hide-marker are `data-cd-*`
  attributes on the element in the versioned TSX; every markup/code exporter strips the prefix; Place
  freely is CSS, not metadata. Rejected: `.meta.json` element map, per-user `view.json` locks.
- `decision:maude/v2-V2-1.4-bound-arrow-hosts`: arrows bind to `ab:<artboard>` and
  `el:<artboard>/<id>[#occ]`; an unresolvable host freezes the endpoint and keeps the bind. Rejected:
  stripping the bind on a missing element (an undo can bring the element back).
