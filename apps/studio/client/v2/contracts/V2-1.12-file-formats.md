# V2-1.12 — File formats across versions (Gate 0 A17)

Spike contract note. Plan: `.ai/plans/feature-maude-v2-redesign.md` (V2-1.12 → V2-2.14, V2-2.16, V2-2.18;
standing rule 15). Gate 0 A17 (signed): v2 writes a `formatVersion: 2` marker per project; a 1.x patch release
(shipped before any v2 rc) opens a v2-format project read-only with "Update Maude to edit"; `maude migrate v2`
upgrades files idempotently with a dry-run and a reverse step.

## 1. Question

> `formatVersion` per project + per file schema versions; what a v1 peer does on read/write; migrator shape
> (dry-run, idempotent, reverse); mixed-peer sync rules on the hub file plane

## 2. What exists today

## 3. Options

1. **A17 as written** (plan default): marker in `config.json`, gate only in the 1.x patch client. *Cost S.*
   *Breaks:* `config.json` never rides the file plane, so a v1 desktop linking to a v2 cloud project never sees the
   marker. Unpatched v1 peers and the cloud cell's 1.x studio write freely. Every v1 write path strips unknown
   fields (§6 probes A, E, G, J), so "read-only" would be a UI promise, not a property.
2. **Option 1 + hub-held format + writers declare their format + lossless readers + field-placement rules**
   (chosen). *Cost M:* one store key + one fence term + one route + 426 doors on the hub; one validator change; one
   banner. *Breaks:* nothing on format-1 projects; v1 peers become read-only on format-2 projects by protocol.
3. **Per-file version bumps only** (annotations `v: 3`, a stamp in every `.meta.json`), no project marker.
   *Cost M–L:* every meta rewritten, a big diff, a CRDT burst per canvas. *Breaks:* v1 shows empty boards (probe
   D); a bumped replica marker makes v1 erase the board (probe F); TSX and meta writes stay unguarded.
4. **Compat writing**: v2 writes only v1-legal shapes into format-1 projects until every peer upgrades. *Cost L:*
   every v2 field feature-gated across all work packages. *Breaks:* parity; every feature built twice.
5. **Minimum client version on the hub** (DDR-242 §5 `minStudioVersion`, never built). *Cost S.* *Breaks:* version
   numbers don't map to formats across the rc and 1.x patch lines; still needs a client declaration; locks v1 out of
   format-1 projects too.

## 4. Decision (DDR draft)

**Title:** Project format version — a config marker, the hub as authority, writers declare, readers preserve.

**Context.** v2 adds fields to versioned files (annotations, `.meta.json`, DS manifests, chat meta). Today's
readers drop what they don't know (§6), and a v1 peer's next write erases v2 data. During the rc soak, v1 and v2
desktops share cloud projects. A17 promises v1 opens a v2 project read-only. That promise has to hold on every
transport (local disk, git, Syncthing, hub doc lanes, hub file plane, cloud browser tab), including for 1.x
builds that predate the patch.

**Decision.**

1. **One integer per project.** `formatVersion`: absent = 1; v2 = 2. Each build has `SUPPORTED_FORMAT` (1.x = 1,
   2.x = 2). A build **edits** a project only when `projectFormat === SUPPORTED_FORMAT`. It reads older formats
   natively and newer formats read-only, best effort. v2 opens a format-1 project read-only until it is migrated.
2. **Where the marker lives.** `.design/config.json` `"formatVersion": 2` for local, git and Syncthing projects. For
   a hub-linked project the hub's project store (`store_meta.formatVersion`) is the authority; the desktop mirrors it
   (raise-only) and the cell seeds it from its checkout's `config.json` (raise-only).
3. **Writers declare, the hub fences.** Every connection and HTTP write to a hub declares its format
   (`maude-format=2` on the WebSocket URL, `X-Maude-Format: 2` on HTTP); absent means 1. A writer is admitted only
   when declared format === project format.
   - **Doc lanes:** the connection is read-only (`connectionConfig.readOnly` plus the per-message `fence`).
   - **HTTP doors:** **426** with the copy. Not 403, because old clients renew credentials on a 403.
   - **Proposals:** a final `{status: 'rejected', code: 'format'}`.
   - **Owner flip:** an owner switches the format with the same barrier as `setMode`, and the notice rides the
     `maude.mode` envelope every 1.x client since DDR-241 already obeys.
4. **Readers preserve.** The shared annotations registry keeps unknown keys on known types the same way it already
   keeps unknown types (bounded, sanitized, sorted after the tail fields). `writeChatMeta` merges into the raw stored
   object. These ship in the 1.x compat release, so desktop, hub and cell all become lossless.
5. **Fields are added by rules, not by version bumps** (§5.1 R1–R7). An additive field never bumps a file's own
   version. The replica marker `~v` is never bumped. Meta additions are top-level only.
6. **`maude migrate v2`.** Dry-run by default, `--apply` to write. It snapshots before writing, applies
   all-or-nothing, and is idempotent. `--reverse` restores byte-for-byte when the files are unedited. Hub order:
   forward flips the hub before the first local write; reverse unflips it after the last.

**Consequences.**

- A 1.x compat release must reach users before any v2 rc. It carries the hub (+ cell DO RPC), the desktop gate and
  the lossless readers.
- 1.x clients that never install the patch still behave read-only through the hub when they run the shared-doc
  path from DDR-241 onward. A write the hub would drop is held: `canWriteDoc` → `isWritable()` reads the handshake
  scope and `maude.mode writable:false`. Only unpatched peers on hub-less transports (git, Syncthing) can still
  strip v2 data. By R6, that exposure is limited to annotation extension fields; v2 meta data is safe because none
  of it lives under `layout`.
- During the soak the cloud fleet stays on the compat image (rc tags never roll it, V2-2.0), so browser tabs on a
  format-2 project are view-only.
- No new runtime-state class (`_state/`, `_history/`, `_trash/` already cover every new path), so the four DDR-115
  lists are unchanged.

**Rejected alternatives.** Options 1, 3, 4 and 5 above, for the reasons listed there. Also rejected:

- Bumping the annotations file `v` for additive fields: blinds v1 (probe D) with no write protection beyond what
  the project gate gives.
- A marker file of its own (`.design/format.json`): bare `.json` is default-closed on the file plane, and a
  file-plane-carried marker would let any editor flip the format by writing a file.

## 5. Contract

### 5.1 Rules for adding a field to a versioned file (binding on every work package; standing rule 15)

| # | Rule | Why (probe) |
| --- | --- | --- |
| R1 | **Additive only.** A field a format adds is optional; absence means the previous behaviour. | v1 never writes it |
| R2 | **Display-ignorable.** A reader that ignores the field still renders the file correctly. Example: `parentArtboard` is membership, not a coordinate frame — `x`/`y` stay world coordinates. | v1 renders the same picture |
| R3 | **No new shapes in old fields.** A value must still parse under the previous field spec: no new member in an existing `oneOf`, no new object shape in an existing field. Use an extension field or a new type. | B: an arrow end `{artboard}` makes v1 drop the whole arrow |
| R4 | **New element kinds are new `type`s** (e.g. a vote stamp). | C: unknown types round-trip verbatim |
| R5 | **Annotation extension fields** sit after `TAIL_FIELDS` (`groups`, `author`, `locked`), sorted by key, default omitted, values `sanitizeJson`-safe, key matching `UNKNOWN_KEY_RE`. A preserving reader then produces the v2 reader's exact bytes, so DDR-241 lane hashes agree. | A, E, G |
| R6 | **Meta additions are top-level keys.** Never under `layout`, never inside `layout.artboards[]`. Per-artboard data goes in a top-level map keyed by artboard id. | H, J: v1 `patchCanvasMeta` drops both |
| R7 | **A non-additive change** bumps that file's own `v` AND the project `formatVersion`, never one without the other. The replica marker `'~v'` is never bumped. | D; F: a bumped `~v` makes v1 erase the board |
| R8 | **Strict v1 readers stay frozen** (amendment 2026-10-09, from V2-1.10): v1's readers of `.footage.json` and `.edl.json` treat a file with ANY unknown key as missing (which invites a re-analysis that overwrites it), so v2.0 adds NO keys to those two formats; new per-clip analysis goes into new sidecars (`assets/<sha8>.transcript.json`, `assets/<sha8>.beats.json`) whose readers keep unknown keys. | V2-1.10 probe |

Reserved top-level meta keys (names fixed here; inner shape belongs to the owner):

| Key | Owner | Contents |
| --- | --- | --- |
| `present` | S3 | order, skip |
| `artboardMeta` | S2 / S3 / S5 / S7 | `{ [artboardId]: { notes, poster, maxFrames, madeBy } }` |
| `links` | S3 | interactions between artboards and canvases |
| `dsRev`, `dsPins` | S10 / V2-1.6 | design-system pinning |
| `video` | S7 | only if tracks are ever stored |

### 5.2 Project marker — where it lives and who sees it

| Transport | Authority | How a peer learns it |
| --- | --- | --- |
| Local / git / Syncthing | `.design/config.json` `formatVersion` | config load + the existing `fs:json` → `reloadConfig` hot reload (≤ 150 ms debounce) |
| Hub-linked desktop | hub `store_meta.formatVersion` | `/health` `formatVersion`, the `maude.mode` notice, cached in `_state/hub-format.json` `{hub, formatVersion, epoch, seenAt}` |

`projectFormat = max(config.formatVersion ?? 1, linked ? (hubLive ?? hubCached ?? 1) : 1)`.

- **Raise-only:** a hub can raise the local value, never lower it. Only the owner's `maude migrate v2 --reverse`
  lowers both.
- **First link / Move to cloud** raises the hub to the local marker (`POST /api/project-format`) before the first
  seed-up.

### 5.4 Writer declaration and the hub fence

**Declaration.**

- **WebSocket:** `maude-format=<n>` on the shared `HocuspocusProviderWebsocket` URL, read in `onAuthenticate`
  from `request.url`, stored as `context.user.format`.
- **HTTP:** `X-Maude-Format: <n>` on every studio → hub request; the studio's hub fetch wrapper adds it once.
- **Absent or not an integer:** the writer is format 1. This is a compatibility declaration, not a security
  boundary — a writer with edit rights can already write anything.

**Fence** (one predicate, both save modes, in `hub-integration.mjs` `fence`):

```
connection.readOnly = !ready                     // store's mode AND format not read yet → closed
                   || acceptedMode()
                   || context.user.readOnly === true
                   || (context.user.format ?? 1) !== state.formatVersion
```

**Doors.**

| Door | Refusal for `declared ≠ project` |
| --- | --- |
| WS content docs | read-only connection; Y updates dropped; handshake scope `readonly` |
| `maude.files` ctl doc | unchanged (already read-only for everyone) |
| File plane PUT / delete / upload sessions, `PUT /api/project-config`, asset routes, comments | `426` `{ "error": "<refusal copy §5.8>", "reason": "format", "formatVersion": 2 }` |
| `POST /api/projects/:p/v1/proposals` | `426` `{ "status": "rejected", "code": "format", "formatVersion": 2, "error": "<copy>" }` — final for every client generation |
| Reads (GET journal, files, docs, `/health`), sign-in / sign-out, export / download | allowed |

### 5.5 Hub API

- **`GET /health`** (public, protocol marker): adds `"formatVersion": <n>` (`null` while unread) and capability
  `format-v2`. The capability means: this hub stores and advertises the format, fences by declared format, its
  validators preserve extension fields, and it serves the route below.
- **`POST /api/project-format`**:
  - Auth: owner-role bearer, operator, or cell secret. Editor and viewer get 403.
  - Body: `{ "formatVersion": 1 | 2, "expectEpoch"?: number }`.
  - 200: `{ "formatVersion": 2, "epoch": 14, "changedAt": "<iso>", "changedBy": "<label>" }`. The same value is a
    200 with no epoch bump.
  - 409: `{ "code": "epoch-stale" | "switch-in-progress" }`.
  - 422: `{ "code": "format-unsupported", "max": 2 }`.
- **Barrier** (the `setMode` order): persist (`store.setFormat`, epoch + 1) → send every connection
  `{ "type": "maude.mode", "mode": <current>, "epoch": <new>, "writable": <recomputed>, "formatVersion": <new> }`
  → wait `switchGraceMs` → fence engaged per message → 200. Proposals wait on the switch.
- **Store.** `state()` adds `formatVersion: Number(meta('formatVersion', 1))`; new
  `setFormat({ formatVersion, expectEpoch, by })` and `raiseFormat(n)` (checkout seed). Both are added to
  `store-remote.mjs` `METHODS` and `apps/cells/project-store.mjs` `STORE_METHODS`.

### 5.6 Studio state and API (1.x patch and v2 alike)

- **New module** `apps/studio/format.ts`:
  - `SUPPORTED_FORMAT`
  - `projectFormat(ctx): number`
  - `formatGate(ctx): null | { projectFormat: number; supported: number; source: 'config' | 'hub' }`
- **`/_config` additions:** `formatVersion`, `formatGate`, and `readOnlyReason: 'role' | 'format' | null`.
  `readOnly` is true when gated.
- **Gate:** `projectReadOnly(req)` returns true when `formatGate(ctx)` is set. The refusal is
  `403 { "error": "read-only", "reason": "read-only", "detail": "format", "formatVersion", "message": "<copy>" }`.
- **Format-gate allowlist:** per-user runtime (`/_canvas-state`, viewport lane of `/_api/canvas-meta`,

  link / sign-in / sign-out. **Comments are refused** (see §9 Q3).
- **Sync while gated:**
  - Nothing goes up: no fs → doc imports, no file-plane up-pushes, no proposals.
  - Pulls and projections continue, and are lossless (P2).
  - The `maude.mode` handler reads `formatVersion`, writes `_state/hub-format.json`, and emits `config-updated`
    so shells refetch `/_config`.

### 5.9 v2 on a format-1 project

- **Reads** natively.
- **Opening:**
  - Local or unlinked project, or the owner of a linked one: the dialog. *Update project* runs the engine through
    the studio route `POST /_api/project/migrate` (main origin only, privileged, never canvas-safe — a shared-file
    patch request to the lead).
  - Everyone else: view only.
- **First sight of a flip.** A v2 desktop whose `_state/hub-format.json` is absent or older than the hub's value:
  - every canvas-owned lane is hub-wins;
  - a divergent local copy is snapshotted to `_history/<slug>/` with reason `pre-format-flip-local` and recorded
    as a `_sync.json` conflict of kind `format-flip-local-kept`;
  - nothing is pushed.

  This extends the DDR-102 decision table with one row, evaluated before newest-wins.

### 5.10 `maude migrate v2`

**CLI** (`cli/commands/migrate.mjs` spawns the bundled bun on `apps/studio/migrate/cli.ts`, DDR-062/177):

```
maude migrate v2 [--apply] [--reverse [--strip]] [--json] [--root <repo>]
```

- **Default is dry-run.** `--apply` writes. `--reverse` returns a project to format 1. `--strip` also removes
  v2-only fields, for peers older than the compat release.
- **Permission tier (A13):** dry-run is read-only and auto-approved; `--apply` shows the permission card in the AI
  chat.
- **Exit codes:**

| Code | Meaning |
| --- | --- |
| 0 | done, or a clean dry-run |
| 10 | already at target (every step `noop`) |
| 11 | refused, nothing written |
| 1 | error |
| 2 | usage |

**Engine** (`apps/studio/migrate/engine.ts`; reused in-process by the studio route):

```ts
export interface MigrateOptions {
  repoRoot: string;
  designRel: string;
  direction: 'forward' | 'reverse';
  strip?: boolean;                                     // reverse only
  hub?: { url: string; token: string; role: string } | null; // from hubs-config; null = unlinked
  now?: () => Date;
}
export function planMigration(opts: MigrateOptions): Promise<MigrateReport>; // read-only (= dry-run)
export function applyMigration(opts: MigrateOptions, plan: MigrateReport): Promise<MigrateReport>;

export interface MigrationStep {
  id: string;
  scope: readonly string[]; // designRoot-relative globs
  forward(files: ReadonlyMap<string, Uint8Array>, ctx: StepCtx): StepResult;
  reverse(files: ReadonlyMap<string, Uint8Array>, ctx: StepCtx, o: { strip: boolean }): StepResult;
}
export interface StepResult {
  writes: Map<string, Uint8Array | null>; // only paths whose bytes change; null = move to _trash/migrate-v2/
  refusals: Array<{ path: string; reason: string }>;
  lost: Array<{ path: string; field: string; count: number }>;
  notes: string[];
}
```

**Steps (format 1 → 2):**

| Id | Forward | Reverse | Bytes changed on an unedited project |
| --- | --- | --- | --- |
| `project.marker` | hub flip (linked) **first**, then `config.json` `formatVersion: 2` | remove the key, **then** hub unflip | 1 file |
| `annotations.check` | prerequisite: the DDR-242 `migrateAnnotationsV2` for any legacy SVG (not reversed). Then every board must parse with `dropped: []`, else refuse | `--strip`: remove extension fields and v2-only types (reported in `lost`) | 0 |
| `meta.check` | every `.meta.json` must parse as an object, else refuse | `--strip`: remove §5.1 reserved keys | 0 |
| `comps.tracks` | none — tracks are derived (C35) | none | 0 |
| `chats.canvas` (per Mac) | add `canvas` from the first `[maude-context canvas="…"]` line when absent | remove `canvas` when it equals the derived value | n |
| `ds.tokens` | per `config.designSystems[]`, emit `system/<ds>/tokens.json` via `ds-check --emit` when absent; `skip` until V2-2.15 lands. Never touches CSS, `components.json`, specimens or canvases — that is Bring-up, A16. | remove when bytes equal the emit or the recorded `after` | one per system |

**Report** (`--json`, also the studio route's body):

```json

  "direction": "forward", "dryRun": true,
  "project": { "designRoot": ".design", "formatBefore": 1, "formatAfter": 2, "treeHash": "sha256:…",
               "linked": { "hub": "https://…", "role": "owner", "hubFormat": 1,

               "files": [ { "path": "ui-home.annotations.json", "action": "modify|create|remove",
```

File lists are capped at 500 entries per step, with a count.

**Invariants:**

| Id | Invariant |
| --- | --- |
| I1 | Dry-run writes nothing anywhere: no lock, no `_state/`. |
| I2 | Apply re-plans and refuses if `treeHash` differs from the plan's. It stages writes and renames; on any failure it restores from the snapshot. All or nothing. |
| I3 | Before the first write, every file to modify or remove is copied to `_history/_migrate/v2-<stamp>/<rel>` together with `report.json`. A failed snapshot refuses the run (DDR-102 §3, fail-closed). Lock: `_state/migrate-v2.lock`. |
| I4 | Idempotent. Forward on a format-2 project whose steps are all `noop` exits 10 with zero writes. Per step, `forward ∘ forward = forward`. |
| I5 | Exact reverse. For an unedited tree, `reverse(forward(T)) = T` byte-for-byte (tree hash excluding `_history/_migrate/**`). Reverse restores the snapshot copy when a file's hash equals the plan's recorded `after`; otherwise it applies the semantic reverse. Without `--strip`, v2 fields stay; P2 readers keep them. |
| I6 | Never touches canvas `.tsx`, DS CSS / `_components.css` / `preview/**`, `assets/**`, `_comments/`, `_trash/`, `_canvas-state/`, `.git`. |
| I7 | Hub order: flip before the first local write; unflip after the last. A crash in between resumes, because §5.2 raise-only lets the next v2 boot adopt the hub value and steps are idempotent. |
| I8 | Never deletes a file it did not create. Removals go to `_trash/migrate-v2/`. |

**Refuses** (exit 11, nothing written):

- project format > 2;
- `config.json` missing or not JSON;
- a board with dropped elements;
- a non-object `.meta.json`;
- a live studio for this project when the call didn't come through it ("Close the project in Maude, or use Update
  project in the app");
- a linked project when the caller isn't owner, the hub lacks `format-v2`, the hub is unreachable, or the epoch is
  stale;
- `--reverse` on a project that isn't at format 2;
- the tree changed between plan and apply.

### 5.11 Mixed-peer sync rules

**Plane A (doc lanes):**

- **D1** Writers whose declared format ≠ the project format are read-only connections (§5.4).
- **D2** Hub validators preserve extension fields (P2), so kernel merge, replica writes and checkout projection are
  lossless.
- **D3** `'~v'` stays 2.
- **D4** An annotations file's `v` changes only under R7.

**Plane B (journal file plane):**

- **F1** The hub never parses Plane-B bytes. A new file kind needs only the classifier entry, in both copies, in
  the same commit.
- **F2** Every write door refuses a mismatched writer with 426: no journal row, nothing materialized. Reads are
  open.
- **F3** A receiver materializes only the classes its own classifier admits. A v1 peer classifies `tokens.json` as
  `never`, so the doručenka honestly shows it as not `at-peer`. That is not a conflict and not
  `referenced-but-unoffered`.
- **F4** A format flip emits no tombstones. Reverse removes only the migrator's own derived files, through the
  normal owner tombstone path. A fenced peer can't push tombstones (F2).

**Release order and capability:** no v2 client writes a format-2 field to a hub without `format-v2`, and no rc is
tagged before the compat release is published.

## Decisions

- `decision:maude/v2-1.12-project-format-marker`
  - **What:** one integer `formatVersion` per project (absent = 1). It lives in `.design/config.json` for local,
    git and Syncthing transport, and in the hub's project store (`store_meta`, DO in cloud) as the authority for
    linked projects. Raise-only mirroring; the cell seeds it from its checkout.
  - **Why:** `config.json` is versioned in git but `never` on the file plane, so a config-only marker is invisible
    to hub peers, and the hub is the only component that can stop old clients.
  - **Rejected:** config-only marker (A17 literal); a dedicated marker file (default-closed and editor-flippable);
    per-file version stamps (probes D, F); hub `minStudioVersion`.
- `decision:maude/v2-1.12-hub-fence-by-declared-format`
  - **What:** writers declare a format (`maude-format` WS param, `X-Maude-Format` header, absent = 1) and are
    admitted only when it equals the project format. Doc lanes become read-only connections via the existing
    per-message fence. Doors answer 426 with the copy. Proposals get a final `{status: 'rejected', code: 'format'}`.
    Owner-only `POST /api/project-format` uses the `setMode` barrier and a `maude.mode` notice carrying `writable`
    + `formatVersion`.
  - **Why:** this reuses DDR-241's fence and the notice old desktops already obey. 403 would trigger old clients'
    credential renewal.
  - **Rejected:** a client-only gate; 403 refusals; closing sockets.
- `decision:maude/v2-1.12-lossless-readers`
  - **What:** the shared annotations registry keeps unknown keys on known types like it keeps unknown types
    (bounded, sanitized, sorted after the tail); `writeChatMeta` merges into the raw object. Shipped in the 1.x
    compat release, so desktop, hub and cell all carry it.
  - **Why:** probes A, E, G, J — every v1 write path strips v2 fields.
  - **Rejected:** relying on the read-only gate alone (the hub projection and kernel merge rewrite boards too).
- `decision:maude/v2-1.12-additive-field-rules`
  - **What:** R1–R7. Additive, display-ignorable fields; no new shapes or enum values in old fields; new kinds are
    new types; annotation extension fields after the tail in sorted order; meta additions top-level only; a
    non-additive change bumps the file `v` and the project format together; replica `'~v'` never bumps.
  - **Why:** probes B, F, H, J.
  - **Rejected:** bumping annotations to `v: 3` for additive fields (blinds v1, probe D); nesting v2 meta under
    `layout`.
- `decision:maude/v2-1.12-migrate-v2-shape`
  - **What:** `maude migrate v2` — dry-run default, `--apply`, `--reverse [--strip]`. Snapshot to
    `_history/_migrate/`, all-or-nothing, tree-hash TOCTOU guard. Idempotent (exit 10 at target), exact reverse on
    unedited trees, hub flip first / unflip last. Steps: marker, annotations check, meta check, comps (derived, no
    bytes), chat canvas link, DS `tokens.json` emit. Exit codes 0 / 10 / 11 / 1 / 2. No new runtime-state class.
  - **Why:** A17 + the DDR-242 §6 migration precedent.
  - **Rejected:** apply-by-default; codemods of TSX or DS CSS (Bring-up owns them); storing comp tracks at
    migration.
- `decision:maude/v2-1.12-v2-edits-only-matching-format`
  - **What:** a build edits only when project format == `SUPPORTED_FORMAT`. v2 opens format-1 projects view-only
    with an owner/local "Update … for Maude 2?" dialog. A first-sight cold-start row keeps divergent local copies
    aside and makes the hub win after a flip.
  - **Why:** symmetric, enforceable, no dual-write feature gating.
  - **Rejected:** compat writing into format-1 projects; auto-migration without consent.
