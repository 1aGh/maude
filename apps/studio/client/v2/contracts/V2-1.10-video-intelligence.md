## 1. Question

> Beat detection, speech regions for ducking, word timings → captions/edit-by-transcript, subject tracking
> for per-format framing (or the B3 fallback)

From the brief: measure beat detection with ffmpeg only against a small JS onset detector, word timings from
the transcribe verb, and speech regions for ducking, on real clips. Produce the data each feature stores
(comp / `.meta.json` fields, under V2-1.12 R1–R7), the verbs (`maude design beats`, captions), the accuracy
and latency numbers, the tracking decision (or the fallback), and the tests.

## 2. What exists today

**Transcription.** `apps/studio/bin/_transcribe.mjs` (behind `maude design transcribe`, DDR-062) runs
whisper.cpp with `-oj -ml 1` and maps each JSON segment to a word in `whisperJsonToWords`. That flag set
splits on **tokens**, not words, so the output carries sub-word pieces and punctuation as "words" (§6.1). The
engine is an explicit choice (`resolveProvider`, `settleAutoProvider`: whisper | elevenlabs | groq | auto,
DDR-164, kg "Transcription gains an `auto` engine"). The cloud engines run through `/_api/generate-jobs`
(modality `transcription`; `generation/adapters/elevenlabs.ts`, `adapters/groq.ts` `groqVerboseToWords`). All
three produce word timings and all three collapse them to an SRT through `generation/captions.ts`
(`reflowWords`, `cuesToSrt`, `wordsToSrt`). **The word timings are then thrown away.** The local path also
leaves whisper's own JSON next to the source: `-of` is `dirname(input)/basename`, so an `assets/<sha8>.mp4`
leaves an `assets/<sha8>.json`. The real Alligators project holds **24** of these bare `<sha8>.json` files
beside 38 `.srt` files. A bare `.json` is default-closed on the file plane (`sync/file-membership.ts`
`classifyProjectFile`), so those word timings never reach a peer. Models: `generation/whisper-models.ts`
(`resolveWhisperModel`; cache `~/.cache/maude/whisper-models` or a user's `--model`). whisper.cpp and ffmpeg
are **soft** dependencies (`plugins/design/dependencies.json` ids `whisper-cpp`, `ffmpeg`), never bundled.

**Footage pipeline** (DDR-163, DDR-183). `ingest-footage` → `smart-frames` (`bin/_smart-frames.mjs`:
gemma → ffmpeg scene cuts + endpoints + midpoints → blind Chromium tier) → `footage-analyst` (vision, writes
`assets/<sha8>.footage.json`, `footage/schema.ts` `FootageAnalysis`: shots with `quality`, `usable`, `note`,
free-text `subject`, **no spatial data**) → `footage-director` (`<slug>.edl.json`, `Edl`; its "beats" are
shots) → codegen in `/design:reel` (skill `footage-director` guide 03: one literal
`<TransitionSeries.Sequence>` per shot, a `CUES` JSON literal and a local `Captions` component for captions,
music "ducked" as a constant `gainDb` when a voiceover overlaps). DDR-163 scoped audio out ("no transcript, no
whisper, no beat detection") and named audio-aware editing a revisit trigger, reading the same
`footage.json` / `edl.json` seams. **`validateFootageAnalysis` and `validateEdl` reject unknown keys**
(`assertKeys`), and `footage-store.ts` `readSidecar` returns `null` for a file that fails validation, so a
v1 reader treats a sidecar with one new key as absent.

**Comp and timeline.** `video-comp.tsx` (`VideoComp`, `window.__maude_seek__`, the determinism rule: every
value is a pure function of `useCurrentFrame()`, DDR-148). `canvas-edit.ts` `enumerateClips` / `ClipInfo`
(`stableId`, `mediaProps.trimBefore`, `playbackRate`, `framing` from the `data-mframe="scale,x,y"` wrapper),
`clip-ops.ts` (`applySplitClip`, `applyTrimIn`, `applyRemoveClipRippled`, `applyClipFraming`,
`clipAbsoluteStart`), one dispatch route `/_api/clip-edit` → `api.ts` `clipEditOp` (verbs `speed`,
`trim-in`, `audio`, `detach-audio`, `framing`, `grade`, `transition`, `split`, `insert-transition`,
`remove-transition`, `set-text`, `to-overlay`, `to-storyline`, `layer-order`, `resolve-placeholder`).
DDR-150 (clip addressing, literal blocks). `client/panels/timeline-snap.js` `computeSnapTargets` (second
ticks, neighbour edges, playhead). `client/panels/TimelinePanel.jsx`. The canvas build
(`canvas-build.ts`, pass 1 rewrites TSX, pass 2 `Bun.build`, imports confined to the design root) bundles
JSON imports. No beat detection, speech detection or subject tracking exists anywhere.

**Tracking.** `.ai/plans/feature-video-tracking-and-stabilization.md` (unbuilt; kg "Debate: video tracking &
stabilization architecture", unanimous `OPENCV_SPINE`: opencv.js in the provisioned headless Chromium, a
versioned parameters-only `assets/<sha8>.track.json`, refusal as a first-class outcome, Apple Vision and
bundled ffmpeg vidstab rejected). It targets camera stabilization and planar corner-pin, not following a
person.

**Decisions that constrain this.** DDR-148 (determinism, Remotion, capture), DDR-150 (literal clip blocks,
the enumerator is the display truth), DDR-163 (sidecars versioned, seconds in source time, frames in output
time, decode in Chromium rather than native binaries), DDR-164 (BYOK, no silent switch to a paid engine),
DDR-177 (the packaged app runs with no `brew`), DDR-183 (footage pipeline egress-free), DDR-115 (sidecars
under `assets/` are versioned, no new `_*` path), DDR-226 (file plane, positive classifier), DDR-054 (hub
content untrusted). `kg search` on "beat detection", "subject tracking", "audio ducking" returns no prior
decision beyond the ones above.

## 3. Options

**Word timings.**
1. Today's flags (`-oj -ml 1`, segment times). *Cost 0. Breaks:* 36 % extra caption items, punctuation and
   sub-words as words, every pause bridged by a word (§6.1).
2. **whisper.cpp `-ojf -ml 1 -sow -dtw <model> -nfa` + per-file timing calibration + energy snap** (chosen).
   *Cost S.* *Breaks:* nothing; +23 % run time.
3. Cloud only (Scribe / Groq). *Breaks:* needs a key and network; can never be auto tier (V2-1.11).
4. whisper.cpp `--vad` (Silero). *Breaks:* a model download; not measured.

**Speech regions for ducking.**
1. Energy on the mixed output. *Breaks:* fails as soon as music is under the speech (§6.2).
2. **Words from the transcript of each clip's own audio, energy only as a labelled fallback** (chosen).
3. A VAD model. *Breaks:* a download and a new dependency.

**Beats.**
1. ffmpeg filters only (`astats` RMS envelope, peak picking, inter-onset histogram). *Breaks:* beat F 0.55,
   tempo wrong on 2 of 5 real tracks (§6.3).
2. **ffmpeg decode (headless Chromium WebAudio when ffmpeg is absent) + a small in-house JS detector:
   spectral flux → autocorrelation tempo with a prior → dynamic-programming beat tracking** (chosen). No new
   dependency (~250 lines).
3. essentia.js / aubio / librosa. *Breaks:* a new dependency (WASM size or Python) and a DDR, for no
   measured gain on this corpus.

**Captions and ducking storage.**
1. Comp-time literals (today's `CUES` array; a `gainDb` per bed). *Breaks:* every trim, split, move or speed
   change has to re-time them; a Claude edit of a clip length silently desyncs captions.
2. **Asset-level transcript (machine output) + derived at build from the comp's clips; human fixes live in
   the comp** (chosen).
3. A `<ClipCaptions from>` child per clip, duplicating `trimBefore`. *Breaks:* two literals to keep equal.
4. Word fixes in the transcript sidecar. *Breaks:* outside ⌘Z and Version history (Plane B, whole-file).

**Subject framing.**
1. **Centre + manual focus-point keyframes** (plan default, B3 fallback) (chosen).
2. AI-seeded keyframes at `smart-frames` times, interpolated. *Breaks:* 76 % in frame on tight crops.
3. Motion-centroid tracker from ffmpeg frame differences. *Breaks:* 83 % on tight crops, 88 % on 16:9.
4. opencv.js tracker now. *Breaks:* a project of its own (the tracking plan); not on any existing verb.

**AI cut streaming.**
1. Codegen once at the end (today). *Breaks:* no shot lands live; Stop has nothing to keep.
2. **A deterministic `reel-place --next` verb, one shot per write, inside the V2-1.15 run** (chosen).
3. Claude `Edit` per shot. Works, costs tokens per shot; allowed as the fallback.

## 4. Decision (DDR draft)

**Title:** Video intelligence — per-asset analysis sidecars, captions and ducking derived from the comp,
in-house beats, centre + manual framing, AI cut placed shot by shot.

**Context.** B3 puts captions word by word, edit by transcript, beats and Cut to the beat, ducking and
per-format framing into v2.0, and lets subject tracking fall back to "centre + manual nudge". The pieces that
exist (three STT engines, the footage analyst and director, the clip op layer) lose word timings, have no
audio analysis and no spatial data. A13 needs each feature to be a readable file or a `maude` verb; V2-1.5
needs human and AI edits in one op log; V2-1.12 needs every new field to leave v1 peers whole.

**Decision.**
1. **Two machine-written, per-asset sidecars** sit next to the source in `assets/`:
   `<sha8>.transcript.json` (words with ids and confidence, speech regions) and `<sha8>.beats.json` (tempo,
   beats, bar phase). They are regenerable analysis — like `.footage.json` — so they are Plane B
   companion-text, versioned, and outside the op log. Their validators **keep unknown keys**.
2. **Human and AI decisions live in the comp TSX** (Plane A, one op log, ⌘Z, Version history,
   attribution): caption style and word fixes (`<Captions>`), cuts (ordinary clips), ducking (`<Duck>`),
   framing (`<Reframe>`). `.meta.json` gets only per-artboard editor state under the reserved
   `artboardMeta` map (`poster`, `snap`, `maxFrames`).
3. **Captions and ducking are derived, never materialised.** At build time, and in one server module, the
   comp's clips (the same `enumerateClips` the Timeline uses) are crossed with the transcripts of their
   sources. Captions and speech regions follow every trim, split, move and speed change with no extra write.
   The `.srt` is an export artefact (C36), not a sidecar.
4. **Words pipeline (every engine writes the same file).** Local: whisper.cpp
   `-ojf -ml 1 -sow -dtw <model> -nfa`. Then the per-file DTW lag is calibrated against energy onsets after
   pauses, each word is trimmed to its voiced frames, and repetition loops are flagged. Cloud engines map
   their provider word timings to the same schema. No more bare `assets/<sha8>.json`.
5. **Speech regions come from words.** Confident (p ≥ 0.35), voiced, non-loop words are merged across gaps
   < 0.8 s and padded by 0.12 s. They are computed on each clip's own audio, never on a mix. Without a
   transcript, a labelled energy fallback (`speech.source: "energy"`) is used.
6. **Beats are in-house.** ffmpeg decode, or headless-Chromium WebAudio when ffmpeg is missing (identical
   output, §6.3), feeds a JS spectral-flux / autocorrelation / dynamic-programming tracker. An octave error
   is fixed by the person or AI (`--bpm`, Half · Double) and stored as `bpmSource: "set"`.
7. **Framing ships the B3 fallback.** The default is centre. A person (or Claude, from frames) adds
   focus-point keyframes in **source time**: `<Reframe focus>`, shared by every linked format, with a
   per-format override. **No automatic subject tracker in v2.0** — none of the existing verbs gives a
   reliable one (§6.4). "Follow a subject" is not built. A later tracker (the tracking plan's opencv.js
   spine) writes the same keyframes.
8. **AI cut streams through the run.** A V2-1.15 run scoped to the target video artboard: footage sidecars
   → beats → EDL (the plan) → `maude design reel-place --next`, once per shot. Each call is one staged write
   (V2-1.5), so shots land live. Stop publishes what is placed. The whole run is one action and one ⌘Z.
   Progress is derived from files.
9. **`.footage.json` and `.edl.json` get no new keys in v2.0** (v1's strict validators drop the whole file).
   Proposed as V2-1.12 rule R8.
10. **Verbs.** `transcribe-local`, `beats`, `captions add|list|export`, `cut-words`, `cut-to-beat` and
    `reel-place` are auto tier (effect `project` or `none`). `transcribe` (engine choice incl. cloud) stays
    prompt tier.

**Consequences.**
- Positive:
  - one analysis per asset, reused by every comp and every peer (content-addressed, synced);
  - captions can't drift from the cut;
  - ⌘Z covers every caption fix, cut, duck and framing change;
  - no new npm dependency;
  - word starts within 200 ms 97 % of the time with base.en (today 79 %);
  - words no longer bridge pauses (4 of 51 against 51 of 51).
- Negative:
  - captions, ducking and framing need new canvas-lib exports, so a 1.x build shows "This canvas uses
    Maude 2" (V2-1.12 §5.8);
  - the canvas build reads transcripts and must rebuild when one changes;
  - word timings are 23 % slower to compute;
  - the free local model is weak on Czech (43–50 % WER against Scribe);
  - beat tempo can be off by an octave (half or double) on some material;
  - per-format framing is manual, so a fast subject in a tight crop needs about one keyframe per second.
- Extends DDR-163 (its audio revisit) and DDR-164 (all engines share one word schema). Amends V2-1.11 §5.3:
  `beats` writes a versioned sidecar (effect `project`, still auto) and speech regions move to
  `transcribe-local`. Leaves the tracking plan in place as the only path to automatic tracking.

**Rejected:** the alternatives in §3. Also rejected:
- bundling whisper.cpp in this spike (a DDR-177 question of its own, Q2);
- `ffmpeg vidstab` (GPL, already rejected by the tracking debate);
- a VAD model download for ducking;
- storing comp-time caption words in `.meta.json` (render content does not belong in meta).

## 5. Contract

### 5.1 Sidecar: `assets/<sha8>.transcript.json`

One per source asset that has sound (video or audio). Written by `transcribe-local`, `transcribe` (cloud),
`maude migrate v2` (from an old `.srt` / bare `.json`). Never hand-edited by people. Claude may write it but
has no reason to (fixes go in the comp).

```ts
// apps/studio/video/schema.ts — dependency-free, footage/schema.ts house style, but PRESERVING
export const TRANSCRIPT_FORMAT = 'maude.transcript';
export const TRANSCRIPT_VERSION = 1;

export interface TranscriptWord {
  id: string;            // "w0", "w1", … unique in the file, never reused after removal
  t0: number;            // seconds in the SOURCE, 3 decimals
  t1: number;            // > t0
  text: string;          // UNTRUSTED (spoken or provider text); ≤ 64 chars
  p?: number;            // 0..1, lowest token probability of the word (absent = provider gave none)
  flags?: Array<'loop'>; // 'loop' = part of a run of ≥ 3 identical consecutive words (whisper repetition)
}

export interface Transcript {
  format: 'maude.transcript';
  v: 1;
  asset: string;                       // "assets/<sha8>.<ext>" — must match the file name
  durationSec?: number;
  lang?: string;                       // ISO 639-1 ("cs", "en"); absent = unknown
  engine: {
    id: 'whisper.cpp' | 'elevenlabs-scribe' | 'groq-whisper' | 'energy' | 'srt-import';
    model?: string;                    // "base", "base.en", "large-v3-turbo", provider model id
    version?: string;                  // engine version string
    timing: 'dtw+energy' | 'segment' | 'provider' | 'cue' | 'none';
    lagMs?: number;                    // the DTW lag removed by calibration (§5.6)
  };
  words: TranscriptWord[];             // sorted by t0; [] when engine.id === 'energy'
  speech: {
    source: 'words' | 'energy';
    regions: Array<[number, number]>;  // source seconds, sorted, non-overlapping
  };
  createdAt: string;                   // ISO
}
```

Invariants:
- **Lenient and preserving:** unknown keys, at the top level and on words, are kept and rewritten
  unchanged. Validation checks required fields, types, ranges and caps only. This is the lesson of
  `assertKeys` (§2).
- Caps: file ≤ 2 MB, `words.length` ≤ 50 000, region count ≤ 20 000.
- `text` is data. It never becomes TSX source; the build injects it as JSON and it renders as a React child.
  Skills treat transcript text as untrusted content: speech in a clip can say anything, including
  instructions.
- A re-run replaces the file (new ids). Comp fixes are keyed by source time (§5.3), so they survive a re-run.

### 5.2 Sidecar: `assets/<sha8>.beats.json`

One per music asset. Written by `maude design beats` (and by the studio when music is added to a comp).

```ts
export const BEATS_FORMAT = 'maude.beats';
export const BEATS_VERSION = 1;

export interface BeatGrid {
  format: 'maude.beats';
  v: 1;
  asset: string;                    // "assets/<sha8>.<ext>"
  durationSec: number;
  analyzer: { id: 'maude-beats'; version: 1; decode: 'ffmpeg' | 'chromium' };
  bpm: number;                      // 2 decimals
  bpmSource: 'detected' | 'set';    // 'set' = a person or AI chose the tempo (Half · Double, --bpm)
  tempoStrength: number;            // 0..1, autocorrelation peak strength (low = weak or no pulse)
  beats: number[];                  // seconds in the source, ascending, 3 decimals
  bar: { phase: 0 | 1 | 2 | 3; confidence: number };  // beats[phase + 4k] are downbeats
  createdAt: string;
}
```

Invariants: lenient and preserving (as §5.1); `beats.length` ≤ 20 000; the timeline draws tall bar ticks only
when `bar.confidence` ≥ 0.4, otherwise every beat tick is the same height; `tempoStrength` < 0.15 means "no
clear beat" (the Music inspector's Advanced says so and Snap to the beat stays off).

### 5.3 Comp vocabulary (new `@maude/canvas-lib` exports, canvas-tsx format, Plane A)

All three are literal-prop components, so the Timeline enumerator and the inspector read them as text
(DDR-150's two-tokenizer rule). Element ids per V2-1.4.

```tsx
// ONE per comp, at the comp root after the series — the Text track, lane 1 (C35).
<Captions
  data-cd-id="captions"
  words="line"                 // 1 | 3 | "line" — "Words at a time"
  position="bottom"            // "top" | "middle" | "bottom"
  font="var(--font-display)"   // token
  highlight="var(--accent)"    // the word being spoken
  maxChars={32}                // line reflow (Advanced), generation/captions.ts reflowWords
  fixes={[                     // JSON literal, written by the studio (JSON.stringify), never hand-inlined
    { src: "assets/7c40e2b1.mp4", at: 3.45, text: "jsem" },   // replace the word playing at source 3.45 s
    { src: "assets/7c40e2b1.mp4", at: 9.10, text: null },     // hide that word
  ]}
/>

// Wraps exactly ONE music <Audio>; the <Audio> keeps its literal src / volume.
<Duck db={-12} attackMs={200} releaseMs={400}>
  <Audio src="assets/2a886bcf.mp3" volume={0.8} />
</Duck>

// Wraps the media element of ONE clip; replaces the data-mframe wrapper when keyframes are set.
<Reframe
  focus={[[0, 0.5, 0.42], [1.5, 0.55, 0.40]]}   // [sourceSec, x, y]; x, y = fractions of the SOURCE frame
  zoom={1}                                     // ≥ 1, punch-in
  fit="fill"                                   // "fill" | "fit" | "blur" (07 ve-fit-fill)
  formats={{ "16:9": [[0, 0.5, 0.55]] }}       // per-format override of focus, keyed by reduced W:H
>
  <OffthreadVideo src="assets/7c40e2b1.mp4" trimBefore={30} />
</Reframe>
```

Rules:
- **Derived data is injected at build, never written to the file.** Canvas build pass 1 adds a hidden prop
  to each `<Captions>` and `<Duck>`, computed from the enclosing comp component. `<Captions>` gets
  `__words: CompWord[]`; `<Duck>` gets `__speech: Array<[frame, frame]>`. The source on disk stays as above.
  The build records the transcript files it read; a change to one rebuilds the canvases that read it.
- `fixes[].at` matches the transcript word whose `[t0 − 0.05, t1 + 0.05]` contains `at`. A fix that matches
  nothing is ignored and reported by `artboards-lint`. A loop-flagged word shows in captions only when a fix
  names it.
- `<Reframe>` reads the output aspect from `useVideoConfig()` width and height. It picks
  `formats["<W:H>"] ?? focus`, interpolates linearly in source time (holding the ends), and centres the
  output-aspect window (scaled by 1/zoom) on the focus point, clamped to the source. No `<Reframe>` means
  centre (B3). An existing `data-mframe` wrapper stays valid and readable; the inspector writes `<Reframe>`
  only when the person sets a keyframe or the comp has linked formats.
- `<Reframe follow="…">` (subject following) is **refused** by `maude design check` in v2.0 (§5.8).
- Escaping: `fixes[].text` is written with `JSON.stringify` (the footage-director codegen security rule) and
  rendered as a React child.

### 5.4 Derivation module (server, build, export and verbs share it)

```ts
// apps/studio/video/derive.ts — pure, no node:* except through injected readers
export interface ClipSpan {
  stableId: string;                       // ClipInfo.stableId (DDR-150)
  track: 'video' | 'video2' | 'music' | 'music2';   // C35 derivation (V2-1.12 §5.3)
  src: string;
  from: number;                           // absolute comp frame
  durationInFrames: number;
  trimBefore: number;                     // source offset in OUTPUT frames (DDR-163 clocks)
  playbackRate: number;
  muted: boolean;
}
export interface CompWord {
  src: string; wordId: string; clip: string;
  f0: number; f1: number;                 // comp frames
  text: string; p?: number; fixed?: boolean;
}
export function compClips(canvasAbsPath: string, source: string, artboardId?: string):
  { fps: number; total: number; clips: ClipSpan[]; unresolved: string[] };   // unresolved = clips whose timing isn't literal
export function compWords(c: ReturnType<typeof compClips>, transcripts: Record<string, Transcript>,
  fixes?: CaptionFix[]): CompWord[];
export function compSpeech(c: ReturnType<typeof compClips>, transcripts: Record<string, Transcript>,
  opts?: { exceptSrc?: string }): Array<[number, number]>;                     // comp frames, merged
export function duckGain(frame: number, speech: Array<[number, number]>,
  o: { db: number; attackFrames: number; releaseFrames: number }): number;    // multiply into volume
export function compBeats(c: ReturnType<typeof compClips>, grids: Record<string, BeatGrid>): number[];  // comp frames
export function transcriptCut(t: Transcript, wordIds: string[], energy?: Float32Array):
  { srcStart: number; srcEnd: number; inPause: boolean };                   // §5.6
export function reframeWindow(focus: [number, number], src: { w: number; h: number },
  out: { w: number; h: number }, zoom: number): { x: number; y: number; w: number; h: number };
```

Semantics:
- **Source time of a comp frame** f inside clip c = `(c.trimBefore + (f − c.from) · c.playbackRate) / fps`
  seconds.
- **A transcript word is shown in a clip** when its source interval falls inside the source range the clip
  plays. During a transition overlap, a word belongs to the clip that holds its midpoint outside the overlap,
  else to the earlier clip. The same source moment used twice shows twice.
- **Speech for ducking** = `speech.regions` of every non-muted clip on Video / Video 2, plus Music-track
  clips other than the ducked one (a voiceover ducks the bed). Mapped to comp frames and merged across gaps
  shorter than attack + release.
- **`duckGain`** is 1 outside speech, `10^(db/20)` inside it, with a linear-in-dB ramp over `attackFrames`
  before each region and `releaseFrames` after it. It is a pure function of the frame (DDR-148).
- **Words that no clip covers** are "cut" — the Transcript panel strikes them.

`GET /_api/comp-media?canvas=<rel>&artboard=<id>` → `{ fps, clips, words, speech, beats, unresolved }`
(main origin only, read-only, minRole comment; never in `CANVAS_SAFE_API` — the canvas gets its data from the
build). It feeds the Timeline's text lane 1, beat ticks and duck line, and the Transcript panel.

### 5.6 Algorithms (numbers are the defaults the tests pin)

**Words** (`transcribe-local`):
1. Decode to 16 kHz mono WAV (ffmpeg, else headless Chromium WebAudio → WAV).
2. Run `whisper-cli -m <model> -f <wav> -of <tmp> -ojf -ml 1 -sow -dtw <model-id> -nfa [-l <lang>]`.
   `-nfa` is load-bearing: with flash attention on, whisper.cpp 1.9.2 returns `t_dtw = -1` for every token.
   Output goes to a private temp dir, **never next to the source**.
3. Word = segment text. `start` = `t_dtw` of its first text token. `end` = the next word's start, capped by
   the segment end and start + 1.2 s. Drop texts with no letter or digit, and non-speech tags starting with
   `[`, `(`, `*` or `♪`. `p` = the lowest token `p`.
4. **Lag calibration:** for each energy onset after a pause ≥ 150 ms (energy > max − 35 dB on 10 ms frames,
   gaps < 60 ms closed, islands < 40 ms dropped), take the first word starting within [−0.1, +0.6] s of it.
   `lag` = the median of (start − onset) when there are ≥ 2 such words, else 0. Subtract `lag` from every
   word.
5. **Energy snap:** shrink each word to its first and last voiced frame (looking back up to 50 ms; minimum
   60 ms). A word with no voiced frame keeps its start and is capped at 120 ms.
6. **Loops:** a run of ≥ 3 identical consecutive words (case- and punctuation-folded) gets `flags: ["loop"]`.
7. **Speech regions:** words with p ≥ 0.35, voiced and not loop-flagged, padded 0.12 s, merged across gaps
   < 0.8 s.
- `--speech-only` skips steps 2–6 and writes `engine.id: "energy"`, `words: []`, and regions from
  band-limited energy (150 Hz – 4 kHz, −35 dB, ≥ 0.35 s silences).

**Beats** (`beats`):
1. Decode to 22.05 kHz mono.
2. STFT, 1024 window, 256 hop (11.6 ms).
3. Onset envelope: log-magnitude spectral flux (half-wave), detrended over ±0.25 s, normalised.
4. Tempo: autocorrelation over 60–200 BPM, weighted by a log-normal prior centred on 120 BPM
   (σ = 0.7 octave), refined parabolically.
5. Beats: Ellis dynamic programming, tightness 100.
6. Bar phase: the beat phase (of 4) with the most < 150 Hz flux.
- `--bpm N` fixes the period and re-runs step 5 only.

**Edit-by-transcript cut** (`transcriptCut`):
- Start: if the gap before the first selected word is ≥ 60 ms, cut at its midpoint; else cut at the quietest
  10 ms frame within ±50 ms of the word edge. The end is mirrored after the last selected word.
- Both edges are quantised to output frames.
- `inPause` is false when either edge is not in silence. The result then says
  "Cut inside a phrase — play it back to check."

**Cut to the beat** (`snap-to-beats` op): each storyline cut point moves to the nearest comp beat within
±½ beat, as a roll edit (the out-point of the left clip and the in-point of the right clip move together),
so the total length is unchanged. A cut point whose clips lack the source handle is left in place and
reported. `--every 2|4` uses every 2nd beat or every bar.

## 9. Open questions (conservative default in bold)

- **Q1 — Loop-flagged words in captions.** Real chants ("jo, jo, jo") look like whisper loops.
  **Excluded from captions and ducking until the person confirms them in the Transcript panel ("May be noise,
  not speech").**
- **Q2 — Bundle whisper.cpp in the .app** (DDR-177: no `brew`)? **Not in v2.0.** The Captions tool explains
  "Captions need speech recognition on this Mac." with **Set up…** (Settings › Advanced, D14). The cloud
  engines stay prompt tier. A bundling DDR is a separate decision.
- **Q3 — Default model for non-English.** **Keep the configured model** (base by default). Words with
  p < 0.5 are underlined in the Transcript panel so they get checked. Settings suggests a larger model for
  other languages.
- **Q4 — A word fix in one video, other videos using the same clip.** **This video only.** "Fix in every
  video" is a later action.
- **Q5 — Lower under speech default.** **On when the comp has clips with speech regions** (07 `ve-music`
  draws it on). −12 dB, 200 ms attack (canvas Advanced), 400 ms release.
- **Q6 — Snap to the beat default.** **On when a beat grid exists** (§5.5).
- **Q7 — Editing the EDL after placement.** **One way:** the EDL is the plan; editing it re-places nothing;
  the comp is the cut.
- **Q8 — Bar ticks.** **Uniform beat ticks below bar confidence 0.4.**

## Decisions

- `decision:maude/v2-V2-1.10-analysis-sidecars`
  - **What:** per-asset `assets/<sha8>.transcript.json` and `.beats.json`, machine-written, Plane B
    companion-text, versioned, outside the op log; validators keep unknown keys.
  - **Why:** analysis is regenerable and shared by every comp and peer. Today's word timings die in a
    default-closed bare `.json` (24 in Alligators).
  - **Rejected:** keeping SRT as the store; a `_*` runtime cache (peers would re-analyse); storing analysis
    in `.meta.json`.
- `decision:maude/v2-V2-1.10-captions-derived-from-comp`
  - **What:** captions and ducking speech are derived at build (and in one server module) from the comp's
    clips × transcripts. Human fixes live in `<Captions fixes>` keyed by source time; `.srt` is an export
    artefact.
  - **Why:** they follow every cut with no write, and fixes are in ⌘Z and Version history (V2-1.5).
  - **Rejected:** comp-time `CUES` literals; per-clip caption children duplicating `trimBefore`; fixes in the
    transcript sidecar.
- `decision:maude/v2-V2-1.10-words-pipeline`
  - **What:** whisper.cpp `-ojf -ml 1 -sow -dtw <model> -nfa`, per-file DTW lag calibration on energy
    onsets, energy snap, non-speech tags dropped, loops flagged. Every engine writes the same schema.
  - **Why:** measured — start p90 324 → 146 ms (97 % ≤ 200 ms), pauses bridged 51/51 → 4/51, items per word
    1.36 → 0.98.
  - **Rejected:** today's flags; a per-model lag table; a VAD model download.
- `decision:maude/v2-V2-1.10-speech-regions-from-words`
  - **What:** ducking speech = confident voiced non-loop words merged across 0.8 s, from each clip's own
    audio; energy only as a labelled fallback.
  - **Why:** energy ducks under crowds (34–97 s false of 113 s) and fails on mixes; words don't (0–1.4 s).
  - **Rejected:** energy on the mix; a VAD model.
- `decision:maude/v2-V2-1.10-inhouse-beats`
  - **What:** ffmpeg (or Chromium WebAudio) decode + a dependency-free JS spectral-flux / autocorrelation /
    DP tracker; tempo overrides stored as `bpmSource: "set"`.
  - **Why:** beat F 0.79 vs 0.55 for ffmpeg-only filters; 5/5 prompted tempos within 0.2 BPM; Chromium
    decode is identical, so there is a no-ffmpeg path.
  - **Rejected:** ffmpeg-only filters; essentia.js / aubio / librosa (new dependency, no measured gain).
- `decision:maude/v2-V2-1.10-framing-b3-fallback`
  - **What:** no automatic subject tracker in v2.0; centre by default plus manual focus keyframes in source
    time (`<Reframe>`, shared across formats with per-format overrides). "Follow a subject" is not built; a
    future tracker writes the same keyframes.
  - **Why:** measured on 59 labelled frames — sparse AI keyframes at `smart-frames` times reach 76 % and a
    motion centroid 83 % on tight crops, against 97 % for one keyframe per second. Centre already gives
    97–98 % for 1:1 and 4:5.
  - **Rejected:** smart-frames-seeded tracking; a motion-centroid tracker; opencv.js now (the tracking plan
    owns it).
- `decision:maude/v2-V2-1.10-ai-cut-reel-place`
  - **What:** the AI cut places shots with `maude design reel-place --next`, one staged write per shot inside
    the V2-1.15 run; Stop publishes the partial cut; one action, one ⌘Z; progress derived from files.
  - **Why:** shots land live and Stop keeps them with no new channel, using V2-1.5 / V2-1.15 as merged.
  - **Rejected:** codegen once at the end; a progress event stream.
- `decision:maude/v2-V2-1.10-strict-sidecars-frozen`
  - **What:** no new keys in `.footage.json` / `.edl.json` in v2.0 (proposed V2-1.12 R8).
  - **Why:** v1's `assertKeys` + `readSidecar` turn a file with one unknown key into "absent", which invites
    a re-analysis that overwrites it.
  - **Rejected:** bumping their versions; adding fields and relying on the format gate alone.
- `decision:maude/v2-V2-1.10-verbs-and-tiers`
  - **What:** `transcribe-local`, `beats`, `captions add|list|export`, `cut-words`, `cut-to-beat` and
    `reel-place` are auto tier; `transcribe` stays prompt; `beats` is effect `project` (amends V2-1.11
    §5.3's `none`); speech regions move to `transcribe-local`.
  - **Why:** local, no network, writes confined to the project (V2-1.11 tier rule).
  - **Rejected:** an engine flag on `transcribe-local` (escalates); one generic `maude design video` verb.
