# V2-1.16 — ACL leak matrix (where a canvas-scoped member could still see other canvases)

Spike contract note. Plan: `.ai/plans/feature-maude-v2-redesign.md` (V2-1.16 → S9). Substrate audit
`I-substrate-audit.md` gap #5. The access model, the predicate module and the credentials are fixed in
**V2-1.7** (`V2-1.7-roles-acl.md`). This note is the per-surface closure list. Row ids `L1`–`L20` are stable; other
notes cite them (spike-home-index cites L1, L8, L9, L14).

## 1. Question

> Where a canvas-scoped member could still see other canvases — sync file plane, Yjs rooms, shared assets,
> git/Version history, Whole-project export/ZIP, ⌘K, usage index, comments, presence — and the server check for each

Brief bar: a canvas-scoped member gets **nothing** about other canvases — no names, thumbnails, history, comments,
presence, or assets only those canvases use. Each surface states what leaks today, the check that closes it, where
the check lives, and the test.

## 2. What exists today

**There is no canvas scope anywhere.**

- Every human credential is project-wide:
  - peer token `scope: '*'`;
  - browser session = a peer token in a cookie;
  - render token `{p, s, r, ro, e}`;
  - the cell's studio child syncs the whole project with the `*` loopback token (`server.mjs`
    `mintLoopbackSyncToken`).
- The one narrowing primitive, `tokens.mjs` `matchesScope(scope, name)`, is compared against **document names**
  (`ws/<w>/<b>/<slug>`) in `onAuthenticate` and `documents.mjs`, and against **file paths** in `journal.mjs`,
  `file-manifest.mjs`, `handleProjectFileRoute`, `file-door.mjs`, `upload-sessions.mjs` and `history.mjs`. No single
  scope string selects one canvas's document *and* its files (V2-1.7 §3 option a).

**Two doors, and both leak:**

- **Peer door** (desktop sync → hub): Yjs canvas documents, the Plane-B journal file plane, the accepted-revisions
  routes, assets and history.
- **Browser door** (cell proxy → one shared studio child): `studio-proxy.mjs` `decide(method, pathname, role)` sees the
  pathname only. Nearly every listing is `read`, which every role holds, and the canvas usually rides in a parameter
  (`file`, `canvas`, `slug`, `path`, `asset`, `sha`) or a body the proxy never parses.

**Three read-only sweeps** (sync planes + presence; assets, history, export; studio indexes, comments, broadcasts)
produced the inventory below. The largest holes:

- `hub-integration.mjs` `handleRoutes` computes `who.scope` and never reads it. `bootstrap` lists every document;
  `lane?doc=&rev=` and `blobs/<hash>` serve any canvas at any revision.
- `/_index-data` (`api.buildIndexData`) lists every file of every canvas, a Runtime group naming each member's
  `_active.<key>.json`, and `canvasDesignSystems`.
- `/_comments-all` (`api.loadAllComments`) returns every canvas's comments. `ws.ts` `broadcast` sends `comments`,
  `fs:*`, `canvas-list-update`, `git-status`, `ai-activity`, `export:job` to every inspector socket. `broadcastHmr`
  sends `canvas-hmr` text patches of any canvas.
- The canvas origin serves any `.design/<group>/**/*.tsx` (transpiled), `.css` and asset to any render-token holder
  (`isCanvasSafeRoute`). `handleCanvas` checks role only on writes; `handleUpgrade` / `handleCanvasUpgrade` never call
  `decide()` or check the collab slug.
- `/assets/<key>`, `/_asset-file/<rel>` and `/_asset-probe` check no scope at all.
- Content-addressed assets (`assets/<sha8>.<ext>`) carry no record of which canvas uses them. The only reference
  scanners are client-side regexes.
- Pre-existing leaks that affect **every** member, not only scoped ones:
  - `/_api/export-jobs` GET lists every member's jobs, and `/download?id=` serves any job's bytes.
  - `/_api/git-committers` (canvas-safe) returns committer names **and e-mails**.
  - The `/_index-data` Runtime group names each member's session key.
  - `exporters/scope.ts` `RAW_EXCLUDES` does not exclude `_chat`, `_untrusted`, `_trash`, `_state`, `_draw`,
    `_reports` from a `project-raw` ZIP.

**Constraints.**

- DDR-054: the canvas origin is untrusted and segregated.
- DDR-209: the role is per request; one child serves all members.
- DDR-210: the canvas capability rides a cookie on the canvas origin.
- DDR-226 §1: the file classifier is the single oracle.
- DDR-241 §7: kernel fence per message.
- `d_b219fd3d7a46532d40cab867`: one matrix; deny by default; reads are classified too (studio-manifest E3 gate).
- V2-1.12: `maude.files` stays one integer; 426 rather than 403 for old-client-visible refusals.

## 3. Options

1. **Both doors enforce, one predicate, server-computed closure** (chosen). Every surface asks
   `apps/studio/access/scope.ts` (V2-1.7 §5.3). The peer door filters for scoped peer tokens (canvas-only editors need a
   local copy so AI works); the browser door filters per request from `x-maude-access`. Every route and socket message
   is classified, and unclassified is a red build. *Cost L:* about 60 insertion points, all listed below. *Breaks:*
   nothing for project-level members (filters are identity functions when `access.role !== null`).
2. **Browser door only:** no scoped peer tokens, so canvas sharing works only in a cell tab. *Cost M* (the peer door
   just refuses). *Breaks:* AI for canvas-scoped editors (A5/A13: AI runs on the Mac against local files), and
   self-hosted hubs without a studio child.
3. **Proxy-side response rewriting.** Filter JSON responses in `studio-proxy.mjs`. *Breaks:* bodies, sockets and
   compiled modules the proxy can't parse; two places to change per route.
4. **UI filtering.** Rejected by rule 12.

## 4. Decision (DDR draft)

**Title:** A canvas-scoped member gets nothing outside the canvas closure — every door filters with one predicate,
every route and message is classified, and invisible answers look like absent ones.

**Context.** V2-1.7 introduces canvas grants. Today no surface knows about them, and about 20 surfaces enumerate or
serve other canvases (§5).

**Decision.**

1. **Universal rules U1–U7** (§5.1) bind every surface.
2. **Classification.** Every studio route (`studio-manifest.mjs` `STUDIO_ROUTES` / `STUDIO_PREFIXES`), every hub
   `onRequest` path, every ws message type and every stateless message carries a `scope` class:
   - `none`: no project data.
   - `canvas`: targets one canvas; the target is extracted and checked.
   - `filtered`: lists across canvases; the handler filters.
   - `project`: project-level; refused for canvas-only sessions.

   An unclassified entry fails `test/access-route-classes.test.*` (the E3 gate pattern).
3. **Closure.** The peer door checks with `sees` / `writes` / `seesDoc` over the server-computed closure (V2-1.7
   G2–G4).
4. **Browser door.**
   - The proxy injects `x-maude-access`.
   - The studio's `withSession` places it in AsyncLocalStorage.
   - `canvasScopeRefusal(req)` beside `readOnlyRefusal` checks `canvas`-class targets.
   - `filtered` handlers filter.
   - Sockets carry access from the upgrade and are filtered in `broadcast` / `broadcastHmr`.
5. **Canvas origin.** The render token carries the grants (`g`); the canvas listener checks every static GET, `?sha=`
   build, collab slug and HMR frame against the closure.
6. **Fixed for everyone in the same change** (they are leaks whatever the scope):
   - export jobs scoped to their requesting session;
   - git-committers replaced by the server-vouched people list;
   - the Runtime group dropped for non-owners;
   - `RAW_EXCLUDES` completed.

**Consequences.**

- A canvas-only member sees, writes and hears only their canvases.
- Residuals are named (§5.4): shared-module source in the closure (L19), the floored `changedAt` of
  `/_cell/state`, timing, and bytes the browser renders.
- Project-level members (owner / member / viewer, and observers on the browser door) keep today's answers except the
  four everyone-fixes in point 6.

**Rejected alternatives.** Options 2–4 above. Also rejected:

- Per-canvas Hocuspocus namespaces (a second naming scheme).
- Distinct 403 vs 404 answers for invisible paths: an existence oracle.

## 5. Contract

### 5.1 Universal rules

| # | Rule |
| --- | --- |
| U1 | **Invisible = absent.** For a canvas-only session, an invisible path, document, comment id, job id or asset answers exactly as a missing one: same status, same body, and omitted from every listing. Targeted reads and writes answer `403 { error: 'not-in-scope', reason: 'not-in-scope' }` for both. Probes answer "absent". Kernel rejections are a final `{ status: 'rejected', code: 'not-in-scope' }`. A v2 client treats `not-in-scope` as final and never renews credentials on it. |
| U2 | **The server filters; the client never receives and hides.** A test asserts the bytes on the wire, not the DOM. |
| U3 | **Everything is classified** (`none` / `canvas` / `filtered` / `project`). Unclassified is red. |
| U4 | **Free text is rewritten or dropped.** Commit subjects and bodies, action labels, AI run labels and export file names that could name other canvases are, for a canvas-only session, replaced with a subject derived from the visible paths only ("Changed Combine-kampan"). A record with no visible effect is dropped. |
| U5 | **Aggregates count only what the session sees.** That covers panel counts, usage counts, journal `head`, "N people" and "N canvases". |
| U6 | **Access is per request / per message.** It is read from the verified credential each time, never cached past the token. `maude.access` (V2-1.7 §5.6) makes clients re-exchange. Sockets opened under a wider claim are closed on `narrowed` / `ended`. |
| U7 | **Project-level sessions are unchanged.** Every filter is the identity when `access.role !== null`. The R3 parity suite (V2-1.7 §7) runs every L-row as owner, member and viewer and expects today's bodies, except the four everyone-fixes. |

### 5.2 The predicate wiring

```ts
// Hub — apps/hub/src/access-gate.mjs (new; the only hub module that turns a credential into an Access)
export function peerAccess(match): { access: Access; closure(): Closure | null };  // from verifyToken's match
export function docAccess(context): { access: Access; canvas: string | null };     // from onAuthenticate context.user
// Studio — apps/studio/access/request.ts (new)
export function currentAccess(): Access;               // AsyncLocalStorage set by server.ts withSession
export function canvasScopeRefusal(req: Request): Response | null;   // beside readOnlyRefusal in guardedRoutes/Fetch
export function targetOf(req: Request, body?: unknown): string | null; // file|canvas|path|slug|asset|sha|/.design/… path
export function visibleTo(ws: ServerWebSocket<WsData>, payload: { file?: string; rel?: string }): boolean;
```

- `matchesScope` stays exactly as it is (DDR-053 machine-token scopes).
- The new checks run **after** it, so a machine token's narrowing keeps working.

### 5.3 The matrix

"Today" means what a person holding a valid credential of any role learns about canvases outside their grant. For
every row the check runs only when `access.canvasOnly`, unless the row says "everyone".

**L1 — Plane-B file plane** (peer door)

- **Surfaces:**
  - `GET /api/journal` (`journal.mjs` `handleJournalRoutes`)
  - `GET /api/files` (`file-manifest.mjs` `handleFilesRoute`)
  - `GET|HEAD /_project-file/<rel>` (`handleProjectFileRoute`)
  - `PUT|DELETE /api/file/<rel>` (`file-door.mjs` `handleFileDoor`, plus the legacy `PUT /assets/…` and
    `/_asset-file/…` aliases)
  - `/api/file-uploads*` (`upload-sessions.mjs` `authorize`, `admit`)
  - `POST /api/journal/report`
- **Today:**
  - Every plane-B path with `sha256`, `size`, `mtimeMs`, `class`, `deleted`, `atMs`, plus the bytes. Media, CSS, MD,
    `*.photo.json`, `*.footage.json`, `*.edl.json`, `*.registry.json` and code modules all reveal canvas names.
  - The project-wide `head` / `epoch` reveal the overall write rate.
  - Peers can only ask "everything since a cursor" or "the whole manifest".
- **Check:**
  - The five `matchesScope(match.scope, path)` call sites additionally require `sees(access, closure, rel)`.
  - The file door and `admit` additionally require `writes(access, closure, landing, {exists})` on `landing =
    target.realRel` (the symlink-resolved path, as today).
  - `/_project-file/` additionally requires `access.can('export', canvasOf(rel))`. Observers have no peer token
    anyway (V2-1.7 §5.4).
  - For canvas-only sessions the journal's `head` is the last **visible** seq. `epoch`, `truncated` and `reanchor` keep
    their meaning.
- **Lives:** `access-gate.mjs` `peerAccess`, called in those handlers. They import `verifyToken` directly today, so
  the call sits next to it.
- **Test:** `apps/hub/test/acl-l1-file-plane.test.mjs`. A canvas-only token for A lists, pulls and probes only A's
  closure. B's assets, B's `.photo.json` and an asset used by B only are absent from journal and manifest and 404 on
  `/_project-file/`. A write to B's sidecar and an overwrite of an A+B asset get `403 not-in-scope`, the same body as
  a missing path. `head` does not move when only B changes.

**L2 — Plane-A Yjs canvas documents** (peer door)

- **Surfaces:**
  - `server.mjs` `onAuthenticate`.
  - Each canvas is one document `ws/<w>/<b>/<slug>`, carrying every lane: `html`, `css`, `meta`, `syncMeta`,
    `comments`, annotations (`sync/codec.ts` `Y_SYNC_TYPES`).
  - `GET /api/documents` and the item route (`documents.mjs` `handleDocumentsRoute` / `handleDocumentItemRoute`,
    which also return `bytes` and tombstone `deletedAt`).
- **Today:**
  - Any document name that passes `matchesScope` (always, for `*`) opens with its full content.
  - `context.user` carries no role and no canvas.
- **Check:**
  - After `matchesScope`: `seesDoc(access, documentName, canvasSlugFromRel)`. When it fails, throw the **existing**
    `authError('token not authorized for this documentName')`, the same reason as out-of-scope today (U1).
  - `connectionConfig.readOnly = !access.can('edit', canvas)` per document. Read-only is per connection, so a viewer's
    comments go through the hub comment door `POST /api/comments` (V2-1.7 §5.6), which checks `seesCanvas` and
    `can('comment', canvas)` first.
  - `context.user` gains `access` and `canvas`, so `fence` and `beforeHandleAwareness` can read them.
  - Both documents routes filter entries and tombstones by `seesDoc`.
- **Lives:** `server.mjs` `onAuthenticate` (shared file → lead patch request), `access-gate.mjs` `docAccess`,
  `documents.mjs`.
- **Test:** `apps/hub/test/acl-l2-docs.test.mjs`. Opening B's document is refused with today's reason string. A's
  document opens, and is read-only where the grant is `viewer`. `/api/documents` lists A only.

**L3 — `maude.files` control channel and pokes** (peer door)

- **Surfaces:** `files-ctl.mjs` (`isFilesCtlDoc`, `createFilesPoke`, `dropCtlAwareness`) and `document-events.mjs`
  `createDocumentEvents`. Today they broadcast `{t:'files', head}` and `{t:'files', head:0, documents:true}` to every
  ctl connection of every scope.
- **Today:**
  - A timing signal for every write anywhere.
  - `documentsPoke` fires on any canvas create, rename, delete or first content.
- **Check:**
  - The payload stays one integer (V2-1.12).
  - Delivery to a **canvas-only** connection becomes per-connection (`connection.sendStateless`) and happens only when
    the appended journal entry or document event is visible to it. `head` = its last visible seq.
  - Project-level connections keep the broadcast.
- **Lives:** `files-ctl.mjs`, `document-events.mjs` (a `visibleTo(connection, entry)` hook).
- **Test:** `apps/hub/test/acl-l3-poke.test.mjs`. B's writes and B's rename produce no frame on A's ctl connection; A's
  writes do.

**L4 — Accepted-revisions routes and the kernel** (peer door, DDR-241)

- **Surfaces:** `/api/projects/:p/v1/{bootstrap, revisions, history, lane, blobs, transactions, mode, parity,
  proposals}` (`hub-integration.mjs` `handleRoutes`; the auth closure in `server.mjs`) and `kernel.mjs` `process()`.
- **Today:**
  - `bootstrap` returns `store.manifest()`: every `doc`, `entry`, `generation`, `path`, `retired`, `movedTo`, lane
    hashes, all `dirs`, `canvasGroups`, `projectConfig`.
  - `revisions` / `history` return every action's `actor`, `label`, `origin`, effects with before/after paths.
  - `lane` and `blobs` serve any body.
  - Kernel rejections `path-conflict {path}` and `generation-stale {generation}` are existence oracles.
- **Check:** `handleRoutes` receives `who.access`.
  - **bootstrap:**
    - `docs` / `dirs` filtered by `seesDoc` / ancestors of visible docs;
    - `canvasGroups: []`;
    - `projectConfig` reduced to the visible canvases' design systems.
  - **revisions / history:** effects filtered, empty actions dropped, `label` rewritten (U4), `actor` = name only for
    non-`invite` holders.
  - **lane:** `seesDoc(query.doc)`.
  - **blobs:** served only when a reverse lookup `hash → (doc, lane)` from the store finds a visible doc. The store
    already holds lane hashes per revision; a `blob_refs` index is added if a lookup proves slow.
  - **kernel `process()`, per op:**
    - `doc.*` lane writes need `can('edit', op.doc)`;
    - `doc.create`, `doc.move`, `dir.move` and `dir.delete` need a project role (canvas-only: refused);
    - `doc.delete` needs `trash` on that doc;
    - `history.restore` without `docs` needs a project role; with `docs`, `edit` on each.
    - Any rejection naming an invisible doc or path becomes `not-in-scope` (U1).
  - `mode`, `parity`, `transactions/:id` (actor-bound) are unchanged.
- **Lives:** `hub-integration.mjs`, `kernel.mjs`, `access-gate.mjs`.
- **Test:** `apps/hub/test/acl-l4-accepted.test.mjs`.
  - Bootstrap, revisions and history as A-only contain no B doc, path, hash or label.
  - `lane?doc=B`, and `blobs/<B lane hash>`, give the same 403 as a random hash.
  - A proposal touching B gets a final `not-in-scope`.
  - A `dir.move` gets `not-in-scope`.
  - A `doc.create` at an existing B path gets `not-in-scope`, not `path-conflict`.

**L5 — Assets** (both doors)

- **Surfaces:**
  - Hub: `GET|HEAD /assets/<key>` (`assets.mjs` `handleAssetRoute`), `GET|HEAD /_asset-file/<rel>`
    (`handleCheckoutAssetRoute`), `POST /_asset-probe` (`handleAssetProbeRoute`, ≤ 1000 paths).
  - Studio: `GET /_api/assets` (`api.listAssets`, ≤ 500); the manifest's `designAssetLane` (any `…/assets/…`
    binary) and `designTokensLane` (any `.css`, including another canvas's same-name `.css`);
    `/_api/photo-edit?asset=` (canvas-safe), `/_api/footage?asset=|slug=`, `/_api/comp-clips?canvas=`.
  - Canvas origin: `/assets/<file>`.
- **Today:**
  - Any asset by key or path, with no scope check on the three hub routes.
  - A batch existence probe.
  - The full asset list.
  - No record of who uses what.
- **Check:**
  - Every read is `sees(access, closure, rel)`. The closure includes statically referenced assets and their sidecars
    (V2-1.7 G2/G3).
  - Probes answer "absent" for invisible paths (U1).
  - `/_api/assets` lists closure assets only.
  - Writes follow `writes()`: create-only new assets. A sidecar write needs every referencing canvas in the edit
    grants; the reverse index comes from the same server-side scanner over all canvases, cached by head.
  - **Everyone:** the three hub routes, which check no scope today, add the `matchesScope` check every other plane-B
    route has.
- **Lives:** `assets.mjs`, `studio-manifest.mjs` lanes + `canvasScopeRefusal`, `api.ts` `listAssets`,
  `access/closure.ts`.
- **Test:** `apps/hub/test/acl-l5-assets.test.mjs` + `apps/studio/test/acl-l5-assets.test.ts`.
  - An asset used only by B: 404 by key, "absent" on both probes, missing from `/_api/assets`, 404 on the main-origin
    lane and the canvas origin.
  - An A+B asset: readable, not overwritable.
  - A photo edit on it: `not-in-scope`.

**L6 — Version history and git** (both doors)

- **Surfaces:**
  - Hub: `GET /api/history` (no `path` = project-wide; allowed only for an unscoped token via `history.mjs`

  - Studio:
    - `/_api/git/log` (path optional), `/_api/git/diff?sha=` (every changed design file), `/_api/git/status`,
      `/_api/git/branches`;
    - `/_api/project/history` (path optional);
    - canvas-origin `?sha=` builds (`http.ts` `serveHistoricalCanvas`, falling back to the hub's `/api/history/file`).
  - Commit messages come from `sync/autocommit.ts` `commitMessage`: subject `design: update N canvases`, a body listing
    `- <canvas>`.
- **Today:**
  - The project-wide log.
  - Diffs naming every file.
  - Any canvas's source at any sha.
  - Subjects with counts; manual commits are free text.
- **Check:**
  - `IMPOSSIBLE_DOC` is generalised: a canvas-only session must name a visible `path` (missing → `not-in-scope`).
  - `handleFile` needs `sees(path)` (against the **current** closure) and `can('export', canvasOf(path))`: raw source
    is the export class (V2-1.7 §5.2).
  - Studio `log` / `project/history`: `path` is forced to a visible canvas. Subjects are rewritten and bodies dropped
    (U4); authors by name only.
  - `diff`: needs `export`; its file list is filtered.
  - `status` and `branches` are `project`-class.
  - `?sha=`: `sees(path)` + `read`. A past version rendered is looking, the same bytes class as the live module.
- **Lives:** `history.mjs`, `git/endpoints.ts` (`log`, `diff`), `http.ts` `serveHistoricalCanvas` (lead patch),
  `canvasScopeRefusal`.
- **Test:** `apps/hub/test/acl-l6-history.test.mjs` + `apps/studio/test/acl-l6-git.test.ts`.
  - The fixture has one commit touching A + B with subject `design: update 2 canvases` and a body naming B.
  - The A-only log shows "Changed A" and no "2", no B and no body.
  - `history/file?path=B` and `git/diff` for that sha contain no B bytes or names.
  - `?sha=` of B: `not-in-scope`.

- **Check:**

## Decisions

- `decision:maude/v2-1.16-both-doors-one-predicate`
  - **What:** canvas scope is enforced at the peer door (Yjs `onAuthenticate`, file plane, accepted-revisions routes
    and kernel, assets, history) and at the browser door (proxy + studio child + canvas origin + sockets), all through
    `apps/studio/access/scope.ts` and a server-computed closure. Filters are the identity for project-level sessions.
  - **Why:** canvas-only editors need a local copy for AI, and the browser door serves everyone else.
  - **Rejected:** a browser-door-only scope; proxy response rewriting; UI filtering.
- `decision:maude/v2-1.16-invisible-equals-absent`
  - **What:** for a canvas-only session, every invisible path, doc, id or asset answers exactly as a missing one: one
    `403 not-in-scope` body for targeted calls, "absent" for probes, omitted from listings, a final `not-in-scope` for
    kernel rejections. Free text naming other canvases is rewritten; aggregates count only visible canvases.
  - **Why:** any difference is an existence oracle (`path-conflict`, probes, 403 vs 404).
  - **Rejected:** distinct "forbidden" answers.
- `decision:maude/v2-1.16-every-route-and-message-classified`
  - **What:** every studio route, hub path, ws message type and stateless message carries a scope class (`none` /
