# V2-1.15 — AI run registry and per-artboard leases

Spike: V2-1.15 (Phase 1). Builds in: S5 (AI chat), S2 (soft locks on objects), the hub release that ships
before any rc (V2-2.18), V2-3.5 (notifications, Dock badge), the quit path in the desktop shell. Status:
proposed, for the lead to merge and record as a DDR. Composes with the merged notes **V2-1.5** (one op log,
one held stage per run, `origin.runId / chatId / madeAt`), **V2-1.4** (element ids; locks as `data-cd-*`),
**V2-1.11** (hooks, `/_api/agent/run/begin … run/end`, the run key is the hook `session_id`) and **V2-1.12**
(hub fence, file formats). Canvas owner: `.design/ui/v2/03 AI Chat.tsx`.

## 1. Question

> Run schema (id, chat, owner, artboards, state), per-artboard leases with TTL on the hub for shared
> projects and locally otherwise, queue persistence, quit/crash release, soft-lock interplay (A10)

From the brief and the register:
- **A4:** one AI per artboard. A second ask waits in line or "Run on a copy". Different artboards run side by
  side. A whole-canvas ask starts on the free artboards first. There is no "Run anyway".
- **A5:** AI runs on this Mac and stops on quit. The dialog warns. "Keep going" on the next launch resumes the
  session. No server-side AI in v2.0.
- **A10:** others see the editor's colour ring and read-only fields + Comment. A hold frees on deselect, blur,
  30 s idle or disconnect. AI holds its run's objects the same way.
- **C27:** chats are personal and stay on this Mac. Others' *running* runs on a shared canvas are visible,
  View only.
- **I-substrate-audit #7:** needs hub leases, a TTL, queue persistence and a two-Mac race test.

Deliverables: run and lease schemas; the hub protocol (acquire / renew / release, TTL, fencing tokens); the
local fallback; the queue's states and persistence; crash and quit recovery; the two-Mac race test; how the
UI pieces (rings, queue, Needs you, View only) read it.

## 2. What exists today

**AI activity is per file, single author, memory only.**
- `collab/ai-activity.ts` `createAiActivity`: a `Map<file, {file, author, startedAt, lastHeartbeat}>`.
  - TTL 30 s after the last heartbeat (`HEARTBEAT_GRACE_MS`), a 5 s janitor.
  - It broadcasts the bus event `ai-activity`.
  - A second `start` on the same file **replaces** the first. Two AIs on one canvas therefore show as one.
- Routes `http.ts` `/_api/ai` (GET, also in `CANVAS_SAFE_API` for the canvas banner) and
  `/_api/ai/start|heartbeat|end` (POST, `sameOriginWrite` + `isTrustedRequestHost`).
  - Callers: `/design:edit` with raw `curl`, keyed by file.
  - `start` also opens `beginAiAction('edit:<file>')`; `end` closes it.
- `server.ts` projects `ai-activity` onto the room awareness (`collab.registry.setAgentEditing`). This is
  the one AI signal that crosses the hub (DDR-120). It is attributed to the driving human's display name.

**The ACP chat (DDR-125 multichat, DDR-146 resume).** `acp/index.ts` `createAcp`:
- **Bridges** are keyed by chat, one `claude` process per chat.
  - A detached bridge lives 5 min (`DETACHED_TTL_MS`), extended while its turn runs up to 30 min
    (`MAX_DETACHED_LIFETIME_MS`).
  - Caps: `MAX_DETACHED_BRIDGES` = 3, `MAX_BRIDGES` = 12.
  - `stopAll()` on dev-server shutdown reaps every bridge. Reaping fails the turn, so T16 **holds** its
    stage. Nothing publishes and nothing marks the chat.
- **`createAgentActivityTracker`:**
  - watches `tool_call` / `tool_call_update` of kinds edit, delete and move on canvas files;
  - drives `ai-activity` and `beginAiAction('acp:<chat>')`;
  - nothing gates the prompt: two chats on the same artboard both write at once.
- **`acp/running.ts`** has two pull registries:
  - `runningChats()`, used by `/_api/acp/running` for the branch-switch warning and `sidecar.rs`
    `has_running_chat` (reaper);
  - `activitySnapshot()`, used by `/_api/acp/activity` (`running | awaiting-input | idle` per chat, seq). The
    native `notify.rs` polls it.
  - Decision D (feature-acp-turn-notifications): that route never carries a chat title or text.
- **Permission prompts** time out after `PERMISSION_TIMEOUT_MS` (120 s) and are denied (fail closed,
  DDR-179).
- **The session id** is persisted per chat in `_chat/<chatId>.session.json` and resumed with `loadSession`
  (DDR-146).

**Presence and soft editing.**
- `use-collab.tsx`:
  - `CollabAwarenessState` has `selection`, `annotationSelection`, `annotationGesture`, and
    `editing: { since } | null`;
  - `useEditingPresence` is a soft heads-up at canvas level with a 5 s idle clear;

- DDR-120 replaced the phase-30 artboard locking (a 30 s lease plus takeover) with that soft presence:

- DDR-078: agents are virtual presence peers derived client-side from `ai-activity`, with one agent per

**Desktop.**
- `lib.rs` kills the sidecar on `CloseRequested` and `RunEvent::ExitRequested` / `Exit`, with **no dialog**.

- `notify.rs` fires OS notifications on transitions read from `/_api/acp/activity`.

**Hub.**

## 3. Options

**Option 1 — leases in the project store, a run registry in the studio, poke + pull, fencing in the kernel
commit (recommended; the plan's default kept for humans).**
- Artboard leases, the waiting line and the fencing counters are store-core tables. They live in the hub
  for linked projects and in the studio's in-process store for local ones. This is the same two-homes model
  as V2-1.5's op log and DDR-241.
- Every lease operation is **one** store method, so it is one SQL transaction and, in the cloud, one DO
  RPC.
- The studio keeps your runs, including prompt text, under `_state/runs/` (per Mac, C27).
- Human soft locks stay on awareness (the plan's default for A10). Only AI holds are enforced.
- Cost: four store methods, five hub routes, one poke kind, one envelope field, a studio registry module,
  and the desktop quit path.
- What it breaks: none of the signed rows. It reverses DDR-120's "no lease" **for AI only**, and keeps its
  reason (orphaned leases) answered by a TTL.

**Option 2 — leases on Yjs awareness (DDR-120 style, "AI is editing" as a claim).**
- No atomic acquire: two Macs that both see "free" both start. That is exactly the race A4 forbids.
- Spoofable by any connection, including read-only ones.
- No FIFO and no persistence.
- Rejected: it fails the two-Mac race by construction.

**Option 3 — leases in hub memory only.**
- Simpler. But a hub or cell restart drops every lease (two AIs on one artboard after a restart) and resets
  the fencing counters, so a late publish from a Mac that slept is accepted over another run.
- Rejected. The store is already transactional in both homes and costs nothing extra.

**Option 4 — a shared CRDT map (a Yjs doc) as the lock table.**
- A CRDT merges concurrent writes by design, so it cannot give mutual exclusion.
- Rejected.

**Option 5 — a lock file under `.design/` on the file plane.**
- Eventual, journal-ordered, and versioned files would carry runtime state (it breaks DDR-115).
- Rejected.

**Option 6 — a hub-side scheduler that also runs the AI.**
- A5 rules out server-side AI in v2.0.
- Rejected.

**Within option 1, rejected sub-variants:**
- *Hold the whole run until every artboard is free (all-or-nothing).* It contradicts 03 rule 3 ("doesn't
  wait"), and hold-and-wait deadlocks two runs that each want the other's artboard.
- *Wait for a lease inside a turn.* A turn that blocks on a lease can deadlock and burns allowance. A run
  never waits inside a turn (L7).
- *Keep leases while a failed run's stage is held.* A held stage waits for a person who may be away for
  days, and others would be blocked behind it.
- *Hard human locks (refuse a human's edit on an object another human holds).* DDR-120's reasons stand: the
  kernel merges independent edits, and DDR-116 resolves the rest.

## 4. Decision (DDR draft)

**Title:** AI runs are registered, and each artboard has at most one AI at a time. The lease, waiting line
and fencing token live in the project store (hub for linked projects, in-process for local ones). Your runs
live on your Mac. Human soft locks stay on awareness.

**Context.** A4 needs one AI per artboard across people. The only cross-Mac AI signal today is a spoofable
awareness heads-up. Two chats on one artboard both write, and quitting kills a turn with nothing published
and nothing said. A5, A10 and C27 add: stop on quit with a warning and Keep going, objects held by whoever
edits them, and others' running runs shown View only. DDR-120 rejected leases for humans because of
orphaned locks. A TTL plus fencing answers that for AI, which is a single writer per run and is not
co-typing.

**Decision.**
1. **A run** is V2-1.5's unit: one prompt turn of one chat (ACP), one terminal Claude prompt (hooks,
   V2-1.11), or one `/design:edit`.
   - An **ask** is what the person sent. It yields one run, plus a **continuation run** for each artboard
     that was busy when it started (same `askId`, same chat, started by itself when the artboard frees up).
   - The studio's **run registry** owns your runs. Their prompt text never leaves this Mac (C27).
2. **One AI per artboard.**
   - A lease is the exclusive AI claim on `(canvas entry, artboard id)`, anyone's AI. People never hold
     artboard leases.
   - An ask with a scope acquires its artboards when it starts:
     - free → granted;
     - busy → a ticket in that artboard's FIFO line ("starts by itself, on top of its result").
   - A whole-canvas ask takes every free artboard now and tickets the busy ones.
   - Run on a copy duplicates the busy artboard **from the accepted content**. A busy run's writes are
     staged and not published (V2-1.5), so the copy really is "from before the busy chat". The run then
     leases the new id.
   - There is no override.
3. **Leases live in the project store.**
   - Tables `ai_runs`, `ai_leases` and `ai_tickets` in store-core:
     - **linked projects:** in the hub's store (self-host SQLite, cloud DO SQLite);
     - **local projects:** in the studio's in-process store (`_state/project-store.sqlite`, V2-1.5 §5.6).
   - Every operation — `begin`, `claim`, `renew`, `end`, `list` — is **one store method = one transaction =
     one RPC**. A read-then-write across two calls double-grants (§6).
4. **TTL and renewal.**
   - A live run expires 30 s after its device's last renewal. The hub's clock is the only clock.
   - The studio renews all of a project's live runs in one call every 10 s.
   - Expiry is applied lazily, inside every store call: lapsed runs release their artboards, and the line
     moves up.
   - A waiting ticket lapses the same way. A Mac that went away loses its place, and when it returns its
     registry re-asks at the back of the line.
5. **Fencing.**
   - Each grant increments that artboard's counter. The run's token is the counter at grant.
   - A run's publish (the V2-1.5 stage proposal) carries its tokens. The kernel's commit checks them in the
     same transaction, and a newer grant rejects it with `lease-fenced`.
   - **Expiry alone never fences.** If nobody was granted the artboard meanwhile, a late publish from a Mac
     that was asleep or offline is accepted.
   - Fencing is a correctness tool for honest clients, not a security boundary: an editor can write
     anything anyway (same posture as V2-1.12's format declaration).
6. **Leases end when the run stops running.** On `done`, `stopped`, `failed` or `interrupted` the leases are
   released. A held stage (V2-1.5 failed / crash) holds no lease. Its Keep later publishes like a person's
   edit and merges over whatever happened since.
7. **Needs you keeps the lease.** It has no timeout while the holder's Mac is online and renewing (03).
   Others keep "Run on a copy".
8. **No waiting inside a turn.** A write that needs an artboard the run does not hold claims it:
   - free → granted;
   - busy → the PreToolUse hook denies `artboard-busy` (V2-1.11), naming whose AI holds it.
   - The model works elsewhere. When the turn ends, the registry records a continuation ticket for the
     denied artboards.
   - Terminal Claude runs only ever claim lazily. They have no scope chip, so they never wait.
9. **The scope chip is the boundary for in-app runs.**
   - A write outside the chip's artboards is denied `out-of-scope`. That includes a shared declaration
     whose attribution (V2-1.5 §5.7) reaches an artboard outside the scope.
   - An import-only addition needs no lease.
   - Any other module-scope change needs every artboard of the file.
10. **Quit and close-tab (A5).**
    - The shell asks first: "Quit while AI is working?" (03 `ai-quit`).
    - On Quit, the registry stops every live run:
      - the ACP turn is cancelled;
      - V2-1.5 `stopped` publishes the partial work with its tokens;
      - the leases are released;
      - the chat gets "Stopped when the app quit · <time>".
      - Waiting asks stop unstarted.
    - Only then is the sidecar killed (budget 5 s).
11. **Crash.**
    - The hub's TTL frees the artboards within 30 s.
    - At the next boot, the registry marks every run that was starting, running, needs-you or waiting as
      `interrupted`. Its V2-1.5 stage is already held.
    - The C37 callout lists them, and each chat shows **Keep going**.
12. **Keep going** is a new ask in the same chat:
    - `resumeOf` = the stopped run;
    - same scope;
    - the ACP session is resumed by DDR-146 `loadSession`;
    - a fixed continuation instruction is sent.
    - It waits in line like any ask, and it is never automatic.
13. **Soft locks (A10).**
    - **A human hold** is an awareness field `holding` on the object being edited. It frees on deselect,
      blur, 30 s idle or disconnect. The hub stamps it with the connection's actor and drops it from
      read-only connections. It is advisory between people: the UI makes fields read-only, and the server
      does not refuse (DDR-120 kept).
    - **An AI hold** is the run's `objects`: its scope elements plus the elements its edits touched. The
      registry publishes them.
    - Enforcement runs both ways between people and AI:
      - the hook denies an AI write on an object a person holds (`soft-locked`);
      - the studio's edit routes refuse a person's edit on an object a live run holds (409 `held-by-ai`) as
        a backstop to the read-only UI.
14. **Visibility (C27).**
    - Every member who can see a canvas sees its live runs: owner, label, artboards, state and objects.
      These drive rings and tags.
    - Only the owner's registry has the prompt text, the transcript and the attachments.
    - The label is the action's future Version history label (V2-1.5), so it exposes nothing new.
    - Canvas-scoped members see only runs on their canvases (V2-1.16).

**Consequences.**
- Positive:
  - A4 holds across Macs and people;
  - the queue survives restarts of the app and the hub;
  - quitting is honest and loses nothing finished;
  - the rings, runs list, Needs you and quit dialog read one model;
  - concurrent runs stay separable for V2-1.5.
- Negative:
  - the hub gains three tables, four store methods, five routes and a poke kind (additive, ships before any
    rc, V2-2.18);
  - every live run costs one renewal per 10 s per project, which keeps a cloud cell awake while AI runs;
  - a malicious editor can hold artboards by renewing forever (an accepted editor-level risk: Run on a copy
    always works, per-actor caps apply);
  - Syncthing-shared local projects (no hub) get one-AI-per-artboard per Mac only. Same posture as A18.
- Partly reverses DDR-120 (leases come back, for AI only). Extends DDR-241 (tables, commit fence) and
  DDR-078 (several agents per canvas, keyed by run). Supersedes the per-file `ai-activity` map as the source
  of AI presence; `ai-activity` becomes a derived v1 view.

**Rejected:** options 2–6 and the sub-variants in §3.

## 5. Contract

### 5.1 Records

```ts
type RunId = string;   // /^r_[A-Za-z0-9_-]{6,64}$/ — minted by the studio (crypto random)
type AskId = string;   // /^a_[A-Za-z0-9_-]{6,64}$/ — = the V2-1.14 outbox record id when the ask was queued
type LeaseKey = { canvas: string; artboard: string };
// canvas = the kernel's stable doc `entry` (survives rename/move); a project not yet on the op log
// uses 'path:<repoRel>'. artboard = the DCArtboard id.

/** The studio's own record of YOUR run — `<designRoot>/_state/runs/<runId>.json`, per Mac, never synced. */
interface RunRecord {
  v: 1;
  runId: RunId;
  askId: AskId;
  resumeOf?: RunId;                    // Keep going
  continuationOf?: RunId;              // a busy artboard's follow-up run
  chatId: string | null;               // null for terminal Claude / /design:edit
  sessionId: string | null;            // Claude Code session_id (V2-1.11 run key); bound on first hook event
  origin: 'maude-chat' | 'claude-code' | 'design-edit';
  actor: string;                       // you
  device: string;                      // this Mac's deviceId (V2-1.5 origin.deviceId)
  label: string;                       // the prompt, shortened ≤ 80 — shared with peers
  prompt?: string;                     // full text ONLY while queued / waiting (sent text lives in the transcript)
  scope: { canvas: string; artboards: string[] | '*'; elements?: ElementRef[] } | null; // null = lazy (terminal)
  copyOf?: LeaseKey;                   // Run on a copy: the busy original
  state: RunState;
  leases: Array<LeaseKey & { token: number; provisional?: true }>;
  waiting: Array<LeaseKey & { position: number; heldBy: RunPublic | null }>;
  touched: Record<string, string[]>;   // canvas → artboards (V2-1.5 §5.7)
  objects: ElementRef[];               // AI hold (A10): scope elements ∪ touched elements, ≤ 200
  doing?: string;                      // the one-line progress ("Headline and date done · button next")
  question?: string;                   // Needs you: the permission / choice text (never leaves this Mac)
  createdAt: number; startedAt?: number; endedAt?: number;
  outcome?: 'done' | 'stopped' | 'failed' | 'interrupted' | 'cancelled' | 'lease-lost';
  stoppedBy?: 'you' | 'quit' | 'close-tab' | 'crash' | 'sleep';
}

> **Amendment 2026-10-09 (from V2-1.10, accepted by the lead):** a run record may carry a studio-local, never-synced `progress?: { done: number; total: number; label: string }` (e.g. "Placing shots — 7 of 14" for the AI cut's `maude design reel-place --next` writes). It is derived from the run's own writes, never from the model's prose, and peers' public view of a run never includes it.

type RunState =
  | 'waiting'     // tickets only — "Waiting for … to finish on Post 1:1"
  | 'starting'    // granted, the turn is being sent (claude may still be setting up)
  | 'running'     // turn active                                           kit: working
  | 'needs-you'   // turn blocked on a permission / choice (03 ai-needs-*)  kit: needs
  | 'ended';      // see outcome                                           kit: done / stopped divider

/** What every member sees (hub `GET /v1/runs`, studio `GET /_api/ai/runs` `others`). */
interface RunPublic {
  runId: RunId; askId: AskId;
  actor: string;                       // the person whose AI it is (face in the tag)
  origin: RunRecord['origin'];
  label: string;
  state: 'waiting' | 'running' | 'needs-you';
  artboards: LeaseKey[];               // held now
  waitingFor: Array<LeaseKey & { position: number }>;
  objects: ElementRef[];
  since: number;                       // hub clock
}
```

A queued ask (offline, AI not connected, setting up, used up) is a **V2-1.14 outbox record**, not a run. It
becomes a run when the outbox releases it: `registry.ask({askId: record.id, …})` is idempotent by `askId`.

### 5.2 Store tables and methods (store-core, both homes; additive — no `STORE_SCHEMA_VERSION` bump)

```sql
CREATE TABLE IF NOT EXISTS ai_runs (
  run_id TEXT PRIMARY KEY, actor TEXT NOT NULL, device TEXT NOT NULL, ask_id TEXT, chat_id TEXT,
  origin TEXT NOT NULL, label TEXT, state TEXT NOT NULL, created_at INTEGER NOT NULL,
  renewed_at INTEGER NOT NULL, expires_at INTEGER NOT NULL, ended_at INTEGER, outcome TEXT,
  objects TEXT);                                          -- JSON ElementRef[] ≤ 200
CREATE TABLE IF NOT EXISTS ai_leases (                     -- the row outlives its holder
  entry TEXT NOT NULL, artboard TEXT NOT NULL, fence INTEGER NOT NULL, run_id TEXT,
  granted_at INTEGER, PRIMARY KEY (entry, artboard));
CREATE TABLE IF NOT EXISTS ai_tickets (
  entry TEXT NOT NULL, artboard TEXT NOT NULL, run_id TEXT NOT NULL, enqueued_at INTEGER NOT NULL,
  n INTEGER NOT NULL, PRIMARY KEY (entry, artboard, run_id));
-- + store_meta keys: runs_seq (change counter), runs_ticket_n
```

| Method | Does (one transaction; sweeps lapsed runs first) |
| --- | --- |
| `runsBegin({runId, actor, device, askId, chatId, origin, label, wants, enqueue})` | Idempotent by `runId` (another actor → `forbidden`). It refuses past the caps. Free keys with no line → grant (`fence + 1`). Keys with a holder **or a line** → ticket when `enqueue`, so a newcomer never jumps a line. Returns `{run, granted[], busy[]}`. |
| `runsClaim({runId, actor, keys, enqueue, expectFence?})` | Adds keys to a live run, mid-run. With `expectFence`, it grants only if the counter still equals it: a CAS that confirms a provisional claim (§5.6). |
| `runsRenew({actor, device, runs:[{runId, state?, objects?}]})` | Extends `expires_at` by the TTL. Takes `state ∈ {running, needs-you}` only while the run holds a lease. Answers `ended: <outcome>` for runs that already lapsed or ended. |
| `runsEnd({runId, actor, outcome})` | Releases the leases (the `fence` is kept), drops the tickets, and grants each freed key to its line's head. |
| `runsList({after?})` | Live runs (`RunPublic`) + `seq`. |
| *(inside `commit`)* `fenceCheck(claims)` | Every `(entry, artboard, token)` must equal the current `fence`; otherwise `StoreConflict('lease-fenced')`. |

- Added to `store-remote.mjs` `METHODS` and `apps/cells/project-store.mjs` `STORE_METHODS`, the same way as
  V2-1.12's `setFormat`.
- Caps:
  - ≤ 20 live runs per actor per project;
  - ≤ 200 keys per run;
  - ≤ 50 tickets per run;
  - `label` ≤ 80 characters (control characters stripped);
  - `objects` ≤ 200 refs, validated against V2-1.4's patterns.
- `TTL = 30 000 ms`, `RENEW = 10 000 ms`.

### 5.3 Hub protocol (`/api/projects/:p/v1/…`, bearer auth, never in either canvas allowlist)

| Route | Body | Answer | Refusals |
| --- | --- | --- | --- |
| `POST runs` | `{runId, askId, chatId?, origin, label, device, wants: LeaseKey[], enqueue?: true}` | `200 {run: RunPublic, granted: Array<LeaseKey & {token}>, busy: Array<LeaseKey & {position, heldBy: RunPublic}>}` | `403 forbidden` (read-only role, or a canvas outside the member's scope) · `429 capacity` |
| `POST runs/:id/claim` | `{keys: LeaseKey[], enqueue?: boolean, expectFence?: Record<string, number>}` | `200 {granted, busy}` | `403` · `409 ended {outcome}` |
| `POST runs/renew` | `{device, runs: [{runId, state?, objects?}]}` | `200 {runs: [{run} \| {runId, ended}]}` | `403` |
| `POST runs/:id/end` | `{outcome}` | `200 {ended, granted: [{runId, …key, token}]}` | `403` |
| `GET runs` | `?after=<seq>` | `200 {seq, runs: RunPublic[]}` · `200 {seq, unchanged: true}` | — (any member who can view; filtered per canvas scope) |

- **Poke:** after any runs change, the hub schedules a coalesced stateless frame `{t:'runs', seq}` on
  `maude.files` (`files-ctl.mjs`, same emitter pattern). Studios pull `GET runs?after=`. Old studios ignore
  unknown `t`.
- **Capability:** `/health` `capabilities` gains `runs-v1`.
- **Envelope:** the kernel proposal envelope gains
  `fence?: { runId, leases: Array<{entry, artboard, token}> }`. `parseEnvelope` validates it (≤ 200
  entries). `commit` runs `fenceCheck` in its transaction. A failure answers
  `rejected` + `code: 'lease-fenced'` + the keys.
  - An old hub ignores the field.
  - A `history.undo` or a held stage's Keep carries no `fence`.
- **Awareness (A10):** `beforeHandleAwareness` deletes `holding` and `editing` from every state whose
  `context.user.readOnly` is true. On the others it overwrites `holding.actor` with `context.user.actor`.
- **Roles:**
  - `begin`, `claim`, `renew` and `end` need edit on that canvas. Can comment and Can view have no AI chat
    panel (C30), and the hub refuses them as well (rule 12).
  - A canvas-scoped member's `wants` outside their canvases → `403` (V2-1.16).

**Invariants (each is a test, §7):**
- **L1** At most one live lease per `(entry, artboard)`, across every actor and device.
- **L2** A lease belongs to one live run, and its device's renewals keep it. 30 s without one → the run
  lapses.
- **L3** Each grant increments the artboard's `fence`. A token is the fence at grant.
- **L4** A publish with `fence` is accepted iff every token equals the current fence. Expiry alone never
  fences.
- **L5** Leases are released when a run ends, whatever the outcome. A held stage holds none.
- **L6** People never hold artboard leases. Their soft locks are awareness, objects only.
- **L7** No lease is awaited inside a turn. A denied claim is a deny plus, at turn end, a continuation
  ticket.
- **L8** Each artboard's line is FIFO by `n`. A newcomer never jumps a non-empty line, even on a free
  artboard.
- **L9** A ticket lapses with its run's TTL. A lapsed ticket is never granted.
- **L10** Every operation is one store call (§6 shows the split shape double-granting).

### 5.4 Studio registry (`apps/studio/ai/runs.ts`, new) and routes (main origin only)

- **Lease home.** One registry per project. It calls the hub (linked, `runs-v1` present) or the in-process
  store (local) through one interface. A linked project on a hub **without** `runs-v1` falls back to the
  in-process store, so it gets per-Mac leases. Diagnostics › AI setup says "AI takes turns per artboard on
  this Mac only — the team server needs an update" (Q2).
- **Persistence.** `<designRoot>/_state/runs/<runId>.json`, written tmp + rename before any hub call. The
  directory is under `_state/`, which is already runtime in all four DDR-115 lists, so there is no new class.
  - Retention: an ended record is pruned after 30 days unless it is its chat's latest run. Cap 500 files.
- **Renewal.** One timer per project, every 10 s, renews every live run in one `runs/renew` call. ACP runs
  are renewed while the bridge's turn is active. Hook-driven runs (terminal Claude, `/design:edit`) are
  renewed by every hook call and by the v1 `heartbeat` route. A hook run with no hook event for 120 s
  lapses (Q4).
- **Binding the hook run key (V2-1.11 Q6).** The bridge spawns each chat's `claude` with
  `MAUDE_CHAT_ID=<chatId>` in its environment. Hook commands inherit it, and `maude design hook` sends it as
  `chat`.
  - `run/begin` with `chat` binds to that chat's `starting` run, so no second run is created.
  - Without `chat`, `run/begin` creates a lazy `claude-code` run keyed by `session_id`.
  - Every `/_api/agent/*` call resolves `(chat ?? session)` to a run.

### 5.5 Run lifecycle

| From | Event | To | Side effects |
| --- | --- | --- | --- |
| outbox (V2-1.14) | released | `waiting` / `starting` | `runsBegin(enqueue)` |
| `waiting` | every wanted key granted, or a whole-canvas / multi-key ask with ≥ 1 granted | `starting` | chat card → Working; prompt sent |
| `starting` | bridge `prompt` accepted | `running` | renew `running` |
| `running` | permission / elicitation pending | `needs-you` | renew `needs-you`; Needs you surfaces (§5.8) |
| `needs-you` | answered | `running` | — |
| `running` / `needs-you` | turn `end_turn` | `ended:done` | V2-1.5 publish with `fence` → `runsEnd` → continuation tickets for keys denied `artboard-busy` |
| any live | Stop · Quit · close tab | `ended:stopped` | ACP cancel → partial publish with `fence` → `runsEnd`; divider "Stopped · <time>" / "Stopped when the app quit · <time>" |
| `waiting` | Cancel · Quit · chat moved to the trash | `ended:cancelled` (quit: `stopped`, unstarted) | `runsEnd`; Keep going offered after a quit |
| `running` | error, token limit, adapter crash | `ended:failed` | stage **held** (V2-1.5) → `runsEnd` |
| any live | studio boot finds it live (crash) | `ended:interrupted` | stage held; C37 callout; `runsEnd` best effort |
| any live | renew answers `ended: lapsed` and a CAS re-claim fails · publish `lease-fenced` | `ended:lease-lost` | stage held; "Post 1:1 changed while this Mac was away" via the V2-1.5 held card |

- **Continuation.** When a ticket of a continuation run is granted, the registry sends that chat a generated
  turn: "Post 1:1 is free now — make the same change there." It does this by itself, which is not "Run
  anyway": the line was respected.
- **The ask is done** when no run with its `askId` is live. The chat's result card "Done — …" waits for that.

### 5.6 Hub unreachable mid-run (linked project)

- Renewals fail quietly while the run keeps writing locally. Its stage is not published until the end
  anyway.
- **A new claim with the hub unreachable** (budget 250 ms in the hook) becomes **provisional**: it is granted
  locally with `provisional: true` and the last fence this registry saw for the key.
- **Before the publish**, every provisional claim is confirmed with `runsClaim({expectFence})`:
  - the CAS succeeds → the real token;
  - it fails → `ended:lease-lost`, stage held.
- **A publish that cannot reach the hub** waits in the DDR-241 outbox with its `fence`. L4 decides on
  arrival.

### 5.7 Run on a copy

- `POST /_api/ai/runs/:id/copy`, available only while the ask waits. It:
  - inserts a duplicate `DCArtboard` with a new id (V2-1.4: the copy gets new element ids and starts
    unlocked), built from the **accepted** content of the original and placed right beside it;
  - leases the new id (free by definition);
  - re-scopes the ask to it.
  It is one run, one action, one version.
- Undo of the run removes the copy (V2-1.5).
- "Keep the copy" is a person's later edit. While the original is held by a live run it is disabled:
  "Post 1:1 is still busy".
- **The agent path** is a file edit: duplicate the busy `DCArtboard` beside it with a new id and edit the
  copy. The `artboard-busy` deny text names it.

### 5.9 Quit, close tab, crash — exact order

1. **Tauri.** `RunEvent::ExitRequested { api, .. }` → `api.prevent_exit()`, then `WindowEvent::CloseRequested`
   → `api.prevent_close()`. The shell asks each project's studio `GET /_api/ai/runs`. If `live > 0`, the
   project webview shows the dialog. Cmd+Q a second time while the dialog is open quits.
2. **Quit** → `POST /_api/ai/runs/stop-all {reason}`. In parallel across runs:
   - ACP `cancel`;
   - wait ≤ 2 s for the turn to settle;
   - V2-1.5 `stopped` publish (DDR-241 outbox if offline);
   - `runsEnd` (best effort, 1 s);
   - write the record.
   Total budget 5 s. Then `sidecar::kill_server`.
3. **Crash / kill -9 / power loss.**
   - The hub frees the artboards on its next sweep after 30 s.
   - At boot: every live record → `interrupted`, `stoppedBy: 'crash'`, then a best-effort `runsEnd` so the
     line moves before the TTL. The held stages are listed in the C37 callout.
4. **Mac asleep.**
   - Runs lapse on the hub after 30 s.
   - On wake, the first renew answers `ended: lapsed`. The registry re-claims each key with
     `expectFence = token`:
     - CAS ok → keep going silently (nobody took it);
     - otherwise → `lease-lost`, the turn is cancelled, the stage is held.

### 5.12 Awareness field for people (S2 builds; contract here)

```ts
// CollabAwarenessState — additive; v1 peers drop unknown keys in sanitizeForeignState.
holding?: {
  artboard: string;            // DCArtboard id
  element: string;             // ElementId (V2-1.4) or a computed id + print
  print?: string;
  at: number;                  // refreshed on each edit gesture, ≤ every 5 s
  actor?: string;              // set by the hub (§5.3); ignored when it comes from the client
} | null;
```

- **Set** while an object is selected **and** either an inspector field for it has focus or an edit gesture on
  it happened within 30 s.
- **Cleared** on deselect, window or app blur, 30 s without a gesture, or disconnect (awareness removal).
- **Peers** treat a hold as free when no update refreshed it for 30 s, measured by the receiver's clock.
- **Sanitised** in `sanitizeForeignState` by `sanitizeHoldingState`: V2-1.4 id patterns, `at` finite and
  ≤ now + 5 s.

## Decisions

- `decision:maude/v2-V2-1.15-leases-in-project-store`: AI artboard leases, the waiting line and the fencing
  counters live as store-core tables. That is the hub's store for linked projects (self-host SQLite, cloud DO
  SQLite) and the in-process store for local ones. Each operation is one store method, so one transaction and
  one RPC. Rejected: awareness claims, hub memory only, a CRDT lock table, a lock file on the file plane.
- `decision:maude/v2-V2-1.15-ttl-and-fencing`: a 30 s TTL renewed every 10 s per project, applied lazily, plus a
  per-artboard fencing counter that the kernel checks inside the commit transaction. Expiry alone never fences;
  only a newer grant does. Rejected: leases without fencing, wall-clock expiry on clients, all-or-nothing
  acquisition.
- `decision:maude/v2-V2-1.15-run-registry-per-mac`: the studio's run registry under `_state/runs/` owns your
  runs (prompt text stays on this Mac, C27); peers see only `RunPublic`. One chat has one active run; asks
  queue FIFO per artboard and per chat; continuation runs pick up busy artboards by themselves. Hooks bind
  through `MAUDE_CHAT_ID`. Rejected: a second "running" map beside the registry, server-side queue state
  holding prompt text.
- `decision:maude/v2-V2-1.15-no-wait-inside-a-turn`: a run never waits for a lease inside a turn. A busy claim
  is a deny (`artboard-busy`) plus a continuation ticket at turn end; the chip is the boundary for in-app
  runs. Rejected: blocking hooks, hold-and-wait.
- `decision:maude/v2-V2-1.15-quit-stops-and-publishes`: Quit and close-tab ask first, then stop every run,
  publish partial work, release leases and mark the chats, before the sidecar dies. A crash lapses by TTL and
  comes back as `interrupted` with a held stage. Keep going is a manual new ask resuming the ACP session.
  Rejected: killing the sidecar mid-turn (today), auto-resume on launch.
- `decision:maude/v2-V2-1.15-soft-locks-ai-enforced-people-advisory`: people's object holds ride awareness
  (`holding`, stamped and filtered by the hub), advisory between people (DDR-120 kept). AI holds (`objects`) are
  enforced both ways: the hook denies AI on a person's object, and edit routes refuse a person on AI's object.
  Rejected: hard locks between people, unauthenticated awareness claims from read-only connections.
