# S8.5b — the cloud render door: how a desktop Maude reaches the cloud renderer

Writer: **S8.5b spike** (2026-10-20). Feeds: S8.5 (`exporters/remote.ts` `CloudRenderDoor`, merged with no door),
V2-1.14 §5.6/§5.11/Q3 (job id = idempotency key; "renders the project as it is when the export starts, after
every change made on this Mac before the ask has gone up"). Constrained by DDR-230 (tenant TSX evaluates only in
`maude-render`; viewer render token; `MAUDE_RENDER_SECRET` stays in the cell), DDR-231 (video on the worker),
DDR-054 (the hub is untrusted to peers), V2-1.7 (roles, A19, grants, observers never get a peer token),
V2-1.16 (one predicate, invisible = absent, every route classified), S9 Q12 (`routes-v2` table).
Prototype + measurement: `apps/studio/test/spike-s8-5b-render-door.test.ts` (12 pass).

## 1. Question

`createHttp` takes `opts.cloudRenderDoor` (`() => CloudRenderDoor | null`); boot passes none, so the Render row is
hidden. What implements `submit / status / artifact` for a desktop, given that the hub's studio proxy accepts browser
cookies only and `maude-render` needs the cell's secret and a public canvas address the desktop does not have?

## 2. What exists (the parts the door reuses)

- **The cell already renders video remotely.** In a workspace cell, `POST /_api/export-jobs` (studio child) runs
  `planExportV2` (spec gate, S8.6 video cap, S8.1b P3/past-version refusals) and the `remote` lane
  (`renderRemotely`) dispatches to `maude-render` with `MAUDE_RENDER_SECRET`, the cell's canvas origin
  (`MAUDE_RENDER_CANVAS_BASE ?? ctx.canvasOrigin`) and the **viewer** render token the hub proxy injects as
  `x-maude-render-token`. Jobs are owner-scoped by session key (`jobs.ts` `get/list/getBytes`; foreign id = missing).
- **The hub already has a bearer API.** `/api/projects/:p/v1/*` rows in `routes-v2/` (votes, comments, present,
  trash, access) authenticate the desktop's **peer token** through `acceptedAuth` → `{actor, readOnly, scope, access}`,
  gated by `runHubRoutes` at the row's capability/scope. For cloud projects that token already comes from the
  control-plane exchange — the desktop holds no other credential and needs none.
- **The cookie proxy's session → headers mapping** is one function, `upstreamHeaders` (strips inbound `x-maude-*`,
  injects role / readonly projection / access claim / user / session key / render token), and `decide()` is the one
  studio manifest. `sessionKeyFor(project, email)` is the job owner key.
- **The closure** (`access/closure.ts` `closureFor` over `diskProjectReader`) is the one import graph both the ACL and
  the canvas build use; it runs identically on the desktop's tree and on the cell's checkout.
- **The park probe** `GET /_cell/state` (sync bearer + `x-maude-sync-park: 1`) answers awake/asleep without waking.

## 3. Options

| | Option | Verdict |
| --- | --- | --- |
| **A′** | **A narrow bearer door on the hub's v2 route table** (`/api/projects/:p/v1/render-jobs…`): the hub builds the cookie proxy's session from the peer token, judges export + canvas scope, checks freshness against its own checkout, and forwards to the studio child's existing `/_api/export-jobs` lane. The cell renders its own synced copy. | **Chosen.** No new credential, no new service, no new account surface; same code path on self-hosted hubs with the `--render` sidecar; every ACL is enforced where V2-1.7 says the authority is (the cell). |
| A | As A′ but with a dedicated cell-side job store keyed by client id. | Folded into A′: the studio queue already owns jobs, owners, files and history; a second store is two truths. |
| B | Control-plane render door (account session) minting a render token for the linked cell. | **Rejected.** No control plane on self-hosted hubs (second implementation or none); the control plane would have to mint canvas capabilities for every tenant (hold or derive the cells' `HUB_SECRET`) — a new power over every tenant's canvas bytes; grants/closure are enforced in the cell, so it must judge again anyway; a D1 job table + a new public production endpoint + account-session use from the desktop, for no security gain; idempotency in D1 while the job lives in the cell. |
| C | Open the studio proxy to the peer bearer on every studio path. | **Rejected.** Turns the whole browser studio API (incl. writes outside the sync contract) into a bearer surface; a stolen sync token's blast radius grows from "sync" to "everything the shell can do". A′ is three rows. |
| D | The desktop uploads the canvas closure; the cell renders that. | **Rejected.** Bypasses the file door's gates (owner-only code modules, size caps, write scope — a canvas-only member could render a shared module they cannot write); bytes leave the Mac twice; needs a staging area (a new runtime path in all four DDR-115 lists) that the canvas origin would have to serve; pins content to the ask, which V2-1.14 Q3 rejected. |
| E | Desktop calls `maude-render` directly. | Rejected in S8.5 already (DDR-230 secret, public canvas address). |
| F | Freshness by hash equality pinned at ASK time. | **Rejected.** Never converges while the person keeps editing (prototype: any later edit = permanent mismatch); contradicts Q3. Fingerprint is taken at **send** time (§6). |

## 4. Decision

1. **The door is the hub's**, three bearer rows in a new `apps/hub/src/routes-v2/render-jobs.mjs`, main hub origin
   only. It authenticates the peer token with `acceptedAuth`, builds a session `{email: actor, role: access.role,
   access, canvasOnly, sessionKey: sessionKeyFor(project, actor)}`, and forwards through a new
   `studioProxy.forwardAs(session, {method, path, body})` that reuses `decide()`, the plan-pause gate, the upstream
   check and `upstreamHeaders`, **and drops `authorization` and `cookie`** (the cookie lane forwards `authorization`
   verbatim — prototype test "the door must drop it").
2. **The cell renders its own synced checkout.** Only the spec, the label and a closure fingerprint
   (`[{rel, sha256|null}]`) leave the Mac. Before forwarding, the hub judges the fingerprint against
   `designRootFor()` (§6); behind → `425 not-synced`.
3. **The client's job id is the studio job id**, owner-scoped (§7). Status and the file are the studio's own
   owner-scoped reads.
4. **Dark by capability.** `/health` lists `render-jobs-v1` only when the hub runs a workspace studio child, a render
   service is configured (`MAUDE_RENDER_URL`) and `MAUDE_RENDER_DOOR=1`. The desktop builds a door only when its linked
   hub lists it; otherwise `door()` is null and the Render row stays hidden (never a dead-end wait).

## 5. Routes and their classes in the four lists

| Route (hub main origin) | Method | Forwards to (studio child) | `routes-v2` row: cap {safe, unsafe} · scope · canvasDoor | Hub studio manifest | Studio writer registry | Canvas allowlists |
| --- | --- | --- | --- | --- | --- | --- |
| `/api/projects/:p/v1/render-jobs` | POST | `POST /_api/export-jobs` `{v:2, spec}` + `x-maude-door-job: <id>` | `{safe: null, unsafe: 'export'}` · `canvas` · `true` | unchanged (`/_api/export-jobs` unsafe `export`; `forwardAs` calls `decide`) | unchanged (`local`) | **neither** |
| `/api/projects/:p/v1/render-jobs/:id` | GET | `GET /_api/export-jobs?id=<id>` | `{safe: 'export', unsafe: null}` · `canvas` · `true` | unchanged (safe `read`) | unchanged | **neither** |
| `/api/projects/:p/v1/render-jobs/:id/file` | GET | `GET /_api/export-jobs/download?id=<id>` | `{safe: 'export', unsafe: null}` · `canvas` · `true` | unchanged (safe `export`) | unchanged | **neither** |

- `:p` = `[A-Za-z0-9._-]{1,128}`, the tenant id or `current` (votes' rule); `:id` = `^i_[a-z0-9]{20}$` (the outbox
  record id). Any other method → 405. Bodies ≤ 256 KB (fingerprint ≤ 2000 entries).
- **No new studio route.** The studio gains: `x-maude-door-job` honoured on `POST /_api/export-jobs` only when
  `renderLane() !== 'local'` (the header is unforgeable from clients: property 2 strips every inbound `x-maude-*`),
  and an `?id=` filter on `GET /_api/export-jobs`.
- **CSRF:** bearer only — the handler reads `authorization`, never a cookie; there is no ambient credential.
  `CANVAS_ORIGIN_ROW` already catches the canvas host (no handler there), so the rows are unreachable from a canvas.
- Scraped by `apps/hub/test/access-route-classes.test.mjs` once the rows exist (it fails unclassified paths).

## 6. Freshness (which bytes, how stale)

- **At send time** (the outbox sender, after the O4 watermark gate), the desktop computes
  `closureFingerprint(designRoot, spec.canvas)`: every rel in `closureFor(grant(canvas)).read`; code/CSS/JSON by
  sha256, content-addressed assets (`assets/<hash>.*`) by presence. Folder scope = the union over its canvases.
  Over 2000 entries → the door answers locally "render it on this Mac".
- **The hub judges** each entry against its checkout: missing or different → `behind`. **Only rels the session
  `sees`** are judged — an out-of-closure rel is skipped silently, so the answer is no existence oracle (prototype:
  "no oracle"). Cell-only files and teammates' edits outside the closure never block. A teammate's edit inside the
  closure is a transient mismatch until it reaches this Mac (live sync converges; the next send matches).
- `behind` → `425 {code: 'not-synced', behind: [≤ 20 visible rels], retryAfterMs: 15000}` (425 is transient in
  `judgeAnswer`). The sender keeps the first `not-synced` time per record; **past 10 minutes online** it answers
  final `409 {code: 'not-synced'}` → G26 with `CLOUD_NOT_SYNCED_WORDS`:
  "Not exported — your latest changes to {file} haven't reached the cloud. Render it on this Mac."
- **Measured** on a real 191-canvas design root: fingerprint p50 2.8 ms, p95 14.9 ms, max 80 ms; entries p50 53,
  max 298. Cheap enough for every send and every hub judgement.
- Staleness bound: the render reads the checkout as of dispatch; anything this Mac had at send time is in it.
  Edits after the send are not (Q3: an export is not a live view).

## 7. Idempotency, resume and cell sleep

- **Submit replay** (crash between send and answer): same owner + same id → `200 {jobId, already: true}` (the studio
  finds it in its jobs map or `_export-history.json`) → `TargetAnswer {ok, already}` → plain `sent` (the sender
  already maps it). Same id, other owner (or a different spec hash) → `409 {code: 'id-taken'}` → G26; never the
  other job. Ids are 100-bit random; a foreign id on status/file answers exactly like a missing one (404).
- **A studio-child restart mid-render** loses the running job (not in history): status 404 → `gone` →
  "Export again". A replayed submit of that id renders again (correct: it never finished).
- **Cell sleep.** The tracker polls every 5 s while a job renders, which keeps the cell awake. Before a poll after
  ≥ 60 s of silence (Mac slept, offline), `status()` first asks `GET /_cell/state` (never wakes); `asleep` → `gone`
  (a sleeping cell lost its jobs and files). A self-hosted hub answers 404 there → skip the probe. So a lost job wakes
  nothing, at most once.
- **Render token expiry while queued** (15 min TTL, minted at submit): every status GET carries a freshly minted
  viewer token and the studio swaps it on a still-queued job (`jobs.ts`, one setter). Browser jobs gain the same.

## 8. Token flow

1. The desktop holds its peer token **T** for the linked hub (per-profile hubs file; cloud projects: minted by the
   cell from the control-plane exchange). Observers never hold one (V2-1.7 §4) — A19 holds by construction.
2. Desktop → `POST https://<hub>/api/projects/current/v1/render-jobs`, `Authorization: Bearer T`,
   `redirect: 'error'` (T never follows a `Location` to another host), body `{jobId, spec, label, expect}`.
3. Hub: `acceptedAuth(T)`; `runHubRoutes` gate (`export`, scope `canvas`); handler: observer (Can view) → 403, a read-only `viewer` (Can comment) goes on (Michal 2026-10-21, see §10); every target
   canvas must hold `export` for the session (`access.can('export', canvas)`); canvas-only + folder/project scope →
   404 (invisible = absent, project-level is `PROJECT_ONLY`); per-actor limits (§10); freshness (§6).
4. Hub mints **R** = `mintRenderToken({subject: actor, role: 'viewer', grants: canvasOnly ? grants : []})` — viewer,
   15 min, grants ride as `g` so the canvas origin enforces the closure even if a door bug slipped a target through.
5. Hub → studio child (loopback) via `forwardAs`: injected role/readonly/access/user/session/render-token/door-job;
   **T is not forwarded**.
6. Studio → `maude-render` with `MAUDE_RENDER_SECRET` + R (DDR-230, unchanged). The worker reaches the canvas only
   through the cell's canvas origin with R. T, `HUB_SECRET` and the control plane are never involved.
7. Status / file: Bearer T again; same session key, so the studio's owner scoping matches.

## 9. Desktop half (`CloudRenderDoor` over HTTP)

`createHubRenderDoor({hubUrl, token: () => string | null, designRoot, fetch, maxArtifactBytes})`; the boot getter
returns it only when the linked hub's `/health` lists `render-jobs-v1` (cached per link, refreshed on reconnect) and a
token exists. Every answer is untrusted (the hub is untrusted to peers):

| Hub answer | `submit` → `TargetAnswer` | `status` → `CloudJobStatus` |
| --- | --- | --- |
| 202 / 200 `already` | `{ok: true, already?}` | — |
| job queued/running | — | `{state, progress}` (numbers clamped, `current ≤ total ≤ 1e6`) |
| job done / failed | — | `done` / `failed` (`error` ≤ 500 chars, shown as text) |
| 404 | `unknown-project` → G17; any other 404 (an invisible canvas answers like a missing one) → G26 | `gone` |
| 401 | → gate `signed-in` | `unreachable` |
| 402 plan · 403 forbidden · 409 `id-taken` / `not-synced` · 422 cap | G21 · G14 · G26 · G26 (cap words) | 403 → `failed` "access-removed" words |
| 425 `not-synced` · 429 · 5xx · network | transient (`retryAfterMs`) | `unreachable` |

`artifact`: streamed with a hard byte cap (reuse `readCapped`), filename through the tracker's untrusted-name rule,
content-type ignored, the job id in any answer ignored (this Mac's id is authoritative).

## 10. Quota and abuse

- Per actor: ≤ 2 door jobs queued+running, ≤ 30 submits/hour → `429 {code: 'busy', retryAfterMs}` (in-memory
  limiter, votes' `createWriteLimiter` shape). Project queue full → the studio's existing 429. S8.6 video cap → 422.
  Plan paused → 402 (the proxy's gate, via `forwardAs`). Fleet full → the worker's 503 fails the job "busy" (today's
  behaviour for browser jobs).
- **Who may ask (Michal 2026-10-21).** Anyone whose role holds `export`: owner, member, **viewer (Can comment)** and a
  canvas-only session on a canvas it may export. A Can comment session renders from the Mac app as it exports from the
  browser: the studio sees the same read-only projection (`x-maude-readonly: 1`) and the caps above are per person, so a
  viewer gets the same 2 in flight / 30 an hour as a member. Can view (observer) holds no `export` (A19) and stays
  refused; a removed member's token no longer verifies and a request with no session has none (401).
- **Render seconds per tenant (Michal 2026-10-21, `decision:maude/v2-michal-render-seconds-in-studio`).** Counted in the
  studio (`exporters/render-seconds.ts`), not the hub: from the moment a cloud-lane job takes its render slot until it
  settles (done, failed, or aborted by its timeout) — never queue wait, never a job refused before it ran. Reported in
  `/_health` as `render.renderSeconds = {total, jobs, bootedAt}` (additive; the hub's `/health.render` carries it to the
  control plane for the privileged caller). It is a running total since boot with the boot time beside it: a restart
  zeroes it and moves `bootedAt`, so a reader can tell a reset from an idle tenant. No billing, no plan gate (M2).

## 11. Self-hosted hubs

Same code. A workspace hub with the `--render` sidecar (`MAUDE_RENDER_URL`) and `MAUDE_RENDER_DOOR=1` lists
`render-jobs-v1` and the door works. A plain sync hub (no studio child) or a hub without a render service lists
nothing: the desktop shows no Render row and videos render on the Mac. Older hubs/cells: no capability, same.

## 12. Threats and mitigations

| # | Threat | Mitigation |
| --- | --- | --- |
| T1 | Stolen peer token used to burn renders or download a person's exports | No widening: T already reads the project via sync. Per-actor caps (§10); revocation/kickLabel ends T; jobs owner-scoped. |
| T2 | Reading another member's job by id | Owner key = session key; foreign id = 404 like missing; ids 100-bit random; submit with a foreign id → 409, never the job. |
| T3 | Canvas-only member exporting outside the closure (folder/project scope, ungranted canvas, foreign artboard ids) | Hub judges every target; studio `grantLaneRefusal` re-judges (must read v2 bodies — S8.5b-1); R carries `g`, so the canvas origin refuses out-of-closure bytes. |
| T4 | Can view downloading (A19) | Observers get no peer token; an observer session → 403 → G14. A read-only `viewer` (Can comment) is NOT refused: it holds `export` and renders as it exports from the browser (Michal 2026-10-21, `decision:maude/v2-michal-viewer-renders-from-mac`; supersedes the earlier "readOnly → 403"). |
| T5 | Header injection (`x-maude-role`, `x-maude-door-job`, forged render token) | Property 2 strip in `upstreamHeaders` (prototype); job id travels in the body, regex-validated; `x-maude-door-job` honoured only off the local lane. |
| T6 | SSRF via spec (pointing the worker elsewhere) | The spec carries no URL; origin is cell env; `pickRemoteOptions` allowlist (unchanged). |
| T7 | Existence/hash oracle through `expect` | Only `sees`-visible rels are judged and named; at most 20 named; invisible ones silently skipped (prototype). |
| T8 | Hostile hub answers (self-hosted or compromised cell) | `redirect: 'error'`; artifact byte cap; sanitized filename; error text capped and rendered as text; clamped progress; own job id authoritative; nothing executed. |
| T9 | Bearer reaching the studio child / worker | `forwardAs` drops `authorization` + `cookie`; the worker gets only R. |
| T10 | Wake abuse / cost from polling a sleeping cell | Park probe first after silence; polling only while a job renders; jobs expire in 24 h (`CLOUD_JOB_MAX_AGE_MS`). |
| T11 | Render token expiry while queued (job fails late) | Fresh R on every status poll (§7). |
| T12 | Cross-tenant render effects | Unchanged DDR-230 posture (single tenant per job, no secrets in the worker). |

## 13. Tests that prove it

- **Hub** (`apps/hub/test/render-jobs-route.test.mjs`, fake studio upstream + fake checkout): bearer only (cookie
  alone → 401); observer → 403, viewer and Can comment allowed (forwarded read-only, status and file reachable, caps still apply), a removed member and no session → 401; canvas-only + project scope → 404, + ungranted canvas → 404, + granted → forwarded with
  `x-maude-readonly: 1` and R carrying `g`; inbound `x-maude-*` and `authorization` absent upstream; `not-synced` names
  only visible rels and never an out-of-closure probe; replay → `already`; foreign id → 404 on status and file,
  409 on submit; limiter → 429; `/health` lists `render-jobs-v1` only with studio child + render URL + flag;
  rows present in `access-route-classes.test.mjs`.
- **Studio** (`test/export-door-job.test.ts`): `x-maude-door-job` ignored on the local lane; honoured on remote →
  job id equals it; second POST same owner → 200 `already`; other owner → 409; `GET ?id=` owner-scoped; queued job's
  render token replaced by a newer one; `grantLaneRefusal` judges `{v:2, spec}` targets (fail-first: today it skips
  them).
- **Desktop** (`test/hub-render-door.test.ts`, fake hub on loopback): the answer table of §9 row by row; redirect not
  followed (bearer never reaches the second host); artifact over the cap refused; filename sanitized; asleep probe →
  `gone` without a status call; no door when `/health` lacks the capability → Render row hidden; the `not-synced`
  10-minute bound turns transient into G26 with the words.
- **Lane test** (boot a real hub + studio child with a fake `maude-render`): submit → done → file on this Mac;
  restart the desktop mid-render → resumes by id; kill the studio child → `gone`.

## 15. Open questions (recommended default)

- **M1 (Michal — public endpoint on production).** The rows sit on every cell's public hub origin beside the existing
  `/api/projects/:p/v1/*` bearer routes. Default: ship dark (`MAUDE_RENDER_DOOR` unset = no capability, rows answer
  404), flip per cell after the security review and the daily render canary (DDR-231 guard rail 1) is green.
- **M2 (Michal — money) — decided 2026-10-21.** Desktop cloud renders add load to the shared `maude-render` fleet.
  Same caps as browser video jobs + §10 per-actor caps; render seconds are counted per tenant in the studio and
  reported through health (§10); no plan gate in this slice.
- **M3 (Michal — money).** Keep finished artifacts in R2 so a cell sleep does not lose them. Default: no; `gone` →
  "Export again" (the 5-s poll downloads within seconds while the Mac is online).
- Q4. Should the desktop's cloud jobs show in the same person's browser Exports panel? Default: yes — same session
  key, same person (prototype pins it).
- Q5. Multi-canvas folder renders over 2000 fingerprint entries. Default: render on this Mac (cloud lane is video).
- No account-model change: the door uses the peer token the desktop already syncs with.
