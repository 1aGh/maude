# V2-4.9: the shell parity contract

**Decision.** One table says which chrome each of the seven shells has, and why every absence is an absence. The
table is derived from the registry and the shell's own models, so a shell cannot gain or lose a control without the
table (and a red test) noticing. The desktop e2e walks the same table against the live shell.

## The seven shells

The nothing-deleted probe's matrix (`scripts/v2-manifest/reach-rules.mjs` `PROBES`), in its order:

| Shell | Surface | How a running page identifies it |
| --- | --- | --- |
| `desktop` | window | `window.__TAURI__`, no `cloud` in `/_config` |
| `browser` | tab | no Tauri, no `cloud`, not read-only |
| `cloud-owner` / `cloud-member` | tab | `/_config` `cloud.role` |
| `cloud-viewer` | tab | `cloud.role` viewer (the hub's `observer` is the same chrome, no toolbar) |
| `viewer` | tab | no `cloud`, `readOnly: true` (a Can comment link on a local project) |
| `embed` | frame | `?embed=1` |

## Where it lives

- `client/v2/shell/shell-parity.js` builds the table (`buildParity()`, `parityFor(id)`). Parts: window tabs, project
  pill, Back to Home, the menu (rows, derived from `PROJECT_MENU` + the registry predicates), the Share cluster, the
  mode switch, the left panel, Inspector / Comments / History, the AI chat, the toolbars (from `MODE_TOOLS`),
  Settings (sections and rows), Diagnostics, the canvas.
- `client/v2/shell/shell-parity.json` is its committed form (`bun scripts/gen-shell-parity.mjs`; `--check` for CI).
  A wdio spec cannot import the client's TS/JSX graph, so the e2e reads the JSON.
- `test/v2-shell-parity.test.tsx` pins the table to the models, renders the real Share cluster and left panel per
  shell, mounts the Settings sheet per shell, and fails when the JSON is stale.
- `apps/desktop/e2e/scenarios/shell-parity.e2e.ts` (+ `helpers/parity.ts`) asserts the table on the live page:
  testids present, every project-menu row (all submenus opened), Settings sections, ⌘K's AI-chat row, the embed.

## The two decisions

1. **A read-only session has Settings › General.** Theme, Inspector words, Canvas and view, panel positions are
   kept in this browser, so a Can comment viewer gets them (local read-only link and cloud viewer alike). Connections
   and Advanced configure the Mac the project lives on and stay the desktop owner's: `sectionsFor(cloud, readOnly)`
   and `rowShown(row, { cloud, readOnly })` in `settings-model.js` are the one rule the sheet, ⌘K and the table share.
   ⌘, opens it for a viewer (it used to be swallowed). A local read-only link has no Account group (it is the Mac
   owner's account); a cloud viewer keeps "Open the cloud dashboard".
2. **A cloud tab says where the AI chat lives.** `ai.chat` is `visible` in `desktop` and `cloud` and `enabled` only on
   the desktop, with `search.note: 'in the desktop app'`; ⌘K lists the greyed row "AI chat — in the desktop app", and
   a click toasts the same sentence (`menu-runner.js`). The menu tree never had an AI chat row. A local browser and a
   read-only link have no cloud story to tell: no row.

## The embed

`embed-view.jsx` seeds its canvas on the ladder with `set-mode { mode: 'preview', caps: NO_CAPS }` (the V2-4.3b
lane, `seq` only grows). Role `view` has no toolbar in any mode, so the embed shows the design and nothing else.

## Role gating (V2-4 gate, resolved)

- The rows V2-4.9 found a Can comment viewer still offered now carry a registry `minRole` (decision
  `maude/v2-4-gate-role-gated-actions`). **Absent** (`visible`): New canvas, New video, Video assemble, New artboard…,
  Select all annotations — they create or select-to-change. **Greyed** (`enabled`): Undo / Redo, Cut / Paste, Paste
  properties — the macOS Edit-menu idiom; a commenter's ⌘Z resolves to the disabled winner and hears the one denial
  line (`role-gate.js`), ⌘X / ⌘V stay WebKit's for the comment composer. **Kept**: New project / Open project (another
  project — the role is per project), Copy and Copy properties (reads). The native File ▸ New Canvas ⌘N, which AppKit
  draws without the hub role, is answered with the denial line by the `menu://action` bridge.
  `test/v2-role-gated-actions.test.ts` and `test/v2-shell-parity.test.tsx` pin it.
