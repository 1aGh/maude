## 3. Options

**Topology.**

| # | Option | Cost | What it breaks / why not |
| --- | --- | --- | --- |

| 2 | **B**: A + `board-reader` + a parallel `artboard-drafter` fan-out + a `ds-switcher` fan-out | three agents, hand-offs, a splice step | measured in §6 |
| 3 | B per helper: keep only the helpers that individually pass the rule | — | this is how the rule is applied (§4) |
| 4 | Agent teams in the product | — | impossible: the chat is `claude -p` (§2, §6) |

**Check dispatch.**

| # | Option | Why / why not |
| --- | --- | --- |
| **1** | one verb `maude design check <file…>` dispatching by file kind, two tiers (`fast` in PostToolUse, `stop` at Stop / SubagentStop / `run.end`), run in-process by bun (or the studio's warm validator) | one parse per file, one output schema, one budget — chosen |

The hook set itself is V2-1.11's (option 1 there); this spike only adds what its I/O needs (§5.4).

## 4. Decision (DDR draft)

**Title:** Maude v2 agents: one writer + skills (topology A) — no board-reader, ds-switcher or artboard-draft
fan-out; an edit-safety harness of one `check` verb (fast / stop tiers), V2-1.11's deny-only hooks with sub-agent
`owns` enforcement, `_runs/` runtime state and the `maude.agent-handoff/1` envelope.

**Context.** K-agent-architecture recommends one writer per run, with sub-agents only for reading, verifying or
owning separate files, and asks for an eval before any split ships. A13 makes files the API, so the safety of raw
edits rests on hooks and a validator, and V2-1.11 fixed their interfaces. The chat is `claude -p` under the ACP
adapter, where agent teams don't exist.

**Decision.**
1. **Topology A.** The chat agent is the only writer of a run's canvases, boards and system files; competence comes
   from skills. Sub-agents are used for exactly four reasons — untrusted input in a sandbox (`reconstruct-*`),
   independent verification (critics, keeper), parallel reading of N separate media files (`footage-analyst`,
   `asset-describer`), and bounded writers of NEW separate files (`draw-agent`, `footage-director`, `ds-migrator`).
   "The board is big" and "there are several canvases" are not reasons: a 300-element board is ~20 k tokens.
2. **The three B helpers are not built.** On the pilot (§6.2) `board-reader` and `ds-switcher` fail the rule on both
   axes (1.2–1.7× slower, 1.1–1.7× tokens, no quality gain); the `artboard-drafter` fan-out fails it on tokens
   (1.58× over two samples) with a latency difference inside run-to-run noise. S12 keeps `asset-describer` and
   `ds-migrator` from K §2.2 (not under test here: they read or create separate files).
3. **`maude design check`** dispatches by file kind with two tiers (§5.3). The fast tier runs in PostToolUse on every
   `.design/**` write: parse, ids, locks, strict boards, schemas — measured ≤ 0.1 s including the hook spawn — **plus
   the sandboxed canvas build** (0.1–0.6 s cold on canvases up to 140 KB, §6.1), so a canvas that parses but no longer
   builds is rolled back at the edit that broke it; a build that would exceed what is left of the 1.5 s budget is
   deferred to Stop. Full lint, `ds-check --canvas`, screenshot freshness and the id re-attach run at Stop /
   `run.end`.
4. **Hooks** are V2-1.11's set; this spike adds SubagentStart, the run-folder context line, sub-agent `owns`
   enforcement, the module-scope rule for shared stylesheets, and hand-off validation at SubagentStop (§5.4).
5. **`_runs/<runId>/`** holds snapshots, bases, the hook log and hand-offs; it is runtime state in all four DDR-115
   lists (§5.1).
6. **`maude.agent-handoff/1`** (§5.2) is the only envelope between the main agent and a sub-agent; critics move to its
   `findings[]`.
7. **No agent teams in the product.** The chat runs `claude -p`; teams stay a tool for building Maude (DDR-130 relay).

**Consequences.**
- S12 builds fewer agents (no board/DS/artboard helpers) and spends the effort on skills, the check verb and hooks.
- Every invariant held by the hooks also holds inside sub-agents (hook inputs carry `agent_type`; plugin agents can't
  declare their own hooks).
- A fan-out can be added later only through the same eval (V2-8.16 re-runs it); this decision is not a ban.
- A large board read in the main context costs a few thousand tokens more than a brief would; measured cheaper than
  a helper overall.

**Rejected.** B as a whole and each helper alone (§6.2); agent teams in the chat (impossible); a second PostToolUse
hook per checker (§3); keeping the canvas build Stop-only as V2-1.11 drafted (it fits the fast budget, §6.1, and a
build error found at the end of a run has already been built upon by later edits).

## 5. Contract

### 5.1 `_runs/` — runtime state, one folder per run

```
<designRoot>/_runs/
  shots.jsonl                       {at, canvas, artboard|null, all, session} — appended by `maude design screenshot`
  <runId>/                          runId = V2-1.15's `r_…` from run/begin; with no studio:
                                    `r_` + first 16 hex of sha256(session_id + ":" + prompt_id)
    run.json                        {runId, session, promptId, startedAt, studio: bool}
    snap/<tool_use_id>.json         {path, existed, content} — bytes before each Edit/Write (rollback source)
    base/<path with / → __>.json    {path, existed, content} — bytes when the run first touched the file
    touched.json                    {"<rel>": {at, by: "main"|<agent_type>, via: "tool"|"bash"}}
    agents.json                     {"<agent_id>": {type, at}} — from SubagentStart
    hooklog.jsonl                   {at, event, ms, agent, tool, path, decision, code} — Diagnostics › AI (V2-2.9)
    handoff/<agent>-<n>.in.json     maude.agent-handoff/1, role "in"  (written by the main agent before a spawn)
    handoff/<agent>-<n>.out.json    maude.agent-handoff/1, role "out" (written by the sub-agent)
    <agent-owned files>             board briefs, drafts, ds-switch proposals… — whatever a hand-off's `owns` names
```

- **Classification (DDR-115, all four lists in one change — a lead-owned patch request, V2-2.16):**
  `git/service.ts` `isMaudeRuntimeState` and `sync/file-membership.ts` `isRuntimeStateRel` (+ the byte-identical
  `apps/hub/src/file-membership.mjs`) add `runs` to the directory alternation
  `_(?:history|trash|…|cache|runs)(?:\/|$)`; `cli/lib/gitignore-block.mjs` adds `${root}/_runs/`; the repo
  `.gitignore` adds `.design/_runs/`. The tripwire fixture list in `test/sync-file-membership.test.ts` gains
  `_runs/r_x/handoff/a-0.out.json` and `_runs/shots.jsonl`. Never synced, never versioned, never in a ZIP export
  (V2-2.8 S8).
- **Retention:** `snap/` is deleted at `run.end` (after `--fix=safe`); a run folder is pruned 7 days after it ended,
  except the newest 20; a file over 4 MB is not snapshotted (no rollback for it — fail-open).
- **Sessions with several prompts** get one run folder per prompt; hooks find the current one through
  `_runs/sessions/<session_id>.json` (`{run, promptId}`), written by the `prompt` event.

### 5.2 `maude.agent-handoff/1`

The JSON Schema is `apps/studio/test/agent-evals/harness/handoff.schema.json` (draft 2020-12; the shipped copy is
`cli/lib/handoff.schema.json`, V2-2.4b). Two shapes, one `$id` (`https://maude.sh/schema/agent-handoff/1`):

```ts
type RelPath = string;                 // repo-relative; no leading "/", no ".." segment
interface HandoffIn {
  contract: 'maude.agent-handoff/1'; role: 'in';
  runId: string;                       // ^r_[A-Za-z0-9_-]{4,64}$
  agent: string;                       // "board-reader" | "design:design-critic" …
  n?: number;                          // worker index in a fan-out (0–63)
  task: string;                        // ≤ 4000 chars, the person's words verbatim inside it
  scope?: { canvas?: RelPath; artboardIds?: string[]; elementIds?: string[] };   // V2-1.4 ids
  owns: string[];                      // the ONLY paths the agent may write (globs, ≥ 1) — enforced by pre-edit
  reads?: string[];
  context?: { brief?: string; ds?: string; dsRev?: string; fidelity?: 'strict' | 'loose'; styleContract?: string | object };
  checks?: string[];                   // verbs the agent must run green ("maude design check <file>")
  budget?: { maxIterations?: number; maxTokensHint?: number };
  output: RelPath;                     // where the agent writes its HandoffOut
}
interface HandoffOut {
  contract: 'maude.agent-handoff/1'; role: 'out';
  runId?: string; agent: string; n?: number;
  status: 'done' | 'partial' | 'blocked' | 'refused';
  summary: string;                     // ≤ 2000 chars — what the final message carries too
  changed: Array<{ file: RelPath; kind: 'new-file' | 'edit' | 'proposal' | 'draft' | 'brief' | 'report'; artboardIds?: string[]; elementIds?: string[] }>;
  evidence?: Array<{ kind: 'check' | 'screenshot' | 'cmd'; cmd?: string; exit?: number; path?: RelPath }>;
  decisions: Array<{ decision: string; why: string; alternatives?: string[]; reversible?: boolean; confidence?: 'high' | 'medium' | 'low' }>;
  findings: Array<{ severity: 'blocker' | 'warning' | 'info'; where?: string; what: string; fix?: string }>;
  open_questions: string[];            // ≤ 20 — the main agent asks the person, never the sub-agent
  result?: object;                     // a reader's payload (a board brief), ≤ 64 KB serialised
  next?: string;                       // "apply-after-review" | "splice" | "none" …
}
```

Rules: `additionalProperties: false` on both; the main agent writes the `in` file and passes the same JSON at the top
of the spawn prompt; the sub-agent's final message is the summary plus the `output` path (≤ 2 k tokens, K §2.4);
critics adopt `HandoffOut` with `findings[]` (their current JSON verdict maps onto it; S12); SubagentStop refuses to end
a hand-off agent whose `output` is missing or invalid (once — §5.4).

### 5.3 `maude design check` — dispatch and tiers

```
maude design check <file…> [--json] [--tier fast|stop] [--against <snapshot>] [--fix=safe]
→ exit 0 ok · 1 errors · 2 usage
--json → [{ file, kind, ok, ms, errors: Finding[], warnings: Finding[], infos: Finding[] }]
Finding = { code, where, what, fix, line?, element?: { tag, label, artboard } }
```

`--against` defaults to the run's `base/` copy, else the last accepted content (V2-1.4 §5.3). `errors` block the write
(PostToolUse rolls back); `warnings` go back to the model as `additionalContext` and never block; `infos` land in the
run result. One parse per file per call; the checkers below share it.

| Kind (by path) | Fast tier — PostToolUse, every write (budget **≤ 1.5 s p95** incl. spawn) | Stop tier — Stop / SubagentStop / `run.end` |
| --- | --- | --- |
| `canvas-tsx` (`**/*.tsx` outside `system/`) | parse (oxc); `DCArtboard` ids unique; V2-1.4 ids: `id-lost` `id-duplicate` `id-expression` `id-format` `locked-changed` `cd-attr-changed` against the snapshot; V2-1.5 `run-overlap` (studio up); canvas build in the sandbox (`buildCanvasSandboxed`, content-hash cached) when it fits the remaining budget, else deferred; **warnings**: V2-1.13 `ds-check --canvas --changed` S-rules (≤ 400 ms, the `ds` checker) | the same against the run's base (catches drift across several edits); any deferred build; `artboards-lint`; full `ds-check --canvas`; screenshot freshness; `--fix=safe` re-attach at `run.end` only |
| `annotations` (`*.annotations.json`) | strict board: every lenient-loader drop is an error; unknown fields; locked elements unchanged; `author` immutable; new elements need `author.kind:"ai"` | same against base |
| `canvas-meta` (`*.meta.json`) | Ajv on the v2 schema (`additionalProperties:false`); no `viewport` (DDR-115); `dsRev` unchanged (V2-1.6: set by verbs only); `dsPending` entries typed by the registry (V2-1.6 §5.9) | same |
| `edl` / `footage` / `photo-edit` | Ajv on the schemas generated from `footage/schema.ts`, `photo/schema.ts` (V2-1.11 §5.2) | same |
| `tokens` / `components` / `ds-config` (`system/<ds>/…`) | `ds-check <ds>` structure (A14) as **warnings**; on a converted system the context says the edit arrives as a review (V2-1.6) | `ds-check <ds> --json` |
| DS-managed (`system/*/revisions/**`, `head.json`) | never reaches check — pre-edit denies `ds-managed` (V2-1.6 §5.12) | — |
| canvas `.css` / `.ts` siblings | `ds-check` S-rules on the changed lines as warnings | — |
| hand-offs (`_runs/**/handoff/*.in.json`, `*.out.json`) | §5.2 schema of the role the file declares (the one runtime path that is checked — helpers run `maude design check <output>` before they stop) | SubagentStop requires it valid |
| other `.json` | parses | — |
| other `_*` runtime, files outside `<designRoot>` | not checked | — |

### 5.4 Hook set — V2-1.11 §5.4 kept; what this spike adds to it

The events, commands, timeouts, budgets and the deny-only / fail-open rules are V2-1.11's. The prototype
(`apps/studio/test/agent-evals/harness/hook.mjs`) implements all of them except the studio routes and adds:

| Event | Addition | Why |
| --- | --- | --- |
| UserPromptSubmit `prompt` | outputs one `additionalContext` line: `Maude run folder for this conversation: .design/_runs/<runId>/ (run id <runId>)` (≤ 200 chars); writes `run.json` + `sessions/<session>.json` | the main agent needs the run id to write hand-offs; V2-1.11 had "nothing" here — additive |
| SubagentStart (**new**) | records `agent_id → {agent_type, at}` in `agents.json`; outputs nothing | SubagentStop must know when the agent started (to find its `output`) and attribution needs the type |
| PreToolUse `pre-edit` | **(a) sub-agent scope:** inside a sub-agent (`agent_type` set) a write outside its hand-off `owns` is denied `out-of-scope`; an agent without a hand-off may write only `_*` runtime paths, unless it is a declared bounded writer (`design:draw-agent`, `design:footage-director`, `design:reconstruct-agent`, S12's `ds-migrator`) writing a NEW file. **(b) module scope:** an edit of a stylesheet / shared module a canvas imports counts as "every artboard of that canvas" for `artboard-busy` (V2-1.15 §4 #9 applied to sibling files — found by the eval's `busy` fixture). **(c)** `ds-managed`: hand edits of `system/*/revisions/**` and `head.json` are denied (V2-1.6). **(d)** the snapshot also seeds the run's `base/` copy | (a) is the enforcement of `owns`, the one invariant K's topology rests on; (b) a shared CSS change is the most common way to "touch" a busy artboard without editing its JSX |
| PostToolUse `post-edit` | runs `check --tier fast` against the snapshot — **now including the sandboxed canvas build** (V2-1.11 had it at Stop); errors → restore + `decision:"block"` whose reason lists `[code] where · what · fix` and ends "The file was restored to before this edit"; warnings → `additionalContext` | as V2-1.11; the build fits the budget (§6.1) |
| Stop `stop` | `check --tier stop` against `base/` + screenshot freshness per touched artboard (via `attributeArtboards`; a whole-file change or a new canvas needs every artboard; `--all-screens`/`--full` count for all) | as V2-1.11 |
| SubagentStop `subagent-stop` | for an agent spawned with a hand-off: its `output` file must exist (mtime ≥ its start) and validate against §5.2, else `decision:"block"` once with the schema errors; the check of the files in its `owns` | as V2-1.11 ("only the files in that agent's `owns`") |
| PreToolUse `pre-bash` | unchanged; best-effort regexes. False positives seen in the pilot (6 denials): `maude design read-annotations … \| python3 -c "…json.load…"` read pipelines were refused as writers; `cp .design/x /tmp` would be too — narrowed per §9 Q5 | — |

Invariants (each a test, §7): hooks never print `ask`/`allow`; a failed fast check leaves the file as it was; a hook
error or timeout exits 0 (the write is not blocked); no hook needs the studio for check, rollback, `owns` or the Bash
rules; every decision is logged with its latency.

### 6.1 Probes and budgets

**Claude Code facts (probes 1–3, `claude -p --plugin-dir plugins/design`).**
- The session lists 28 agents, including `design:_draw-design-rules` and `design:_draw-motion-rules` (rule files
  registered as agents — S12 moves them).
- With and without `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` the `-p` tool list is **identical** (`Task`, `SendMessage`,

### 6.3 What the harness itself showed

- **The module-scope rule works and is needed.** "Make the headlines one step bigger on every artboard" (busy
  fixture): both runs first tried the shared `Onboarding.css` rule, were denied `artboard-busy` (Tereza's AI holds
  `hub`), then set the size on the four free headlines inline, left `hub` and Jonas's held button alone and said so.
  Without §5.4(b) a shared-CSS edit silently restyles the busy artboard.
- **Stop gate:** 5 blocks across 28 Stops, all for missing screenshots (3–5 artboards each, no check problems);
  every agent then took them; no loop (the second identical block lets go).
- **Post-edit rollback:** 0 of 154 edits failed the fast check — the models kept ids and locks on their own; the hook
  is the guarantee, not the mechanism of compliance. The rollback path is covered by the self-test instead.
- **Hand-offs:** in the first pass all 11 helper hand-offs failed the schema on the first write — partly a
  **harness defect** (the validator reported both `oneOf` branches, telling an "out" file it lacked `task`/`owns`) and
  partly invented shapes (`decisions` as strings, `findings` as strings, extra `note`/`mapping` keys). After the fix
  (role-specific validation, the item shapes in the agent prompts, `maude design check` validating hand-offs) 6 of 11
  were valid on the first write and the rest corrected themselves (2 after their own `maude design check`, 4 after one
  SubagentStop block). The affected B trials were re-run, not scored as topology results.
- **B-specific failure mode seen:** in a `ds-switcher` run the main agent's summary said "all four proposals pass
  `maude design check`" while every helper's hand-off said the check could not be run — the summary step invents
  verification (K's "telephone game"). Hand-off `evidence[]` with exit codes is the antidote; it is now required by
  the prompts.
- **Grader defects found and fixed** (each re-graded, none an agent failure): the studio rewrote the board fixture in
  canonical form on load (fixture made canonical; boards compared by elements, not bytes); a new `DCSection` around a
  new artboard and an added import counted as "every artboard" (the graders use a lenient attribution: added imports,
  section labels and lines-added-only shared declarations don't reach existing artboards; the **hook keeps V2-1.5's
  strict closure**); the ballot-read grader counted the words "_state/votes/" in a spawn prompt as a read; a helper's
  `sed -i` on its own `_runs/` file counted as a design write.
- **Judge noise:** the same `board-reader` answer (theme counts with loose stickies folded in, which the rubric allows)
  was judged pass in one run and fail in the other; the judge also missed the gitignored `_trash/` until it was listed
  in its prompt. The model judge is the last signal, never an invariant (K §3.4, A9).
- **Infra-failure:** a network outage (ENOTFOUND) cut both sides of the `n1` re-run after ~280 s. Marked
  `infra-failure`, excluded, re-run (the harness now detects it from the result text).
- **Harness finding → B3** (now V2-2.8 B3, `decision:maude/v2-2.8-b3-annotate-absolute-path`): `maude design
  read-annotations "<absolute path>"` returns an empty board and `annotate "<absolute path>"` writes a new board named
  after the whole path. A `board-reader` hit it (it got "0 elements" and fell back to reading the board file); that
  trial is scored on the code graders as usual — the fallback is not counted against B.
- **Permission friction (both topologies, every run):** compound commands such as `PORT=$(maude design server-up) &&
  maude design screenshot …` or `ls .design && maude design runs list` don't match `Bash(maude:*)` and are denied in a
  prompt-less session; agents recovered by splitting them. V2-2.4b's skills should show one verb per command, and
  `screenshot` should start the server itself.
- **Cost of the harness on the agent:** none measurable — hook latency is milliseconds; the only extra turns are the
  Stop gate's screenshots (product behaviour) and the hand-off corrections.

### 6.4 Extrapolation — why the full run was not started

| | Pilot (measured) | Full run (30 tasks × A/B × 3) |
| --- | --- | --- |
| Pairs | 10 in the final set (17 run, incl. re-runs) | 90 |
| In-lane time per pair | mean 4.7 min (0.8–11.5 min), plus a 30 s gap | ≈ 90 × 5.2 min ≈ **7.8 h of lane time** |
| Wall clock on the shared lane | ≈ 2.9 h for 17 pairs, about half of it queueing behind other teammates' suites (a 3.5 h network outage excluded) | realistically **12–20 h** |
| Model usage (list price) | final set $28.9 (agents $26.3 + judge $2.6); all 35 runs ≈ $52 | ≈ **$260–300** |

That exceeds the ~6 h stop line of the brief, and the pilot hit the account's weekly usage limit, so — per the lead's
call (2026-10-10) — this note carries the pilot as the evidence. The pilot is **conclusive for the decision**: no
helper wins on either axis in any aggregate, so the default (A) stands without further runs. What the full run
needs: an uninterrupted lane window of ~8 h (or ~4 h with two pairs at once — wall-time comparisons then get noisier,
equally for both sides); ~$280 of model usage; `~/Maude/alligators` on the Mac (tasks n2, e4, e5);
`bun apps/studio/test/agent-evals/run.mjs suite --tasks all --trials 3 --skip-done --out <dir>` resumes after any
interruption. A cut-down decisive slice — the 16 helper tasks × 3 trials + the 14 controls × 1 — is 62 pairs,
≈ 5.4 h and ≈ $190. Given §6.2, the result most likely to change is the drafter's, and only if its latency gain turns
out consistent; the board and DS helpers would need a reversal of 7-of-8 samples.
