## 1. Question

> How Home is served; where recents/pins/thumbnails/open-tab state live; how Home talks to project sidecars without
> leaking across origins

Signed constraints: **A1** (native macOS window tabs; Home is its own window tab, ⌘T, "Back to Home"; tab avatars and
status glyphs are not built), **C38** (a project-less Home server mode — one shared loopback instance serving the same
client bundle in Home mode; the shell owns the cross-project index: recents, pins, open tabs, thumbnails cache),
**C3** (native File menu: New canvas ⌘N · New project… ⇧⌘N · Open project… ⌘O · New Home tab ⌘T; a Window menu),
**C6** (each project tab is bound to one account), canvas 11's open-once, resting tabs past 5 and relaunch-restores-all
(`pn-windows`, `pn-tab-a20`, `pn-relaunch`), DDR-054 (the canvas origin is untrusted), DDR-109 (loopback-only navigate,
per-window CSP, IPC key).

## 3. Options

| # | Option | Cost | What it breaks |
| --- | --- | --- | --- |
| **1** (plan default, chosen) | **Project-less Home server mode** (`maude-server --home`, one loopback instance) serving the same bundle in Home mode; the index is files each project server writes about itself; the native shell owns windows, the project registry and live state, and brokers every cross-project read | one new server entry + route table; window model in Rust | nothing — every origin keeps talking only to itself |
| 2 | Home on the app's own origin (`tauri://localhost/index.html`) | no extra process | local app content gets every command by default; the bundle is origin-relative (`/_config`, `/_api`), so Home would need CORS fetches into loopback servers — the cross-origin channel this note exists to avoid |
| 3 | Home at `/_home` on one project sidecar ("the boot sidecar") | no new process | Home shares a project's origin and storage; a project-scoped server serves every project's data (dissolves DDR-185's per-project boundary); Home dies when that tab rests or closes |
| 4 | Rust serves Home over a custom URI scheme with Home APIs in Rust | no Bun process | a second server implementation in Rust; no reuse of the TS indexer, matcher or cloud client |
| 5 | Home page fetches each project sidecar directly (CORS allowlist per port) | no index files | N cross-origin channels; any project origin can be reached from Home and back; CSRF/DNS-rebind surface multiplied by tab count |

## 4. Decision (DDR draft)

**Title:** Home is a project-less studio server mode behind the native shell; projects describe themselves in files;
only Home and the shell read across projects.

**Context.** A1 makes every project its own native window tab on its own loopback origin. Home (01, 02, 11) needs
what no single project server holds: recents and pins across projects, open tabs with their AI state, projects by
account, "Shared with you", projects "not on this Mac yet", and pictures of canvases in closed projects. Today the
shell has one window and one "displayed project" string, first launch borrows a scratch project, and the shell's
probes trust a URL read from a file inside the (untrusted) project.

**Decision.**

1. **One Home server.** `maude-server --home --state-dir <dir>` — the same compiled binary (DDR-009, DDR-177; no new
   sidecar), loopback only, one per app run. Rust spawns it at launch, before any project, supervises it like a
   sidecar (respawn ≤ 3, same give-up dialog), never counts it in the project pool and never reaps it. It serves the
   client bundle with `/_config.mode = 'home'` and its **own** route table (`apps/studio/home/routes.ts`, §5.3), not
   the project `http.ts` table. It has no `.design/`, no canvas origin, no ACP, no sync, no file watcher on any
   project. Project mode keeps failing loud without `.design/`; only the explicit `--home` flag reaches Home mode.
2. **Windows.** At most one Home window (label `home`) and one window per open project (label `p-<pid>`, §5.2); no
   `"main"`. Every window gets `tabbing_identifier("maude")`, and on macOS ≥ 14 `data_store_identifier` derived from
   its label. A new window is attached as a tab of the calling window (`addTabbedWindow:ordered:`), whatever the
   user's "Prefer tabs" setting.
3. **Open once.** Opening an open project — from Home, ⌘K, a link, ⌘O — focuses its window and its tab. Picking a
   project on Home replaces the Home tab (the project tab is placed right after Home, then Home closes — 11 flow 4,
   "one Home at a time"). ⌘T and Menu › Back to Home focus Home or open it as a new tab.
4. **Running cap 5.** At most five project servers run. Opening a sixth rests the least-recently-focused idle
   project: its server stops, its tab stays (splash in the resting state), and focusing the tab wakes it. A project is
   never rested while AI is running or waiting for the person, while it holds unsent changes, or while an export or
   generation job runs; if every candidate is busy the cap overflows (today's rule). Relaunch restores every tab
   resting; only the front tab runs.
5. **Where state lives** (§5.5):
   - **Rust `app-state.json` v2** — the project registry (pid → root, name, account profile, last opened), the
     recent-projects order and the tab session. Nothing else.
   - **Per project, per person, inside the project** (travels with the folder, the same in every shell, already an
     IGNORED/`never` runtime class): `_canvas-state/_pins.json` (pins) and `_canvas-state/_recent.json` (when each
     canvas was last opened).
   - **Machine index** `~/.maude/index/v1/projects/<pid>/` (snapshot, thumbnails, picture descriptions — V2-1.17).
     Outside the project, so no DDR-115 list changes and no Syncthing churn.
   - **Live only, never on disk:** which windows are open and focused, resting state, AI state per project.
6. **No HTTP between origins.** The Home page talks to the Home server (same origin) and to Rust (IPC). A project
   page talks to its own server and to Rust. Rust probes project servers (authenticated, decision 8) and asks the Home
   server on a project window's behalf (internal bearer). The Home server never calls a project server; a project
   server never calls the Home server; a canvas iframe reaches none of it.
7. **IPC authority by window role, checked twice.** Home commands are granted by a capability Rust adds at runtime
   once the Home server has bound (`CapabilityBuilder::new("home").window("home").remote(<exact Home origin>)`), and
   each Home command re-checks in Rust that the caller's label is `home` and its current URL origin is the Home
   origin. Project commands check the label is `p-<pid>` and the URL origin is that project's current server. A
   project window can read across projects only through `index_search` (§5.4), scoped to projects bound to the **same
   account profile**, with names, places, kinds and small pictures — never sources, comments, chats, history or trash.
8. **Authenticated shell ↔ server probes.** Rust passes each spawn `MAUDE_SHELL_INFO_FILE` (an app-owned path,
   outside the project) and a per-spawn `MAUDE_SHELL_TOKEN`. The server writes its port there as well as to
   `_server.json`; Rust's probes read only the app-owned file and call `GET /_api/shell/status` with the token. A
   planted `_server.json` or a fake responder is no longer believed (closes `notify.rs`'s follow-up and
   `has_running_chat`'s identical pattern).
9. **Cloud lists are Home-only.** "Shared with you" and "not on this Mac yet" come from a new control-plane route
   `GET /api/home` per account profile, called by the Home server with that profile's device token (§5.7).
10. **Can view opens a cell tab with no IPC** (V2-1.7: observers never get a local copy). A third window role
    `c-<hash>` may navigate to an `https` cell URL inside the configured cloud zone (the zone rule `open_cloud_url`
    already enforces) and is in **no** capability. This amends DDR-109's loopback-only navigate for that role only.
    Until security signs that amendment, the conservative path holds: the row opens in the system browser through
    `open_cloud_url`.

**Consequences.**

- The welcome-project hack goes: first launch is the Home window (02 `ob-first-launch`), served by the Home server.
- Every `"main"` site in `lib.rs` / `sidecar.rs` becomes "the window for this pid"; `SidecarState.project_root`
  becomes `windows` + `focused` (§5.2). `export_download_url`, `save_export`, `pick_*` and `resolve_dev_server_url`
  answer for the **calling** window.
- Closing a project window no longer quits: its server stops after a 10 s grace (a confirm first if AI is running,
  A5 wording). Closing the last window leaves the app running (macOS convention); the Dock icon reopens Home.
- One more Bun process for the app's lifetime (the Home server). Its RSS is measured in V2-3.3; budget ≤ 120 MB.
- `data_store_identifier` isolates projects from each other on macOS ≥ 14 (no more inheriting another project's
  localStorage when ports swap); it does **not** make localStorage survive a port change. The registry therefore
  remembers a **preferred port per project** (§5.5) and Rust spawns with `--port <p>` (falls back to the ladder when
  taken). Anything that must survive still lives on disk (D20, V2-2.7).
- The Home window holds no project's data in its storage; it can be closed and recreated at no cost.

**Rejected alternatives.** Options 2–5 (§3). Also rejected:

- **Several Home windows** — canvas 11: "one Home at a time"; open-once by label covers Home too.
- **Keeping a `"main"` label** — a label must mean a role, or the per-role IPC checks of decision 7 cannot hold.
- **Pins in Rust `app-state.json`** — invisible to the browser and cloud shells, and lost when the folder moves.
- **The index under `~/.config/maude/`** — it is a rebuildable cache, and config dirs get synced with dotfiles.
- **The index inside the project (`_cache/`)** — Syncthing/folder copies would duplicate and churn it, and Home would
  have to read every project tree to list it.
- **Cross-project ⌘K computed by each project server reading other projects' snapshots** — any code path in a
  project (including an agent's `curl-local`, V2-1.11 S4) would then reach other projects; Rust brokering keeps the
  scope decision out of every project process.

### 5.2 Window model (Rust: `apps/desktop/src-tauri/src/windows.rs`, new)

**Identity.**

- `pid = "l" + hex(sha256(realpath(root)))[0..16]` for a project on this Mac (a managed cloud copy too — its root is
  under app data). `pid = "c" + hex(sha256(serverUrl + "\0" + projectId))[0..16]` for a cloud row not on this Mac.
  The same derivation lives in TS (`apps/studio/home/pid.ts`) and is pinned by a parity test.
- Labels: `home` · `p-<pid>` (regex `^p-l[0-9a-f]{16}$`) · `c-<16 hex>` (cell tab). Labels never change.
- `data_store_identifier = sha256("maude-window:" + label)[0..16]` on macOS ≥ 14 (probed via
  `NSProcessInfo.operatingSystemVersion`); skipped and logged below 14.
- Title: the project's `projectLabel ?? name`, passed through `notify::sanitize_notify_field` (control characters
  stripped, ≤ 200 chars) — AppKit draws it, and the value comes from the untrusted project.

**State** (`SidecarState` grows):

```rust
pub struct WindowEntry { pub role: Role, pub last_focused: u64 }
pub enum Role { Home, Project { pid: String, root: String }, Cell { url: String } }
pub struct SidecarState {
    pub instances: Mutex<HashMap<String /* root */, SidecarInstance>>,   // as today, + shell_token, info_file
    pub windows:   Mutex<HashMap<String /* label */, WindowEntry>>,
    pub focused:   Mutex<Option<String /* label */>>,
    pub home:      Mutex<Option<HomeInstance>>,                          // the Home server, outside the pool
    pub shutting_down: AtomicBool,
    pub tick: AtomicU64,
}
// "the displayed project" = the project of `focused`; `project_root` is removed.
```

**Algorithms.**

| Operation | Behaviour |
| --- | --- |
| `open_project(target)` | Resolve root (pid → registry, or a picked folder). Refuse a folder without `.design/` (today's check and copy). If a `p-<pid>` window exists: unminimize, focus, select its tab, emit `shell://opened-existing` to it (toast "Alligators brand is open in this window."), forward `target.canvas/artboard` as `shell://navigate`. Else: spawn-or-attach its server (`spawn_for`), create the window on `index.html` (splash), attach it as a tab after the caller, navigate when the server is up (DDR-109 guard unchanged), then apply the cap (row "rest"). From Home: close the Home window once the new tab is key. |
| `new_home_tab()` (⌘T, Back to Home) | Focus `home` if it exists, else create it as a tab of the focused window and navigate to the Home origin. |
| Window `Focused(true)` | `focused = label`; stamp `last_focused`; if the window is resting, wake it (spawn, navigate when up). |
| Window close (⌘W, ×) | Home: close. Project: if `/_api/shell/status` says AI is running or waiting → native confirm, title "Stop AI in Alligators brand?", primary **Stop and close**, **Cancel** (A5 voice). Else close, keep the server 10 s (reopen is instant), then `shutdown_instance`. Last window closed: app keeps running; `RunEvent::Reopen` opens Home. |
| Rest (cap) | After any spawn, while running servers > 5: candidates = project windows not focused, sorted by `last_focused`; skip any whose status is busy (`ai.running + ai.awaiting > 0`, `unsent`, `jobs > 0`); rest the first: `shutdown_instance`, navigate the window to `index.html` (resting state), keep the title. None idle → overflow. |
| Relaunch | Read `session.tabs`; create every window in saved order as tabs of the first; only `session.focused` spawns; the others start resting. Toast to the front window via `shell://tabs-restored {count}`: "20 tabs reopened. Each one starts when you open it." |
| Respawn after a crash | Re-navigate the window **for that root** (was `"main"` + `still_shown`); a closed window means no navigate. |
| Deep link | `deep_link.rs` parks per target: a `maude://` link naming a project resolves through `resolve_project_for_link` → `open_project`; the payload is delivered to that window only (`emit_to`). |
| Notifications | `notify.rs` polls every running instance whose window is **not focused** (was "≠ project_root"); a click focuses that window. |

**Splash states** (`apps/desktop/src/index.html`): `resolve_dev_server_url` now answers for the calling window —
Home → the Home origin; a running project → its URL; a resting project → `{ resting: true, name }`, and the page shows
the project name and "Opens when you come back to it." until focus wakes it. Still no input from the page
(DDR-109 §1).

### 5.3 Home server mode

**Boot.** `server.ts` branches before `createContext()`: `--home` imports `apps/studio/home/main.ts`. Inputs (env, all
set by Rust): `MAUDE_HOME_STATE_DIR` (Home-only state), `MAUDE_INDEX_DIR` (default `~/.maude/index`),
`MAUDE_HOME_TOKEN` (32 random bytes, hex; the internal bearer), `MAUDE_SHELL_INFO_FILE`, `MAUDE_CLOUD_URL`,
`XDG_CONFIG_HOME` passthrough. It binds `127.0.0.1` on the remembered Home port (§5.5) or the next free one, writes
`{pid, port, url, started, mode:'home'}` to `MAUDE_SHELL_INFO_FILE` only (there is no `.design/`), and serves.

**Guards.** Every non-static route: `isLoopbackHost(Host)` (DNS rebinding), `sameOriginRead` / `sameOriginWrite`
(Fetch Metadata + Origin), and the request header `x-maude-home: 1` — a custom header forces a CORS preflight from
any other origin, and the Home server answers no CORS headers and `405` to every `OPTIONS`. So a project page (same
site, other port), a canvas iframe or a web page can neither read nor write Home routes. JSON bodies ≤ 64 KB.
`Cache-Control: no-store` except pictures.

| Route | Method | Answer |
| --- | --- | --- |
| `/`, `/dist/*`, `/_client/*` | GET | the client bundle (same `serveIndexHtml` + static lane as a project; no guard) |
| `/_health` | GET | `{ ok: true, mode: 'home', version }` |
| `/_config` | GET | `{ mode: 'home', shell: 'home', version, cloudOrigin, formatSupported }` — no project fields |
| `/_home/index?pids=…` | GET | `HomeIndex` for the given pids (V2-1.17 §5.2/§5.6): per project summary + canvas rows + `stale` flags |
| `/_home/thumb/<pid>/<key>.jpg` | GET | the picture if `<key>` is referenced by that pid's snapshot, else `404` (same body as missing); `image/jpeg`, `nosniff`, `private, max-age=31536000, immutable` |
| `/_home/search?q=…&pids=…` | GET | the V2-1.17 matcher over those projects (Home's ⌘K) |
| `/_home/recent-searches` | GET / POST | Home's recent searches (`home.json`, ≤ 20, this Mac) |
| `/_home/pins` | POST `{pid, canvas, pinned}` | writes `<root>/.design/_canvas-state/_pins.json` (§5.5) — only when `pid === pidOf(realpath(root))`, where `root` is the snapshot's `project.root` and `.design/` exists |
| `/_home/projects/create-local` | POST `{name}` | creates `~/Maude/<name>` (C4 naming; " 2", " 3" on collision) with the `scaffold-design.ts` scaffold; `{root, pid}`. The page then calls `open_project` |
| `/_home/cloud?profile=<id>` | GET | §5.7 — that profile's cloud listing (cached 60 s; offline → last good + `offline: true`) |
| `/_home/cloud/prepare` | POST `{profile, server, projectId}` | the same code as the project route `/_api/projects/prepare`, for a project not on this Mac; the page then calls `managed_project_open` |
| `/_home/internal/search` · `/_home/internal/thumbs` | GET | Rust only: `Authorization: Bearer $MAUDE_HOME_TOKEN` (constant-time), and refused when the request carries `Origin` or `Sec-Fetch-Site` (a browser never gets in, even with the token) |

**What the Home server may read:** `MAUDE_INDEX_DIR/**`; each registered project's `.design/_canvas-state/_pins.json`
and `_recent.json`; for a **closed, stale** project only, its canvas sources, `.meta.json` and top-level `assets/`
listing — read-only, through the V2-1.17 indexer, to rebuild its snapshot; per-profile `cloud.json` (token) for §5.7.
**May write:** `MAUDE_INDEX_DIR/**` (rebuild, GC), `MAUDE_HOME_STATE_DIR/home.json`, `_pins.json` as above, and a new
project folder via `create-local`. **Never** reads `_chat/`, `_comments/`, `_history/`, `_trash/`, `_state/`, hub
credentials, or any project's live server.

### 5.4 Tauri commands and events

Every command resolves the caller from the `tauri::Webview` it is invoked on — label **and** current URL origin —
never from an argument.

| Command | Caller | Args → returns | Check |

```ts
  projects: Array<{
    pid: string; root: string; name: string; profile: string;
    place: 'tab' | 'resting' | 'closed'; label?: string; focused: boolean;
    ai?: { running: number; awaiting: number };   // live, from the authenticated probe

  recent: string[];                                                 // pids, MRU, ≤ 50

```

Events (`emit_to(label, …)`, never app-wide): `shell://state` (Home; debounced 250 ms on tab, rest, focus, profile or
AI change) · `shell://opened-existing {name}` · `shell://navigate {canvas, artboard}` · `shell://intent` (nudge;
the page calls `take_pending_intent`) · `shell://tabs-restored {count}` · `index://changed {pids}` (Home, and project
windows of the same profile).

**The create-from-Home intent** (01 `cf-home-prompt`): Home sends `open_project({pid}, intent:{kind:'create-canvas',
prompt})`; Rust parks the intent for the target window (prompt text never in a URL); the project client takes it,
creates the canvas (C4 naming from the prompt) and starts the AI run (S5). A new project from Home is
`create-local` first, then the same call.

**Capabilities.** `capabilities/project.json`: `windows: ["p-*"]`, `remote: http://localhost:*` + `127.0.0.1:*`,
today's permissions + `allow-index-search`, `allow-take-pending-intent`, `allow-new-home-tab`,
`allow-open-project`, `allow-open-project-folder`, `allow-relink-project`. Runtime capability `home` (added when the
Home server binds): `window("home")`, `remote("http://localhost:<H>/*")` and the 127.0.0.1 twin, permissions
`allow-shell-state`, `allow-open-project`, `allow-open-project-folder`, `allow-new-home-tab`, `allow-relink-project`,
`allow-managed-project-open`, `allow-managed-projects-list`, `allow-open-cloud-url`, `allow-resolve-dev-server-url`,
`allow-send-notification`. The splash (app-local origin) keeps `allow-resolve-dev-server-url` in both. The e2e
capability's `windows` becomes `["home", "p-*"]`. `c-*` windows are in no capability.

**Native menu** (V2-1.3 §5.8 generates it): File › New canvas ⌘N (`menu://action {id:'canvas.new'}` to the focused
window; on Home it means "Start with an empty canvas" in the target project) · New project… ⇧⌘N · Open project… ⌘O
(`open_project_folder`) · New Home tab ⌘T (`new_home_tab`); a Window menu with the predefined macOS tab items (Show

### 5.5 Where state lives — files and schemas

**Rust `<app_config_dir>/app-state.json` v2** (atomic tmp + rename, 0600):

```json
{
  "v": 2,
  "projects": {
    "l3f2a…": { "root": "/Users/x/Maude/alligators", "name": "Brno Alligators", "profile": "default",
                "port": 4402, "addedAt": 1760000000000, "lastOpenedAt": 1760001000000, "managed": null }
  },
  "recent": ["l3f2a…", "l9be0…"],
  "session": { "tabs": [ { "label": "home" }, { "label": "p-l3f2a…", "pid": "l3f2a…" } ],
               "focused": "p-l3f2a…", "savedAt": 1760001000000 },

  "last_project": "/Users/x/Maude/alligators",
  "recent_projects": ["/Users/x/Maude/alligators"]
```

- `recent` ≤ 50 (was 10); `projects` entries whose root vanished are kept and shown as "isn't where it was"
  (`pn-cant-open`) until the person picks Find the folder… or the entry ages out (90 days unopened).
- `last_project` / `recent_projects` keep being written for one release, so a downgrade to 1.x still reopens the last
  project. Read order: v2 keys, else migrate v1 (each `recent_projects` path → a registry entry; `last_project` → a
  one-tab session).
- `port`: the preferred loopback port remembered per project (first free port from the ladder on first spawn); Rust
  passes `--port <p>` and falls back to the ladder when it is taken (C34: the port stays display-only in Settings).
- `profile`: the account binding (C6, V2-3.1 owns `profiles.json`); `default` for every migrated entry.

**Per project, per person** (the `_canvas-state/` runtime class — already in all four DDR-115 lists: `git/service.ts`
`isMaudeRuntimeState`, `cli/lib/gitignore-block.mjs`, `.gitignore`, `sync/file-membership.ts` `isRuntimeStateRel` +
hub mirror; **no list changes**):

```json
// <designRoot>/_canvas-state/_pins.json

// <designRoot>/_canvas-state/_recent.json  — capped at 200 entries, oldest dropped
{ "v": 1, "opened": { "ui/2026/dresy/Uniformy-2027.tsx": 1760001000000 } }
```

Writers: the project server (main-origin routes `POST /_api/pins`, and `_recent.json` on every canvas open — the
same moment `_active.json` changes) and the Home server (`/_home/pins` for a project whose server is not running).
Both use one module (`apps/studio/home/user-state.ts`): read-modify-write, atomic rename, no in-memory cache, so two
writers lose at most one toggle in a race. A move rewrites keys: `moveCanvas` / `moveFolder` (`api.ts`) already
relocate a canvas's slug-keyed `_canvas-state/` files through `canvas-artifacts.ts`; they gain a key rewrite inside
these two files. Trash: a pinned canvas moved to the trash drops its pin.

**Machine index** — V2-1.17 §5.5. **Home-only** — `<MAUDE_HOME_STATE_DIR>/home.json`
`{ "v": 1, "recentSearches": [{ "q": "letak a6 predni", "at": …, "results": 5 }] }`.

### 5.6 How Home builds its page

1. `invoke('shell_state')` → registry, places, profiles, live AI.
2. `GET /_home/index?pids=<every registered local pid>` → summaries and canvas rows (pins and `openedAt` merged in by
   the Home server from each `_canvas-state/` file).
3. `GET /_home/cloud?profile=<id>` for each profile with a cloud account → `projects[]` and `shared[]`.
4. Merge on the page: **Pinned** = pinned rows; **Recent canvases** = rows by `openedAt` (filter by project); **Shared
   with you** = `shared[]`; **Projects** grouped by profile: local registry entries (`in a tab` · `this Mac only`) ∪
   cloud projects without a local copy (`not on this Mac yet`, matched by hub URL / managed key, with **Open**).
5. Live updates: `shell://state` and `index://changed` re-run steps 1–2 for the changed pids only.

A format-gated project (V2-1.12 P3) opens view-only from every Home entry point; Home shows its row normally.

### 5.7 Cloud data source — `GET /api/home` (control plane, S9 builds it)

Auth: `Authorization: Bearer mpt_…` (the profile's device token, as `GET /api/projects`). Answer:

```json
{
  "account": { "email": "you@work-studio.cz" },
  "projects": [ { "id": "alligators", "name": "Alligators brand", "role": "owner", "ownerName": null,
                  "state": "active", "url": "https://alligators.cloud.maude.sh", "updatedAt": 1760000000000 } ],
  "shared": [ { "projectId": "nabor-2027", "projectName": "Nábor 2027", "ownerName": "Tereza",
                "canvas": { "path": "ui/web/Mapa-arealu.tsx", "name": "Mapa-areálu" } | null,
                "role": "observer" | "viewer" | "member", "grantedAt": 1760000000000, "grantedBy": "Tereza" } ]
}
```

- `shared[]` = project memberships where the account is not the owner ∪ canvas grants (`canvas_grants`, V2-1.7),
  **only rows whose grantee is the caller**, link-sourced grants dropped when the link is off or expired; effective
  role = max(project role, canvas role) (V2-1.16 L14). UI words: observer → Can view, viewer → Can comment, member →
  Can edit (CONTRACT §6). "3 new this week" counts rows with `grantedAt` in the last 7 days not yet opened on this Mac.
- Self-hosted hubs have no control plane: no `shared[]` and no "not on this Mac yet" for them in v2.0.
- A control plane without the route (`404`) falls back to `GET /api/projects` (projects only, no `shared`).
- Pictures: a cloud row not on this Mac shows the project square, not a canvas picture (cells render no thumbnails in
  v2.0 — V2-1.17 §5.8).
- **Open** on a row: Can edit / Can comment → `/_home/cloud/prepare` → `managed_project_open` → `open_project`.
  Can view → decision 10 (a `c-*` cell tab once signed; the system browser until then).

### 5.8 Security invariants (each is a test, §7)

1. No route on the Home server answers a request without `x-maude-home: 1`, with a foreign `Host`, or with
   `Sec-Fetch-Site` other than `same-origin`/`none`; `OPTIONS` is `405` with no CORS headers.
2. Internal routes refuse any request carrying `Origin` or `Sec-Fetch-Site`, and any bearer other than
   `MAUDE_HOME_TOKEN`.
3. `shell_state`, `managed_project_open` and the Home-only arguments of `open_project` refuse every caller whose label
   is not `home` or whose URL origin is not the Home origin (including a `p-*` window that navigated to the Home
   URL).
4. `index_search` never returns a row from a project bound to another profile, never the caller's own project, and
   never a field outside V2-1.17's cross-project projection.
5. A picture key is served only through a snapshot of a pid the caller may read; a missing and a forbidden key give the
   same `404` (V2-1.16 L14 — no existence oracle).
6. Rust probes use only the app-owned info file and the per-spawn token; a `_server.json` pointing elsewhere changes
   nothing.
7. No window other than `c-*` navigates outside loopback; `c-*` only to `https` in the cloud zone; `c-*` has no IPC.
8. No prompt, path or token appears in a URL query (intents are parked in Rust).
9. A canvas iframe can invoke nothing (DDR-109 leg b, re-asserted for `p-*` windows).

## 6. Evidence

- **Code read** (paths and symbols in §2): one `"main"` window and four `get_webview_window("main")` sites;
  `SidecarState.project_root` as the single "displayed" project; `kill_server` on any window close; probes reading
  `_server.json`; `capabilities/default.json` granting everything to any loopback origin in `main`.
- **Tauri 2.12.1 API surface** confirmed in the crate source: `tabbing_identifier`, `data_store_identifier` (macOS ≥ 14),
  `Manager::add_capability` behind the default `dynamic-acl` feature, `CapabilityBuilder::{window, remote}`. tao has no
  `tabbingMode` → explicit `addTabbedWindow:ordered:`.
- **Fetch Metadata is enough to fence a sibling port**: a project page on `localhost:A` fetching `localhost:H` is
  `Sec-Fetch-Site: same-site`, which `sameOriginRead` refuses; the custom header forces a preflight the Home server
  never answers.
- **The probe-target problem is real**: `notify.rs` and `sidecar.rs` both re-read `_server.json` from the project
  root each tick (their own comments call it untrusted).
- **Index and picture costs** that make "files written by each project, read by Home" viable (V2-1.17 §6): snapshot
  read+parse 1.4 ms, staleness stamp 3.1 ms, ≈ 92 KB per Alligators-scale project; 94 cached covers ≈ 3.1 MB.
- **L21** (V2-1.16, found while designing the renderer): an export capture renders untrusted canvas code on the main
  origin. Probe on the unlinked Alligators copy: the same scratch canvas calling `fetch('/_api/ui-prefs')` gets
  `200 {"theme":"light",…}` under the main-origin capture and `403 Forbidden (canvas origin)` on the canvas origin.
  Reported to the lead; nothing here reaches a project's main origin from rendered content.
