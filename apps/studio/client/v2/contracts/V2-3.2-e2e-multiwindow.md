# V2-3.2 spike: desktop e2e with several windows (tabs)

**Decision.** The multi-window scenarios use plain W3C window commands. The embedded provider
(`tauri-plugin-wdio-webdriver` 1.2.0) uses Tauri window **labels** as handles, so `switchToWindow('p-<pid>')` is the
whole switching API. `window_labels` stays as a debug cross-check, not as a fallback. Never use `browser.tauri.execute` or
`browser.tauri.switchWindow`'s validation: both need the `tauri-plugin-wdio` bridge (`window.__wdio_original_core__`),
which this app does not ship. Evidence: 3 runs, last one 10/10 green (`spike/v2-3.2-multiwindow.e2e.ts`); spike code
in `src-tauri/src/e2e_spike.rs` (branch `v2-3.2-e2e-spike`). macOS 26.5.1; screen unlocked; app window on screen.

## Ceiling: a background tab is frozen
A non-selected tab is `document.hidden === true` and gets **0 rAF/s**. The selected tab gets 73–74/s. DOM queries,
`execute` and `invoke` still work in a hidden tab. Anything gated on animation frames, motion or layout settling does
not run there: canvas render, `waitForDisplayed` after a transition, screenshots. **Bring the tab to the front first**:
`e2e_focus_window(label)` (`set_focus` selects the tab) made it visible in **79 ms** at 73 rAF/s. Driving a tab without
selecting it is a false red, the same failure class as a locked screen.

## Product findings the V2-3.2 builder must fix (not harness)
1. `lib.rs` `on_window_event` → `CloseRequested` → `sidecar::kill_server` **drains the whole pool**. Closing any tab
   (⌘W, X) kills every server: `/_health 200` before, `Load failed` after closing p2. Make the action per label: stop
   that project's instance (after the grace period) and quit only on the last window.
2. Capabilities: `default.json` and `e2e-webdriver.json` must list `["home", "p-*"]` (and `c-*` once cell tabs exist).
   The V2-1.1 home gate goes in Rust, not in the capability (one capability cannot tell Home from a project).
3. `lib.rs:422/604` and `sidecar.rs:664/843` `get_webview_window("main")` must resolve the window by label
   (`windows.rs`).

## Harness edits (every `"main"` the e2e harness assumes)
- `e2e/wdio.conf.ts:158` `browser.tauri.switchWindow('main')` → `'home'`. Keep the call: its side effect, setting
  `userSwitchedWindowCache`, is what the comment wants. Also set `windowLabel: 'home'` in two places: as the service
  option, and as the capability key `'wdio:tauriServiceOptions'`, which the Rust session-create reads
  (`session.rs:45`). Both default to `'main'`, and direct eval falls back to `"main"` (`direct_eval.rs:40`). Without
  them, a run with no `main` window fails with `Window 'main' not found. Available: [p-…]`.
- `scenarios/share-link.e2e.ts:33`, `s20-deployment.e2e.ts:191,323`, `team-project.e2e.ts:102`,
  `multiplayer/{cloud-entry:39,selfhost-entry:43,surface:791}` `switchWindow('main')` → `'home'`, or the project label
  from `projectWindow()`.
- `capabilities/e2e-webdriver.json` `windows: ["main"]` → `["home","p-*","c-*"]`. `tauri.e2e.conf.json` has no label.
  It inherits `app.windows[0]` (no label = `main`) from `tauri.conf.json`, so when V2-1.1 moves window creation into Rust
  (`app.windows: []`) nothing changes there.
- `helpers/native.ts` `invokeTauri` is already per-window (W3C execute). No change.

## Pattern (new `helpers/windows.ts`)
```ts
export async function labels(): Promise<string[]> { return (await browser.getWindowHandles()).sort(); }
export async function waitWindow(label: string, present = true, timeout = 10_000) {
  await browser.waitUntil(async () => (await browser.getWindowHandles()).includes(label) === present,
    { timeout, interval: 50, timeoutMsg: `window ${label} present=${present}` }); }
export async function focusTab(label: string) {        // select the tab AND drive it
  await browser.switchToWindow(label);
  await invokeTauri('e2e_focus_window', { label });     // debug-only command (lift from e2e_spike.rs)
  await browser.waitUntil(() => browser.execute(() => !document.hidden), { timeout: 5_000, interval: 50 }); }
export async function closeTab(label: string, next: string) {
  await browser.switchToWindow(label); await browser.closeWindow(); // destroy: no CloseRequested
  await waitWindow(label, false); await focusTab(next); }
```
Timings: allow 10 s for open → handle and 30 s for handle → `canvas-list` (cold sidecar), poll every 50 ms. No retries
are needed: no flake in 3 runs. To exercise the **user** close path (CloseRequested and the grace period), call
`invokeTauri('e2e_close_window', {label, destroy:false})`, not `closeWindow()`. Wrap any function passed to
`browser.execute` that declares named inner functions in a string, because of the TS loader's
`__name is not defined` error.

## Build + run used
`CARGO_TARGET_DIR=<main>/apps/desktop/src-tauri/target CARGO_NET_OFFLINE=true <main>/apps/desktop/node_modules/.bin/tauri
build --debug --no-bundle --config src-tauri/tauri.e2e.conf.json --config '{"build":{"beforeBuildCommand":null},
"bundle":{"resources":null,"externalBin":null}}'`. The cold build took **3 min 24 s** of cargo (211 s wall); the
incremental one took 26 s. The worktree has no node_modules or staged binaries, so I swapped `target/debug/maude-desktop`
into a scratch copy of the existing e2e `Maude.app` (sidecar 1.9.0). Run: `MAUDE_E2E_APP=<copy>/Contents/MacOS/maude-desktop
TAURI_WEBDRIVER_PORT=4471 NO_OPEN=1 MAUDE_NO_AUTOBUILD=1 wdio run ./spike/v2-3.2.conf.ts` (24 s). The real lane uses
`pnpm test:e2e:desktop:build`. In runs 1 and 2, a `SecurityAgent` prompt was frontmost for about 4 s during boot
(cause unknown; the app stayed drivable).
