## 2. What exists today

**AI surface.**
- Claude drives Maude through skills plus direct `Edit`/`Write` of `.design/` files, plus `maude design
  <verb>` (DDR-062: plugins reach executable logic only via `maude`).
- The in-app chat is an Agent SDK session through the ACP adapter (`apps/studio/acp/bridge.ts`):
  - `newSessionParams` sends `settingSources: ['user']` (DDR-144), `mcpServers: []`, and
    `allowedTools = MAUDE_DEFAULT_ALLOWED_TOOLS = ['Read','Glob','Grep','Bash(maude:*)','WebSearch','WebFetch']`.
  - It injects the bundled `design` + `kgai` plugins (DDR-168, `plugin-bootstrap.ts`); their
    `hooks.json` hooks do load in chat sessions.
- No `disallowedTools`. `bypassPermissions` and `dontAsk` skip the bridge's `requestPermission`.

**Write gate.**
- `acp/write-scope.ts` auto-approves (`allow_once`) `Write|Edit|MultiEdit|NotebookEdit` whose resolved
  targets are inside the pinned **repo root**.
- `PROTECTED_IN_PROJECT` paths (`.git`, `.claude`, `CLAUDE.md`, `.mcp.json`, `package.json`, lockfiles,
  `.github/workflows`…) still prompt.
- Bash writes are not path-checked.

**`Bash(maude:*)` is wider than it looks.**
- It covers every top-level `maude` command: `hub`, `config set`, `init`, `harness`, `codex`, `kg`.
- It covers the human lifecycle verbs `design link/adopt/unlink/detach/bulk-deletes`.
- It covers `curl-local` (`apps/studio/bin/_curl-local.mjs`), which takes any method, `--data` and
  `--output` against any loopback port. The studio accepts no-`Origin` loopback requests, so this one
  auto-approved verb reaches **every** studio route: git push/discard, trash prune, paid generation,
  sync settings.
- The bridge's own comments name the residuals: redirection (`maude design slug foo > ~/.zshenv`),
  `exec bun run` in `draw-build`, and unscoped `--out` on eight helpers.
- The prior decision `acp-readonly-bash-verbs-cut-redirection-is-arbitrary-write` cut
  `Bash(ls|cat|…:*)` for exactly the redirection reason and left `Bash(maude:*)` open as MEDIUM.

**Hooks.** `plugins/design/hooks/hooks.json` and `plugins/flow/hooks/hooks.json` have **only
`SessionStart`** (preflight, kg session-sync). No PreToolUse, PostToolUse, UserPromptSubmit or Stop.
DDR-185 ruled out SDK *callback* hooks for permission (live JS can't cross the ACP JSON-RPC boundary);
plugin *command* hooks are a different mechanism and do run.

**Attribution and grouping.**
- `acp/index.ts` › `createAgentActivityTracker` watches chat tool calls of kind edit/delete/move on
  canvases. It feeds `collab/ai-activity.ts` (banner, presence) and opens `beginAiAction('acp:<chat>')`.
- `sync/action-stage.ts` turns an AI action into one transaction and one history entry, **only in
  accepted-revision (linked) mode** (`beginAiAction` returns early otherwise). Solo projects get no
  grouping.
- Writes made through `maude` verbs (Bash, kind `execute`) are not tracked.
- `/design:edit` step 4.5 calls `/_api/ai/start` with raw `curl`, which prompts in the chat.

**Formats.**
- `.annotations.json` is `{"format":"maude.annotations","v":2,…}`, one element per line, deterministic
  order (`annotations/schema.ts`, `registry.ts`; DDR-242).
- Load-time validation is lenient: a bad element is dropped and reported.
- AI writes through `annotations/ai-write.ts` › `AiBatch` are strict: unknown fields are errors, the
  whole batch fails, `author:{kind:'ai'}` is stamped, and `expect` merges with concurrent human edits.
- `validateBoard` (strict, for file edits) does **not** exist yet.
- `apps/studio/canvas-meta.schema.json` exists but is documentation only.
- There is **no** JSON Schema for annotations, comments (`_comments/`), tokens, components,
  `.photo.json`, `.footage.json`/`.edl.json` or `_active.json` (prose only); TS validators exist for
  some.
- Annotation lock is a UX guard, not a permission (DDR-246).

**Missing operations.**
- No `maude design open`. `_active.json` is server-written from the client; the server broadcasts
  `{type:'active'}` but the client has no handler. The only agent→UI route is `/_api/acp/focus`.
- No `trash` verb: `/_api/sync/trash` list/restore/prune exist, and `DELETE /_api/canvas` soft-deletes
  to `_trash/` (decision `trash-scanner-restore-prune`).
- No `history` verb: `/_api/project/{history,restore,undo}` exist, linked mode only, and
  `history.rollback()` has no route.
- `/design:rollback` copies `_history/` snapshots with `ls`/`cp`.

**Loopback API.**
- The CLI finds the studio via `<designRoot>/_server.json`; its `url` is untrusted at every consumer
  (decision `_server.json`'s url is untrusted — validate loopback).
- Guards are `isTrustedRequestHost` (loopback Host), `sameOriginWrite` (no-Origin allowed) and
  `sameOriginRead`. There is no token.
- `DELETE /_api/acp/chat` has **no guard at all** (flagged to the lead, out of scope here).

**Claude Code facts this relies on** (docs, checked 2026-10-09 via the claude-code-guide agent):
- Plugin hooks run in `-p`/SDK sessions and inside subagents (`agent_id` in input).
- Plugin agents can't declare hooks; plugins can't ship permission rules.
- A PreToolUse hook `deny` beats the user's allow rules; a hook `allow` never bypasses a user deny/ask;
  a hook `ask` **forces a prompt even when the user allowed the tool**; a silent exit 0 leaves the normal
  flow unchanged.
- PostToolUse `decision:"block"` + `reason` shows the reason next to the tool result.
- Stop `decision:"block"` makes Claude continue (loop-guard via `stop_hook_active`).
- Command-hook timeouts fail open. Hooks of one event run in parallel.
- Hooks can take an `if` permission-rule filter (`"if": "Edit(.design/**)"`, best effort).
- `MultiEdit` is legacy (tools: `Edit`, `Write`, `NotebookEdit`).
- Bash prefix rules are aware of `&&`, `||`, `;`, `|`. Redirect targets are "checked against Edit
  rules" per the docs, which contradicts the 2.1.220 PoC → must be re-verified (§7).

## 4. Decision (DDR draft)

**Title:** Files are the API — registry AI paths, schema-checked formats, `maude` verbs for non-file
operations, plugin hooks as the transaction layer, per-verb permission tiers.

**Context.** A13: Claude drives every v2 capability by editing readable files or running a `maude`
verb; there is no MCP layer. Today half the v2 capabilities have no AI path (H §2.14). The other half
work only through raw file edits that bypass v2 invariants: trash, versions, locks, one AI per
artboard, attribution and element ids. The only blanket CLI rule, `Bash(maude:*)`, reaches the whole
studio API through `curl-local`.

**Decision.**
1. Every `ActionDef` declares `effect`, `minRole`, `undo`, an optional `server` route and `params`
   schema, and exactly one `agent` path:
   - `file` — a documented, versioned format plus the skill section that teaches it;
   - `cli` — a `maude` verb;
   - `human` — a reason from a closed list (A13 (c)).
   The registry generates `actions.manifest.json`, the docs, `/design:help`, `maude design help` and a
   `studio-actions` skill index from it.
2. Every file Claude may edit has a JSON Schema under `apps/studio/schema/` (generated from the TS
   validator where one exists) and a skill section. `maude design check` validates a file against it,
   strictly for AI writes.
3. A non-file operation gets a `maude design` verb whose tier is a property of the **verb name**; a flag
   never raises a verb's effect, so a riskier variant is a separate verb.
4. The design plugin's `hooks.json` runs one dispatcher, `maude design hook <event>`, on
   SessionStart, UserPromptSubmit, PreToolUse, PostToolUse and Stop/SubagentStop. The hooks:
   - bracket the run;
   - refuse writes that break an invariant (busy or soft-locked artboard, out of the run's scope,
     `rm`/`mv` of a canvas, non-`maude` writers into `.design/`, whole-file `Write` over a canvas);
   - validate every `.design/**` write and roll it back on failure;
   - attribute the change.

   Hooks emit only `deny` (for an invariant) or nothing — **never `ask`, never `allow`** — so the
   user's own permission rules and Claude Code's default flow stay untouched (P3). Studio-dependent
   decisions fail open when no studio is running. File validation does not need the studio.
5. Maude's default allow list in the chat (`MAUDE_DEFAULT_ALLOWED_TOOLS`) replaces `Bash(maude:*)` with
   generated per-verb rules for verbs whose effect is `none` or `project`. Every other verb shows the
   permission card. Human-only capabilities have no verb designed for the agent.

**Consequences.**
- Raw edits stay the main write path (J P1: "code mode" is the strongest position) and become safe
  through hooks.
- Some steps now prompt where they didn't: `curl-local`, `generate`, `draw-build`, `to-lottie`,
  `ensure-browser`, `import-figma`. The plugin commands that used `curl-local` move to purpose verbs.
- Terminal users get the same hooks via the marketplace plugin, but no Maude allow list (plugins can't
  ship one). The docs give a paste-in snippet.
- Partly supersedes DDR-185's "`curl-local` is free under `Bash(maude:*)`".

**Rejected.** Options 2–5 (§3); a PreToolUse hook that emits `ask` for writes (overrides the user's
allow rules — P3 rejected exactly this in `bridge.ts`); a per-launch capability token for loopback
routes (the agent can read any file the token would live in; H's token was for MCP).

## 5. Contract

### 5.1 Registry AI fields (extends V2-1.3 §5.2)

```ts
// apps/studio/actions/types.ts — additions
export type Effect =
  | 'none'         // reads, computes, navigates the user's window, writes only runtime `_*` state
  | 'project'      // writes versioned files of THIS project; undone by the run's undo step
  | 'destructive'  // removes/replaces content beyond the run's undo step (trash move, restore over now, explode)
  | 'shared'       // changes what other people see or receive outside the file plane (post a comment as you, resolve, resync, publish, link)
  | 'external';    // third-party network, paid providers, downloads, writes outside the project, runs model-authored code

export type FormatId =                       // each has a schema + a skill section (§5.2)
  | 'canvas-tsx' | 'canvas-meta' | 'annotations' | 'comments' | 'tokens' | 'components'
  | 'ds-config' | 'photo-edit' | 'footage' | 'edl' | 'design-config';
export type SkillRef = `${'design' | 'flow'}:${string}`;   // 'design:whiteboard#stickers'
export type HumanReason =                    // closed — a new value needs a lead-owned change + a decision id
  | 'invite' | 'roles' | 'links' | 'clear-trash' | 'accounts' | 'hub-link' | 'billing'
  | 'summon' | 'report-bug' | 'view-pref' | 'native-window' | 'onboarding';

export type AgentPath =
  | { path: 'file'; format: FormatId; skill: SkillRef; how: string }   // how: one line, imperative
  | { path: 'cli'; verb: string; skill?: SkillRef }                    // 'maude design trash move'
  | { path: 'human'; because: HumanReason; note?: string };

export interface ActionDefAI {
  minRole: Role;                             // THE role gate: isVisible requires rank(role) ≥ rank(minRole); the server route enforces it (rule 12)
  effect: Effect;
  undo: 'step' | 'version' | 'none';         // step = one undo step (an AI run is one step); version = a Version history entry
  params?: JSONSchema;                       // draft 2020-12 object schema: ⌘K argument UI, verb flags, route body
  server?: { route: string; method: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE' };   // the ONE implementation UI and verb share
  agent: AgentPath | { path: 'pending'; package: string };   // 'pending' allowed only per §5.7 ratchet
  askAI?: string;                            // prompt template for "Ask AI to …" rows and empty states (S5/S11)
}
// ActionDef (V2-1.3) & ActionDefAI. `visible.minRole` is not used on actions — the generator lints it.
```

Rules:
- Only actions with `kind !== 'place'` need `agent`.
- `exec:'shell'` UI-only actions with `effect:'none'` use `agent:{path:'cli', verb:'maude design open'}`
  when they navigate (open canvas, artboard, mode, a panel), else `human:'view-pref'` (theme, minimap,
  fold state).
- `fromCanvas: true` ⇒ `effect:'none'` (V2-1.3 invariant 3).

Two cross-cutting rules on verbs:
- **Output confinement (closes "unscoped `--out`").** Every verb's `--out`/`--out-dir`/`--output`

  Anything else exits 2 with "Pick a path inside the project".
- **Flags never escalate.** A test lists each auto verb's flags and fails on any flag that adds network,
  overwrite, delete, cloud lane or code execution.

| SessionStart | `""` | existing preflight **+** `maude design hook session-start` | 8 | 2 s |
| UserPromptSubmit | — | `maude design hook prompt` | 3 | 300 ms |
| PreToolUse | `Edit\|Write\|MultiEdit\|NotebookEdit` | `maude design hook pre-edit` | 3 | 300 ms |
| PreToolUse | `Bash` | `maude design hook pre-bash` | 3 | 300 ms |
| PostToolUse | `Edit\|Write\|MultiEdit\|NotebookEdit` | `maude design hook post-edit` | 5 | **1.5 s** |
| PostToolUse | `Bash` | `maude design hook post-bash` | 3 | 300 ms |
| Stop, SubagentStop | — | `maude design hook stop` | 60 | 10 s |

- **Invocation.** Each command uses the existing fallback chain: sibling `cli/bin/maude.mjs` when the
  plugin ships next to the CLI, else `command -v maude`, else `exit 0`.
- **The dispatcher.** It is an in-process node subcommand: zero deps, about 45 ms cold start
  (measured). It reads the hook JSON on stdin and resolves `designRoot` from the nearest
  `.design/config.json` above `cwd`. It exits 0 with no output for any path outside `designRoot`.
- **Studio reachability.** It finds the studio through `<designRoot>/_server.json`, validates the URL is
  loopback, and allows 300 ms to connect. On any studio failure — no file, refused connection,
  timeout, non-2xx — the studio-dependent part is skipped (**fail-open**).
- **Command-hook timeouts also fail open** (Claude Code semantics). A budget overrun therefore never
  blocks a write; it only loses the guard for that call.

**Decisions each event may emit.** Hooks never emit `ask` and never emit `allow`.

| Event | Does | May output |
| --- | --- | --- |

Side effect: claims the touched artboards for the run (V2-1.15 lease) | `permissionDecision:"deny"` + `permissionDecisionReason` (names the person or run and the next step), or nothing |
| pre-bash | best-effort parse of the command. Deny `rm`/`git rm`/`unlink` of a canvas or versioned `.design/**` file → `use-trash` ("Move it to the trash: `maude design trash move …`"). **Loopback routes.** Main origin only: never in `CANVAS_SAFE_API` or the canvas routes map (DDR-088),
with a `GET → 405` and canvas-origin `403` test. Loopback Host required. No-Origin (CLI) allowed.
Routed through the V2-2.5 route table.

```
POST /_api/agent/run/begin   {session, promptId?, actor:'maude-chat'|'claude-code', label?:string≤80}
                             → 200 {run:'r_…', state:'open'}                      (idempotent)
POST /_api/agent/edit/check  {session, toolUseId, tool:'Edit'|'Write'|'NotebookEdit', path,
                              edit?:{old:string,new:string,replaceAll?:boolean} | {content:string}}
                             → 200 {decision:'none'}
                             | 200 {decision:'deny', code:'artboard-busy'|'soft-locked'|'out-of-scope'|'read-only',
                                    reason:string, who?:string, artboards?:string[]}
POST /_api/agent/check       {path, tier:'fast'|'stop', strict:true, snapshot?:string}
                             → 200 {ok:true} | 200 {ok:false, errors:[{where,what,fix}]}
POST /_api/agent/edit/touched {session, toolUseId, path?, via:'tool'|'bash', since?:number}
                             → 200 {artboards:string[], lostIds:string[], trashed:string[]}
POST /_api/agent/run/end     {session, outcome:'done'|'stopped'|'failed'|'warnings'}
                             → 200 {undoStep?:string, version?:string}
```

- **Run identity.** The run is keyed by Claude Code's `session_id` (present in every hook input).
  The ACP bridge's `createAgentActivityTracker` stops opening its own `beginAiAction`. It becomes a
  consumer of the run the hooks opened, matched by the session id the adapter persists for
  `loadSession`; the same server state is reached either way. Until V2-1.15 lands, `run/begin|end` wrap
  today's `beginAiAction`/`endAiAction` and `ai-activity`.
- **Subagents.** Hook inputs carry `agent_id`/`agent_type`. pre-edit refuses a subagent write outside
  its hand-off `owns` (V2-1.18) with code `out-of-scope`. Read-only agents (critics, `board-reader`)
  have no `Edit`/`Write` tools at all (S12).
- **No studio.** check and rollback still run, so terminal users get validated writes. Locks, claims,
  queue, attribution and trash parking are skipped.

### 5.5 Permission tiers in the AI chat

- `MAUDE_DEFAULT_ALLOWED_TOOLS` = `['Read','Glob','Grep','WebSearch','WebFetch', …manifestAutoRules]`.
  `manifestAutoRules` is generated from the manifest: one `Bash(maude design <verb>:*)` per auto verb,
  plus `Bash(maude kg context:*)`, `Bash(maude kg resolve:*)`, `Bash(maude kg doctor:*)`,
  `Bash(maude version:*)`, `Bash(maude doctor:*)`, `Bash(maude config show:*)` and
  `Bash(maude config get:*)`.
- `Bash(maude:*)` is gone. `acp-session-allowed-tools.test.ts` asserts the generated list equals the
  manifest's auto verbs, and that no `prompt` or `human` verb appears.
- **What is not changed:**
  - `settingSources:['user']` — the user's own allow/deny/ask rules apply on top (P3). A user who
    allows `Bash(maude:*)` themselves gets every verb without prompts; that is their call.
  - `write-scope.ts` — in-project file writes are still auto-approved, with the protected-path list.
  - DDR-179 modes.
- **Terminal Claude Code.** Plugins can't ship permission rules, so `site/content/docs/…/ai-permissions.mdx`
  (generated) gives the auto-tier rules as a paste-in `permissions.allow` snippet. Nothing writes the
  user's settings for them.
- **Redirection.** Claude Code's docs say output-redirect targets are checked against Edit rules and
  working directories. That contradicts the 2.1.220 PoC behind the earlier `cat >` cut, so the PoC
  becomes a test against the bundled `claude` (§7). If redirection still self-approves, open question
  Q3 applies.

### 5.6 Version handshake

- `/_health` returns `manifestVersion` (sha256 of the manifest's ids + verbs + schemas, first 12 hex).
- The design plugin ships a copy of the manifest. session-start warns when the two differ and the
  plugin's is older.
- `scripts/check-version-parity.sh` asserts the bundled plugin copy matches the generated manifest.
- Action ids and verbs are append-only; a rename keeps an alias.

### 5.7 Parity coverage (V2-2.4b) — only ratchets down

`apps/studio/test/ai-parity-coverage.test.ts` reads the generated manifest and
`apps/studio/actions.parity.json` (lead-owned):

```json
{ "humanMax": 0, "pendingMax": 0, "pending": [], "humanDecisions": { "view-pref": "decision:maude/v2-…" } }
```

(The numbers are set when V2-2.4b lands; the values shown are placeholders.)

It fails when:
1. an action has no `agent`;
2. `pending` actions outnumber `pendingMax`, or a pending id is missing from `pending[]` (each entry
   names its package). `pendingMax` starts at the count of v1 actions migrated by V2-2.4, must reach
   0 at the V2-2.4b gate, and stays 0 afterwards, because rule 14 makes every new action land with its
   AI path in the same change;
3. the count of `human` actions exceeds `humanMax` — `humanMax` may only be lowered;
4. a `human` action's `because` has no entry in `humanDecisions`;
5. a `file` action's `format` has no schema or its `skill` section is missing (grep for the anchor);
6. a `cli` action's verb is not in `maude design help` or doesn't exit 0 on `--help`;
7. any action with `server` lacks a per-role refusal test (rule 12; the role suite from V2-1.7/S9).

Raising `humanMax` or adding a `HumanReason` is a lead change that cites a decision id; the diff is the
audit trail.

### 5.8 Invariants

1. Hooks never emit `ask` or `allow`.
2. Every `.design/**` write by Claude's file tools is validated; a failed fast check leaves the file as
   it was.
3. A canvas file is never hard-deleted or moved by Claude's Bash.
4. An auto-tier verb has effect `none` or `project`, and no flag raises it.
5. Agent routes are main-origin only.
6. Every action has exactly one AI path.
7. The UI path and the AI path of an action give the same result (contract test per package).

## 9. Open questions (conservative default in bold)

- **Q1 — AI critic findings as attributed comments** (A13) are `shared` and so prompt once per
  `comments add --as-ai` call. **Default: prompt, batched — one call per critic round with a findings
  file.** If that proves noisy, lowering it needs a decision.
- **Q2 — `draw-build` / `to-lottie` prompt on every build round** (they run model-authored code), which
  slows `/design:draw`. **Default: prompt.** Proposed path out: a declarative `draw-build --spec
  <json>` that runs no model code, as its own auto verb.
- **Q3 — If the redirection PoC (§7) still self-approves `maude design … > outside`.** **Default:
  pre-bash denies output redirection of a `maude` command to a path outside the repo root and temp
  dir.** This is an invariant guard, not a permission change; helpers never need it.
- **Q4 — Is `trash move` prompt-tier too strict?** Moving a whole canvas to the trash is reversible.
  Removing an artboard by `Edit` is parked automatically and never prompts. **Default: prompt for
  canvases**, matching H §3.3.
- **Q5 — Lazy-`Write` guard threshold (40 lines).** **Default: 40.** V2-1.18's eval may tune it.
- **Q6 — ACP session id ↔ hook `session_id` identity** is undocumented for the ACP adapter.
  **Default: the hook's `session_id` is the run key.** The bridge looks up its chat's run by the
  persisted adapter session id. If they ever differ, the bridge stops bracketing and only the hooks do.
