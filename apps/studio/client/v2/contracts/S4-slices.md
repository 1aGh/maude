No product code in this note — it is the order of work for `v2-builder`s.

## 1. Scope recap

S4 turns the whiteboard layer into canvas 15: the Preview toolbar's tools with their popovers and per-person
memory; stickies (tilt, auto-size, stack + Fan out, author line, Resolve); Marker tips and inks; arrows with kinds,
labels and **bound ends on artboards and elements** that follow live and go dangling honestly; annotations that
**ride with their artboard**; sections with Fold; Templates + AI "describe it"; the Stickers gallery (vote stamps,
Recent, packs, search, follow-pointer drop at 160 px, Replace / Flip); stamps and formal votes (A18); sticky ↔
comment; quiet rendering in Edit with click-through, ⇧P, LOD mosaic below 25 %; the Layers tab as the annotation list
in Preview; video time pins; print rules; the Can comment denial; FigJam into the canvas; AI read / apply / write.

**Phase 4 already ships (do not redo):**
- Preview toolbar from `bridge/canvas-modes.ts` `MODE_TOOLS.preview` (H N C M A R T E S, minRoles, `tips` for M,
  `popover`/`panel` slot fields); `tool-palette.tsx` renders the `marker-tips` + `shape-kinds` popovers (the
  `sticky-colours` popover is declared, not rendered — colours still live in AnnotationsChrome's swatch tray,
  decision V2-4.5a); keys moved per rule 13 with `MOVED_KEYS` rows.
- `toolbar-rect` / `tool-panel-open` lane (`client/v2/shell/use-tool-panels.js`, `acceptFromCanvas`, generic
  `ROLE_DENIAL` for non-editors) opening today's `StickerPicker.jsx` anchored; `insert-sticker {path, follow?}` is
  in `dgn-protocol.ts` (`follow` declared, not honoured — the drop still lands mid-view).
- Registry: `annotation.*` (group, ungroup, lock, duplicate, z-order, copy, cut, chain, edit-text, nudge, remove),
  `select.all-annotations` ⇧⌘A, `view.annotations` ⇧P.
- Format: DDR-242 JSON board, ops, replica, lock (DDR-246), V2-2.14 lossless readers (unknown keys kept on known
  types, after `TAIL_FIELDS`), V2-2.4b strict `validateBoard` + `schema/annotations.v2.schema.json`.
- Server: `/_api/annotations(/ops)` (canvas-safe), `/_api/stickers` (main-origin), hub `role-matrix.mjs`
  (`annotate` = edit, refused for viewer), comments anchored to annotation ids (#134/#136), `includeAnnotations`
  export option, `annotate --board` templates, `import-figma --board` (FigJam → a new canvas).

## 2. Open questions resolved

| # | Decision | Why |
| --- | --- | --- |
| Q1 | Artboard / element binds are **extension fields** on the arrow: `startHost` / `endHost` = `{ ref: 'ab:<artboard>' \| 'el:<artboard>/<id>[#occ]', nx?, ny?, label, box? }`. The existing `start` / `end` stay free points `{x, y}` and cache the last resolved endpoint. | R3: `{el:'ab:…'}` in `start` fails `elId` and v1 drops the whole arrow (probe B). With a cached free point a v1 peer renders the arrow frozen where it was (R2). |
| Q2 | **Dangling is derived, never stored.** An unresolvable `ab:` / `el:` host keeps the bind, draws from the cached point, dashed with an open circle, and shows the card from `label`. Restoring the element re-attaches. Only a person removes the bind (Point to… or delete). Annotation-to-annotation hosts keep today's strip-and-freeze (Excalidraw semantics). | V2-1.4 §4.8. Keeps the shipped behaviour that `annotations-bindings.test.ts` pins. |
| Q3 | **Ride-with-artboard = `parentArtboard` membership; `x`/`y` stay world.** During a drag the layer only translates members on screen (no writes). On commit, one op batch moves members and refreshes the arrow caches, and it joins the artboard move's undo record (one ⌘Z). Membership is set on create / drop from the element's centre. A section owns its members. A locked item still follows. | R2. Membership you can see ("On Post 1:1 · moves with it"). Rejected: artboard-relative coordinates (break v1); geometry at move time (picks up loose notes, differs per screen). |
| Q4 | **Re-route frame budget (measured).** `draw/geometry.ts` `routeConnector` on a 31-board layout (Bun, this Mac): grid 20 = 8.9 ms p50 / 15.3 p95 for 4 arrows to neighbours; grid 40 with obstacles filtered to the pair's bbox = **1.75 / 2.05 ms for 4**, **5.7 / 6.8 ms for 10**. Long cross-canvas routes at grid 20 cost 38 ms for 10. **Contract:** ≤ 4 ms of routing per frame; while dragging, grid 40, bbox-filtered obstacles, and a cache keyed on grid-quantised endpoints; arrows over budget keep their last route moved with the host until a later frame (time-sliced queue). One full grid-20 route per arrow on settle; settle eases on `--dur-soft` (160 ms); reduce motion jumps. Gate: `perf.sh` drag p95 ≤ 18 ms with 10 bound arrows on canvas 15 (baseline 17.8 ms, `notes/annotations-v2/perf.md`). | Measured, not argued. Bench in the scratchpad: `route-bench.ts` (S4.2 commits a repo copy). |
| Q5 | **Votes (A18).** Local: a `vote` element plus one `ballot` element per voter (two new types, R4). The id is `ballot-<vote>-<voter>`, so concurrent voters never write the same element. Other people's ballots are hidden in the UI until `state: 'ended'`, and the sheet says so. Cloud: the hub holds ballots and the timer (`/api/projects/:p/votes`); the board carries only the `vote` element (targets, `endsAt`, voters-done count) and, at the end, the tallies. Whoever is first to open it as an editor writes the result section (idempotent id `vote-<id>-result`). | A18. A single `ballots` field would be one merge unit, so concurrent voters would overwrite each other. |
| Q6 | Ballots need **Can comment**; starting and ending a vote needs Can edit. **Stamps need Can edit** (they are annotation elements; hub `annotate` = edit). | an-viewer shows Hand + Comment only. A vote is feedback, not drawing. |
| Q7 | **One stamp per person per kind per spot** is enforced by the id: `stamp-<spot>-<author>-<kind>` (`spot` = target id or a 40 px world cell). A second stamp is an upsert. Clusters and counts are derived. A local author id can be forged, which is accepted: formal votes are the secure path. | No server needed, and the rule is deterministic across peers. |
| Q8 | **Per-person memory** (last sticky colour, ink, Marker tip, Recent stickers ≤ 12, Hide resolved stickies per C29) goes in `ui-prefs.ts` under a new `annotations` key: `~/.config/maude/prefs.json`, with `localStorage` as the fallback in a cloud tab. The iframe gets it through `annotation-prefs` (s2c) and writes through `annotation-prefs-set` (c2s, active). Per machine; no cross-device sync in v2.0. | The canvas origin has no prefs route (DDR-054). Rejected: iframe `localStorage` (canvas origin, lost in WKWebView); `_canvas-state` (per project, not per person). |
| Q9 | **Sticky ↔ comment** runs as one main-origin route per direction. It writes the comment and trashes the sticky (or the reverse) in one transaction and returns an undo token. The undo record is `cross-store` (V2-1.5). The comment keeps the sticky's author and adds `from {kind:'sticky', id, author, convertedBy}`. | The iframe can't reach comment routes, and Undo has to restore both stores. |
| Q10 | **EH-P4-2 is folded into S4.3.** The shell honours `tool-panel-open` only (a) while the canvas iframe is the shell's `document.activeElement`, (b) at most once per 500 ms, and (c) anchored to the reported `toolbar-rect`. `m.anchor` is ignored unless it lies inside that rect ± 16 px. `placePanel` clamps below the top chrome band. | A pure predicate a test can turn red. Rejected: a shell-side gesture gate, because E is pressed inside the iframe. |
| Q11 | **The Templates panel is S4's** (canvas 15 owns it; V2-1.2 §5.5 `section (+ templates panel)`). The `tool-panels.js` comment "AI templates are S2" is stale; S4.3 fixes it. | Precedence: topic-owning canvas. |
| Q12 | **Arrow to an unstamped element:** the shell stamps it through S2's stamp route (`stampIds`, V2-1.4 §5.2) and the bind is made after that. If the file is busy (run lease, T11), the bind falls back to `ab:<artboard>` (the edge) with the tag "Bound to the artboard". | Never a computed (8-hex) id in a durable ref (V2-1.4). |
| Q13 | Pack order and names follow **CONTRACT C13** (FigJam Doodle · Life Style · Opposing Thoughts · Project status, names trimmed), not canvas 15's order. Resolved stickies follow **C29**: ⌘K "Hide resolved stickies", per person (not canvas 15's "Show"). Section `folded` is shared (it is in the file). | Precedence: Gate 0 / CONTRACT over the canvas. |
| Q14 | **an-vs** is an explainer. Each table row is verified by behaviour (keys, Resolve semantics, export rule, who can), not by a new surface. | Nothing to build except what the other rows already need. |

**Risks:**
1. **Drag-bus re-renders.** `dragCurrent` is React state in `canvas-lib.tsx`, so live re-route could re-render the
   layer every frame. Mitigation: C1 exposes a subscribe/ref API, and the S4.10 perf gate is run red-first.
2. **v1 peers on hub-less transports strip extension fields** (V2-1.12 consequence). Members then stop riding and
   binds fall back to the frozen arrows. This is accepted and documented in the format doc. The mixed-sync test
   pins it in both directions.
3. **Element rects during a drag** come from a cache taken at drag start. An element that changes size mid-drag is
   re-measured on settle only.
4. **Ballot secrecy in the cloud depends on S9's role matrix and Y-doc lanes.** If ballots never enter the board
   and are never broadcast, no lane can leak them. Ethical-hacker runs on S4.6 + S4.14.
5. **CLAUDE.md taxonomy drift.** It lists `*.annotations.svg` as versioned; `.annotations.json` is the live format
   (inventory contradiction 18). Lead patch: add `.annotations.json` to the doc's VERSIONED list. The four lists
