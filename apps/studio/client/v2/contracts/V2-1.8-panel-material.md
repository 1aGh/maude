# V2-1.8 — Floating panel material on WKWebView

Spike of the Maude v2 run (plan `.ai/plans/feature-maude-v2-redesign.md`, Phase 1). Feeds **V2-4.1** (window body
= canvas edge to edge, floating panels), **V2-4.5** (the toolbar island in the canvas iframe), **V2-8.8**
(performance gate) and the DS work in **S10 / V2-2.15** (the `--island-*` tokens). Status: proposed, for the lead
to merge and record as a DDR. Composes with the merged notes **V2-1.2** (floating panels overlay a full-width
canvas iframe; `data-occludes` + `occluded-insets`) and **V2-1.13** (`--island-*` → `--x-island-*`, `island` →
Panel `floating` / `ext.Island`).

## 1 · Question

> `backdrop-filter` islands over a panning canvas: `maude design perf --engine safari --studio` on the
> Alligators-scale fixture, several passes; **go** only if p95 frame time and long-task count stay within the
> pre-v2 run's spread; otherwise the material falls back to a solid surface + the DS shadow (record the numbers
> in the DDR).

Also from the brief: Chromium for comparison; the numbers table (engine × variant × p50/p95/long tasks/spread);
the fallback CSS contract (which token or material when blur is off; per-engine or global); the benchmarks V2-8.8
re-runs.

## 2 · What exists today

**The material.** `.design/system/maude-v2/preview/_components.css` · `.island`:
`background: var(--island-bg)`, `backdrop-filter` and `-webkit-backdrop-filter: blur(var(--island-blur))
saturate(1.4)`, `border-radius: var(--radius-lg)`, `box-shadow: var(--island-shadow), inset 0 0 0 0.5px
var(--island-edge)`. The tokens are in `colors_and_type.css`, in both theme blocks:

- `--island-bg` is `--bg-1`'s colour at 0.88 alpha ("frost, never peek-through").
- `--island-bg-strong` is the same colour at 0.96 (inspector, AI chat panel).
- `--island-blur` is 16px.
- `--island-shadow` is the soft island shadow (CONTRACT §7: "islands float on a soft shadow, not a drop shadow").
- `--bg-1` is commented "island / panel body".

Four more DS files repeat the blur declaration literally:

- `preview/_layout.css` (the specimen header bar);
- `preview/ui_kits-desktop-index.css`;
- `preview/elevation.css`, twice: `.el-slab--island` and `.el-card--island`.

The DS lock (kg "Design system locked: maude-v2") is the reason for the material: "frosted ~88%-opaque islands …
no peek-through".

**Today's studio has no `backdrop-filter` over a moving canvas.** The only use in `apps/studio/client` is the
report-bug scrim (`3-shell-maude.css` · `.rb-scrim`, `blur(2px)`), shown over a still canvas. The canvas's own
floating toolbar (`tool-palette.tsx` · `.dc-tool-palette`) is a solid surface with a shadow. The pre-v2 baseline
therefore already contains one solid island inside the iframe.

**The canvas renders differently per engine.** `canvas-lib.tsx` · `IS_WEBKIT` / `writeTransform`:

- WebKit (Safari and the Tauri WKWebView shell) pans and zooms `.dc-world` with `transform: translate() scale()`.
  It keeps `will-change: transform` during the gesture and releases it on settle (`crisp`) to re-raster.
- Blink uses CSS `zoom`.

kg "RCA: Safari / WKWebView canvas zoom" explains the split. kg "RCA: Velký canvas se seká při pan/zoom" finds
that a fit-all view of a big canvas is the painful state: every board paints, nothing is culled, and the
world plane is tiled past WebKit's texture limit.

**The benchmark.**

- `apps/studio/bin/perf.sh` (`maude design perf`) dispatches to `_perf-probe.mjs` for Chromium (agent-browser, the
  bare `_canvas-shell.html` page only) or `_perf-probe-safari.mjs` for WebKit (safaridriver; `--studio` clicks
  `canvas-row-<slug>` and switches WebDriver into `canvas-frame`; `--parent-css` injects CSS into the studio
  document).
- Both lanes run one in-page gesture: `_perf-shared.mjs` · `harnessSource` sends 60 plain wheel pan frames and
  40 ctrl-wheel pinch frames, with an optional ⌘0 fit first. It records rAF deltas inside the canvas document and
  `longtask` entries.
- `medianOf` discards the first pass, reports medians and `p95Spread`, and the tool reads any delta below the
  spread as noise.
- kg "Canvas render perf: benchmark harness lands; refactor gated on a WKWebView measurement" records why the
  WebKit lane exists: headless Blink showed 60 fps where the user saw jank.

**Two defects of the harness, found by this spike.** Both make the WebKit `--studio` numbers wrong, so V2-8.8 has
to fix them first (§7):

1. **WebKit throttles the canvas iframe until the user interacts with it.** The canvas runs on its own origin
   (DDR-054). WebKit caps rAF in a cross-origin frame without user interaction at about 30 fps. Measured in the
   studio before and after one real WebDriver click into the frame (`scratch diag-throttle.mjs`):

   | Measured document | p50 | p95 |
   | --- | --: | --: |
   | Parent, idle | 14 ms | 15 ms |
   | Canvas frame, idle, no interaction | 28 ms | 42 ms |
   | Canvas frame, after one click | 14 ms | 15 ms |

   Synthetic `dispatchEvent` wheels don't count as interaction. So every `perf.sh --engine safari --studio` number
   taken without a click is quantised to the throttle (28/42 ms), and a heavier variant reads the same as a
   lighter one. A real user clicks into the canvas almost at once, so the measurement has to do the same.
2. **WebKit has no `longtask` entries.** The harness's long-task count is always 0 on Safari ("count stays 0" in
   `harnessSource`), so the rule's "long-task count" cannot be read there. This spike counts **long frames** (rAF
   delta ≥ 50 ms, the Long Tasks API threshold) on both engines. It also records frames ≥ 25 ms, and long frames
   in the settle window.

## 3 · Options

1. **Blur everywhere: `.island` as designed.** *(plan default — "go")*
   - *Cost:* none to build.
   - *Breaks:* nothing visible. Risk: the go rule fails in 3 of 20 valid comparisons (§6). The cost scales with
     the area of the island in device pixels, which is 4× on Retina, and with refresh rate (ProMotion 120 Hz,
     external 144 Hz). It showed at 2× on 144 Hz.
2. **Solid surface + the DS shadow everywhere.** *(the plan's named fallback)*
   - *Cost:* one token flip, plus routing five literal blur declarations through it.
   - *Breaks:* the 12% blurred see-through behind regular islands goes (4% behind `--island-bg-strong`). The DS
     lock already says "no peek-through".
3. **Per engine: blur on Blink, solid on WebKit (or the reverse).**
   - *Cost:* engine detection in both documents (shell and canvas iframe).
   - *Breaks:* the browser shell, cloud tab and desktop look different, against V2-4.9's single parity contract.
     It also guesses wrong: the one consistent blur regression was in Chromium (2× at 144 Hz), not WebKit.
4. **Blur at rest, solid during a gesture** (toggle on the canvas's gesture start/settle).
   - *Cost:* a new `dgn` message or a shared flag across documents, and a material change on every pan.
   - *Breaks:* adding and removing a backdrop layer recomposites at gesture start and end, exactly where WebKit
     already hitches (the RCA's settle re-raster). The panels would visibly flicker on every pan, the same
     fidelity pop the RCA addendum reverted for LOD.
5. **Native vibrancy** (`NSVisualEffectView` through Tauri).
   - *Breaks:* it applies to the window background only. It cannot sit between two DOM layers (an island over
     the canvas iframe), and the browser and cloud shells have no equivalent.

## 4 · Decision (DDR draft)

**Context.** maude-v2's floating chrome is the `.island` material: a 16 px backdrop blur behind an 88% opaque
body (96% for the inspector and the AI chat panel). v2 puts these islands over a full-width canvas iframe that the
user pans and zooms all day (V2-4.1). WebKit is the desktop engine and composites `backdrop-filter` through Core
Animation backdrop layers. The plan's rule: blur ships only if p95 frame time and long-task count stay within the
pre-v2 run's spread, otherwise a solid surface + the DS shadow.

The spike measured it on the real studio (today's chrome) with the Alligators fixture's heaviest canvas
(Combine-kampan, 21 artboards, fit-all). There were four islands of v2 size and two iframe geometries, Safari
26.5 and Chrome 154, in four batches, every pass inside the single test lane under `caffeinate`. The machine's
display changed mid-run, so the batches cover two displays:

- an external 5120×1440 display at 144 Hz and dpr 1;
- the built-in Liquid Retina at 60 Hz and dpr 2 — the common MacBook case.

**Decision.**

1. **No-go for `backdrop-filter` on islands. v2 islands ship the solid material:** `--bg-1` surface,
   `--island-shadow` and the 0.5 px `--island-edge` hairline. Measured at the same geometry, blur pushed p95 or
   long frames past the baseline's spread in **3 of 20 valid comparisons**; the solid material in **0 of 17**. The
   three:
   - WebKit, 60 Hz: +2 long frames.
   - WebKit, Retina, full width: +1 long frame.
   - Chromium, 2× at 144 Hz: p95 doubled from 13.9 ms to 27.8 ms, one extra pair of vsyncs, with zoom p95 at
     41.6 ms and real `longtask` entries in every pass (median 3, against 0).

   Blur's cost sits at the noise floor. The rule says go only when it is within the noise, and it is not.
2. **The choice is global, not per engine.** One material on every engine and shell. No engine detection
   anywhere for the material.
3. **The material is a token switch, not a component fork.** `.island` reads a new `--island-backdrop` token
   (`none` now). Glass returns by changing tokens only, once V2-8.8 passes on a dpr-2 WebKit display and on a
   ≥ 120 Hz Chromium (§5 M5).
4. **Recorded beside it, because it decides V2-4.1/V2-8.8 regardless of material:** on WebKit, the **full-width
   canvas iframe** is the real regression.
   - Measured at fit-all on Combine-kampan, with no islands at all.
   - At Retina dpr 2, p95 grows from 19 ms to 268 ms (r3) and from 27 ms to 468 ms (r4). At dpr 1 and 144 Hz it
     grows from 55 ms to 154 ms.
   - It sits in the zoom path: zoom p95 goes from 17 ms to 274 ms and from 18 ms to 497 ms, while pan p95 is
     unchanged.
   - Pinning the iframe at today's size with the same CSS gives 27 / 24 ms, so the cause is the size, not the
     method.
   - Halfway between the two sizes (1314×813) gives 37 ms, with zoom p95 at 54 ms. It is a threshold, not a
     slope.
   - It exists today in any large studio window. v2 only makes it the default.

**Consequences.**

- The maude-v2 DS changes in one place (`colors_and_type.css`, both themes) plus five literal declarations routed
  through the token (§5). The v2 design canvases under `.design/ui/v2/` follow through the token and need no
  edits. Their screenshots lose the faint see-through, which the DS lock already ruled out.
- The canvas toolbar island in the iframe (V2-4.5) uses the same token, so both documents always agree with no
  message.
- `prefers-reduced-transparency: reduce` is satisfied by construction. If glass returns, it must still force
  solid there (M6).
- V2-8.8 cannot pass "within the pre-v2 spread" on WebKit until the large-viewport zoom regression is fixed in
  `canvas-lib.tsx`. That fix belongs to lane L1 before V2-4.1 makes the iframe full-width (§8). The material
  decision does not depend on it: solid and blur were measured against the same full-width baseline.
- `perf.sh` needs three fixes before V2-8.8 can trust a WebKit studio number: a click into the frame, a
  long-frame count, and a studio lane for Chromium (§7).

**Rejected alternatives.** Option 1 fails the rule (3 of 20 comparisons outside the spread). Option 3 breaks shell
parity and keys on the wrong engine. Option 4 trades a steady cost for a hitch plus flicker at every gesture
start and end. Option 5 can't put an effect between two DOM layers. The pilot also rejected `--shadow-md` for the
fallback shadow. It costs the same as `--island-shadow` (a static shadow is rastered once into the island's own
layer), so CONTRACT §7's soft island shadow decides.

## 5 · Contract

### 5.1 Tokens and the rule (maude-v2; names after V2-2.15 in brackets)

```css
/* colors_and_type.css — BOTH theme blocks (light and dark); values reference --bg-1, so each theme gets its own */
--island-bg:        var(--bg-1);   /* [--x-island-bg]        was --bg-1 @ 0.88 alpha */
--island-bg-strong: var(--bg-1);   /* [--x-island-bg-strong] was --bg-1 @ 0.96 alpha */
--island-backdrop:  none;          /* [--x-island-backdrop]  NEW — the material switch.
                                      Glass value (not shipped): blur(var(--island-blur)) saturate(1.4) */
/* --island-blur, --island-edge, --island-shadow: unchanged */

/* preview/_components.css */
.island {                                         /* [Panel variant="floating" · ext.Island .x-island] */
  background: var(--island-bg);
  -webkit-backdrop-filter: var(--island-backdrop);
  backdrop-filter: var(--island-backdrop);
  border-radius: var(--radius-lg);
  box-shadow: var(--island-shadow), inset 0 0 0 0.5px var(--island-edge);
  color: var(--fg-0);
}

@media (prefers-reduced-transparency: reduce) {   /* a no-op today; it binds the day glass returns */
  .maude-v2[data-theme="light"], .maude-v2[data-theme="dark"], :root {
    --island-bg: var(--bg-1); --island-bg-strong: var(--bg-1); --island-backdrop: none;
  }
}
```

Route these through the same three tokens (no literal `blur(` left in maude-v2):

- `preview/_layout.css` — the specimen header bar;
- `preview/ui_kits-desktop-index.css`;
- `preview/elevation.css` · `.el-slab--island` and `.el-card--island`.

`elevation.css`'s specimen keeps showing "island" as a level. Its caption names the material "solid, soft
shadow".

### 5.2 Rules

- **M1 — One place.** In v2 chrome CSS — the shell under `apps/studio/client/v2/**`, the canvas-side chrome in
  `tool-palette.tsx`, `canvas-lib.tsx` and the annotations layers, and the maude-v2 DS — a `backdrop-filter` is
  either `var(--island-backdrop)` (the island rule and the specimens that show it) or the literal `none`. One
  exception: a modal scrim over a canvas that is not interactive (today's `.rb-scrim`), because nothing pans
  under it.
- **M2 — No peek-through.** With `--island-backdrop: none`, `--island-bg` and `--island-bg-strong` are opaque in
  both themes (alpha 1). An island never shows the canvas through it.
- **M3 — Global.** No engine, shell or user-agent condition selects the material. The desktop, local browser,
  cloud tab, viewer and embed all render the same island (V2-4.9 parity).
- **M4 — Both documents.** The canvas's own toolbar island (V2-4.5, rendered in the iframe) uses `.island` / the
  same tokens. No `dgn` message carries the material.
- **M5 — The way back to glass.** Glass returns only by setting `--island-backdrop` to the glass value and
  `--island-bg` / `--island-bg-strong` back to 0.88 / 0.96 alpha, after V2-8.8 shows both conditions:
  - E within D's spread (p95 and long frames) on WebKit at dpr 2;
  - the same on Chromium at ≥ 120 Hz.

  It is a token edit plus a DDR line, with no component change.
- **M6 — Accessibility.** If glass ever returns, `prefers-reduced-transparency: reduce` forces the solid material.
  On the desktop, the macOS "Reduce transparency" setting arrives through that media query where WKWebView
  supports it; if it doesn't, the solid default is already compliant.
- **M7 — Budget for V2-8.8.** For each engine at dpr 2, the shipped v2 shell (islands mounted, canvas full width)
  on Combine-kampan at fit-all must keep:
  - median gesture p95 ≤ the pre-v2 median p95 + the pre-v2 spread;
  - median long frames (≥ 50 ms) ≤ the pre-v2 median + its range.

  Both baselines use the same window size and pass count (≥ 5 kept passes). This is the plan's rule written as
  a test.

### 5.3 What it costs to look at

The solid material differs from the glass one only in what shows through: 12% of a blurred canvas behind a
regular island, 4% behind the inspector and the AI chat panel.

Safari screenshots of both on the Retina display (`shots/E-full-blur.png`, `shots/F-full-solid.png`, same scene,
2880×1696) differ in one place. Where artboards pass under the AI panel's lower edge, the glass shows a faint grey
smear and the solid shows nothing. Panel text, edges, radius and shadow look identical (judged by eye, not a pixel diff).

## 6 · Evidence

### 6.1 Method

- **Fixture.** An unlinked APFS clone (`cp -c`) of `~/Maude/alligators/.design` (`ui/`, `assets/`, `system/`,
  `config.json`, annotations, `_canvas-state`). `linkedHub` was stripped; `_sync.json` and `_state` were not
  copied. That gives 103 TSX modules (~93 canvases). The canvas is `ui/2026/combine/Combine-kampan.tsx`: 21
  artboards counted at render (`[data-dc-screen]`), the canvas V2-8.8 names. The original was never written.
- **Server.** The worktree's studio (`feat/maude-v2` @ `358eacd6`, committed `dist/`, today's pre-v2 chrome):
  `NO_OPEN=1 MAUDE_NO_AUTOBUILD=1 bun run apps/studio/server.ts --root <fixture> --port 4781`.
- **Batches.** Every batch is one `scripts/v2-test-lane.sh --wait 3600 -- caffeinate -dimsu bash batch*.sh …`
  that boots the server, runs every variant on every engine and stops it. `uptime` is recorded before every
  engine × variant run. The Retina batches also wait for a 1-minute load under 8 first.
- **WebKit lane.** `perf.sh --engine safari --studio --fit-all --repeat 6`, plus the spike-only flags (not
  committed):
  - `--interact`: one real WebDriver click into the canvas frame, which lifts the §2 throttle;
  - `--parent-js`: mounts the islands;
  - `--window`, `--variant`, `--passes-out`.
- **Chromium lane.** A spike-only studio-mode driver: the repo's Playwright 1.61.1 runs headed system Chrome 154
  through the same steps (row click, parent-js, one real click, the same `harnessSource`, the same validation and
  median). Viewport and dpr match the Safari window.
- **Passes.** 6 per engine × variant; the first is discarded, so there are 5 kept passes per cell and per batch.
- **Islands.** Mounted in the studio document over the canvas iframe with `pointer-events: none`, using the real
  material: the maude-v2 token file re-scoped from `:root` to `.maude-v2`, so it cannot restyle today's chrome,
  plus the `.island` rule verbatim. Sizes, as briefed:
  - left panel 280 × 720;
  - AI panel 360 × 720;
  - toolbar 560 × 56, bottom centre;
  - Share cluster 420 × 40, top right.
- **Variants.**

  | Variant | Iframe | Islands |

  | A-base | today's | none |
  | B-blur | today's | `.island` |
  | C-solid | today's | §5.1 material |
  | D-full-base | full window (v2 geometry: `position: fixed`, inset 0) | none |

  | F-full-solid | full window | §5.1 material |
  | G-pinned-same | today's rect, but `position: fixed` like D | none (control for the method) |

    at a size limit, not a cost that grows with area.
