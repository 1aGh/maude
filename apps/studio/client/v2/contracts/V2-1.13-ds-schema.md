## 3. Options

1. **G §4–§6 as written** (plan default). Cost M. It breaks in four places:
   - **Keeper writes.** E6 asks the keeper to write `meta.dsPins`, but the keeper is read-only. Persisted derived
     pins also churn versioned meta and conflict on concurrent edits (arrays without `id` → `mergeJson`
     `{ok:false}`).
   - **Value checks.** `--bg-4` not monotonic, studyfi's `--space-N` multiples and the lightness of `--accent` are
     value relations. Checking them breaks A14 "never values".
   - **Budget and tier.** Putting `--plan --apply` (with a screenshot diff) inside `ds-check` breaks the PostToolUse
     budget (V2-1.18, 1.5 s) and the read-only auto-approve tier (A13).
   - **Shadowing.** The study's fallback layer declares every functional role on every `[data-theme]` element. A
     direct layered declaration beats an inherited value, so a role a system declares only on `:root` changes in
     every nested theme wrapper.
2. **G §4–§6, tightened** (chosen). The same tiers, names, levels and engine, with five changes:
   - pins are computed, never stored;
   - collisions are detected only from names and value types;
   - the engine gets a verb of its own;
   - fallbacks are per system and define only names the system never declares;
   - canvases get a fourth state, `blocked`.

   Cost M. Breaks nothing on today's canvases: in this repo, no canvas uses a functional name its system lacks (§6).
3. **Registry as a TypeScript module.** Cost S. Breaks A13 (files are the API): Claude, the CLI shim and the hub
   mirror read JSON without bun.
4. **Per-project registry overrides** (a project may rename roles). Breaks the premise of switching ("a name means
   the same thing in every system") and team libraries.
5. **JSON-Schema-only validation of `tokens.json`.** Breaks A15: until S10 the CSS is the source, so a schema over
   a derived file proves nothing about the file canvases render.

## 4. Decision (DDR draft)

**Title:** Design-system schema v1 — one registry file, structural checks, per-system fallbacks, a
deterministic-first Bring-up engine.

**Context.** Switching systems without mapping tokens (A14) needs one shared meaning per name, and a checker that
proves a system and a canvas follow it. The G study counted 36,411 `var()` uses across 208 canvases. 65 % already
hit the 68 DDR-043 names; aliases, literals, wrappers, kit imports and name collisions break the rest. DDR-043
forbids judging values, and A16 forbids touching other projects.

**Decision.**

1. **One registry.** `apps/studio/schema/ds-schema-v1.json` (validated by `ds-schema-v1.schema.json`) is the single
   source for the role list, value types, theme rule, sub-role suffixes, slot kinds, own namespace, aliases,
   collisions, the component class contract, the 40-name icon vocabulary, the `.t-*` type roles, the S-rules and
   the levels. Critics, keeper, templates, fallbacks and the `/design:new` cheat-sheet read it or are generated from
   it; none restates it.
2. **Tiers:**
   - Tier 1 = 95 names: the 68 DDR-043 names (3 presence names gated by `activeFamilies`) and 27 functional roles.
   - Tier 2 = 7 slot kinds, plus extra accents (`--accent-N`) and named extensions.
   - Tier 3 = `--x-*` tokens, `.x-*` classes and `ext.*` components. A canvas may also declare `--c-*` locals.
3. **Structural checks only:** presence, per-theme presence for colour roles, value **type**, and collisions
   detectable from names and types (`type`, `signature`). Value relations (ordering, lightness, multiples) are
   `notes` handed to the Bring-up AI step, never part of a level.
4. **Fallbacks.** They are generated from the registry. Per system, the shell injects only the roles and classes the
   system never declares, in `@layer maude.fallback`, inline, before the tokens. A single-theme system is never
   colour-inverted.
5. **Levels.** Systems: Conformant 0 · Missing roles 10 · Private-only 11. Canvases: `switchable` · `review` ·
   `blocked` · `pinned`. Exit 12 marks canvas blockers; exit 13 a refused write.
6. **Two verbs.**
   - `maude design ds-check` is deterministic and read-only by default. `--emit` writes `tokens.json`;
     `--fix=mechanical` applies canvas autofixes.
   - `maude design ds-upgrade` is the Bring-up engine: analyse → mechanical plan → AI judgement → validate → stage →
     visual proof → review → apply. Apply is one undo step and never runs implicitly.
7. **Pins are computed, never persisted** (`ds-check --json`, the usage index of V2-1.6 §5.13). `meta.dsPinned:
   true` is the only stored pin.
8. **Freeze rule.** Registry v1's required content is frozen. Aliases, `judgement` collision rows and recommended
   components may be added, because they are additive. A new required role means registry v2 plus a project
   `formatVersion` bump (V2-1.12 R7).

**Consequences.**

- maude and maude-v2 move from 10 to 0 in V2-2.15 through `ds-upgrade`, under its visual proof.
- C7 stops false-failing every system. The keeper's Pass B never degrades again.
- Cells get the same facts once the config door carries `schema`, `rootClass` and `themes` (P-5).
- Studyfi / Alligators systems are untouched by the run (A16). Users there see the in-app offer.

**Rejected alternatives.** Options 1, 3, 4 and 5 above. Also rejected:

- a computed dark inversion for single-theme systems (a visual prior, DDR-043);
- name or kind heuristics that auto-pin moodboards;
- system-file changes inside `ds-check --fix` (system edits need the visual proof, so they go through
  `ds-upgrade`).

**Evolution rule.** Registry v1 is frozen for anything that can lower a level: roles, value types, the theme rule,

collision rows, `extended` components, `packs` and slot `roleHints`, because those are additive and never lower a
level. Anything else is `ds-schema-v2.json`, plus project `formatVersion` 3 (V2-1.12 R7).

### 5.3 Registry content (the exact lists)

**5.3.1 Value types** (structural; each form is a parser production in `ds/check.ts`, with tests):

| Type | Accepted forms |
| --- | --- |
| `color` | `var-ref`, `hex` (3/4/6/8), `color-function` (`rgb[a]` `hsl[a]` `hwb` `lab` `lch` `oklab` `oklch` `color` `color-mix`, incl. relative-colour `from`), `named-color` (CSS named list + `transparent` + `currentcolor`), `light-dark` |
| `length` | `var-ref`, `zero`, `dimension` (any CSS length unit), `percentage`, `math` (`calc` `min` `max` `clamp`) |
| `length-or-none` | `length` forms + `none` |
| `duration` | `var-ref`, `time` (`ms`, `s`), `math` |
| `easing` | `var-ref`, `easing-keyword`, `cubic-bezier`, `steps`, `linear-function` |
| `number` | `var-ref`, `zero`, `number`, `math` |
| `line-height` | `var-ref`, `zero`, `number`, `dimension`, `percentage`, `normal`, `math` |
| `font-family` | `var-ref`, `family-list` (comma list of quoted strings / identifier sequences, ≥ 1 entry) |
| `shadow` | `var-ref`, `none`, `shadow-layers` (comma list; each 2–4 lengths, optional `inset`, optional colour) |

- **Resolving `var-ref`.** The checker follows `var()` inside the same system: same theme block → invariant blocks
  → `:root`, depth ≤ 8.
- **Unresolved and cyclic refs.** An unresolved ref gives `unresolved-ref` (level 10, never a type error); a cycle
  gives `unresolved-ref` too.
- **Out of scope.** Magnitudes, ordering and colour values are never checked.

**5.3.2 Theme rule.** A `perTheme` role must be declared, for every theme in the system's `themes`, in a counted
rule (top-level, or inside `@layer`; never `@media`, `@supports` or `@container`) whose selector list contains:

- `.ds[data-theme="<t>"]`, or
- `.<rootClass>[data-theme="<t>"]`, or
- `:root`, only for the system's default theme.

A `light-dark(a, b)` value in a rule covering every theme counts for both light and dark. Inheritance never counts —
that is the V18c invisible-text bug.

### 5.5 Fallbacks CSS

**Generator.** One function, `renderFallbacks(registry, declared?)` in `ds/fallbacks.ts`. It has two outputs:

- **`ds-schema-v1.fallbacks.css`** = `renderFallbacks(registry)` (everything), committed and drift-gated
  (`scripts/gen-ds-schema.mjs --check`). Consumers: handoff bundles, code that adopts a system, readers.
- **The shell's per-system block** = `renderFallbacks(registry, declaredBy(system))`. `declaredBy` is the set of
  custom-property names declared anywhere in the system's tokens CSS (top-level or `@layer`, any theme), plus the
  class roots declared in its `_components.css`. Every role or class in that set is **omitted**.

**Shape.**

```css
@layer maude.fallback;                         /* first statement: the lowest layer */
@layer maude.fallback {
  :where(:root, .ds, .<rootClass>, [data-theme]) {
    --accent-on-soft: var(--accent-text);      /* only names the system never declares */
    --scrim: color-mix(in oklch, var(--fg-0) 45%, transparent);
    /* … */
  }
  @supports not (color: oklch(from red clamp(0, (0.62 - l) * 1000, 1) 0 0)) {
    :where(:root, .ds, .<rootClass>, [data-theme]) { --status-error-fg: var(--accent-fg); /* … */ }
  }
  :where(.t-title) { font: var(--weight-semibold) var(--type-2xl) / var(--lh-2xl) var(--font-display);
                     letter-spacing: var(--tracking-tight); }
  /* core component fallbackCss for classes the system never declares */
}
```

**Invariants:**

- **F1.** Declared on every theme wrapper, so `var(--accent)` resolves to the wrapper's own theme values.
- **F2.** It defines only names and classes the system never declares, so it can never shadow a system value —
  inherited or direct. The only pixels that change are on canvases that referenced an undeclared name or class:
  they go from broken to derived. (The study's unfiltered layer would have overridden a `:root`-only
  `--tracking-tight` in every nested `[data-theme]` wrapper.)
- **F3.** Unlayered system CSS always wins over `@layer maude.fallback`. The leading `@layer maude.fallback;`
  statement makes it the lowest layer even when the system or canvas uses layers.
- **F4.** No visual prior. Colours derive from the system's own tokens, weights are the CSS numeric weights, tracking
  is `0`, and focus geometry is `2px`.
- **F5.** Single-theme systems get no inversion. Dark previews show the one theme's values, with the reason
  `single-theme`.
- **F6.** `ds-check` lists every role served by the fallback (`tier1.servedByFallback`), so nothing is silent.

**Injection** (patch requests P-1, P-2):

- `_shell.html` gets `<style id="canvas-fallbacks" data-canvas-css="fallbacks"></style>` immediately before
  `<link id="canvas-tokens">`.
- `serveCanvasShell` fills it with the per-system block for the system named by the request's `tokens` param. It
  caches by the sha256 of the tokens and components files. Inline styles are allowed by both canvas CSPs, so there
  is no new route and no canvas-origin allowlist change.
- The shell order is fallbacks → tokens → components → layout.

### 5.6 Conformance levels, reasons, exit codes

**System level** = 11 if any 11-reason, else 10 if any 10-reason, else 0:

| Reason | Level | Meaning |
| --- | --- | --- |

| `type-collision` | 11 | a Tier-1 value has the wrong type (§5.3.8) |
| `signature-collision` | 11 | a `signature` collision row matches |
| `missing-functional` | 10 | one of the 27 v1 roles is not declared (served by the fallback) |
| `theme-gap` | 10 | a `perTheme` role is missing in a declared theme's blocks |
| `single-theme` | 10 | `themes` has one entry |
| `no-ds-scope` | 10 | a theme block lacks `.ds[data-theme]` |
| `unprefixed-own` | 10 | a declared name that is neither Tier 1, Tier 2, `--x-*`, nor an inverted alias |

**Notes** never set a level: `judgement` collision rows, `ladder-order` (space / type / radius / dur not strictly
increasing), `legacy-accent-name`.

**Canvas state** (first match wins):

1. **`pinned`** — `meta.opt_out_scope === "full"` or `meta.dsPinned === true`.
2. **`blocked`** — any blocking finding: S2 `undefined` or `foreign`, S5 `kit-module` or `other-system`, S9. The
   switch and update reviews list a blocked canvas unticked, with its reason.
3. **`review`** — pins are non-empty: S1 literal colours, `--x-*` uses, a `--c-*` block, `ext.*` imports.
4. **`switchable`** — otherwise. S3, S4, S6 and S8 warnings don't change the state.

### 5.7 S-rules (checkable predicates)

A canvas's **sources** are its `.tsx`, its sibling `.css`, and every stylesheet it imports that resolves inside
`<designRoot>/` but outside `system/` — for example `ui/v2/_kit.css`, whose `--k-*` names are canvas-local (§6
found 10 such uses that a sibling-only scan miscounts as undefined). Parsing: TSX with `oxc-parser` (already a
dependency); CSS with `ds/css-scan.ts`. Fixes go through `magic-string` (already a dependency) and touch only the
matched span.

| Rule | Predicate (finding when true) | Kinds → severity (default / `dsFidelity: strict`) | Autofix |
| --- | --- | --- | --- |
| S1 colour literals | a CSS declaration value, a JSX `style` value (string / static template part), or a JSX `fill` `stroke` `stopColor` `stop-color` `color` `floodColor` `lightingColor` attribute contains a colour form (§5.3.1) whose arguments contain no `var(`, or a named colour other than `transparent` / `currentcolor` / CSS-wide keywords | `literal` → warning / blocker; counted as pin `literal-colour` | — (AI restyle on switch) |
| S1 exemptions | `--c-*` declarations (pin `local-palette`); a subtree under `data-ds-exempt` listing `S1`; inside `<DrawProof>`; `url()`; canvas state `pinned` | — | — |
| S2 `var()` names | for every `var(--n …)` (fallback arguments recursively): ok if n is Tier 1, a Tier-2 pattern / companion / extension name, a `--x-*` the system declares, or a name declared anywhere in the canvas sources | `alias` (n in the alias table, context matching) → autofix; `foreign` (declared only by another system in this project) → blocker; `undefined` → blocker | `alias` → v1 name |
| S3 type literals | `font-size` `font-weight` `letter-spacing` `font-family` `font` (and camelCase) with a literal value that contains no `var(--type-|--display-|--lh-|--weight-|--tracking-|--font-)`, on an element without a `.t-*` class | `literal` → warning / warning | — |
| S4 box literals | `padding*` `margin*` `gap` `row-gap` `column-gap` `border-radius*` with a literal length or percentage other than `0`, not built only from `var(--space-*|--radius-*)` and unitless numbers; `DCArtboard` props, width / height / position / transform are exempt | `literal` → warning / warning | — |
| S5 system imports | an `import`, `export … from`, dynamic `import()` or CSS `@import` resolving under `<designRoot>/system/` | `own-css` (its own system's `colors_and_type.css` / `preview/_components.css`) → autofix; `fonts` → S8; `kit-module` (ts/tsx/js) → blocker for a new canvas, warning for an existing one (blocks the state either way); `other-system` → blocker | `own-css` → remove the import |
| S6 wrapper | a JSX element whose static `className` has a token equal to a `designSystems[].rootClass` or the project `rootClass` and that carries `data-theme` | `wrapper` → warning (autofix) | token → `ds` |
| S7 identity | an inline `<svg>` with path data outside `<Icon>` / `<Logo>` while the system ships `preview/logo.*` or an icon map | delegated to keeper A.8; severity per DDR-141 | — |
| S8 fonts | `@font-face` in canvas sources; an import of a CSS with `@font-face`; a `<link>` to a font service; a literal `font-family` not in the system's `--font-*` stacks | `font` → warning / warning | — |
| S9 meta | a canvas outside `system/` has no `.meta.json`, or `meta.designSystem` is absent or not a `config.designSystems[].name` | `meta` → blocker | — (needs a decision; `/design:new` always writes it) |

- **Change-scoped linting.** For `/design:edit` (`--changed <file>:<from>-<to>`), findings are reported only on
  changed lines, so legacy debt doesn't block an unrelated edit.
- **Fix invariants** (`--fix=mechanical`): byte-minimal, idempotent, and the element ids / `data-cd-id`
  survive (V2-1.4 check). Only `alias`, `own-css` and `wrapper` are mechanical.
- **Switch** (S10 builds; data here):
  - Rewrite `meta.designSystem` and delete `meta.dsRev`.
  - Write `meta.dsPairing` only for slot names the target lacks, paired per §5.3.5 using the source system's counts
    at switch time. The shell emits the pairing as canvas-scoped aliases (`--display-4: var(--display-3)`).
  - The switch touches no canvas source; the AI restyle pass (pins only, one undo step) is a separate AI run.
  - A switch to or from an `11` system is refused: the dialog offers Bring-up.

### 5.8 `maude design ds-check`

```
maude design ds-check [<ds>… | --all] [--canvas <file>… | --canvases] [--changed <file>:<from>-<to>…]
                      [--json] [--quiet] [--hook] [--cheatsheet]
                      [--emit] [--fix=mechanical [--dry-run]] [--root <repo>]
```

- **Reads** `.design/config.json`, plus, per system: `tokensCssRel`, `preview/_components.css`, `tokens.json`,

- **Permission tiers** (A13, V2-2.4b): without a write flag it is read-only and auto-approved. `--emit` and `--fix`

- **Delivery** (DDR-062 / DDR-177): `apps/studio/bin/ds-check.sh` → `_ds-check.mjs` under the bundled bun. Its

### 5.10 "Bring it up to the schema" — the engine (`ds-upgrade`)

**Entry points.**

- **In the app** (13 `ds-multi-schema`): the amber dot, or a switch to or from an 11 system, opens the dialog.

## Decisions

- `decision:maude/v2-1.13-registry-single-file`
  - **What:** `apps/studio/schema/ds-schema-v1.json` plus its JSON Schema is the one source for roles, types, theme
    rule, suffixes, slots, own namespace, aliases, collisions, components, icons, type roles, S-rules and levels.
    Critics, keeper, templates, fallbacks and the cheat-sheet read it or are generated from it.
  - **Freeze rule:** required content is frozen in v1; aliases, `judgement` rows and recommended components are
    additive.
  - **Why:** G §6 E1; A13 (a readable file Claude and the CLI read without bun).
  - **Rejected:** a TypeScript registry; per-project overrides.
- `decision:maude/v2-1.13-structural-collisions-only`
  - **What:** levels depend on presence, per-theme presence of colour roles, value type, and `type` / `signature`
    collisions. Value relations (`--bg-4` order, studyfi spacing multiples, accent lightness) are `notes` for the
    Bring-up AI step.
  - **Why:** A14 "structure, never values"; DDR-043.
  - **Rejected:** ordering and lightness collision checks (G §1.5 as a gate).
- `decision:maude/v2-1.13-per-system-fallbacks`
  - **What:** fallbacks are generated from the registry. The shell injects inline, before the tokens, in
    `@layer maude.fallback`, only the roles and classes a system never declares. No inversion for single-theme
    systems; neutral non-colour fallbacks (tracking `0`).
  - **Why:** the unfiltered layer shadows `:root`-only system values in nested theme wrappers. A per-system subset
    can never shadow, and changes no pixel in this repo.
  - **Rejected:** G §4.6's all-roles block on every `[data-theme]`; a new canvas-origin route for the CSS; a
    computed dark inversion.
- `decision:maude/v2-1.13-levels-and-exit-codes`
  - **What:** systems Conformant 0 / Missing roles 10 / Private-only 11, with the §5.6 reason table. Canvases
    `switchable` / `review` / `blocked` / `pinned`. `ds-check` exit 12 for canvas blockers, 13 for a refused write,
    1 / 2 for error / usage.
  - **Why:** the `bootstrap-check` and `migrate` precedents. A canvas with a blocking finding can't be honestly
    called switchable or review.
  - **Rejected:** three canvas levels only.
- `decision:maude/v2-1.13-pins-computed-not-stored`
  - **What:** switchability pins (`literal-colour`, `--x-*`, `--c-*`, `ext.*`) are computed by `ds-check` and the
    usage index; only the explicit `meta.dsPinned: true` is stored. `dsPins` stays reserved with no writer. A switch
    writes `meta.dsPairing` only for slot indices the target lacks.
  - **Why:** the keeper is read-only; derived data in versioned meta goes stale, churns, and arrays without `id`
    conflict in `mergeJson`.
  - **Rejected:** the keeper writing `meta.dsPins` (G E6/E7).
- `decision:maude/v2-1.13-two-verbs-ds-check-ds-upgrade`
  - **What:** `maude design ds-check` is deterministic and fast, read-only unless `--emit` or `--fix=mechanical`
    (canvas fixes only), with a non-blocking `--hook` mode and `--cheatsheet`. `maude design ds-upgrade` is the
    Bring-up engine: analyse → mechanical plan → AI judgement → validate (V1–V8) → stage (before/after copies) →
    prove (headless per-artboard ΔE diff) → review (four lines) → apply as one undo step behind the dialog or the
    permission card. It is never implicit.
  - **Why:** the PostToolUse budget, A13 permission tiers, A16 consent.
  - **Rejected:** `ds-check --plan --apply` (G E2); system edits in `--fix`.
- `decision:maude/v2-1.13-c7-fix`
  - **What:** C7 counts families as 1 + distinct `--accent-N` indices. Sub-roles (`hover active fg soft on-soft text
    glow`), inverted aliases and legacy accent names never count.
  - **Why:** today's suffix strip false-fails maude (2) and maude-v2 (3) under `single` (§6).
  - **Rejected:** extending the sed suffix list (it would still count `--accent-tint`-style native names).
- `decision:maude/v2-1.13-ds-virtual-module`
  - **What:** `@maude/ds` resolves per canvas build to `system/<ds>/preview/_ds.tsx` or the canvas-lib defaults
    (14 core + Logo / Icon / Text + `ext`). `<DSRoot>` renders `class="ds" data-theme`. Every theme block lists
    `.ds[data-theme]`.
  - **Why:** G B4 (78 canvases with hard-coded wrappers) and B6 (24 kit importers).
  - **Rejected:** keeping root-class wrappers, or direct `system/<ds>/preview/_*` imports.
