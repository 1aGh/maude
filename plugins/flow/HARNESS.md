# Host conventions

Use these conventions in Claude Code and Codex. They translate names in the shared Markdown; they do not change the workflow's checks or the host's permissions.

- **Invocation.** `/flow:verb` denotes `commands/verb.md`. Claude Code exposes that command directly; Codex exposes `$flow:source-command-verb`. Ordinary skills keep `$flow:skill-name` in Codex. Use the installed skill catalog to locate another plugin; never guess its cache version. A `Skill` call means load that skill with the host's native mechanism, or read its entry file when no Skill tool exists. Follow only references needed for the current step; do not preload whole directories.
- **Arguments and paths.** `$ARGUMENTS`, `$BRIEF` and positional placeholders mean the user's supplied workflow input. Codex does not interpolate Claude command templates: parse the message and bind needed values explicitly before using shell examples; never execute an unresolved placeholder. Project paths belong to the target project. Plugin paths belong to the installed plugin containing this file. Resolve Markdown links relative to the file containing them. Where old prose uses `$CLAUDE_flow_ROOT`, resolve this plugin root from the loaded file; do not assume that variable exists in an ordinary shell. Use `maude` for executable helpers.
- **Tools and models.** `Read`, `Edit`/`Write`, `Bash`, search and screenshot names describe operations; use the host's actual tools. Inherit the user's selected model and reasoning settings. Do not translate Claude model names to guessed OpenAI model IDs or hardcode model choices.
- **Specialist roles.** Claude uses the registered `flow:role` agent. In Codex, use a native subagent, supply the bounded task and absolute path to `agents/role.md`, and require it to read that role and its relevant references before acting. Include needed project context and explicit role restrictions; children may not inherit loaded skills. Never silently skip a required reviewer. If subagents are unavailable, report that limit and use only a fallback already allowed by the workflow. Markdown `tools:` restrictions are not an enforced Codex whitelist: if a task needs a hard isolation boundary, require an equivalent native permission setup or stop that task. Do not describe a generic child as sandbox-isolated merely because it received a role file.
- **Questions and teams.** `AskUserQuestion` means the host's available question UI, or a concise chat question when no suitable tool is available. Respect the current host mode and session authorization; collect only missing answers and do not ask again for an already authorized action. A suggested default is not approval. Team relay requires actual native messaging; an environment flag alone proves nothing. Otherwise use the debate protocol's independent review and consolidation mode.
- **Dependencies and memory.** Install both Maude plugins for the complete workflow set. Before a workflow needs a CLI, MCP server or external skill, check availability and use its documented fallback or report the missing capability. Installation of Markdown does not install these dependencies. When recording or consulting decisions, load `flow:kgai-backend`. Perform its read/write checkpoints explicitly; do not rely on a Claude transcript hook firing in Codex. Hooks may be untrusted or unavailable. Never enable kgai, approve store trust, change stores or configure remote sync merely to make a check pass.

For project instructions, Claude reads `CLAUDE.md`; Codex reads `AGENTS.md`. Keep the active host's file current through `flow:claude-md-keeper`. Never mechanically replace product names, tool names, URLs or filenames throughout an existing instruction file.
