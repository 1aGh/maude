# Map Codebase: Architecture Snapshot

Follow [host conventions](../HARNESS.md) for Claude Code or Codex.

## Objective

Produce a structured snapshot of the project's architecture, stack, conventions, and key files. The output is written to `.ai/context/codebase-map.md` so that other commands (`plan-feature`, `execute`, `verify-work`) can read it instead of re-discovering the repo from scratch every session.

## Package Manager Auto-Detection

> This command uses `<pm>` as a placeholder for your package manager. Detect it:
>
> - `pnpm-lock.yaml` → `pnpm`
> - `yarn.lock` → `yarn`
> - `package-lock.json` → `npm run`

## Process

### 1. Detect Project Type

- Check for monorepo indicators: `pnpm-workspace.yaml`, `lerna.json`, `nx.json`, `turbo.json`
- If monorepo, identify the workspace root and enumerate packages/apps
- If single-repo, treat the root as the sole project

### 2. Map Directory Structure

```bash
# Top 3 levels, excluding build/dependency artifacts
find . -maxdepth 3 -type d \
  -not -path '*/node_modules/*' \
  -not -path '*/.git/*' \
  -not -path '*/dist/*' \
  -not -path '*/build/*' \
  -not -path '*/.next/*' \
  -not -path '*/coverage/*' \
  | sort
```

### 3. Identify Key Files

Scan the root and first-level directories for:

- **Entry points:** `src/index.ts`, `app/`, `pages/`, `main.ts`
- **Config:** `tsconfig.json`, `vite.config.*`, `next.config.*`, `jest.config.*`, `vitest.config.*`, `.eslintrc.*`, `eslint.config.*`
- **CI:** `.github/workflows/`, `.gitlab-ci.yml`, `Jenkinsfile`
- **Tests:** `__tests__/`, `*.test.*`, `*.spec.*` — note the pattern and runner
- **Docs:** `README.md`, `CLAUDE.md`, `CONTRIBUTING.md`, `docs/`

### 4. Extract Framework Versions

```bash
# Read versions from package.json(s)
cat package.json | grep -E '"(react|next|vue|angular|express|fastify|typescript|vitest|jest)"' || true
```

For monorepos, also check workspace root and key app `package.json` files.

### 5. Detect Conventions

- **Naming:** Are files kebab-case, camelCase, PascalCase?
- **Imports:** Absolute paths (`@/`) or relative (`../`)?
- **Test framework:** vitest, jest, mocha, playwright?
- **Linting:** eslint, biome, prettier?
- **Commit style:** Check `commitlint.config.*`, `.commitlintrc.*`, or commit history

### 6. Read Project Constraints

- Read `CLAUDE.md` (or `.claude/CLAUDE.md`) for hard rules, prohibited packages, and conventions
- Read `.ai/workflows.config.json` for structured identity, platforms, tracker, boundaries
- Read any `.claude/rules/*.md` for path-scoped constraints
- Read any `.ai/docs/rules.md` for app-scoped constraints

### 6.5 Map Design Artifacts (design plugin)

If the project uses the design plugin, capture its canvas workspace so a fresh session sees the design surface alongside the code. **Read-only.**

1. Resolve the design root: `paths.designRoot` from `.ai/workflows.config.json` (default `.design`). If the directory doesn't exist → skip this section entirely.
2. Read `<designRoot>/config.json` → `designSystems[].name` + `defaultDesignSystem` for the list of design systems.
3. Walk `<designRoot>/**/*.meta.json` (excluding `_history/`). For each, read `title`, `designSystem` (falls back to `defaultDesignSystem`), `status` (default `draft`), `tags`, and `last_modified`.

```bash
DESIGN_ROOT=$(jq -r '.paths.designRoot // ".design"' .ai/workflows.config.json 2>/dev/null || echo ".design")
if [ -d "$DESIGN_ROOT" ]; then
  jq -r '.defaultDesignSystem as $d | .designSystems[]? | "- \(.name)\(if .name==$d then " (default)" else "" end): '"$DESIGN_ROOT"'/system/\(.name)/"' "$DESIGN_ROOT/config.json" 2>/dev/null
  find "$DESIGN_ROOT" -name '*.meta.json' -not -path '*/_history/*' 2>/dev/null | wc -l
fi
```

### 7. Write Output

Create directory if needed:

```bash
mkdir -p .ai/context
```

Write the structured snapshot to `.ai/context/codebase-map.md`.

## Refresh

Re-run `/flow:setup-codebase-map` at any time to update the snapshot. The command always overwrites `.ai/context/codebase-map.md` with the latest data.

**When to refresh:**

- After adding a new app or package
- After major dependency upgrades
- After changing CI configuration
- When the map feels stale (>7 days old)

## Usage by Other Commands

Commands like `plan-feature`, `execute`, and `verify-work` should:

1. Check if `.ai/context/codebase-map.md` exists
2. If it does, read it before doing ad-hoc codebase analysis
3. If it doesn't, suggest running `/flow:setup-codebase-map` first but continue without it
