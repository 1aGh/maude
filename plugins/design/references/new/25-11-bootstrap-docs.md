### 11. Bootstrap docs

For a new canvas:
1. **Add to the `.meta.json` the create wrote** (one Edit of the existing file, never a new one): `title` stays; set `subtitle` (one line from the brief), `brief` (the brief, verbatim), `platform` (`mobile` with `--mobile`), `sections` + `artboards` extracted from the drafted JSX, **`opt_out_scope` from step 4**, and **`brief_sha: $BRIEF_SHA8` from step 3.6** — the byte-identical-brief key the step-3.6 short-circuit scans on the next run. `designSystem` and `kind` were set by the create; leave them. Subsequent `/design:edit` iterations on this canvas read these fields and inherit the scope + DS automatically — no re-asking on every edit. In multi-DS projects, the `designSystem` field is what `flow:design-system-guard` and `design-system-completeness-critic` use to scope their checks to the right DS. **(BLANK mode ends in step 3.5 and INGEST adds `annotations_sha` in step 6b — neither reaches this normal-mode addition.)**
2. **If `<DESIGN_ROOT>/INDEX.md` doesn't exist** → invoke `/design:setup-docs --full` (regenerates both INDEX.md and README.md from all canvases). **Do NOT improvise a hand-written INDEX.md** — `/design:setup-docs` is the source of truth and the AUTO-MAINTAINED marker depends on it. Improvised INDEX gets overwritten on next `/design:setup-docs` run, and any rows added by hand are lost.
3. **Else** (INDEX.md exists) → add a row to `<DESIGN_ROOT>/INDEX.md` for the new canvas (or invoke `/design:setup-docs` without `--full` to do the incremental update for you).
4. If `<DESIGN_ROOT>/README.md` doesn't exist after step 2, generate it via `/design:setup-docs --full` flow.
5. Update `<DESIGN_ROOT>/README.md` "Last updated" line. **This step is non-skippable** — if you used `/design:setup-docs --full` in step 2, it's done; if you wrote the INDEX row by hand, you must update README too.
