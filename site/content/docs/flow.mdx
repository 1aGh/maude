Ten commands. The daily verbs stay one-word terse (`plan`, `execute`, `validate`, `done`); the rest wear a group prefix (`bug-rca`, `bug-fix`, `record-ddr`). Variants are flags, not separate commands: `/flow:validate --security`, `/flow:plan --prd`, `/flow:execute --quick`. Coming from the older 30-command surface? See [Flow migration](/docs/flow-migration).

The canonical catalog: [`plugins/flow/CATEGORIES.md`](https://github.com/1aGh/maude/blob/main/plugins/flow/CATEGORIES.md). Live command list: Claude Code's native `/help`.

## Setup. One-shot bootstrapping

Run once per project (or once per major restructure).

| Command | What it does |
| ------- | ------------ |
| `/flow:init` | Scaffold `.ai/`, auto-detect stack, populate `workflows.config.json`, defer to `/init` for `CLAUDE.md`. |
| `/flow:init --context` | Prime the agent with the codebase map + `CLAUDE.md`. |
| `/flow:init --map` | Snapshot architecture into `.ai/context/` for cross-session reuse. |
| `/flow:init --kgai` | Import existing decisions into the kgai knowledge graph. |
| `/flow:plan --prd` | Draft a PRD + auto-generate phase plans + execution README. |

## Daily. Every-cycle workflow

| Command | What it does |
| ------- | ------------ |
| `/flow:plan "<feature>"` | Context-rich feature plan grounded in PRD + design system. |
| `/flow:execute [plan-path]` | Execute an implementation plan task-by-task with an Edit-Verify loop. Slices are delegated to the `flow:worker` role agent. |
| `/flow:execute --quick` | Trivial-change fast-path. Skip plan cycle, go edit, verify, commit. |
| `/flow:run <plan>` | Drive a plan to completion as a goal. Opt-in capped Stop hook; `--pause`, `--resume`, `--status`, `--stop`. |
| `/flow:validate` | Full pipeline: static + tests + build + scenario + a11y + design. |
| `/flow:done` | `/validate` gate, DDR sweep, commit, push, PR, execution report, retro, archive. |
| `/flow:release` | Walk the project's release runbook step-by-step with explicit confirmation. `--changelog` authors the changelog entry. |

## Validate. One command, several lanes

`/flow:validate` runs the pipeline; flags run a single lane.

| Command | What it does |
| ------- | ------------ |
| `/flow:validate --fast` | Light scoped per-file check (what the Edit-Verify loop runs). |
| `/flow:validate --security` | Security review (`security-auditor` + `ethical-hacker` subagents), aggregated report, gates on `severityFloor`. |
| `/flow:validate --a11y` | Accessibility audit (WCAG 2.1 AA). |
| `/flow:validate --visual` | Visual regression check with screenshots. |
| `/flow:validate --review` | Pre-commit self-review of uncommitted changes. |
| `/flow:validate --scenario` | Cross-platform UI scenario with screenshot evidence. |

## Bug. Incident workflow

| Command | What it does |
| ------- | ------------ |
| `/flow:bug-rca <issue-id>` | Analyze and document root cause for a GitHub issue. |
| `/flow:bug-fix <issue-id>` | Implement the fix from the RCA document. |

## Record. Knowledge capture

| Command | What it does |
| ------- | ------------ |
| `/flow:record-ddr "<title>"` | Record a Design Decision Record. |

The execution report and the retrospective are now steps of `/flow:done`.

## Role agents

`/flow:execute` and `/flow:run` hand bounded work to three role agents: `flow:worker` (implements one self-contained task slice), `flow:spike` (answers one open question with a throwaway prototype) and `flow:scout` (read-only inventory). The `flow:context-budget` skill holds the rules for what each may read and return.
