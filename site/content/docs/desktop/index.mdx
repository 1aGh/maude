The **desktop app** is Maude with no terminal. Download it, open a project, and start designing — canvases, Version history, sharing and AI all live in the window. It keeps itself up to date in the background.

New here? [Getting started](/docs/getting-started) walks from download to first canvas. [Around the window](/docs/desktop/window) names every piece of the screen.

## Install

1. **[Download](/desktop)** the installer for your platform — `.dmg` (macOS), `.msi` (Windows) or `.deb` (Linux).
2. Open it. On macOS, drag Maude to Applications; on Windows, run the installer; on Linux, `sudo apt install ./Maude_*.deb`.
3. Launch Maude. It opens on **Home**: say what to make, start with an empty canvas (<kbd>⌘N</kbd>), **Open project…** (<kbd>⌘O</kbd>), or sign in to Maude Cloud.
4. You land in a working project. No terminal at any step.

### System requirements

| Platform | Minimum | Installer |
| -------- | ------- | --------- |
| macOS    | 13 Ventura (Intel or Apple Silicon) | `.dmg` |
| Windows  | 10 (64-bit) | `.msi` |
| Linux    | Debian 12 / Ubuntu 22.04 (64-bit), WebKitGTK 4.1 | `.deb` |

Disk: ~250 MB. AI runs on your own Claude account (Pro or Max, or an API key) — see [What AI needs](#what-ai-needs). Codex and opencode can run in the chat too: [Other AI agents](#other-ai-agents-advanced).

### Media playback on Linux

Linux renders canvases through WebKitGTK, which plays a canvas's audio and video through **GStreamer**. Installing the `.deb` with `apt` pulls the plugin packages in for you and there is nothing more to do.

Installing any other way — a repackaged `.deb`, a distro package, an extracted tree — you need them yourself, because most distros ship them as *optional* dependencies of WebKitGTK. Without them a canvas containing audio or video takes the whole view down with no error message.

<Callout type="warn" title="Install the GStreamer plugins">
| Distro | Command |
| ------ | ------- |
| Arch / Omarchy | `sudo pacman -S --needed gst-plugins-good gst-plugins-bad gst-libav` |
| Debian / Ubuntu | `sudo apt install gstreamer1.0-plugins-good gstreamer1.0-plugins-bad gstreamer1.0-libav` |
| Fedora | `sudo dnf install gstreamer1-plugins-good gstreamer1-plugins-bad-free gstreamer1-libav` |

Maude checks for these at launch and posts a notification naming the command for your distro if they are missing.
</Callout>

**On AMD graphics**, Maude also sets `WEBKIT_GST_DISABLE_GL_SINK=1` for itself at startup. GStreamer's GL video sink asks Mesa's `radeonsi` driver for a colour-buffer format it rejects, and the pixel readback that follows faults — an upstream bug that kills the view a few seconds into playback. The workaround decodes video in software instead; the cost is some CPU. To opt out and keep the GL sink, set the variable yourself before launching:

```sh
WEBKIT_GST_DISABLE_GL_SINK=0 maude-desktop
```

Any value you set wins — Maude only fills it in when you have expressed no preference.

### What AI needs

Canvases, Version history and sharing work the moment you open the app — no extra setup. **AI** is the one part that reaches outside it, and it runs on your own Claude account.

The first time you use **Ask AI**, one sheet asks you to **Connect** your Claude account. Maude sets up what it needs and opens your browser to sign in; your prompt waits and runs as soon as you are connected. Nothing to install by hand, and nothing blocks the rest of the app while AI is not connected.

<Callout type="info" title="The plugins are already loaded">
The AI chat panel loads the `design` and `flow` plugins into its own session, so `/design:*` and `/flow:*` resolve with nothing to add to a marketplace. A power user who also installed the plugins gets a no-op — no double-load, no version skew.
</Callout>

If AI stops working, **Menu › Diagnostics › AI setup** lists each piece with a status word and a fix for whatever is missing, and **Check AI setup again** re-runs it. The `maude` command-line tool is only needed for the longest multi-step `/design:*` workflows (screenshots, critic passes); the everyday "change this canvas" path works without it. See the [CLI](/docs/cli) when you want it.

### Other AI agents (Advanced)

Claude is the AI Maude is built around, and it stays the one the app asks you to connect. If you already use another coding agent, the chat can run it too.

- **Maude only looks at what is on this Mac.** When it finds Codex or opencode installed, the empty AI chat shows one quiet line: *Codex is on this Mac. Use it in Maude too?* **Connect** starts that agent's own sign-in. **Not now** hides the line for good. Nothing else changes, and a Mac with only Claude sees nothing new.
- **Settings › Connections › AI agents** lists every agent Maude found, with its state: Connected, Sign in, Untested version, or Unavailable.
- **Pick the agent per chat.** With two or more agents connected, a small chip in the composer picks the agent for a new chat. A chat keeps the agent it started with.
- **The same limits as Claude.** Maude starts Codex and opencode with its own rules: they read your project and the folders you granted, write only inside the project, never your passwords, keys or Maude's own settings, and stay off the web. Before an agent's first chat, Maude checks on this Mac that those rules hold, and it stops an agent that steps outside them. Replies and errors are labelled with the agent's name, so you know who said what.
- **Agents Maude cannot confine** (Gemini CLI, GitHub Copilot CLI, Goose, Cursor agent, for now) sit under **Advanced** in that card. They run only after you allow them for a project.
- **Your own API key.** Under **Advanced** you can give an agent its own API key instead of its sign-in. Claude can use an Anthropic API key too: that bills the API account, not your Claude plan, so it is off until you turn it on.

Codex runs through Maude's bundled adapter and **your own `codex` install** (0.154 or newer). Install Codex the way OpenAI describes, sign in once, and Maude finds it.

## Auto-update

Maude polls a signed release feed and downloads new versions in the background. When one is ready a quiet callout says so, with one action: **Restart now**. Click it and you're on the latest build. To look yourself, use **Maude › Check for Updates…** in the Mac’s own menu bar or **Settings › Advanced › Check for updates**. There's no `npm install`, no terminal. Updates are signed with an ed25519 key; the app refuses any update whose signature doesn't verify, so a tampered feed can't push a rogue build.

## Unsigned builds (early releases)

Until platform code-signing certificates are wired, installers may be **unsigned**:

- **macOS** — Gatekeeper blocks the first launch. Right-click the app → **Open**, then confirm. You only do this once.
- **Windows** — SmartScreen shows a warning. Click **More info → Run anyway**.

Signed builds remove these prompts; auto-update artifacts are always signed regardless.

## Teams

The desktop app connects to a self-hosted [hub](/docs/hub) under **Settings › Connections** — no `maude design link` in a terminal. Once linked, cursors, comments and edits sync in real time with everyone on the project. To invite people to a Maude Cloud project, use **Share…**; see [Share links](/docs/share-links).

## What's included

- **Canvases** — every canvas is a live, multi-artboard surface; the Canvases panel lists them, with Layers and Assets beside it.
- **Version history** — every saved version of the project with **Restore**, and <kbd>⌘Z</kbd> for the last step (AI's changes included).
- **Sharing** — one Share sheet: Invite people, Copy link, Move to Maude Cloud…. Live collaboration over Maude Cloud or your own hub.
- **AI** — an AI chat panel and **Ask AI** (<kbd>⌘/</kbd>) on your own Claude account.
- **Export** — one Export sheet (<kbd>⇧⌘E</kbd>) for images, PDF, video and handoff.
