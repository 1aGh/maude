Most design tools bolt AI onto a human workflow. Claude's own canvas is a chat box that forgets everything by morning. Maude is built around Claude from day one, so canvases are real files, and the same repo-native model runs `flow`'s plan-to-ship loop too. That's the whole pitch.

**Start with the desktop app.** Download it, open a project, say what to make. No terminal, no signup to try it, no telemetry. <kbd>⌘K</kbd> searches everything.

Open-source. MIT. If it crashes, `git pull` and try again. That's the entire support contract.

## Advanced / Explore Maude

Everything the desktop app does is also available from a terminal, a plugin or a server you run yourself. None of it is needed to get started.

- **`design`**. Canvas-first iteration on `.tsx` canvases under `.design/`, driven by `/design:*` slash commands in Claude Code or Codex. Select an element and the next `/design:edit` knows which one you mean.
- **`flow`**. The agentic loop that ships things eventually. Second-brain `.ai/` workspace, project-agnostic via per-repo `workflows.config.json`. Same plugin runs in Next.js, Expo, Go, anything.
- **`maude`** (legacy alias: `mdcc`). Small CLI. Scaffolds the `.ai/` workspace, reads and writes config, boots the design dev server, runs health diagnostics (`doctor`), manages the sidecar cache, and hosts the optional sync hub.

<Callout type="info" title="Claude Code and terminal Codex">
The same canvas and workflow procedures are available through
[native Codex plugins](/docs/codex). Codex can drive Studio through the Maude CLI,
project files and browser tools. This does not switch Studio's built-in ACP chat.
</Callout>

## Why both plugins together?

The two plugins share a worldview. **Claude Code is the IDE. The repo is the source of truth.** Decisions get written to `.ai/decisions/`. Plans get archived to `.ai/plans/archive/`. Design mocks live in `.design/` next to the production code they precede. Nothing lives only in a chat scroll.

Install one, install both. They're independent.
