## Context

FigJam-parity v3 adds the manipulation layer (grouping, duplicate, z-order, align, snapping, connector binding) and a bidirectional AI surface to the annotation system. Three data-model decisions shape everything downstream and deserve a record. Constraints: the whole `.annotations.svg` is ONE LWW value in the collab Y.Map (no per-stroke CRDT until Phase 10), legacy files must round-trip byte-identically (the Phase-24 canary), and the sanitizer is an element allowlist + attribute denylist over a fixed vocabulary.

## Decision

1. **Groups are a flat tag-array, not a parent node.** Every stroke carries optional `groupIds: string[]`, ordered deepest → shallowest (outermost = LAST element) — the Excalidraw model, serialized as `data-group-ids="g_a g_b"`. There is no group element; selection logic expands a clicked stroke to everything sharing its outermost id. tldraw's lifecycle rules are copied as pure helpers (`normalizeGroups`: empty group self-deletes, singleton dissolves; `groupStrokes` reorders members contiguous at the front-most member's z). *Why:* a flat attribute survives the whole-SVG LWW sync with zero reparenting transactions, fits the sanitizer (one inert attribute on existing elements), and is trivially legible to AI readers. A parent-node model (tldraw) buys transform inheritance we don't need — annotations have no nested transforms.

2. **Arrow binds are embedded on the arrow, single-sided.** `startBind`/`endBind: { hostId, nx, ny }` with the anchor normalized over the host bbox and snapped to the {0, ½, 1}² magnet grid (FigJam connector magnets, Excalidraw `fixedPoint` semantics); serialized `data-start-bind="<id> <nx> <ny>"`. No reverse index on hosts (Excalidraw's `boundElements`): per-canvas stroke counts are small, so `recomputeBoundArrows` linear-scans — one attribute, one owner, no two-sided consistency to maintain. Bound endpoints are DERIVED from the host on every mutation; deleting the host strips the bind and freezes the endpoint (arrow survives — Excalidraw `fixBindingsAfterDeletion`). The stored x1/y1/x2/y2 stay authoritative for legacy consumers.

3. **The AI write surface is a CLI verb, not an HTTP route.** `maude design annotate` (Bun, `bin/annotate.mjs`) consumes a typed ops vocabulary (`create` sticky/text/shape/arrow, `connect`, `group`, `delete`) plus a `--flow` nodes/edges mode with layered auto-layout. It renders strokes through the CANONICAL serializer and the same allowlist sanitizer (both moved to React-free `annotations-model.ts` precisely so a headless consumer can import them), then PUTs to a live server (collab broadcast → open canvases update live) or writes the file directly. *Why:* DDR-054 keeps privileged/agent surfaces off canvas-reachable HTTP; DDR-062 makes `maude` the plugin-to-executable contract; and a typed op vocabulary (the @tldraw/ai pattern) means the model can never hand-author SVG that drifts from the schema. Every AI stroke is stamped `data-author="ai"` (provenance, filterable) and never enters a user's local undo stack. `update` is deliberately absent from v1 — delete + recreate keeps the verb honest about LWW. *(Amended by [DDR-242](./DDR-242-annotations-v2-element-model.md): v2 syncs per element, so `annotate` now has `update`; the board is `<slug>.annotations.json`, and the SVG serializer survives only for migration and legacy paste — see also [DDR-244](./DDR-244-annotations-v2-stroke-view-is-the-editing-end-state.md).)*

Supporting calls riding on these: z-order stays plain array order (no fractional index — whole-SVG LWW has no concurrent reorder to reconcile); the strokes clipboard is a `{"maudeStrokes":1}` JSON text payload on the OS clipboard (works cross-canvas, never collides with the media-intake paste because the capture-phase listener claims it first); the model extraction (`annotations-model.ts`) is the DDR-067 single-source rule applied one level up — serializer, parser, sanitizer, and geometry live React-free so the canvas, tests, and the annotate verb share one implementation.

## Consequences

- A future Phase-10 per-stroke CRDT can keep all three choices: flat `groupIds` and embedded binds map 1:1 onto per-stroke map entries.
- The sanitizer needed NO new elements — all v3 state is inert `data-*` attributes on the existing vocabulary (poisoned bind values clamp on parse, mirroring the arrowhead rule).
- Concurrent AI write + live user drawing is LWW over the whole file; the verb's contract says read-then-write and the help text warns. Acceptable until Phase 10.
- ~~Anchored-text labels on polygons are impossible~~ — **resolved in Wave G**: `AnchorHost = RectStroke | EllipseStroke | PolygonStroke`, so diamonds/triangles host centered text identically to rect/ellipse (and the `annotate` verb anchors their labels too).

## Addendum — security posture (Wave H review)

A defender + ethical-hacker pass on the closing diff found the classic surfaces clean (no new HTTP route, byte-faithful sanitizer move, `fileSlug` slash-flattening blocks traversal, no shell/exec/proto-pollution in `annotate.mjs`, paste re-serializes through the canonical sanitizer + re-mints ids). Three hardening fixes landed in response, plus one documented residual:

- **Egress allowlist (annotate F2).** `annotate.mjs` PUTs to `_server.json.url` only when that resolves to a **loopback http(s) origin** (`isLoopbackHttpUrl`); any other host falls back to the local file write. The dev-server is loopback-only (DDR-054), so this closes the SSRF/exfil primitive a poisoned/foreign `_server.json` would otherwise open (the Wave-G foreign-worktree `_server.json` incident was the benign demonstration).
- **Non-finite geometry clamp (parser F4).** `svgToStrokes` now routes every geometry parse through `pfloat()` (`Number.isFinite ? v : fallback`) and `polygonBBox` skips non-finite vertices. Previously a synced `x="1e999"` survived as `Infinity` into render math while `read-annotations`'s `num()` coerced it to `0` — the AI reader and the human saw the stroke at different positions (a content-spoof side-channel). Both views now agree on finite coords.
- **`data-author` is provenance, NOT trust.** The value is clamped to the literal `"ai"` on parse, but a peer SVG can still *carry* it, so it must never gate trust. Recorded in the SKILL.md trust-model note; agents that run an autonomous read→write loop must treat all `read-annotations` content (author field included) as untrusted, and keep untrusted-text ingest out of any context holding an exfil channel (the prompt-injection trifecta — mitigated structurally for the verb by the loopback egress, behaviorally for the loop by the doc guidance).
- **Residual (accepted, pre-existing):** `PUT /_api/annotations` accepts an arbitrary `file` from the canvas origin (LWW sibling overwrite) — inherited unchanged from before this feature, governed by DDR-054; the `annotate` verb adds no new exposure.
