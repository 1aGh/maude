## P0 — the AI chat / CLI cannot export at all (2.1.0 loopback-key regression)

### B1 · `maude design export` → 401 `api-key-required` against the app (also #221)
- Confirmed in code: `cli/commands/design.mjs` ~1068 POSTs `/_api/export` (and `-estimate`,
  `-preflight`) with only `content-type` — it never uses `studioHeaders`/`studioHeadersFor`
  (`cli/lib/studio-locate.mjs`). Phase-2 key gate refuses it. Same class as the hub-signin return
  fixed in 2.1.1 (0fa21f6b6): sweep every CLI/helper loopback fetch for a missing key
  (`grep -rn 'fetch(\`http://\(localhost\|127\)' cli apps/studio/bin` — the perf probes too).
- Second half: `desktop-locate.mjs key --root <repo> --port 46401` exits 11 (unverified) although
  the app's server is live and answering — the attest/registry path never hands the CLI a key, so
  even a fixed export call has nothing to send. Find why attest returns unverified for an app-owned
  server (servers.json / cli.sock path).
- `maude design exports again <id>` works (goes through the app socket) but only replays an old
  spec. A new export (scope, `text=outline`, …) must be possible from the CLI and from the AI chat.
- Tests: fail-first — CLI export against a required-mode server succeeds with the key, refuses
  without; desktop-locate verifies an app-owned server.

## P1 — export quality

### B3 · Print PDF: an artboard outside the viewport comes out without images and webfonts
- LetakA6 Print PDF (canvas-as-separate): page 3 (first artboard of section 2) had no `<img>`
  (group photo, QR) and the COLR font SignsColor/SignsFill fell back to Times-BoldItalic; pages
  1, 2, 4 fine. Uniformy-2027 page 3 same. Selection-only export of that artboard is fine; a warm
  re-run is fine → a race.
- Cause per code: `apps/studio/bin/_pdf-playwright.mjs` waits on `document.fonts.ready` and the
  first `[data-dc-screen]` once after load, then per artboard pins to 0,0, `scrollIntoView`, and
  calls `page.pdf()` at once. `.dc-positioned` has `content-visibility:auto` (canvas-lib.tsx
  ~3506), so off-screen content neither renders nor loads until scrolled.
- Fix: per iteration after scroll wait for `document.fonts.ready` + every `<img>`/`<image>` in the
  artboard `decode()`/`complete` + 2× rAF; or turn `content-visibility` off for the capture.
  Same check in `_png-playwright.mjs` and the render service path.
