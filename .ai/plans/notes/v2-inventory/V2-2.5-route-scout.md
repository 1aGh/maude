## 1. How routes are registered today

- `createHttp(...)` at http.ts:1307 is one closure; everything below lives inside it.
- **`routes` map** (http.ts:1763 → ~6091): an object literal with 4-space-indented `'/path': (req) => …` keys, about 153 of them.
  - It opens with `...laneRoutes.exact`, then `/_health`, and closes with `/_hmr`, `'/'` and `/index.html`.
  - Each handler checks its own method and guard; nothing is centralised.
- **`guardedRoutes`** (http.ts:6630–6670) wraps every entry in `readOnlyRefusal(req) ?? handler(req)`.
  - The allowlist is `readOnlyAllowed` (1758), built from `READ_ONLY_ALLOWED_WRITES` (481), `READ_ONLY_ALLOWED_WRITE_PATTERNS` (545) and the lane specs.
- **`handleFallthrough`** (http.ts:6097) runs in this order:
  1. `laneRoutes.dynamic`;
  2. `/_api/comments/<id>/reply`;
  3. `/_client/`, `/_canvas-runtime/`, `/_canvas-shell`, `/assets/`, `/_stickers/`, `/_media/`;
  4. designRoot static files.
- **`CANVAS_SAFE_API`** (http.ts:6521–6537) is 11 exact paths, used only by `isCanvasSafeRoute` (6539).
  - Besides those, it allows `/_health`, `/_canvas-shell*`, comment-mount, client CSS, `/_canvas-runtime/*`, the comments-reply regex, designRoot assets and `/assets/*`.
- **`canvasRoutes`** (http.ts:6693) holds only `/_api/git-committers`, a projection without e-mails.
- **In server.ts:**
  - the `startCanvasServer` routes map (~578–612) has 12 hand-listed entries;
  - `captureRefusal` is at 554 and `readOnlyRoutes()` at 567;
  - canvas `fetch` (~620–686) runs: capture gate → collab WS → `/_ws` → shell → `isCanvasSafeRoute` 403 → `http.fetch`;
  - `pruneForWorkspace(http.routes)` is at 304.
- **The two canvas lists are hand-mirrored, and no test compares them.**

## 2. Precedent — `routes/table.ts`

- `RouteSpec { method: 'GET'|'POST', path (:param), origin: 'main', readOnly: 'allowed'|'refused', handle(req, params) }` at table.ts:8. `origin` is literally `'main'` only.
- `matchRoute` supports `:param` segments only.
- `mountRoutes(specs)` returns `{ exact, dynamic, readOnlyAllowed }`.
- Existing lanes: `routes/outbox.ts`, `routes/project-format.ts` (with a deps object).
- They are mounted at http.ts:1701 (`guardLane`, an origin + host double gate), concatenated at 1711–1727, `exact` spread first in `routes` (1764), and `dynamic` called first in the fall-through (6099).
- `test/routes-table.test.ts` covers dispatch, 405, dynamic and the read-only allowlist. It does not cover the http.ts wiring or canvas parity.
- Missing so far: a canvas origin flag, a per-spec guard kind, and prefix routes.

## 5. Risks of a move-only split

- **Shared closure state.** Handlers close over `ctx`, `api`, `projectReadOnly`, `roleReadOnly`, `readOnlyRefusalFor`, `gateNow`, `outbox`, `projectIndex`, `STAGED_FORMAT_GATE_OPTS`, the guards, and module helpers. Each `routes/<area>.ts` takes a deps object, as `ProjectFormatDeps` does. Never import a global `ctx`.
- **Order.** Exact `routes` entries run before `fetch`. In the fall-through, lane `dynamic` runs first, then the comments reply, then client/runtime/assets/stickers/media, then static files. A new `:param` table called earlier could shadow these.
- **Wrapping.** `guardedRoutes` applies `readOnlyRefusal`. A table mounted outside it bypasses the role and format gate (`guardLane` checks only origin and host).
- **Two allowlists, plus an implicit third.** The `/_api/comments/<id>/reply` regex is a third, fall-through-only entry. `/_api/git-committers` is served from `canvasRoutes`.
- **Workspace prune** iterates `http.routes` keys, so table keys must merge before the wrap.
- **Not verified:** per-route guard type for every group, duplicate keys, the full scraper list, the `/_api/comments/*` bodies beyond reply, and whether `canvasRoutes` needs the table too.

## Proposed split and first tests

- One table, `routes/index.ts` (`ALL_SPECS`). `RouteSpec` gains `origin: 'main'|'canvas'` and an optional `prefix`. `CANVAS_SAFE_API` and the canvas server map derive from the `origin: 'canvas'` specs.
- Extract new areas first.
- Files: `acp.ts` (acp/claude/preflight), `sync.ts` (sync/project/workspace/hub), `git.ts` (git/github/figma), `cloud.ts`, `media.ts` (export/generate/import), `edits.ts` (source edits + artboards), `canvas.ts` (the canvas-safe set), `misc.ts` (diagnostics/report/…).
- **Test 1, route table.** No duplicate path+method across the specs; `readOnly` agrees with `READ_ONLY_ALLOWED_WRITES`; mount order (a `:param` spec never shadows an exact route); `Object.keys(http.routes)` equals the table exact paths plus the legacy keys, with nothing lost.
- **Test 2, `CANVAS_SAFE_API` parity.** Every `CANVAS_SAFE_API` entry is a canvas-map key, and every canvas-map key is in `CANVAS_SAFE_API` or is `/_health`. `/_api/git-committers` comes from `canvasRoutes`. `/_api/export` and `/_config` are in neither list. Each canvas-safe route answers GET 405 on the capture origin.
