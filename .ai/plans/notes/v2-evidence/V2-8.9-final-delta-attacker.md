## Threat model

The new trust decisions in this delta are mostly about attribution:
- **Who made a change:** `bashMayWrite`/`READERS` decide whether a shell call opens the run's claim-only window. Outside the window, a change lands as the person's own "changed outside the app" action. That means no "Made by AI", no one-step AI Undo, and on a hub-linked project it is published as the person.
- **What the edit gate blocks:** `checkIntroduced` now blocks only findings it sees as new against a snapshot, so whoever controls when the snapshot is taken controls what the gate calls "pre-existing".
- **Hub-supplied undo data:** a hostile hub feeds the new undo-collision check its effects, blobs and lane heads.
- **Hub-supplied format:** a hostile hub feeds the format number, which is now written into the versioned `config.json` at detach and at pull.

The attackers are the four the repo names: canvas code, a hostile hub or peer, a malicious repo, and prompt injection that drives the agent.

One point bounds the impact of everything below. **None of these is an execution gate.** Nothing auto-approves a command because `bashMayWrite` returned false; the bridge's approval path never calls it. And the edit gate does not check any of the C4 rules: Bun macro imports, the import-extension allowlist and canvas-ness are not checker findings. `macro-guard.ts`, `closure.ts` and `isCanvasSource` enforce them at run time, so none of them can be waved through as "pre-existing". Artboard ids are re-checked against `ARTBOARD_ID_RE` by every consumer (edit-ops, comments, kinds, exporters). So the worst outcomes here are integrity problems: who gets credited, what Undo reverts, and how clean a run's report looks.

## Exploit chains

- **F1/F2 to F4 (gate laundering).** Either bypass plants a construct with no base snapshot. Any later edit then makes it "pre-existing" to both gates. Even if the plant was a python call that did get a window, the result is the same: F4 does not depend on attribution. Promoted severity stays low, because the edit gate is advisory (Stop blocks once, then the run ends `warnings`) and all security rules are enforced at run time.
- **F3 + Discard.** Injected "run the tests" opens a window of several minutes. The person's outside saves fold into the run, the run fails and is held, and Discard reverts the person's work. Low, as round B A1 rated it; version history can bring the work back.
- No viable chain across the earlier findings (L-F1/L-F2, D1–D4, M1/L1–L3, N1–N3, round B A1–A4, L1, L2, P1). The new collab `stampRole`/tombstone work closes round B L1/A2 rather than building on them.

## AI / MCP attack surface

- **Tools:** no MCP server or tool description was added. New text reaching the agent is product copy: the S1 restore hint, the "pre-existing" findings (with ids hashed, never echoed), and comment-door errors (code only for AI callers).
- **Model output to downstream systems:** the agent's shell text now decides attribution (F1–F3). It never decides approval.
- **Trifecta:** structurally unchanged from earlier rounds. One addition: an F1/F2 write on a hub-linked project goes out through file sync as the person, not the AI. Bash itself still needs Claude Code's card, though, so the hub-audience mitigation (H-R2-1) is not bypassed.
- **Confused deputy and excessive agency:** `migrate` is a `destructive` tier verb, so the AI gets a card. Apply also requires `Sec-Fetch-Site: same-origin`, and the hub enforces owner-only for the save-mode switch. A canvas-origin script or a cross-site page cannot reach the route (main origin only, CSRF-gated).
- **Dashboard link:** `cloud.dashboardUrl` comes only from the cell operator's `HUB_DASHBOARD_URL` env variable. Neither a hub nor a repo can steer it.

## Creativity finding

`bindVars` was added to make the deny guard *see more*. In the new `bashMayWrite`, it makes the guard *trust more*. Before, a non-literal redirect target failed closed. Now `printf -v` (a builtin on the READERS list) re-points a variable the binder thinks is `/dev/null`, so a redirect into a canvas reads as a write to a sink (F1d).
