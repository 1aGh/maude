**L1 · Low · test harness, not product: `apps/desktop/e2e/helpers/dist-fresh.ts:78-108`**
- The new "whitespace-only commit" exemption deletes all whitespace from the whole file (`replace(/\s+/g, '')`) before comparing. That includes whitespace inside string literals, template literals and regex sources.
- **Failure scenario:** a commit changes the client copy `'Sign in'` to `'Signin'`, or edits a template literal's spacing, after the bundle was committed. The guard calls the stale `client.bundle.js` fresh. The e2e lane then tests old bytes, which is exactly the "served a stale bundle" problem the r12 guard exists to stop.
- **Fix:** only exempt files whose diff is formatter-only. Either compare `biome format` output of both sides, or compare tokens instead of raw text with whitespace stripped. At minimum, give up (keep the time rule) if any changed line contains a quote or backtick.

**I1 · Info: `apps/hub/src/server.mjs:1843-1856`**
- `/api/file-limits` now gets its own 5-per-60-s per-IP budget. Before, it shared the budget with sign-in and the other routes.
- An unauthenticated caller can therefore check up to 5 more tokens per minute per IP, on top of the other routes. A valid token shows up as `quotaUsed` appearing in the response.
- Tokens are long random values (`mhc_` + 64 characters) checked by HMAC, so guessing them stays out of reach. Metering still happens before verification, and once over the limit the route answers without the quota data, so it fails closed. The new test pins both of these.
- Worth knowing: the other routes on the shared bucket (file door, project-config door) only meter requests with an invalid token. File-limits was the only route that charged valid reads, so the fix is correctly narrow. No action needed.

**I2 · Info: `apps/studio/sync/index.ts:2919-2950` and `7137-7139`**
- With `cellPairing` set, the seed never writes, so `config.json` stays absent and every boot of a paired studio counts as a fresh link again. Each boot allows one undeclared group, then closes.
- After that, `pathOpts` falls back to the default groups (`system`, `ui`). A teammate's second non-default group, say `brand/x.tsx`, is refused by the paired studio's pull and lands at the design-root fallback `brand-x.tsx`, where nobody sees it.
- On the hub side, the kernel's `checkCanvasPath` has `allowUndeclaredGroup: !groups`. In an unconfigured cell it accepts any group that passes the charset, no-`..` and slug-back checks. This is the designed "the owner sets it through the project-config door" posture, not a widening. The containment rules in `canvas-path.ts` still apply.
- This is a correctness issue, not a security one. It shows up as soon as a project has two or more non-default groups and no owner config. **Fix if wanted:** in a paired studio, take `canvasGroups` from the hub's bootstrap instead of the studio defaults, or leave the relaxation open while `cellPairing && !config`, since the hub is already the boundary.

**I3 · Info: `apps/desktop/src-tauri/src/windows.rs:1385-1404`, `lib.rs:177-188`**
