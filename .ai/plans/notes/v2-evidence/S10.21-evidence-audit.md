## Gaps the audit found (not fixed here)

1. **Four registry actions have no client writer:** `ds.canvas-update`, `ds.canvas-leave`, `ds.restore-token` and
   `ds.clear-token`. Each has a route and a verb. But nothing under `client/` posts `/_api/ds/canvas`,
   `/_api/ds/restore` or `/_api/ds/clear`, and `menu-runner.js` has no handler, so the Trash "Restore" is not wired.
   The parity test drives these four through the route the registry names and lists them in `NO_CLIENT_WRITER`.
   Wiring one shrinks that list. The fix belongs in S1-owned files.
2. **Only the page derives Dark when it follows Light.** A Light edit (`ds.set-token`) on a token whose Dark follows
   makes the page send a derived Dark as well. The file that the registry's agent text describes carries Light only,
   and the engine does not derive Dark for a plain pending edit, so the two results differ. The parity test pins this
   as a finding (`test/ds-agent-parity.test.ts`). It is an open question for the lead.
3. **Revision ids depend on time once a token is trashed.** The `tokens.json` field `trashed.at` is inside the
   revision body. This is by design (`ds-formats.md`). It does mean that the same action does not give the same
   revision id in two different projects.
