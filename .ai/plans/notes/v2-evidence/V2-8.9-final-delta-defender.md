**Checked and clean**
- **Window-opening path:** `shellOpensWindow` only returns a yes/no. Tool-call ids come from ACP, and the hook paths use `hookKey`. The SessionStart restore line is a fixed string with nothing filled in.
- **Ways to slip a new error past the gate, other than D1 and the known delete-and-re-add:**
  - The 80-bit truncated sha256 can't realistically be collided.
  - `key` survives `cleanFinding`.
  - A file that fails to parse (`parse`/`json`/`board-drop`) never counts as pre-existing, before or after.
  - With no base, every finding counts as introduced.
  - Checks that need `against` exist only in the after run, so they always block.
  - The post-edit snap name uses the unpredictable `tool_use_id`.
- **Undo refusal:** `textUndoConflict` only refuses; any error lets the undo go ahead as before. The slug regex blocks `..`, and `contested` is capped at 5000. Nothing crosses canvases, because the ledger is keyed by action id.
- **Owner gating:**
  - Studio side: `projectRoleForAccount` treats `admin` as owner, matching the hub. Role-less records default to `member` (no switch).
  - Hub side: it admits `admin` and machine tokens without an owner. That predicate predates this range and is shared with `/api/project-format`.
  - Apply still requires `Sec-Fetch-Site: same-origin`.
- **`/_config.saveMode`:** it is only in the main-origin `/_config`, which is in neither allowlist.
- **Dashboard link:** it opens `process.env.HUB_DASHBOARD_URL`, set by the operator, with `noopener,noreferrer`. It is not attacker-controlled.
