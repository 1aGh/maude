## Method

* **axe-core 4.12.1** through `agent-browser a11y` (the engine vendored in the binary — nothing downloaded; it audits the
  page frame tree, so the canvas iframe is scanned with the shell), tags `wcag2a, wcag2aa, wcag21a, wcag21aa,
  best-practice`, `region` off (as in waves A and B), `prefers-reduced-motion: reduce` so no scan reads a mid-transition
  colour. Chromium 1600×1000. Artboard content (`.dc-artboard-body`, the fixture's own markup — e.g. VideoFormats'
  `<Img src>` without `alt`) is the person's design, not Maude's chrome: excluded.
* **Surfaces, each in dark AND light** (theme through `POST /_api/ui-prefs`, page reloaded): shell (top bar, project pill,
  share cluster, mode switch, present options), left panel (Canvases + kind chips + search, Layers, Assets, New canvas),
  project menu + File / Edit / View / Help, ⌘K palette, Share, Export, Settings (General / Connections), Version history,
  keyboard sheet (?), the edit toolbar and its menus (pen, shape, image, component, More), the inspector for an artboard,
  an object, text (also while typing), a sticky, a picture, a print canvas, six video canvases (clip selected, timeline
  open), Preview, Present options, and — through a stubbed Tauri global — the AI chat (ask, Advanced), the desktop
  menus and Settings › Connections. **Home** (`--home`, page secret) and the **native tab strip page** (the real
  `strip.html`/`strip.js` with a stubbed `tabs_state` channel, default + "All tabs" list, 9 tabs) and the two other
  desktop pages (`index.html`, `root-missing.html`) were scanned on their own.
  Pass 1: ~65 states × 2 themes on the tree as merged; pass 2 after the fixes below on a rebuilt bundle.
* Raw axe JSON per state and the per-state screenshots are in the session scratchpad (not committed); the table below
  is the record.
* **Not claimed:** axe returns "incomplete" for text over gradients / overlaps / tiny counters (10–35 nodes per
  state, mostly `.kf-chip-n`, `.st-empty-*`, the dock). Those are not proof of a pass; every incomplete group seen was
  looked at in a screenshot and none read as low-contrast, but a manual contrast sweep of the floating panels over a
  busy canvas is still owed.

### The 48 lint-ratchet findings (2514b578c)

`useSemanticElements` (the bulk), `noStaticElementInteractions`, `useAriaPropsSupportedByRole`, `noSvgWithoutTitle` ×3,
`noNoninteractiveTabindex` ×1, plus non-a11y regressions the same rounds added (`noControlCharactersInRegex` in four
files, `noAssignInExpressions` in `ds/token-write.js`). Fixed properly where a semantic fix exists, with no visual change:
decorative SVGs got `aria-hidden` (the trashed-banner glyph, the music lane; the easing curve got a `<title>`), the AI
mark in History / the object history got `role="img"` (its `aria-label` was on a bare span, which names nothing),
`token-write`'s `put` became an `if`, the control-character regexes carry a `biome-ignore` placed where biome reads it
(the old `eslint-disable` and a comment two lines above the statement did nothing), the timeline's cut-as-code `<pre>` keeps
its `tabindex` (a scrolling code block must take focus) with a reason. `Advanced`'s `aria-pressed` on a radio stays because
the kit paints the chosen segment from it (reasoned ignore). Every deliberate `role="group"` / `radio` / `checkbox` / scrim carries a one-line reason in its `biome-ignore`
(a fieldset brings its own border and min-width; a tri-state tick cannot be a native checkbox; a pointer-only scrim has
Cancel / Esc for the keyboard). The baseline file was **lowered** (109 → 99), never raised.

## Result of the audit

* **0 blockers (serious / critical) on any scanned surface after the fixes**, dark and light. The remaining axe
  reports are moderate best-practice rules, listed so a decision can be taken rather than hidden:
  * `landmark-one-main` / `page-has-heading-one` on the **tab strip** and the two small desktop pages (`index.html`,
    `root-missing.html`: no `h1`) — child webviews that are a tab bar / a notice, not documents; left.
  * `landmark-unique` ("Layout") when **Settings is open over the inspector**: the Settings group and the inspector
    section are both `<section aria-label="Layout">`. The sheet is `aria-modal`; axe does not honour that. Left —
    renaming either label is a copy decision (tests pin the Settings group names).
  * The fixture's own `<img>` without `alt` (VideoFormats) — the person's design.
* Dark and light are not symmetric for axe: light is where the presence tones bite (fix 2); dark is where the accent
  chips bite (fix 1). Both themes were scanned for every state.

## Keyboard-only run of the create flow (recorded step by step; `kb.mjs`, real key events, no pointer)

Project with no canvases (what Home's "Start with an empty canvas" opens), release build, 1600×1000:

```
0  open                                   focus: input "Describe the first canvas"
1  Tab · Tab · Enter                       Send → "Start with an empty canvas ⌘N" → a new canvas opens, focus in the canvas
2  F · Tab · Enter                         size picker (focus in "Search sizes") → first tile "Desktop · Fixed size" → artboard added + selected
3  Tab                                     walks objects in reading order
4  T · Enter                               a text is added at its default size and selected
5  Enter                                   the text opens for typing, whole text selected, focus in the editor   <- fixed (#4, #5)
   type "Hello keyboard"                   the editor shows the words
   Enter                                   commits — written to the file: <p …>Hello keyboard</p>
6  ⌘Z                                      the words go back to "Text" (file: Text)
7  ⇧⌘E                                     Export sheet, focus on "Export ↵"; Tab walks Scope → Format → Other… → Size →
                                           Annotations → File name → Save to → Advanced → Cancel → Export and WRAPS (trapped);
                                           Esc closes and focus returns to the canvas; ⇧⌘E then ↵ exports and closes
```

Also walked by keyboard: the empty-canvas "New artboard" door (Tab ×11 from the load: pill → modes → present → panels → Share →
Undo → Redo → Zoom → door → left panel), the project menu, Home (pill → search → ask box → three starters; the target
chip, "Start with an empty canvas" and "Open project…" are disabled in a browser tab — the banner says so).

Noted, not fixed (not blockers; decisions for the lead):

* **Esc** in a text editor *cancels* the edit (Enter commits); board 14 says Esc "steps back out". And Esc on a selected
  object clears the selection rather than stepping to the parent (`object.step-out` has no key listener either —
  the same gap as ↵ had; Esc is shared with tool-cancel and popovers, so it needs a design call, not a drive-by).
* The keyboard-walk Tab never moves DOM focus into the canvas objects (selection + live region carry it); that is the
  documented model, but a screen-reader user on a real VoiceOver run should confirm the live region is enough.
