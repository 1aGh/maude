## What is over budget, with cause

1. **Covers: 206–245 s against 45 s.** Eight canvases never produce a cover: `unavailable:failed` for
   `ui/2026/combine/Combine-admin.tsx` and all seven `ui/club-web/*` (admin-details, admin-states, admin, flows,
   public-states, responsive, website) — the `kind="web"` canvases. Each is retried to the failure cap with the
   renderer's 10–20 s waits (`bin/_thumbs-playwright.mjs`), which is ~170 s of the total; the 87 that succeed take
   p50 0.58–0.86 s each (Phase 1: 0.15–0.18 s, so some of that is this Mac's load). V2-2.17 recorded 94/94 covers in
   35–38 s on the same project, so this is a regression or a clone difference — **not fixed here**: needs the renderer
   owner (reproduce: `bun scripts/v2-index-bench.ts --root <unlinked clone> --skip-artboards --skip-assets --skip-versions`;
   the JSON now lists the failed rels). Likely first stop: why a web artboard is not found/stable for the card shot.
2. **Version pictures 754/1477 ms against 300/800**: unchanged from V2-2.17 ("preferred fix: mount only the target
   artboard"); not attempted.
3. **Asset tiles look vacuous.** 189 of 194 tiles report `missing` (a glyph, no picture) in 2 ms each, where Phase 1
   rendered 193 real pictures (12 s, p50 49 ms). Either the bench lost access to `assets/` after the canvas-origin
   frame capability (C4) or the tile path is not drawing pictures. The ≤ 30 s budget is met trivially and means
   nothing until a tile of a real picture is seen. Needs the asset-tile owner.
4. **LOD / 64 boards at < 25 %**: the cost is the artboard render count (5,312–5,440 per gesture, pre-v2 2,944), not
   the annotation board: the same canvas with **0** annotations renders 5,312 times as well. See `V2-8.8-perf.md`
   Finding 1; the one fix tried (`DCArtboard` unused controller subscription) is committed, tested and gains ~2 % —
   the real cause is still open (V2-4.1).

## Not measured / limits
- Frame-time numbers need a GPU/display: the mini refuses them (idle rAF 10–30 Hz). Its panel scroll figures
  (116–133 ms) are therefore invalid and not used.
- Presence is simulated at the awareness layer (real y-websocket clients, no UI beyond the faces); no pointer cost of
  12 cursors beyond that.
- Home first paint is a plain-browser read; the desktop shell's own Home paint is not measured here.
