**(3) Main thread and TOCTOU:**
- **No deadlock.** `send_user_message` runs `handle_user_message` inline when called on the main thread (`tauri-runtime-wry-2.12.1/src/lib.rs:263-280`). The closure sends on an unbounded channel before `recv_timeout`, so the main thread never waits on itself. This is the same path the old `webview_getter!` used. Off the main thread, the old `recv()` waited forever; the 5 s timeout now refuses instead. A late reply after a timeout is ignored safely.
- **TOCTOU (informational, not new):** the URL is read when the gate runs, not when the page sent the call. WebKit's `URL` can already show a navigation that has started but not finished. wry's `url()` read the same property, so this delta adds nothing. Navigation guards and `is_loopback_url` still limit where a tab can go.

**(4) The `unsafe` block is sound.** On macOS, `PlatformWebview::inner()` is the pointer to wry's `WryWebView`, which is a subclass of `WKWebView`, so the cast is valid. The owning reference is held for the whole closure call, and the borrow does not outlive it. It runs on the main thread, which `WKWebView` requires. `URL` and `absoluteString` can both be nil and are handled as optional, so nothing unwraps.
