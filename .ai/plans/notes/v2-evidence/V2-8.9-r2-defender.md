# V2-8.9 delta defender review: `20b4215eb..f0f7183fe` (UX audit r2)

**One blocker (Medium, A3): the new "Connect" button in the format callout.** It is a second, unprompted way to approve a project's committed team-server link. That approval is exactly what the earlier sync-link fix made a deliberate act, because it sends this Mac's credential to that server.

I checked the ~150 changed non-doc source files, read-only. `.ai/workflows.config.json` has no `security.severityFloor`, so the default floor is **medium**. The scope defaults to classic + ai + supply-chain.

## Blockers (at or above medium)

### M1. The format callout's "Connect" approves the committed team-server link in one click (A3, medium)
- **Where:** `apps/studio/client/v2/shell/format-update.js:126-131` (the `link-unconfirmed` state), `:27` (the copy), and `apps/studio/client/v2/shell/format-update.jsx:259-270` and `:352-358`, where the button POSTs `/_api/sync/link/confirm`.
- **Why it matters:** the earlier fix (`sync/link-consent.ts`, gate-b-sec4) treats a committed `linkedHub` as a claim, because a cloned repo can name a team server this Mac already has a credential for. Approving it gives that server this Mac's credential. It then uploads the clone into the victim's server and pulls the server's files into a tree whose git remote the attacker controls. Until now the only door was the Share sheet, which the person has to open themselves ("This project says it syncs with X. Connect?"). This range adds a second door. It shows up unprompted the moment the project opens, and the copy presents Connect as the way out of "View only": "…Connect to it, and the project moves to Maude 2 by itself."
- **Exploit sketch:** commit a format-1 project whose `.design/config.json` names the victim's own team server. The victim clones it and opens it. The callout reads "points to a team server this Mac isn't connected to: hub.company.com. Connect". The host looks right because it *is* the victim's real server, so naming it gives no protection. One click records the link, restarts sync with the victim's credential, and the files flow both ways.
- **What still holds:** the route still requires `Sec-Fetch-Site: same-origin` and edit access (`routes/sync.ts:116-129`). A canvas cannot trigger it, so this is a weaker consent step, not a route bypass.
- **Fix:** make the callout's action open the Share sheet's existing Connect row instead of POSTing directly. Or add a confirm step that says where the link came from: "Maude did not link this folder on this Mac. Connect only if this folder came from your team." Drop the "moves to Maude 2 by itself" encouragement from the button's sentence. If Michal accepts the one-click door, record it as a decision and this drops to a warning.

## Warnings (below the floor)

### L1. A canvas can now read this Mac's account name when git `user.name` is unset (low, information disclosure)
- **Where:** `apps/studio/http.ts:3716-3718`. `/_api/git-user` now returns `localAuthor(...)`, falling back to the macOS account short name (`os.userInfo().username`). The route is on the canvas-safe list (`routes/canvas-origin.ts:58`, `http.ts:8153`).
- **Exploit sketch:** canvas code fetches `/_api/git-user`. Its network access is limited, but it can write the name into a canvas comment or element, which then syncs to the team server.
- **Fix:** give the canvas origins a narrower answer, the way `canvasCommitters` does for committers. The canvas gets the git name or "You", never the OS-account fallback.

## Checked, no finding
- **P1 Image tool / `place-image`:**
  - The canvas listener checks `e.source === window.parent` and then calls `acceptFromShell`, which also checks the origin. The protocol entry is `gate: 'parent'`, with `asset` capped at 512 characters and `label` at 200. Read-only canvases do nothing (`editing/place-image.tsx:135-143`).
  - The shell posts only to `cfg.canvasOrigin` (`use-tool-panels.js`).
  - The result is one `image.place` edit, which a canvas could already ask for itself, so the canvas gains no new write. The label is rendered as React text.
  - A canvas that asks for the picker (`tool-panel-open {image|generate}`) is still held to the existing three checks: its frame must have focus, there is a minimum gap between opens, and the person must be able to edit. `generate` only opens the dialog; the paid call still needs its own quote.
- **P6 `recentColours`:**
  - The server enforces ≤8 entries per project and ≤256 projects, the `MAP_KEY` id pattern, refuses prototype keys, and limits characters with `RECENT_COLOUR_RE`, which has no `;{}<>"'`. Writes merge per project key (`ui-prefs.ts:352-367`, `:475-483`).
  - The route is main-origin only, behind the same-origin write and DNS-rebinding checks, with a 4 KiB body limit.
  - The pattern does allow `url(//host)`, but the shell's CSP is `img-src 'self' data: blob:` (`http.ts:420`), so a swatch cannot load a remote image.
  - A colour typed under "Other colour…" must pass `isCssColor`, which rejects `;{}` and `var()`, before it is written through `/_api/edit-css`.
- **P2/P5 routes:**
  - No new routes in `routes/*.ts` or `home/*.ts`; the only change is a new `location` field on `create-local`.
  - `checkLocation` resolves the path and accepts only a folder inside the home folder (no hidden folders, not `~/Library`) or a real `/Volumes/<drive>`. `/Volumes/Macintosh HD` resolves to `/` and is refused.
  - The `Library` check compares case-sensitively. That holds because Bun's `realpathSync` returns the on-disk case: I tested `~/library` and got `~/Library`. Node's does not, so this matters only if the code is ever run under Node.
  - `pick_project_location` is Home-only and front-only, granted at runtime, and kept out of `default.json`. Its E2E override env is compiled only into debug builds.
- **P3:**
  - The toast slot goes to shell notices first. Canvas text cannot push a shell notice off screen, and it is still rate-limited.
  - The mode live region contains only fixed mode words.
  - The focus-ring change is CSS only.
- **`roleFallbackSpans`:** the exemption covers only the fallback inside a `var(--role, …)` whose name is in the registry's role list, and the parenthesis scan matches correctly. A colour outside that span is still flagged. This is a design-system lint, not a security boundary.
- **New code inserted into canvas source** (`insert-shape` text, `reorder` placed-copy, `slot-defaults`, DS conversion): the text role must match `^t-[a-z][a-z0-9-]*$`, coordinates must be finite and within range, the result must re-parse, and DS page file names come from a safe character set.
- **Range-wide grep:** no new `innerHTML`, `dangerouslySetInnerHTML`, `eval` or `new Function`. The new canvas-to-parent `postMessage(...,'*')` calls are existing protocol messages (`open-export`, `duplicate-request`). No new fetches to outside hosts. No new code touches the keychain or `~/.config/maude`; `roleSource` returns only `'stored'|'missing'|'none'` for this Mac's own record, and the token itself is never exposed.
