## Checked and clean

- **Release builds and the e2e markers.** The WebDriver plugin is still `#[cfg(debug_assertions)]`. The new `is_e2e_env` is the only marker a release build reads, and it only narrows what runs (D1). `MAUDE_E2E_FORCE_CLAUDE_STATUS` pass-through predates this range and also only simulates "missing".
- **Which `claude` runs (probe.ts, readiness.ts, login-state.ts).** Under markers, the resolver answers only `MAUDE_CLAUDE_BIN`, still content-pinned through `contentStillTrusted`. The readiness login-shell fallback is skipped and the real installer is refused unless `MAUDE_E2E_FAKE_CLAUDE_INSTALL=1`. Normal launches are unchanged: an empty `MAUDE_E2E_*` does not count, and a unit test pins that. `bridge.ts:1425-1449` pins `CLAUDE_CODE_EXECUTABLE` to the same resolver, so the adapter cannot fall back to an SDK-bundled CLI. Env and project content cannot redirect the binary (D1 reasoning).
- **port.ts / server.ts.** This is a straight extraction. The precedence `--port` > `PORT` > `MDCC_DEV_PORT` is unchanged. The e2e base is 47399–47408, the binding is still loopback (`listenLoopback`), and explicit ports are still fatal.
- **local-kernel.ts (r12 superseded chain).** Bus events `source-writing` and `source-written` are emitted only internally, from `routes/edit.ts`, and the bus takes no network input. `noteWritten` still requires `canvasOfRel(rel) === normalised rel`, so no other path can be named. A replay happens only when the chain starts on the store head's bytes (`baseHash`) and ends on the disk's bytes. A broken chain drops the queue rather than resurrecting bytes. Labels stay capped at 120 chars. The local home only (`isLocal()`); no new file writes: this range has no `_history/<slug>/` recovery-copy code (the V2-8.17 overlap work the brief names is not in `d23057cda..HEAD`), so there is no new slug or traversal surface.
- **routes/edit.ts.** No change to the ACL, the route table or the canvas-origin allowlists. Only the event emission and the `base` field were added.
- **client/v2/access/\*, share-cluster\*.jsx, save-status.js.** `canEditOn` now returns false first for a follow-cap frame. That is stricter, and equivalent to the old `frameAccessOn` OR. `editsInAppOnly` and `appOnly` change only wording and hide the Ask button. Server enforcement is untouched. There are no HTML sinks.

There are no EXIT-trap collisions: no other sourced helper sets a trap. `_no-egress.sh` still applies after the per-run `maude-rects-$$` default, because the session becomes `…-noegress` and the proxy is pinned to `127.0.0.1:9`. `_perf-probe.mjs` parks through argv-array `ab()`.
