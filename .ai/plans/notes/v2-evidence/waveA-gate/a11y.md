# Wave-A gate: accessibility audit (WCAG 2.1 AA)

Branch `feat/maude-v2`, studio 1.9.1, committed `apps/studio/dist` client. Own studio on a scratch project
(`s2-rig setup`, port 4471, S5 fake ACP agent, `MAUDE_CANVAS_ORIGIN_SPLIT=0`). Playwright Chromium 1600x1000 with a
`window.__TAURI__` stub, axe-core 4.13.0 (wcag2a/aa, wcag21a/aa, best-practice; `region` rule off, see Notes).
Shell and the canvas iframe were scanned as separate documents. Screenshots: `./a11y/*.png`.
Canvas artboard content (`.dc-artboard-body`, the user's own design) is out of scope: its heading-order and
landmark findings belong to the fixture, not to Maude.

**Result: 4 blockers (B1 tree structure; B2 to B4 colour contrast, one token family), 8 warnings.** The gate needs 0.

## Blockers (WCAG 2.1 AA)

### B1. 1.3.1 / 4.1.2 (A): `role="tree"` has a non-treeitem child (axe `aria-required-children`, critical)
- Surface: left panel, Canvases list. Present in every scan (Edit, Preview, palette open, light theme).
- Selector: `[data-testid=canvas-list]` (`.st-tree`) contains `[data-testid=canvases-head-project] > button[data-testid=canvases-sort]`
  (`aria-haspopup`). A tree may hold only `treeitem` / `group`; the "Recent" sort header sits directly inside it.
- Fix: render the head (`canvases-head-project`, with the sort button) as a sibling ABOVE the `role=tree` element,
  not inside it. Do not paper over with `role=none` on the button.

### B2. 1.4.3 contrast (AA): `--fg-3` text is 3.03:1 dark, 3.11:1 light (needs 4.5:1, 11px text)
- Root cause: token `--fg-3` in `client/styles/1-tokens-maude.css` (dark `oklch(0.5 0.01 250)` at line 38 = #5f6469 on
  #12161b; light `oklch(0.66 0.01 260)` at line 149 = #8f9298 on #fff).
- Sites seen: `[data-testid=canvases-foot]` ("5 canvases · ⌘K searches every project",
  `v2/canvases/canvases.css:530`), `[data-testid=ai-suggest-why]` (AI chat after a finished run, `v2/ai/ai.css:194`).
  Any other `var(--fg-3)` text will fail the same way.
- Fix: lift `--fg-3` where it carries text: dark to about `oklch(0.62 0.01 250)`, light to about `oklch(0.52 0.012 260)`
  (re-measure; target >= 4.5:1 on `--bg-1` and `--bg-2`). Or keep `--fg-3` decorative-only and point text at `--fg-2`.

### B3. 1.4.3 contrast: inspector "None" values 2.61 / 2.90 dark, 2.33 light
- Surface: inspector, frame selected and text selected. Selectors: `[data-testid=insp-chip-ab-background]`,
  `[data-testid=insp-chip-fill]`, `[data-testid=insp-border-none]` (`.insp-chip-face--none`, `.ed-none.insp-none`).
- Cause: colour is `--fg-2` (fine) but the parent `.insp-row-v` has `opacity: 0.6`, which drops it to #5c6166.
- Fix: stop dimming by opacity on `.insp-row-v` for the "None" state; use the existing `--fg-2` at full opacity.

### B4. 1.4.3 contrast: command palette, selected row meta 4.24:1
- Surface: ⌘K palette, the highlighted row. Selector: `[role=option][aria-selected=true] .st-pal-meta` (e.g. "ui"),
  `v2/search/search.css:80`. fg #8e9398 on selected bg #263047.
- Fix: on the selected row set `.st-pal-meta` to `--fg-1`, or lighten the text. Light theme passes.

(B2 to B4 are one family: low-emphasis text tokens. One token pass plus the `.insp-row-v` opacity should clear all three.)

## Warnings

W1. Project hard rule 3 (not a WCAG AA failure): Start a vote sheet is `aria-modal="true"` but focus is not trapped.
Tab leaves the sheet into the page behind (vote inputs, then the callout, project pill, mode buttons).
Shortcuts sheet traps correctly (Close, Advanced, Find cycle) and the palette keeps focus on its combobox;
the vote sheet should match them. `[data-testid=vote-sheet]`.

W2. `aria-allowed-role` (minor): `<form class="an-vsheet" role="dialog">` is not an allowed role on `form`. Wrap the form
in a `<div role="dialog" aria-modal aria-labelledby="an-vsheet-h">`.

W3. Focus return: closing the vote sheet with Esc leaves focus on the canvas iframe body, not the opener
(palette returns focus to its opener correctly; the context-menu and shortcuts sheet land on the canvas body too, acceptable
because the opener is a pointer or chord).

W4. Version history (`[data-testid=vh-panel]`): opened from ⌘K it does not take focus (focus stays on the mode
button) and Esc does not close it; only `vh-close` does. Panel is a labelled `aside`, so F6 reaches it. Move focus
to the panel (or its heading) on open and close on Esc when focus is inside.

W5. Trash view (`canvases-trash`): Esc does not leave the view; only `canvases-trash-back` does. Focus does not move into
the view on open. Same pattern as W4.

W6. Project hard rule 5: AI chat composer `textarea[name=input]` is named only by `placeholder="Ask AI…"`, no
`aria-label`. axe passes (placeholder fallback). Add `aria-label="Message to AI"`.

W7. Canvas context menu (`[role=menu]` in the canvas iframe) has no accessible name (no `aria-label`). Items, arrow-key
roving and Esc all work.

W8. The canvas frame region for F6 has no accessible name of its own beyond the iframe title
(`Canvas: .design/ui/Site.tsx`); fine for AT, but the F6 landing is `body` of the frame, not the focusable
`.dc-canvas[tabindex=0]` (which has no role or name). Add `role="application"` or `role="group"` + `aria-label` there.

## Notes
- axe `region` (all content in landmarks) is a best-practice rule and fires on the shell and the canvas
  (`.st-modes`, `.lp-tabs`, `.st-grip`, preview bar). The shell has labelled `nav` / `aside` regions but no `main`
  or `header`. Not counted.
- `heading-order` and `landmark-unique` on artboard content come from the fixture's own markup; not counted.
- Small controls are 32x32 (toolbar slots). Desktop app, 44px rule is mobile-only; not applicable.
- Focus ring: chrome buttons get `outline: 2px solid oklch(0.68 0.18 268)` plus a 5px 16% halo (`:focus-visible`), well above
  3:1. The canvas selection is the same hue but a different shape (frame + handles + numbered tab badges 1.1 to 1.6),
  and keyboard focus on the canvas sits on the frame body, so the two do not collide. The composer
  has no outline on the textarea itself; its `form.chat-box` border switches to the accent on focus (adequate).
- Pointer-only selection handles exist, but every object is reachable by Tab / Return / Esc (tab-order.tsx);
  live region in the canvas frame announces selection ("Jedeme v zeleném., frame, 6 items. Press Return to go inside.").
- Reduced motion: with `prefers-reduced-motion: reduce` no animation or transition above 50ms runs in the shell
  or canvas (palette, preview, present checked).
- "New here?" callout (`callout-tour-usage`) sits over the top of the canvas at 1600px and is in tab order
  before the shell controls; dismissable. Not counted.
- Possible visual regression, outside a11y: in Preview, after placing a sticky, the "Book a call" button rendered as a full
  width black bar (`.ai/.../20-annot-sticky.png`) where it was a small button before. Not investigated.
- Per-surface results (after dedupe of B1 to B4): shell Edit: B1, B2. Preview: B1 (main). Inspector frame/text: B3.
  Canvas context menu: 0. Palette: B4. "?" sheet: 0 (dark and light). Version history: 0. Trash (empty and with item): 0.
  AI chat empty: 0, finished run: B2. Annotation toolbar with sticky selected (Preview): 0, every control named.
  Start a vote sheet: W1/W2 only. Present mode: 0. Light theme re-run: B1 to B3 again, palette/shortcuts/AI clean.
- Every interactive control in all scanned surfaces has an accessible name (custom scan of buttons, roles,
  tabindex, plus a cursor:pointer-without-role scan for div-onClick: none found).
