## Findings

**L1 · A participant connected straight to the hub can forge their presence role (low, display only).**
`apps/studio/collab/room.ts:404` stamps the role only on states from the room's own connections. The hub's
`beforeHandleAwareness` (`apps/hub/src/server.mjs:2278`) neither stamps nor strips `role`. `presence/fields.ts:46`
`sanitizeRole` accepts any of the four roles, and `client/v2/shell/save-status.js:169` plus `presence/faces.jsx` show
it. Exploit: a Can view or Can comment user connects to the hub with their own token and publishes `role:"owner"`.
Peers then see "· Owner". Nothing grants rights from this role, and names are client-chosen anyway, so the only
effect is impersonation. Fix: the hub stamps `role` from `context` access in `beforeHandleAwareness`, next to
`stripSummon`. Alternatively, the studio bridge deletes `role` from any hub-relayed state the hub did not stamp.

**L2 · The narrowing keep compares against the per-canvas role, not the whole claim (low, not exploitable today).**
`apps/cloud/access-forward.mjs:745` sends `role: after.roleFor(canvas)`, which is the max of the project role and
the canvas grant. `apps/hub/src/routes-v2/access.mjs:251-254` (`keepsOnly`) then spares any project-wide token with
that role and no grants. Example: someone with project Can view plus Can edit on canvas X is narrowed to Can
comment on X. A stale project-wide Can comment token would survive, although that is more than the person's claim
after the change. In practice every token minted for this person carries the grant shape and dies. The stale token
can only exist if an earlier narrowing's notify failed, which `accessWentDown` deliberately swallows. Fix: send
`role` only when `canvas === null`, or when the claim after the change has no grants and
`roleFor(canvas) === after.role`. Better still, compare the whole claim (role + exact grant set) on the hub.

## Pre-existing, not counted against round B

**P1 · The dev MinIO listens on every interface with fixed root credentials (medium).**
`cli/lib/workspace-plan.mjs:263-266` sets the root credentials (`maude-dev` / `maude-dev-secret`), and lines
679-681 publish `"9000:9000"` and `"9001:9001"`. Round B moved Caddy to `127.0.0.1:80` for `--local`, but
`--local --dev-minio` still exposes MinIO to the LAN, so anyone on the Wi-Fi gets root on the asset bucket. Fix:
bind to `127.0.0.1:`, or drop `ports:` (the hub reaches it at `minio:9000` on the compose network).

## Checked and clean

- **Comment door** (`sync/comment-door.ts` → hub `routes-v2/comments.mjs:363-406`). The client strips
  author/authorId/authorKind/from, uses `redirect: 'manual'`, and sends the hub token only to the linked hub. The hub
  takes the author from the verified session and ties the canvas to the doc slug, and `ops.ts` rejects `not-yours`.
  No rewriting other people's threads and no forged author. A stale `canEdit` fails closed.
- **Can view `me` bearer.** The ended-session memo runs only on a token that fails verification, keyed by the
  token's digest, and returns one of the stored ACCESS_REASONS, so there is nothing to probe. ACCESS_ROWS is
  unchanged and every other route keeps its gate.
- **Narrowing keep.** It reads the token store's claims (`listOwnerClaims`), never the presented claim, and only the
  person's own tokens. Self-hosted and link-off narrowings pass no role, so every token dies. `kickEmail` still
  closes every socket.
- **Notice name and role.** `/internal/access-changed` needs the tenant secret. `noticeName` strips C0/C1,
  zero-width, bidi and BOM characters and caps at 80. The role is allowlisted, and the studio (`cleanName`,
  `NOTICE_ROLES`) and the client (`accessWord`) check both again. The risk is cosmetic only.
- **Invite `via`.** Kept only as "invite" next to a thread, and dropped from a project-tab caller (`via_for`). The
  toast name comes from the stored thread author.
- **Debug-only Rust.** `bar_state` is `#[cfg(debug_assertions)]` and the tab-menu click sits inside the debug block.
- **Shell-verb stage opener** (`acp/design-write-verb.ts`, `acp/index.ts:428`). It only calls `stage.begin`
  (attribution and one-step Undo). It grants no permission and no lease, and Bash tiers are unchanged. Canvas text
  can at most open a spurious stage (informational).
- **Env and ports.** Deleting `NAPI_RS_NATIVE_LIBRARY_PATH` exposes less. `MAUDE_PORT_BASE` is a range-checked
  integer, not explicit, and not a secret. perl `setsid` passes args through `--` with no shell.
- **`hubs.json` account.** It passes the `safeAccount` regex, is display-only, and is served on the main origin only.
- **Awareness ownership** (`room.ts` `ownAwareness`). A connection can't overwrite or remove other connections' or
  hub-relayed states, and malformed frames are dropped.
