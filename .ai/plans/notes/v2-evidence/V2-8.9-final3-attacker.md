## Findings

**L1. When the owner declares folders, a teammate's canvases become owner-only code.** `apps/hub/src/file-membership.mjs:301` (and its `.ts` mirror), `journal.mjs:~1520-1556` (walk-import), `file-door.mjs:484`
1. On an unconfigured cell, an editor creates `brand/x.tsx`. The kernel accepts it, the cell's studio writes it to the checkout, and the classifier calls it a canvas, as intended.
2. The owner later declares folders, either through the project-config door or because a fresh desktop link seeds `[system, ui, <first folder pulled>]` and pushes it up.
3. `brand/x.tsx` is still on disk, but the classifier now says `code-module`. The hub's reconciler (walk-import) finds it and journals it as a new row.
4. It now travels on the owner-trusted lane: every desktop that allowed code modules pulls it, and the owner's own desktop auto-commits it to git under the owner's name. Teammates can no longer edit or delete it, because writing code modules needs the owner's token.

The opposite direction happens on upgrade: the owner's existing `components/*.tsx` on an unconfigured cell turn into canvases any editor can edit. A file's trust class follows the current config, not who wrote it. Execution stays inside the canvas sandbox, and files pulled this way are flagged untrusted on desktops, which is why this is Low.

Fix: when a path's class moves from canvas to code-module, don't journal it as code. Hold it as `never` until the owner adopts it explicitly, or record that it came from the doc lane.

**L2. A folder name that differs only in case can drop the owner's canvases out of the cell's scan.** `apps/studio/sync/index.ts:6872`
1. Cells run on Linux, where `Brand/` and `brand/` are different folders. The owner has canvases in `Brand/`.
2. An editor creates a doc at `BRAND/zz.tsx`. Its slug is different, so it is accepted and written.
3. The scan keeps only the first of two case-equal folder names, in directory-listing order, which on Linux is effectively hash order. When `BRAND` comes first, `Brand/` is not walked.
4. The owner's canvases then count as "on the hub only". Pulling them is refused because the file already exists (`admitPullTarget`), so they stop syncing on the cell.

This is availability only. An editor can retry with other case variants until one wins.

Fix: walk every real folder that matches, rather than de-duplicating names ignoring case, or refuse a second case-variant of an existing folder in the pull check.

**L3. The pull path accepts runtime-state and `node_modules` folders that the scan excludes.** `apps/studio/sync/canvas-path.ts:77`, `:186-193`
- The path charset allows a leading `_`. The kernel and the cell's studio, now permanently under the hub boundary, therefore write a teammate's `.tsx`, `.css` and `.meta.json` into `_state/`, `_comments/`, `_history/<slug>/` (a fake rollback snapshot) and `node_modules/`.
- The scan (`scanGroupPaths`) and the classifier's `relShape` both exclude these folders.
- What held: canvas builds refuse imports from `_` folders and refuse bare npm imports, and the DDR-115 runtime-state lists keep these files out of commits.
- What is pre-existing but now reachable for longer: on a fresh desktop link, `noteLearnedGroup('_trash')` would declare a runtime folder as a canvas group.

Fix: refuse a first path segment that starts with `_` or equals `node_modules` in `validateCanvasPath` whenever undeclared groups are allowed, and the same in the kernel.

**L4. The new "comments paused" flag (`cg=1`) is only a UI hint, and the server does not block every comment write under the format gate.** `read-only-mode.ts:53-73`, `ws.ts:656-727`, `server.ts:634/700/888`, `collab/room.ts:329-333`, `client/hooks/use-canvas-bridge.jsx:1079-1100`

**Infos**
- **I1** `dist-fresh.ts:96`: after a `>` that is not `=>`, `>=` or `>>` (a comparison or a TS generic), the JSX-text heuristic reads up to the next `<` or `{` without respecting backticks. A newline or indentation change inside a template literal there is hidden, and tabs become spaces inside quoted strings.
