# V2-8.8 Performance — pan/zoom, pre-v2 against v2 (2026-10-25)

Budget (V2-1.8 M7): on the Combine-kampan-scale canvas at fit-all, per engine at dpr 2, the shipped v2 shell
keeps **median gesture p95 ≤ pre-v2 median p95 + the pre-v2 spread** and **median long frames (≥ 50 ms) ≤ pre-v2
median + its range**. "Floating panels within the V2-1.8 budget" is the same test: the studio shell with its
islands over a full-width canvas against the pre-v2 docked shell.

## Method
- Instrument: `apps/studio/bin/perf.sh` (the ruler is this tree's, for both arms). New lane `--engine chromium
  --studio` (`_perf-probe-studio.mjs`, Playwright, Retina page 1600×1000, measures inside the cross-origin canvas
  iframe with the shared `harnessSource`, records the world scale). One batch = `scripts/v2-perf-bench.sh`:
  release-builds both arms, boots each on its own copy of the generated fixture, 7 passes (first discarded → 6 kept),
  summary by `scripts/v2-perf-summary.mjs` (M7 rule pinned by `scripts/test/v2-perf-summary.test.mjs`, red with the
  p95 bound removed).
- Pre-v2 = `fcc24f4dd` (v1.9.1; v1.10.0 differs only in a version string under `apps/studio`). v2 = this branch.
- Fixture: `apps/studio/test/fixtures/gen-format-fixture.mjs` — **93 canvases**, `ui/c12.tsx` with **21 artboards**,
  unlinked, deterministic. (Not the real Combine-kampan: synthetic bodies; fit-all scale 0.113 v2 / 0.12 pre-v2.)
- Machine: Apple M5 (this Mac), **loaded by the other agent sessions** (load 9–34 during the batches, recorded in
  each `env.txt`). Three batches, arms interleaved in time, two orders: local1 `base v2`, local2 `v2 base`,
  local3-fix `v2 base` (with the DCArtboard fix below).
- **Mac mini is not usable for frame timing.** Its headless Chromium has no display/GPU: idle rAF 10–30 Hz, so the
  occlusion guard refuses every pass (`mini-batch1/*.log`). The mini was used for the display-free numbers only
  (V2-8.14).
- **WebKit: not measured.** `perf.sh --engine safari --studio` against the pre-v2 server, run on this Mac: *"the page
  was occluded — the studio delivered no idle frames"* (screen locked / Safari not in front). The lead re-runs it:
  `scripts/v2-test-lane.sh -- scripts/v2-perf-bench.sh --base fcc24f4dd2fb18808640eada339f623dee28ae50 --order "base v2" --lanes webkit --repeat 7 --out <dir>`
  and again with `--order "v2 base"`, on an unlocked screen with Safari in front (the bench kills its servers; the
  `webkit` lane is local-only).

## Finding 1 — v2 renders every artboard ~1.8× as often per gesture (still within M7 at 21 boards)
Per 100-frame gesture: 21 boards 1,785 renders (v2) vs 966; 64 boards 5,440 vs 2,944 (≈ 83 vs 46 per board). This is the
`v2-2.20-fit-all-raster-cost` finding, now measured on both arms. In-page counting (temporary instrumentation,
reverted) on the 21-board canvas, v2: `measured` (`useArtboardBounds`, a ResizeObserver) changed 798× (38 per board:
one per zoom frame — Blink's CSS `zoom` changes the observed size every frame), `surface` 168×, world context 147×;
~30 renders per board are not explained by any tracked value.

## Finding 2 — the fit-all cost bites at 64 boards (LOD lane, V2-8.14): v2 is worse than pre-v2
See `V2-8.14-perf.md` (annotation LOD): v2 p95 82.8–100 ms vs 66.6; p50 33–50 vs 17.5.

## Fix landed (small, tested, but not the cause) — `canvas-lib.tsx`, one commit
`DCArtboard` called `useViewportControllerContext()` and never read it, so each burst start/end/publish re-rendered
every board. Removed (comment left). Test `apps/studio/test/v2-perf-artboard-rerender.test.tsx`: **red before** (72
renders over 3 bursts × 12 boards, limit 36), **green after**; 183 canvas/artboard/viewport/perf tests green; tsc 0.
Real-browser effect is small (1,785 → 1,743 and 5,440 → 5,312 renders; no frame-time change), so the fit-all cost is
still open: next candidates are in Finding 1 (stop `useArtboardBounds` re-rendering on zoom-induced size changes during
a gesture; find the ~30 unexplained renders per board). That is V2-4.1's scope and a shared file (canvas-lib.tsx).

## Verdict
Chromium: M7 **met** (studio + bare). WebKit: **not measured** (screen occluded; lead re-runs, command above).
Fit-all render count 1.8× pre-v2 → open item for V2-4.1.

## WebKit lane, measured (p8-e2e, 2026-10-26, this Mac, visible unlocked screen)

Safari via safaridriver, studio shell, Combine-kampan `ui/c12` (21 artboards) fit-all on the Alligators-scale fixture,
Retina 2x, 1600x1000, 7 passes per arm, both orders (`p8-perf/webkit-ab`, `p8-perf/webkit-ba`), base = fcc24f4dd (v1.9.1).
Screen-lock + window probes held for the runs (caffeinate -d for the duration); the real `~/.config/maude` was untouched.

| webkit-ab | pre-v2 | 131 (20) | 140 | 27 (2) |

Pooled over both orders: p95 v2 184 vs pre-v2 130 + spread 36 -> FAIL; long frames 40.5 vs 27 + range 2 -> FAIL; zoom p95
212 vs 143. **WebKit M7 is NOT met**: v2's gesture p95 is 1.4x pre-v2 and its long frames 1.5x, outside the spread in both
orders (so not order noise). p50 is 17 ms in both arms (the idle frame is fine; the gesture frames are not). Chromium stays met.

Instrument fixes needed to get a number at all (`apps/studio/bin/_perf-probe-safari.mjs`):
1. The v2 Canvases panel folds `ui/` away, so `canvas-row-ui-c12` is not in the DOM; the probe opens the canvas by
   `?open=<path>` when the row is absent.
2. v2's canvas frame is full-bleed under floating islands: the in-frame "empty world" click can land on an island and the
   frame then stays rAF-throttled (idle p50 33 ms), so the probe refused to record. Attempt 2 now presses the frame element
   from the shell. The base arm needs neither.
