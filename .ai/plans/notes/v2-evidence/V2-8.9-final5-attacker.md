## V2-8.9 delta attacker review: `e308179d0..3fba09b78`

**Verdict: pass, no blockers.** I found two low findings, one informational note and no chains. Your prize, `grantedBySlug`, holds up under every naming trick you listed. Its one real gap is that it doesn't check stored grants. Everything below comes from reading the code; I ran nothing.

**Why the predicate is sound.** The only file the new rule lets through is `stem.css`, and only when `stem.tsx` doesn't exist, has no meta, and its slug matches nothing but granted files. A file at a path is a canvas for four reasons: its source, its meta, its board (keyed by slug) or a stored grant (`isCanvas`, `closure.ts:683-702`). The rule checks the first two directly. The board is keyed by slug, so it can only belong to canvases sharing that slug, and the rule requires all of them to be granted. So the stylesheet it admits never had an owner of its own. Its only protection was the granted canvas's own board. Stored grants are not checked (L1 below).

### How each naming trick fails

- **Upper-case extension (`stem.TSX`).** The twin scan uses `/\.(tsx|html)$/i` and `canvasSlugFromRel` drops the extension case-insensitively, so `stem.TSX` counts as a non-granted twin and the import is refused.
- **Case in names or folders, `-`/`_`, whitespace, `%2D`/`%2F`, nested folders, the same slug in another folder.** The slug is lower-cased after folding, and the scan covers every listed `.tsx`/`.html`. Any non-granted twin, canvas or not, sets `foreign` and the rule fails closed. A file that is only listed under another case is never resolved (`env.files.has(dep)` at `:849`), so the import is blocked.
- **`.html` owner.** It is checked per owner. If it exists, `files.has` stops the rule and `isCanvas` takes over.
- **Unicode NFC/NFD.** Comparison is by exact string and `toLowerCase` doesn't normalise. A mismatch leaves the import unresolved, which blocks it. On Linux an NFD/NFC pair are two different slugs, and each owner exists, so the rule doesn't apply.
- **Memo scope.** `slugOwned` is created inside `walkImports` (`:763`), so it lasts one walk over one fixed file snapshot. Nothing is shared between walks or requests. The closure cache key includes the generation, bumped on every file change (`filters.ts:600-605`), plus the full config including known canvases. A twin created later bumps the generation and gets a fresh walk. The only window is the watcher's delay, which every closure decision already has.
- **macOS case-insensitive disk vs Linux cells.** If `combine-admin.tsx` is missing from the listing but exists on disk under another case, the scan still sees the real name, and the lower-cased slug matches. A foreign case variant is therefore foreign. Linux treats both names as separate strings, and the third test pins that. The two systems differ only for characters where JavaScript's lower-casing and APFS case folding disagree (final sigma ς/σ, NFC/NFD). For an attack, the victim's stylesheet would have to be stored under a different case than its `.tsx` *and* sit in a folder layout that avoids an APFS collision. Even then, the code before this delta already admitted it whenever the slug had no board. That gap predates the delta (I2).

### Findings

**L1 (low): `grantedBySlug` skips the stored-grant check.** `apps/studio/access/closure.ts:765-780`, call site `:789`.
- In `!granted.has(owner) && !grantedBySlug(owner) && env.isCanvas(owner)`, `grantedBySlug` runs before `isCanvas`. `isCanvas`'s rule that a stored grant makes a path a canvas "whatever its file says" (`:689`, p8-c4b) is therefore bypassed.
- **Chain:** victim canvas V is a slug twin of the attacker's granted A, e.g. `ui/a/b.tsx` vs `ui/a-b.tsx`. V has a grant, so the cell's hub lists it as known, but V's `.tsx` and meta are missing from the listing while `V.css` is present. That can happen during a file-plane sync window where the stylesheet lands first, after a delete that leaves the stylesheet behind, or with a symlinked `.tsx` (see L2).
- The attacker's frame on A imports `./a/b.css`. The walk admits it, adds it to `read`, and also adds the assets it references to the closure (`existingAssetRefs`, `:940`).
- **Not reachable without** the victim creating a slug twin, plus a race or a leftover file. Impact is reading another canvas's CSS and the assets it references.
- **Fix:** at the top of `grantedBySlug`, return false when `env.cfg.knownCanvases` contains `owner`. Pin it with one more case in `test/p8-perf-814-closure-case.test.ts`.

**L2 (low): the twin scan trusts the file listing to be complete, and it isn't.** `apps/studio/access/request.ts` `diskProjectReader.list`.
- The listing skips dot-names at every depth, `node_modules` and symlinks (`e.isFile()` is false for a symlink entry), and stops at `LIST_CAP` = 20000 files. A twin left out of the listing counts as not foreign.
- On a Linux cell, folders are read in hash order. A member who can write assets (the canvas-safe `/_api/asset` route) could steer the file count so the cap falls between a twin's `.css` and its `.tsx`. That needs exact count control and a slug twin, so it's theoretical.
- Plain imports fail closed in this situation because the target is never resolved. `ownedOf`/`slugTwins` (board and comment ownership) has the same listing dependence and predates the delta.
- **Fix:** if the listing hits the cap, mark the closure as blocked. Consider treating symlinked canvas-shaped files as foreign.

**I1 (no finding): `apps/studio/bin/_tile-draw.mjs:72`.**
- This is a straight extraction plus a switch from `toBlob` to `toDataURL`. `toDataURL` throws a SecurityError on a tainted (cross-origin) canvas exactly as `toBlob` did, so no new cross-origin read.
- An SVG drawn through an `<img>` loads no outside resources.
- The source URL, the page and the thumbnail-cache keys are unchanged (`page.evaluate(drawTile, …)` sends the function source).
- **Not reachable:** a planted asset can't make the renderer read another origin or reach another project's thumbnail cache.

**I2 (no finding): the a11y client edits.** They only change `aria-*`, `tabIndex`, `role` and CSS colour tokens. They add no new HTML sinks; the only `innerHTML` in the diff is a test reset in `p8-a11y-final.test.tsx`. `v2-index-bench.ts` `--dump-replies` writes only to a local path you give it. One note from before this delta: on APFS, a stylesheet whose case differs from its canvas (e.g. `Report.tsx` + `report.css`) with no board for that slug is admitted by the plain `isCanvas` path anyway. The new rule doesn't make that worse.
