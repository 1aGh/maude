## Attack chains tried

1. **Get a project, deep link, hub or planted file to flip e2e mode, then plant a `claude` binary (code exec with the person's Claude credentials).** BLOCKED.
   - Every Rust e2e switch that grants something is `#[cfg(debug_assertions)]`: CONFIRM_TEAM_SERVER, PICK_DIR, FAKE_GITHUB_LOGIN, SAVE_PATH, OPEN_PATH(S), FAKE_KEYCHAIN, NO_KEYCHAIN, RUNNING_CAP, SHELL_LOG, RESTORE, ON_TOP, FRAME_PROBE. The new `is_e2e_env` is not gated, but it can only narrow: it keeps the inherited launchd PATH instead of sourcing the login shell.
   - On the TS side, `isE2eEnv` likewise only takes away: `resolveClaudePath` → null unless `MAUDE_CLAUDE_BIN` is set, there is no login-shell fallback in readiness, and the real installer is refused.
   - The markers come only from the app's launch env. There is no `process.env` write driven by a project, config, hub or deep link (grep of non-test studio code: only build.ts). `deep_link.rs` routes by project and does not touch env.
   - `MAUDE_CLAUDE_BIN` was already honoured in release before this range, with a content pin when Maude provisioned it. Nothing new here.
   - Planting via relative PATH entries: the sidecar has no `current_dir`, so it inherits `/` from a Finder launch. `resolve_login_path` runs `$SHELL -ilc` with cwd `/`. A project-relative PATH entry therefore can't resolve into the project.
   - The adapter is pinned to the resolved path (`CLAUDE_CODE_EXECUTABLE`). In an e2e lane with no stub, the session is refused instead of falling back to PATH.
2. **Hub or peer drives the sync-recovery slug/path, or floods copies (V2-8.17).** OUT OF RANGE.
   - offline-overlap.ts and the recovery writer last changed in dbd731dd3, an ancestor of d23057cda, so neither is in this delta.
   - Spot check: the `_history/<slug>/sync-recovery/` notice takes `canvas.slug` from the local canvas index, and the toast renders it as React text. Not re-reviewed in depth.
3. **Launder an AI or outside write as the person's `edit`, skipping AI-run review, through the new early note or the superseded chain (local-kernel.ts:776-885, routes/edit.ts:246-254).** NO GAIN.
   - Notes come only from the studio's own `/_api/edit-op` write. That route is `origin: 'main'` with its ACL unchanged.
   - Attribution keys on byte-identical content. An outside write that matches a note is literally the bytes the person asked for.
   - The chain replay needs `baseHash` to equal the store head, and labels are capped at 120 characters.
   - Memory is bounded by `MAX_SUPERSEDED` = 16 entries per canvas, all of them studio-written.
   - A note left behind by a failed write lives 30 s and only matches identical bytes.
4. **Canvas-only or viewer session reaches a write through the share-cluster change.** NO.
   - The change is client-only and narrows: `canEditOn` now returns false whenever the frame is follow-cap read-only.
   - When the frame is read-only, the "Ask to edit" button is replaced by an "edit in the desktop app" tip.
   - Server gates are unchanged, and grant names and canvas names render as React text.
5. **Cross-project bleed through a stale capture page, the root cause of the r10 incident.** BLOCKED cross-project; the same-project residual is L-F2.
   - The shell page opens no collab socket; only the canvas frame does.
   - The canvas realm can't write body lanes (lock 2, collab/origins.ts).
   - A frame from project A carries an `fc` minted under A's per-project frame key, so B's canvas listener refuses it.
   - The capture origin refuses WebSocket upgrades.
   - A desktop tab put to rest is navigated to the splash before its port is freed (windows.rs `rest_window`).
6. **Shell or argument injection, or a non-loopback target, in the new bin helpers.**
   - `_ab-park.sh` and `_ab-headless.sh` take no untrusted input. Session names are `$$`-derived or caller env, and `_no-egress.sh` still appends `-noegress` after the per-run name, so no-egress launch options still apply to a fresh daemon.
   - URL construction and `maude_url_guard` are unchanged, and no EXIT-trap collisions were found.
   - `_perf-probe.mjs` parks the page through argv arrays.
   - The new idle timeout (60 s) and park-on-exit shorten how long a canvas page stays reachable.
7. **Syncthing-writable evidence or files steering the gate scripts.**
   - v2-gates still never interpolates evidence into a shell.
   - The new tee and log-dir lines use `date` and lane names, and the lane names come from tracked `apps/desktop/e2e/package.json` script keys. Anyone who can write that file can write v2-gates.mjs itself, so it is no new boundary.
   - remote-lane.sh only moved its config root and TMPDIR, and dropped the explicit cloud/hubs pointers. They now derive from `XDG_CONFIG_HOME` = `$H/cfg`, still inside the throwaway slot HOME.
   - Pre-existing residual, not counted: command-gate evidence is self-asserted JSON (`pass`, `head`, `cmd`, `qualityHash`), so a tree writer can forge a pass. The currently untracked `.ai/scenarios/maude-v2/gates/V2-8.3.json` is that kind of file. The attest gates re-hash their reports, but the command gates can't prove the command ran.
8. **AI/MCP.**
   - No MCP server was added and no tool descriptions changed.
   - New text the agent may read is fixed product copy, plus lane logs under `$TMPDIR/maude-v2-8.3/`, whose content comes from repo fixtures.
   - Trifecta status is unchanged from round 2: still structurally present, and still mitigated by the hub-linked writer-verb card (H-R2-1 fix).
   - The isolation work closes a real confused-deputy lane in the test harness. Before r13, an e2e lane's sidecar sourced the person's rc files and spawned the real signed-in `~/.local/bin/claude` with the real HOME and keychain under spec-driven UI.
