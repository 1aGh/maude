# Security review — S8.5b cloud render door

- **Slice:** S8.5b-4 (lane test + review), 2026-10-20, branch `s8-5b-4`.
- **Scope:** the whole door as merged on `feat/maude-v2` — S8.5b-1 (`apps/studio/exporters/door-fingerprint.ts`,
  `exporters/jobs.ts` client id / owner idempotency / token swap, the `http.ts` `x-maude-door-job` + `?id=` patch),
  S8.5b-2 (`apps/hub/src/routes-v2/render-jobs.mjs`, `studio-proxy.mjs` `forwardAs`, `server.mjs` wiring and
  `/health` capability), S8.5b-3 (`apps/studio/exporters/hub-render-door.ts`, the send-time fingerprint in the
  cloud sender).
- **Against:** the threat list of the contract, `apps/studio/client/v2/contracts/S8.5b-cloud-render-door.md` §12
  (T1–T12), plus what the end-to-end run turned up.
- **Method:** code reading of the three halves, and a new end-to-end test against a real hub process and a real
  studio child with a fake `maude-render` (`apps/hub/test/render-door-lane.test.mjs`). A header tap between the hub
  and the studio child (the hub's own `MAUDE_STUDIO_BIN` seam) records every request the studio receives, so
  "the token never reaches the studio" is observed, not inferred. The lane test was mutation-checked: with the
  freshness verdict disabled, the studio's owner check removed and the bearer copied into an upstream header, four
  of its five tests went red.
- **Production posture:** unchanged. The door stays dark (`MAUDE_RENDER_DOOR` unset ⇒ no `render-jobs-v1`, rows
  answer 404). Turning it on per cell is M1 (Michal).

## Findings

| # | Severity | Finding | Status |
| --- | --- | --- | --- |
| F1 | **Medium** | The desktop door's park probe (`GET /_cell/state`) did not send `x-maude-sync-park: 1`. The cell's Durable Object answers the probe by itself only when that header and a bearer are present (`apps/cells/cell-config.mjs` `isCellStateProbe`). Without it the probe is an ordinary `/_*` path, and every `/_*` path wakes a sleeping cell. So the one call meant to find out whether a cell slept *without waking it* woke it, once per job per silence (T10 broken). | **Fixed** in `55e0d5b0c`. |
| F2 | **Medium** | A status poll's fresh render capability for a canvas-only session carried **every** exportable grant of the session, not the job's canvas. The studio swaps that token into a still-queued job (T11), so the worker could render with a capability wider than the submit gave it. This contradicts contract §8.4 and decision `v2-S8.5b-2-render-grants-narrowed` ("carries only the target canvas's grant; rejected: carrying all of the session's grants"). It weakens the defence-in-depth layer that holds the worker to the closure if a door bug lets a target through (T3). | **Fixed** in `47db1a9ae`. |
| L1 | Low | Freshness judging hashes files synchronously on the hub's event loop. A member can send up to 2000 correct hashes of large visible files (up to 64 MB each) followed by one wrong one: the hub hashes all of them, answers 425, and the submit counts against neither the active cap nor the hourly cap (only the 60-per-minute limiter). Impact is limited to the member's own tenant: a cell is single-tenant, and a member can already push large files through sync. | Open — see "Recommendations". |
| L2 | Low (UX) | The hub passes on a studio refusal's `code` and `message` only. A 422 `nothing-to-export` body carries `error`, not `code`/`message`, so the desktop shows the video-cap words ("longer than one export may be") for an export that has nothing in it. Found by the lane test (a canvas with no `kind="video"` artboard). | Open. |

No finding at severity high or critical.

## Fixes in this slice (fail first, then green)

- **F1** — `apps/studio/exporters/hub-render-door.ts`: the probe sends `x-maude-sync-park: 1`.
  Test: `apps/studio/test/hub-render-door.test.ts` "an ASLEEP cell: gone, without a status call…" now asserts the
  header. Red without the fix (`Expected "1", Received null`), green with it.
- **F2** — `apps/hub/src/routes-v2/render-jobs.mjs` `status()`: a canvas-only session reads the job first with no
  capability, then (job unfinished) with grants narrowed to `job.spec.canvas`; the status projection moved into
  `answerStatus`. Test: `apps/hub/test/render-jobs-route.test.mjs` "S8.5b-4 F2: a status poll's fresh capability is
  narrowed to the JOB's canvas, like the submit's" (new canvas-only token `tok-canvas2` with two grants). Red
  without the fix (`…?id=i_…40 widened the grants`), green with it.

## Recommendations (not done here)

- **L1:** memoise the hub-side file hash by `(realpath, size, mtimeMs, ctimeMs, ino)` so a repeated judgement costs a
  `stat`, or give one judgement a byte budget; and/or count a `not-synced` answer toward the hourly limiter. Either
  removes the amplification without changing the contract's answers.
- **L2:** relay the studio's `error` as `code` when `code` is absent, so `nothing-to-export` reaches the desktop as
  itself and not as the video-cap words.
- **Metering (contract §10, last bullet):** not built — see the slice hand-back (`## Continue`).
